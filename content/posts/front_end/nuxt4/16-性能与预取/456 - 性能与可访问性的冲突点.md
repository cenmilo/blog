把 Lighthouse 分数提上去的做法，和把键盘用户路走通的做法，不是每条都能同时满足。文档把两边要求写在两个分区里，谁也不提谁——所以冲突要靠你自己撞。

这一篇只做一件事：把冲突逐条放回**两边的原句**，然后说清哪一边可以让步、哪一边不行。

## 冲突一：永不水合 vs 需要交互

性能侧，延迟水合被写成提升可交互时间的手段，`hydrate-never` 是策略之一。

但组件目录那一页的最佳实践里，官方自己给它划了线：

> **Avoid `hydrate-never` on interactive components:** If a component requires user interaction, it should not be set to never hydrate.

同一节还有一条配套：每个策略都有它的适用场景（`hydrate-when` 适合不一定需要水合的组件、`hydrate-after` 适合能等固定时长的、`hydrate-on-idle` 适合浏览器空闲时才需要的）。

**这一条没有折中空间**：组件要交互，就不能设 `hydrate-never`。性能收益要从别的策略里找。

## 冲突二：真链接 vs 少一个组件

可访问性侧，Links 一节的理由是这么给的：

> Use `<NuxtLink>` for in-app navigation. It renders a real `<a href="...">`, which means it is focusable, appears in the tab order, and works with middle-click and "open in new tab", all of which you would have to reimplement on a `<div>` with a `@click` handler calling `navigateTo`.

注意它点名反面是什么：**一个带 `@click` 调 `navigateTo` 的 `<div>`**。这类写法有时是为了"少引一个组件、少一份预取"，而官方列出的代价是可聚焦性、tab 顺序、中键与新标签页打开——**这三项都不是能用 CSS 或属性补回来的**。

反过来也要清楚自己让掉了什么：`<NuxtLink>` 带来的是自动预取（442），不是负担——它只在浏览器空闲、非离线、非 2g 时才取。

## 冲突三：`custom` 拿到样式，丢掉预取

设计系统常常要求链接自己控结构，这就走到 `custom`。可访问性上没有损失（你仍然可以自己渲染 `<a>`），但性能侧那条 `::note` 写得很清楚：

> With the `custom` prop, `prefetch`, `prefetchOn` and `prefetchedClass` do not attach handlers or classes automatically. Use the custom slot's `prefetch`, `prefetched` and `shouldPrefetch` values to implement this behavior.

两全的办法官方也给了（`v4.5` 起的插槽示例）：把 `@pointerenter` 与 `@focus` 都接上，并且**先用 `shouldPrefetch('interaction')` 判断，再调 `prefetch()`**。少了前半句，等于绕过了浏览器忙/离线/2g 那套让步规则——性能与体验一起坏。

## 冲突四：`noScripts` 省掉 JS，也省掉交互

性能侧的 near-zero JavaScript 配方（453 末尾）依赖 `noScripts` 这条路由规则。可这一项自己的说明后半句是官方写死的：

> The page simply never hydrates, which means nothing on it is interactive.

同一节还补了一条更具体的：**交互岛屿在 `noScripts` 路由上不会变为可交互**——"`nuxt-client` 水合的组件与可交互的岛屿插槽依赖一段内联脚本来搬移 teleported 内容，所以在 `noScripts` 路由上它们不会变为可交互"。

CSS 不受影响（"CSS is unaffected: stylesheet links and inlined styles are still rendered, so the page looks identical"）——**页面看起来一模一样，但按不动**。这是最容易在项目里被忽略的一组：外观验收过不了这个问题，只有拿键盘或读屏点一遍才会暴露。

判据因此变成内容性质：纯读的文字页可以上 `noScripts`，任何需要点击、输入、展开的东西都不行。

## 冲突五：`external` 正确导航 vs 少一次预取

可访问性侧要求：链到 `public/` 里的文件或同域另一个应用时，要标 `external`，否则"浏览器会执行一次真实导航，而不是去匹配一个不存在的路由"。

性能侧要知道的是代价：`external` 让 `<NuxtLink>` 渲染成标准 `<a>` 并**绕开 Vue Router 的逻辑**（官方原话"bypassing Vue Router's internal routing mechanism"），于是这条链接不再走客户端导航那一套预取。

**这里可以让步的是性能**：静态文件和跨应用链接本来就不该被路由预取，标 `external` 才是正确的。

## 冲突六：占位、样式与位移

555 那篇的取舍在这里也有一个可访问性侧面。`ClientOnly` 把默认插槽 tree-shake 出服务端构建，官方括号里那句是 CSS 可能不内联；而 `clientNodePlaceholder` 那一节的 `::warning` 又写它会让 `class`/`style` 不进 SSR HTML。

两条都会造成**内容突然出现导致的位置变化**。对键盘与读屏用户，意外的布局位移会把焦点从刚激活的元素上带走。官方给的解法只有一句："If you need styled placeholders to prevent layout shift, use `<ClientOnly>` with a `#fallback` slot instead."——**占位要有真实结构和样式**。

## 冲突七：焦点管理插件 vs 插件成本

可访问性页给的"每次导航后把焦点移进主区"的配方，是一个客户端插件：

```ts [app/plugins/focus-main.client.ts]
export default defineNuxtPlugin(() => {
  useRouter().afterEach((to, from) => {
    if (to.path === from.path) {
      return
    }
    nextTick(() => document.getElementById('main')?.focus())
  })
})
```

性能页对插件的警告是：插件在水合阶段运行，数量多或初始化贵会造成阻塞。

这一对要不要取舍，取决于内容量：那个插件里只有一层 `afterEach` 加一次 `nextTick`，没有初始化开销。官方**没有给"这类小插件的成本量化"**（文档未记载），所以别拿性能页那句通用警告去否掉一条可访问性要求；真要判，就在 DevTools 的性能记录里看这段有没有出现在关键路径上。

顺带一提，同一页的 skip link 配方是纯 HTML 与 CSS（`position: absolute; left: -9999px`，聚焦时 `position: static`），**没有任何性能代价**，可以直接采纳。官方还提醒 `<main>` 本身不可聚焦，要给它 `tabindex="-1"`，并且不要用正值——正值会把元素插进别人的 tab 顺序里。

## 还有一处不是性能问题但值得记

Scroll Behavior 一节写着默认行为（新路由滚到顶部、返回时恢复位置、命中锚点时滚动），改法是指向 `scrollBehaviorType` 或自己写 `router.options.ts` 里的 `scrollBehavior`。最后一句是可访问性要求：

> Bear in mind that smooth scrolling should respect the user's `prefers-reduced-motion` setting.

**平滑滚动要尊重 `prefers-reduced-motion`。** 性能那一页没有提 reduced motion，也没给动画的成本句（文档未记载这一点），所以这条只能按可访问性要求执行，不用两边权衡。

## 自查

- 不能两全的一条：需要交互的组件不要设 `hydrate-never`（官方原话）。
- `<div @click>` 换掉 `<NuxtLink>` 丢的是可聚焦、tab 顺序与中键打开，这些补不回来。
- 用 `custom` 就得自己把 `prefetch` 接回去，并且先判 `shouldPrefetch`。
- `noScripts` 的页面外观一致但**没有任何东西可交互**，交互岛屿在其中也不会激活——只用在不需交互的内容页。
- 标 `external` 会失去路由预取，但那是正确行为；静态文件本来不该预取。
- 占位用 `#fallback` 给真实结构，避免位移把焦点带走。
- 焦点管理那个客户端插件很轻，别用性能页的通用警告去否它；skip link 零成本可直接加。
