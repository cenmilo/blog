首页要等接口回完才吐 HTML。浏览器在这两秒里什么都没有——空白屏、没有可点的东西。

流式渲染把这件事切成两段：**先给壳，再给正文**。Nuxt 这边是一个实验开关，代价写得比效果更详细。

## 开关做什么

官方定义一句，信息量很足：

> Enables SSR streaming to dramatically improve Time to First Byte (TTFB). When enabled, the server sends the HTML shell (including `<head>`, styles, preload hints, and entry scripts) immediately, then streams the rendered body content progressively using Vue's `renderToWebStream`.

四个要素：**目标是 TTFB**、**壳里含哪四样**（head、样式、预加载提示、入口脚本）、**正文用 Vue 的 `renderToWebStream` 逐步推**、发送顺序是壳立刻、正文随后。

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  experimental: {
    ssrStreaming: true,
  },
})
```

这一节没有"enabled by default"那句，按默认关处理。

## 代价一：状态与响应头有个分界线

官方把这条写成一句原则加一份清单：

> Streaming commits the HTTP status and headers with the first byte, so anything that mutates the response after that point cannot reach the client. This is inherent to streaming, not a Nuxt-specific bug.

分界线就是壳冲出去那一刻（The boundary is the shell flush）：

| 位置 | 结果 |
| --- | --- |
| Nuxt 插件与 Nitro 插件里的改动（渲染开始前跑完） | **能到客户端** |
| 组件渲染期间写的 `setResponseStatus()`、`useResponseHeader()`、`useCookie()` 写入，以及 h3 的 `setHeader()`/`appendResponseHeader()` | **被丢弃**——包括在路由中间件或 `<script setup>` 里 `await` 之后写的 |

想保住一次响应改动，官方给两条路：**把它挪进插件**，或者**把这条路由请出流式**——静态地用 `routeRules: { '/path': { streaming: false } }`，或者在 `render:route` 钩子里设 `ctx.prefersStream = false`（按请求决定）。

开发模式下这条不会静默失败：流式处理器会打一条警告，点名被丢弃的改动和路由。

## 代价二：head 标签注册得赶在壳之前

另一条 `::warning` 讲的是 SEO 最容易中的一处：

> The renderer waits for the first render pass before flushing the shell, so `useHead`/`useSeoMeta` called synchronously in `<script setup>` (before any `await`), in plugins, or in middleware render into the shell `<head>` as usual. Tags registered later (after an `await` in setup, or inside a nested `<Suspense>` boundary) cannot reach the already-sent `<head>`; they are delivered as inline scripts that patch the DOM on the client.

所以三类标签分三种命运：

| 标签来源 | 流式下的去向 | 谁能看见 |
| --- | --- | --- |
| setup 里同步（任何 `await` 之前）、插件、中间件里注册的 | 进壳的 `<head>` | 所有人 |
| `await` 之后或嵌套 `<Suspense>` 里注册的 | 变成内联脚本，客户端打补丁 | **只有效果 JS 的客户端**；不在 `botRegex` 里的爬虫、链接预览抓取器、`curl` 完全看不到 |
| JSON-LD、`noscript`、正文位置的标签 | 在 `</body>` 前渲染成真标记 | 所有人 |

官方的结论句是：把其他 SEO 关键标签（canonical、社交卡片 meta）保持同步注册，或者给这条路由关掉流式。

## 七种请求会自动退回缓冲

第一条 `::warning` 列了完整清单——这些情况下不发流，改用缓冲渲染，或者直接短路成重定向/错误响应：

1. `routeRules` 给该路由设了 `noScripts`、`cache`、`isr`、`swr`、`redirect` 或 `streaming: false`
2. `ssr: false` 的路由（本来就是 SPA 渲染）
3. 命中 `botRegex` 的爬虫/机器人 user-agent
4. 预渲染的路由（`nuxt generate`）
5. 服务端 `navigateTo()` 重定向，来自插件、中间件或页面 setup
6. 初始渲染（壳冲出去之前）抛出的致命错误

这里能看到一个交叉影响：**缓存类路由规则和流式互斥**。第 451 篇讲 `swr`/`isr` 时你会发现，给一条路由加缓存等于把它排除在流式之外。

## 爬虫默认被排除在流式之外

> Streaming is automatically disabled for bot and crawler user agents (such as Googlebot, Bingbot, etc.) to ensure search engines receive fully-rendered HTML for SEO safety. The default pattern matches indexing crawlers only; Lighthouse and other audit tools deliberately fall outside it so synthetic measurements reflect the same streamed response real users get.

两点要注意：**默认模式只匹配索引类爬虫**，Lighthouse 是**故意不匹配**的（这样你测到的就是真实用户拿到的那份流式响应）；而 `botRegex` 是**替换**默认模式而不是追加——官方原话是"list every crawler you want to keep out of streaming"，所以自定一个就要把想排除的都列全：

```ts
experimental: {
  ssrStreaming: {
    botRegex: /googlebot|bingbot|my-internal-crawler/i,
  },
}
```

按路由控制则是 `routeRules` 里加 `'/no-stream/**': { streaming: false }`。

## 样式：两段 FOUC 都有官方说明

第一条是开发模式的：

> in development, Vite serves SFC `<style>` blocks as JavaScript modules that inject styles client-side after the module evaluates, with no corresponding `<link>` in the shell. With streaming, the browser starts painting the streamed DOM before those style-injection modules run, so SFC-defined styles flash unstyled briefly.

官方的解法是把**决定首屏外观的样式放进全局 CSS**（`css: ['~/assets/main.css']`），因为全局 CSS 会以 `<link rel="stylesheet">` 进壳的 `<head>`，在正文开始流之前就生效；并提醒这条**只影响 `nuxt dev`**，生产构建会把样式抽成真实 CSS 文件（或按 `features.inlineStyles` 内联），**要用 `nuxt build && nuxt preview` 验流式的视觉效果**。

第二条是生产环境的，位置在嵌套异步组件上。官方的解释连着样式归属：

> An async component that is rendered *inside another async component* is instantiated only once its parent resolves, after the first chunk has streamed. Its SFC `<style>` misses the post-shell styles chunk and is emitted in the closing HTML instead, behind the component's own DOM.

四条规避方法（官方列的）：把影响首屏的样式放全局 CSS；用工具类样式（Tailwind、UnoCSS，它们进的是入口样式表）；把自带关键 `<style>` 的异步组件直接放在 `<Suspense>` 边界下面而不是套在另一个异步父组件里；或者给该路由关流式。最后一句划了范围：**不在首屏的、非关键的 scoped 样式没问题**，那一下闪只影响 above-the-fold 内容。

顺带把壳里到底有什么说清（这条 `::note` 也解释了 LCP 收益从哪来）：

> **Route styles are streamed, JS hints are entry-only.** ... Streaming improves TTFB on every route; LCP gains are largest on routes whose JS overlaps the entry chunk.

也就是：**TTFB 每条路由都改善，LCP 的收益在"路由 JS 与入口 chunk 有重叠"的那些路由上最大**；路由自己的 JS chunk 不会从壳里预加载，浏览器要解析完入口脚本才发现它们。

## 出错与岛屿

流式已经开始后报错（HTTP 状态已提交）：`payload.error` 被设上，闭合标签照样发成一个完整文档，**客户端在水合时接到错误并渲染错误页**。壳冲出去之前就报错：走缓冲错误渲染，带正确的状态码。

组件岛屿是兼容的：官方说渲染器把每个岛屿的 teleport 作为惰性的 `<template>` 发在文档末尾，再用一段在**水合之前**执行的内联脚本搬回原位，对应用代码透明。例外是 `features.noScripts` 加岛屿——搬位的脚本不能跑，于是退回缓冲渲染。

CSP 也处理了：流式渲染器会发出几段绕过 unhead 的内联脚本与样式（bootstrap 队列、IIFE、suspense head 推送、岛屿搬位、路由 `<style>`），**如果渲染出的 head 脚本上有 `nonce`，渲染器会自动复用到所有这些上面**，模块只需给 head 脚本加 nonce；要给组件渲进正文的脚本打 nonce，用 `render:html:chunk`。

## 模块怎么接

四个钩子，官方列明各自时机与能改什么：

| 钩子 | 时机 | 可用信息 / 能改什么 |
| --- | --- | --- |
| `render:route` | 每次请求、渲染开始前（流式与否都触发） | 读 `ctx.canStream` 看这条路由能不能流；设 `ctx.prefersStream = false` 强制本次用缓冲。**只有 `canStream && prefersStream` 才流式** |
| `render:html` | 壳冲出去之前触发一次，第二个参数带 `streaming: true` | `htmlAttrs`、`head`、`bodyAttrs`、`bodyPrepend` 的改动能上线；`body`/`bodyAppend` 的改动被丢弃（开发模式警告）。只改 head 的模块（CSP、OG、统计 meta）无需改代码 |
| `render:html:chunk` | 渲染器每产出一段、入队之前 | 改 `ctx.chunk: Uint8Array` 做字节级转换（例如注入 nonce）；读 `ctx.index` 分辨首段与后续段 |
| `render:html:close` | 正文流结束后、闭合标签之前 | 改 `ctx.bodyAppend: string[]` 追加末尾标记（正文末的统计脚本、服务端渲染的调试块） |

官方的 Nitro 插件示例（给 head 里的 script 补 nonce，流式与缓冲两条路都适用）：

```ts
export default defineNitroPlugin((nitro) => {
  nitro.hooks.hook('render:html', (ctx, { event }) => {
    const nonce = event.context.cspNonce
    if (!nonce) { return }
    for (let i = 0; i < ctx.head.length; i++) {
      ctx.head[i] = ctx.head[i].replace(/<script(?![^>]*\snonce=)/g, `<script nonce="${nonce}"`)
    }
  })
})
```

## 自查

- 开的是 `experimental.ssrStreaming`，效果是壳立刻发、正文用 `renderToWebStream` 推；目标是 TTFB。
- 两条硬分界：状态与响应头必须在壳之前定；head 标签必须在壳之前注册。
- 七种情况自动退回缓冲，其中包括**该路由有 `swr`/`isr`/`cache`/`noScripts`/`redirect`**。
- `botRegex` 是替换不是追加；Lighthouse 故意不匹配。
- 开发模式 SFC 样式会闪、生产环境嵌套异步组件会闪，解法都是把首屏关键样式挪到全局 CSS 或工具类，验证要跑 `nuxt build && nuxt preview`。
- 出错时分两种：壳前走缓冲错误页带正确状态码，壳后靠 `payload.error` 让客户端渲染错误页。
