前面几篇都是一个组件一个组件地讲。这一篇换一个视角：**一次点链接，页面上哪些东西不动、哪些东西换掉，为什么这么切。** 这个"不动的部分"就是应用外壳。

## 官方确实用了 shell 这个词

在讲静态托管兜底时，官方的原话是：**"静态主机需要为客户端路由和缺失路径提供一个 HTML shell（外壳）。"** 为此 Nuxt 发出两个 SPA 兜底文件：

| 文件 | 官方说明 |
| --- | --- |
| `200.html` | 当你希望**由客户端路由来接手这个 URL** 时，对未匹配的路径提供这个文件 |
| `404.html` | 当主机应当**保持 404 状态、同时仍然加载你的应用**时，提供这个文件 |

这两句把外壳的定义说尽了：**外壳是那份"先撑住界面、再把路由交给浏览器"的 HTML。** 它必须能在任何路径下都渲染出一个可用的骨架——因为主机不知道用户要的页面存不存在。

## 组件层面：固定区与路由区的分界

把 090 那张五层表按"换不换"重新排一次：

| 区域 | 归谁 | 官方给的"换/不换"依据 |
| --- | --- | --- |
| **固定区**：布局 | `app/layouts/*.vue` | 定义就是"包裹在你的页面外层、**避免在页面之间重新渲染**的 Vue 组件" |
| **固定区**：根组件 | `app.vue` | 默认入口点，**为应用的每一个路由渲染其内容**；往它加的东西（JS 和 CSS）全局生效、每个页面都包含 |
| **固定区**：进度条 | `<NuxtLoadingIndicator>` | 用途是"在页面导航**之间**显示一个进度条"；放在 `app.vue` 或 `app/layouts/`，与出口并列 |
| **固定区**：播报 | `<NuxtRouteAnnouncer>` | 渲染一个隐藏 live region，**在每次导航之后**写入新的页面标题；同样与出口并列 |
| **路由区**：页面 | `<NuxtPage>` + `app/pages/*.vue` | 页面"为每一个特定路由模式表示一个视图"；`app/pages/` 里每个文件代表一个不同路由 |
| **路由区**：布局选择 | 页面元数据 | "自定义布局可以作为页面元数据的一部分来设置"——布局归属固定区，但**选哪个**是路由区决定的 |
| **交接处**：出口本身 | `<NuxtPage>` | 它是 `<RouterView>` 的包装，"额外照管内部状态" |

注意"布局选择"这一行：**选哪个布局是随路由变的，布局内容是不变的**。这也是官方建议"只有一个布局就用 `app.vue` + `<NuxtPage />`"的原因——那时候所谓布局其实就属于固定区，套一层 `layouts/default.vue` 只是多绕一手。

## 为什么换页顺序决定了外壳该怎么写

外壳最怕的一件事是"它以为页面已经卸载了"。官方对 `<NuxtPage>` 的说明正好给了这条：

> 在一个典型的 Vue 应用中，新的页面组件**只有在前一个组件完全卸载之后**才会挂载。然而在 Nuxt 中，由于 Vue `<Suspense>` 的实现方式，新的页面组件会在前一个组件卸载**之前**挂载。

于是固定区必须接受一个事实：**换页的那段时间里，新旧两个页面同时存在。** 三条直接影响外壳的结论：

1. 外壳里"页面卸载后再做什么"的逻辑不可靠——因为新页面已经挂载了。依赖全局副作用（滚动位置、共享 ref、`document` 上的事件）的代码要能扛住这段重叠。
2. 布局的 `onMounted` 不会因为换页而重跑（这正是它存在的理由——避免页面之间重新渲染），所以**每个页面都要有的东西不能指望布局重新初始化**。
3. 反过来，路由区里的东西会在换页时重建或复用——由 `pageKey` 决定（092），这是外壳与路由区之间唯一的"要不要重建"开关。

## 固定区的三个成员各自站在哪

`app.vue` 里的结构，官方给的形态就是这样：

```vue [app/app.vue]
<template>
  <NuxtLoadingIndicator />
  <NuxtRouteAnnouncer />
  <NuxtLayout>
    <NuxtPage />
  </NuxtLayout>
</template>
```

三个要点：

- `<NuxtLoadingIndicator />` 和 `<NuxtRouteAnnouncer />` 都是**与页面出口并列的兄弟节点**，官方在两处示例里都是这么放的——它们不包裹任何内容，只是各自占一份 DOM。
- `<NuxtLayout>` 包 `<NuxtPage>`：布局负责外壳的"可视结构"（页头页脚），页面出口是它 `<slot />` 的落点。
- 单布局时可以不要 `<NuxtLayout>`，直接把 `<header>` + `<NuxtPage />` + `<footer>` 并列写在 `app.vue` 里，官方给的正是这个形态。

固定区还有第四种形态：**多出口**。v4.5 的命名视图让一个路由同时填进父组件里的多个 `<NuxtPage>` 出口（`<NuxtPage />` 与 `<NuxtPage name="sidebar" />`），这时"固定"与"更换"的边界被下推到页面内部——主列换页、侧栏按另一个名字换，URL 不变。

## 进度条与播报是外壳的"反馈层"

这两个组件容易被当成装饰，其实它们是外壳存在的意义：**路由区更换时，用户需要知道发生了导航，而浏览器已经不告诉他了。**

官方的原因写得很清楚：一旦应用完成水合，路由就在客户端进行，**document 永远不会被重新加载，浏览器也不再替你播报新页面或重置焦点**。

| 反馈 | 由谁提供 | 关键默认值 |
| --- | --- | --- |
| 视觉上的"正在换页" | `<NuxtLoadingIndicator>` | `height` 3 像素、`duration` 2000 毫秒、`throttle` 200 毫秒（快于间隔的起止被吞掉） |
| 读屏软件知道换了页 | `<NuxtRouteAnnouncer>` | `politeness` 默认 `polite`、`atomic` 默认 `false`；**播报内容取自 document 标题** |
| 页内变化（非导航）的播报 | `<NuxtAnnouncer>` + `useAnnouncer` | 官方要求：不是导航的页内更新要用这两个，别用路由 announcer |

**播报那一格有个前提**：announcer 读的是 Unhead 渲染出的标题，如果两个路由共用同一个 `<title>`，用户在它们之间什么都听不到。所以外壳要做响，标题必须每个路由不同。

## 切到纯客户端时，外壳换成人

如果你把整站设成 `ssr: false`——官方给的写法就是这一行配置——那么连"首屏"都不再有服务端产物，外壳要提前一步出现。官方的要求是：

> 如果你使用了 `ssr: false`，你也应当在 `~/spa-loading-template.html` 放置一个 HTML 文件，写入你希望用来渲染加载屏的 HTML；**它会一直渲染到你的应用完成水合。**

这一篇不展开它（下一篇 104 专讲），只要记住它在分层里的位置：**它是水合之前唯一的一份内容，比 `app.vue` 更早，甚至不属于 Vue 组件树。**

## 一张自查用的清单

| 问题 | 判据 |
| --- | --- |
| 这块内容换页时要不要保留？ | 要保留 → 属于固定区（`app.vue` / 布局 / 两个反馈组件）；不要 → 属于 `app/pages/` |
| 不同页面需要不同外壳吗？ | 需要 → `app/layouts/` + 页面元数据；只需要一套 → 按官方建议写在 `app.vue` |
| 这段代码是不是"每个页面都要"？ | 是 → 放固定区，但注意官方那句"加进 `app.vue` 的 JS 和 CSS 是全局的"，体积也是全局的 |
| 它是不是靠"上一个页面已卸载"来工作？ | 是 → 需要重写，因为新页面在旧页面卸载**之前**就挂载 |
| 用户怎么知道导航发生了？ | 固定区里要有一个答案：进度条、标题变化，或两者 |
