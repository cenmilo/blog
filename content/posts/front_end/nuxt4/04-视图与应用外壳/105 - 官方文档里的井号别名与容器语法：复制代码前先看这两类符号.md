照着文档抄代码，最常撞上的两类怪东西：一种是 `import ... from '#app'` 里那个带井号的包名，一种是文档里那些 `:::note`、代码块顶上那个方括号文件名。这一篇把它们一次认全——**前者要照抄，后者必须丢掉。**

## 一、以 `#` 开头的是别名，不是包名

先看官方 `alias` 配置项给出的默认值，全表十项：

```json
{
  "~": "/<rootDir>/app",
  "@": "/<rootDir>/app",
  "~~": "/<rootDir>",
  "@@": "/<rootDir>",
  "#shared": "/<rootDir>/shared",
  "#server": "/<rootDir>/server",
  "assets": "/<rootDir>/app/assets",
  "public": "/<rootDir>/public",
  "#build": "/<rootDir>/.nuxt",
  "#internal/nuxt/paths": "/<rootDir>/.nuxt/paths.mjs"
}
```

这一表里有四点值得单独记住：

| 结论 | 依据 |
| --- | --- |
| 带 `#` 的**也是别名**，和 `~`/`@@` 同级 | 它们就写在 `alias` 的默认值里 |
| 别名指向的是**目录/文件**，不是 npm 包 | 右值全是路径 |
| 编辑器能认，是因为官方那句"**这些别名会被自动加入生成的 TypeScript 配置**（`.nuxt/tsconfig.app.json`、`.nuxt/tsconfig.server.json` 等），所以你直接就有完整的类型支持与路径自动补全" | 类型来自生成的那几份配置（076） |
| webpack 上下文里访问别名**必须加 `~` 前缀** | 官方 callout："Within a webpack context (image sources, CSS - but not JavaScript) you *must* access your alias by prefixing it with `~`." |

最后一行是历史坑：图片源和 CSS（但不含 JavaScript）走 webpack 那条解析，别名前面不加 `~` 就找不到。

## 二、四个高频井号别名各自管什么

| 说明符 | 官方定位 | 用在哪 |
| --- | --- | --- |
| `#shared` | 在 `alias` 默认表里，指向 `/<rootDir>/shared`；官方另有原文："你在 `shared/` 文件夹里创建的其他任何文件都必须使用 `#shared` 别名（由 Nuxt 自动配置）来手动导入" | `import capitalize from '#shared/capitalize'` |
| `#server` | 在 `alias` 默认表里，指向 `/<rootDir>/server`；"你可以用 `#server` 别名从 `server/` 目录里的任何位置导入文件" | `import { formatUser } from '#server/utils/formatUser'` |
| `#build` | 在 `alias` 默认表里，指向 `/<rootDir>/.nuxt`；构建器页也说虚拟应用（入口、路由表、插件、组件注册表等）"在 `#build` 之下" | `import metaConfig from '#build/meta.config.mjs'` |
| `#internal/nuxt/paths` | 在 `alias` 默认表里，直接指向一个文件 `/<rootDir>/.nuxt/paths.mjs` | 框架内部路径工具 |
| `#imports` | **不在上面那张表里**，但官方有原文："Nuxt 用 `#imports` 别名暴露每一个自动导入，必要时可以用它把导入写成显式的" | `import { computed, ref } from '#imports'`、`import { updateAppConfig, useAppConfig } from '#imports'` |
| `#app` | **也不在那张表里**，却是官方示例里最常用的说明符 | `import { useRoute } from '#app'`、`import type { NuxtError } from '#app'`、`import type { $Fetch } from '#app'` |

`#app` 那一条有个必须看到的上下文。官方在 `useRoute` 那一页把两种写法并排贴出来：

```ts
// @errors: 2300
import { useRoute } from 'vue-router'
// ✅ use Nuxt's `useRoute` composable
import { useRoute } from '#app'
```

**`// @errors: 2300` 那行是给上面那句标错的**——也就是说显式导入时，`from 'vue-router'` 是官方点名的问题写法，`from '#app'` 才是打了勾的那个。

`#server` 还有一条范围限制，官方写成 note：**`#server` 别名只能在 `server/` 目录内使用，在客户端代码里从 `#server` 导入会导致错误。**

## 三、这些不是别名：`~` 开头的路径与 `@`

`~`、`@`、`~~`、`@@` 四格也在同一张默认表里，其中 `~` 与 `@` 都指向 `<rootDir>/app`、`~~` 与 `@@` 都指向 `<rootDir>`。

顺带一条容易混的：官方文档里大量出现的 `~~/server/api/hello.ts` 这种写法，就是"相对 `rootDir`"的意思（086 讲过基准为什么是 `rootDir`）。看到 `~~/` 开头，脑子里换成"项目根目录"即可。

## 四、文档站的排版语法：复制时要丢掉的

文档正文不是纯 Markdown，而是带组件语法的写法。你复制时会撞见这些：

| 你看到的 | 它是什么 | 该怎么办 |
| --- | --- | --- |
| `::note` … `::`、`::tip` … `::`、`::warning` … `::` | 提示框 | 只读内容，行本身丢掉 |
| `:::callout{type="warning"}` … `:::` | 带类型的提示卡（官方配置参考页大量用它，例如 `server.builder` 那条"供内部使用、API 未定稿"的警告就是 `:::callout{type="warning"}`） | 同上 |
| `::code-group` … `::` | **并列的多个代码标签页**，通常是"同一件事的 npm / pnpm / yarn / bun 版本"或"app.vue / pages/index.vue 两个文件" | 挑你用的那一个标签页抄，别整段抄 |
| `::read-more{to="..."}` | 指向另一页的链接卡 | 顺着链接读，那页才是完整说明 |
| `::link-example{to="..."}` | 官方示例仓库链接（例如 `https://nuxt.com/docs/examples/routing/pages`） | 想看可运行代码就点它 |
| `::video-accordion{title="..."}` | 折叠的视频 | 忽略，纯附加材料 |
| 标题后面的 `:badge[v4.5]{color="info" size="xs" .align-middle}` | **版本徽章** | 必须看！见下 |

这些是文档站的渲染指令，不是 Vue 也不是 TypeScript 的语法。**把它们连行一起粘进 `.vue` 或 `.ts`，构建不会替你转换**：在模板里它们就是一行普通文本，在 `<script>` 里就是非法语句或注释。

## 五、徽章与文件标签：不能丢的两类信息

上面那张表里大部分符号可以直接扔掉，但**有两类必须读进去**，因为它们承载的是"能不能用"和"放哪儿"。

### 版本徽章

官方在章节标题上直接标版本，例如：

- `## Server Alias :badge[v4.3]{...}` → `#server` 别名是 v4.3 起的
- `## Named Views :badge[v4.5]{...}` → 命名视图（`name@view.vue`）是 v4.5 起的
- 组件页用 important 块标：`<NuxtRouteAnnouncer>` "This component is available in Nuxt v3.12+."、`<NuxtTime>` "This component is available in Nuxt v3.17+."
- 布局 props 标 `:badge[v4.4]{...}`

**抄之前先看这一格**：本机 Nuxt 版本低于徽章要求的，那段代码不会生效。版本对照的做法是用 `nuxt info` 看当前项目信息（042）。

### 代码块的文件标签

三反引号后面带方括号，那是**文件名与位置**，不是代码：

```vue [app/app.vue]
<template>
  <NuxtPage />
</template>
```

```bash [Terminal]
npx nuxt cleanup [ROOTDIR] [--cwd=<directory>]
```

| 标签写法 | 含义 |
| --- | --- |
| `[app/app.vue]`、`[server/api/hello.ts]`、`[error.vue]` | 这段代码该放在这个路径（注意 Nuxt 4 的 `app/` 前缀） |
| `[nuxt.config.ts]`、`[props]` | 配置文件 / 参数说明 |
| `[Terminal]`、`[npm]`、`[pnpm]` | 命令与包管理器版本 |
| `[Directory Structure]` | 这不是代码，是目录树 |
| `[With useHydration]` / `[Without useHydration]` | 前后对比的两段，配合 `::code-group` 使用 |

`::code-group` 外面还常见一个 `{sync="pm"}` 之类的参数（安装页那组就是），意思是**这几段是同一操作在不同包管理器下的同步标签页**——挑自己那一个抄。

## 六、复制前四步检查

1. **看标题上有没有 `:badge[...]`**，对一下自己的 Nuxt 版本。
2. **看围栏上方的 `[文件路径]`**，确认落到的目录对不对（尤其 `app/` 前缀与 `server/` 是相对 `rootDir`）。
3. **只取围栏内部的代码**，把 `::note`、`:::callout`、`::code-group` 这些行删掉；标签页只留你在用的那一个。
4. **确认 `#` 说明符是原样保留的**——`#imports`、`#app`、`#server`、`#shared`、`#build` 都是要照抄的，别顺手改成相对路径；改成相对路径在 `server/` 深层路由里尤其容易出事（官方写 `#server` 的动机就是"避免 `../../../utils/formatUser` 这种相对路径"）。
