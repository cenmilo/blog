  摘要：这一篇把视图这一层从请求到屏幕串成一条链路，并给出每一站的判据。链路是：**一次 URL 请求 → 服务器环境里运行 Vue 代码 → 返回一份完整渲染的 HTML → 浏览器解释它、Vue 重新接管并水合 → 之后路由在客户端进行、document 不再重新加载**。水合之前有一份只属于它的界面：**如果你用了 `ssr: false`，就应当在 `~/spa-loading-template.html` 放一个 HTML 文件，它会一直渲染到应用完成水合**——这一层比 `app.vue` 更早，而且不属于组件树。组件层的官方定义是"Nuxt 提供若干组件层级来实现应用的用户界面"，第一站是 `app.vue`：**默认情况下 Nuxt 把这个文件当作入口点，并为应用的每一个路由渲染它的内容**，所以往它里面加的任何东西（JS 与 CSS）都会是全局的、包含在每一个页面里。第二站是 `<NuxtLayout>`：**用 `<NuxtLayout />` 组件可以在 `app.vue` 或 `error.vue` 上激活 `default` 布局**，布局是"包裹在你的页面外层、避免在页面之间重新渲染的 Vue 组件"，用 `<slot />` 显示页面内容，`app/layouts/default.vue` 默认使用，自定义布局作为页面元数据设置，而**只有一个布局时官方建议改用 `app/app.vue` 配 `<NuxtPage />`**。第三站是 `<NuxtPage>`：它是"显示位于 `pages/` 目录中的页面所必需的"、是 Vue Router `<RouterView>` 外层的包装并"额外照管内部状态"，否则 `useRoute()` 可能返回不正确路径；它内部依次是 RouterView →（可选 Transition）→（可选 KeepAlive）→ Suspense → `<component :is="Component" />`，因此换页时**新页面会在前一个组件卸载之前挂载**。第四站才是页面自己的内容，而它可以再放一个 `<NuxtPage>` 来装子页面（官方："要显示 `child.vue` 组件，你必须插入 `<NuxtPage>` 组件到 `app/pages/parent.vue` 内部"），也可以用 `name@view.vue` 与 `<NuxtPage name="sidebar" />` 开多个出口。最外面还有一层可以跳过客户端 JS：**服务端组件（官方同时称"也叫岛屿组件"）在服务器上渲染、HTML 嵌入页面、它的 JavaScript 一点都不会发给客户端，其依赖（markdown 解析器、高亮库）同样留在服务器上**。

视图这一层讲了不少篇目。这一篇不分新知识点，只做一件事：**把一次请求走到屏幕的每一步排成一条链，每步标上"谁来管、判据是什么、去哪一篇细看"。** 卡住的时候按这条链从上往下找。

## 一条链路

```
一次 URL 请求
   ↓
服务器环境里运行 Vue 代码，返回一份完整渲染的 HTML（内容已在页面里，爬虫不必等）
   ↓
浏览器解释这份 HTML → Vue 再次运行同一份代码、绑定监听 → 这一步叫水合（Hydration）
   ↓
此后路由在客户端进行：document 不再重新加载，浏览器不再替你播报新页面、也不重置焦点
   ↓
app.vue（入口点，为每一个路由渲染其内容）
   ├── <NuxtLoadingIndicator />   固定区：导航之间的进度条
   ├── <NuxtRouteAnnouncer />     固定区：把新页面标题写进隐藏 live region
   └── <NuxtLayout>               固定区：包裹页面、避免页面之间重新渲染
         └── <slot />  ← 这里落 <NuxtPage />
               └── 页面组件（app/pages/*.vue）
                     ├── <NuxtPage />          子页面出口（嵌套路由必须自己插）
                     ├── <NuxtPage name="…">   命名视图出口（v4.5）
                     ├── 组件（app/components/*.vue，自动导入）
                     └── 岛屿 / .server.vue     客户端零 JS
```

图上每一站的证据：

| 站 | 官方依据 | 篇目 |
| --- | --- | --- |
| 服务端跑 Vue 代码 | "Nuxt 在服务器环境里运行 JavaScript（Vue.js）代码，并向浏览器返回一份完整渲染的 HTML 页面" | 027、090 |
| 水合 | "曾经在服务器上运行的同一份 JavaScript 代码，现在在客户端（浏览器）**再一次**运行，通过把它的监听器绑定到 HTML 上使页面可交互（因而称为**通用渲染**）。这被称为 **水合**。" | 090、103 |
| 客户端导航后 | "一旦你的应用完成水合，路由就在客户端进行，于是 document 永远不会被重新加载，浏览器也不再替你播报新页面或重置焦点。" | 101、103 |
| `app.vue` | "默认情况下，Nuxt 把这个文件当作**入口点**，并为应用的**每一个路由**渲染它的内容。" | 054、090 |
| 固定区两个组件 | 两者官方都要求放 `app.vue` 或 `app/layouts/`，且与页面出口并列 | 101、102 |
| 布局 | "布局是包裹在页面外层、为多个页面包含公共 UI 的包装器"；"`app/layouts/default.vue` 会被默认使用" | 059、094 |
| 页面出口 | "`<NuxtPage>` 组件是显示位于 `pages/` 目录中的页面所必需的" | 091、092 |
| 子页面 | "要显示 `child.vue` 组件，你必须插入 `<NuxtPage>` 组件到 `app/pages/parent.vue` 内部" | 092 |
| 命名视图 | "单个路由可以通过给每个出口一个 `name` 渲染进父组件里的多个 `<NuxtPage>` 出口" | 092 |
| 岛屿 | "它在服务器上渲染，它的 HTML 被嵌入页面，而它的 JavaScript 一点都不会发给客户端。" | 106、107 |

## 链路之外还有三个入口

这三样不在图上，但同一时间可能出现在屏幕上，找错位置会白查：

| 情况 | 走的是哪条路 | 判据 |
| --- | --- | --- |
| 出错 | **`error.vue`**，它不是路由、不能用 `definePageMeta` | 页面渲染链之外的独立入口（056） |
| `ssr: false` | 首屏由 **`~/spa-loading-template.html`** 顶着，直到应用完成水合 | 这段比 `app.vue` 更早、不属于组件树（104） |
| 静态托管兜底 | **`200.html`**（让客户端路由接手）与 **`404.html`**（保持 404 状态同时仍加载应用）；默认 `404.html` 是个空壳 | 由 `nuxt generate`/`nuxt build --prerender` 写出，普通 `nuxt build` 不写（103） |

## 四张总表

### 表一：单根元素到底在哪儿是硬要求

| 场景 | 官方要求 |
| --- | --- |
| 页面 | "页面**必须有单个根元素**以便页面之间的路由过渡。**HTML 注释也被视为元素。**" |
| 启用 `<Transition>` 的页面组件 | "如果你在页面组件里启用 `<Transition>`，请确保该页面只有一个根元素。" |
| 要动画化的页面或布局 | "你想动画化的页面或布局必须有**单个根元素**。多个根元素（片段）的页面或布局无法被动画化，所以过渡不会运行、在路由之间导航甚至可能报错。" |
| 服务端组件与岛屿 | "服务端组件（以及岛屿）必须有单个根元素。（HTML 注释也被视为元素。）" |
| 布局的根 | 根元素不能只是 `<slot />`；做布局过渡时官方建议 `<NuxtLayout />` **不要**当页面根元素 |

**这四条是同一件事的不同入口**，遇到"过渡不跑/岛屿渲染异常"先数根元素——包括注释。

### 表二：什么代码会在服务端跑

| 代码 | 官方结论 |
| --- | --- |
| `<script setup>` 里的 `const counter = ref(0)` | "在服务端和客户端环境都执行" |
| 事件回调 `handleClick` 的函数体 | "只在客户端环境执行" |
| middlewares 与 pages | "在服务端运行，并在客户端水合时运行" |
| 插件 | "可以在服务端或客户端或两者渲染"（**注意：渲染岛屿时插件会再跑一遍**，除非对象式插件设 `env: { islands: false }`） |
| 组件 | "也可以被强制只在客户端运行"（`<ClientOnly>`）；反向是岛屿（客户端零 JS） |
| 组合式函数与工具 | "按其使用上下文渲染" |

### 表三：水合时机的三个特例

| 现象 | 原因（官方原话） |
| --- | --- |
| 换页时新页面先挂载、旧页面后卸载 | "由于 Vue `<Suspense>` 的实现方式，新的页面组件会在前一个组件卸载**之前**挂载。" |
| `fullPath` 渲染进模板造成不匹配 | 浏览器发出的请求不带片段（`#` 之后的部分），服务端那次算出来的值与客户端不同（路由篇展开） |
| 岛屿里用 `useId` 造成不匹配 | "`nuxt-client` 加载的组件在岛屿的应用里服务端渲染、却由主客户端应用水合，所以 `useId` 在服务端与客户端返回不同的值，造成水合不匹配。" |

### 表四：配置侧的四个同名项

| 你写的 | 管什么 | 别和谁混 |
| --- | --- | --- |
| `spaLoadingTemplate` | `ssr: false` 页面的水合前加载屏 | `devServer.loadingTemplate`（类型 `function`，开发服务器） |
| `app.pageTransition` / `app.layoutTransition` | 全局页面/布局过渡 | `<NuxtPage :transition>` 上的过渡**不能**被单页 `definePageMeta` 覆盖 |
| `experimental.componentIslands` | 岛屿（默认 `'auto'`，出现岛屿即启用） | `ssr: false`（整站不服务端渲染） |
| `experimental.clientFallback` | `<NuxtClientFallback>` 的总开关 | 不开就没有这个组件 |
| `app.config.ts` | 响应式、可两侧访问、**会进客户端包** | `runtimeConfig`（服务端私有、可被 `NUXT_` 环境变量覆盖） |

## 八种常见错法与对应站

| 现场 | 卡在哪一站 | 篇目 |
| --- | --- | --- |
| 页面空白、内容不显示 | `app.vue` 里没有 `<NuxtPage />`（或没有 `app/pages/`） | 090 |
| 嵌套子页面空白 | 父页面里没插 `<NuxtPage>` | 092 |
| 布局完全没套上 | 布局名没规范化（`errorLayout.vue` 要传 `error-layout`），或名字无效又不带 `fallback` | 094 |
| `useRoute()` 路径不对 | 用 `<RouterView>` 替了 `<NuxtPage>` | 091 |
| 换页时副作用重复触发 | 没考虑新页面在旧页面卸载前挂载 | 091、103 |
| 过渡不跑 | 页面多根元素，或同时换布局却只配了 `pageTransition` | 091、094 |
| 读屏用户听不到换页 | 两个路由共用同一个 `<title>` | 101 |
| 岛屿里的状态读不到 | 岛屿是隔离的 Vue 应用，provide/inject、Pinia、`useState` 都过不去，只能传 props | 106 |

## P04 收尾

到这里，"界面是怎么拼出来的"这条线已经完整：**外壳（固定区）+ 出口（`<NuxtPage>`）+ 页面（含子页面与命名视图）+ 特殊层（错误页、加载屏、兜底文件、岛屿）**。从下一篇开始换一条线：**路由**——文件怎么变成路由记录、参数怎么取、中间件怎么拦、过渡怎么配。

  - 原文："Server components (also called island components) invert this. A server component is rendered on the server, its HTML is embedded in the page, and none of its JavaScript is sent to the client. Its dependencies (a markdown parser, a highlighting library) stay on the server too."
