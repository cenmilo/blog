## 屏幕上那行注释

`server/api/console/metrics.get.ts` 文件头原来有这一行：

```
// 文件名后缀 `.get` 让它只接 GET，其它方法回 **405**（同一节明写的匹配规则）。
```

上一站量过一次三种形状，读数是 404。这一节把同一个地址的方法位一次问完，把这句话按现量改掉——因为**注释里的状态码是会给别人当依据用的**：客户端同事看到"405"就会去写"方法不对时提示用户换一个方法"，而屏幕上永远不会出现那一支。

## 方法全谱：一次问完

```
E2E_PORT=3244 npx playwright test --project=site test/e2e/metrics-endpoint.spec.ts
```

```
[方法全谱] {"地址":"/api/console/metrics","各方法":{"GET":"401","HEAD":"404","OPTIONS":"404","POST":"404","PUT":"404","PATCH":"404","DELETE":"404"},"对照_get打到post文件":404,"对照_post打到delete文件":404,"有allow头的形状数":0,"地址形状":{"/api/console/metrics":"401","/api/console/metrics/":"401","/api/console/metrics.json":"404","/API/CONSOLE/METRICS":"404"},"错误体回声的地址":{"/api/console/metrics":"http://localhost:3244/api/console/metrics","/api/console/metrics/":"http://localhost:3244/api/console/metrics/","/api/console/metrics.json":"http://localhost:3244/api/console/metrics.json","/API/CONSOLE/METRICS":"(没有这一位)"}}
  4 passed (17.9s) ／ 3 skipped
```

这张读数里有四件事值得单独说。

**第一，`GET` 是唯一进到 handler 的那一支**，值是 401 而不是 404——这一位正好当对照组：地址认得、但没登录，所以走到守卫被挡下；其余方法是地址层面就没命中。判据钉的是"方法不匹配就不执行 handler"这条硬事实，而把状态码钉成 **404**（`expect(spectrum.POST).not.toContain('405')` 那一句是留着当护栏的：哪天升级到回 405 了，这条会红，那时才需要重写客户端分支）。

**第二，`HEAD` 也是 404**。按 HTTP 的语义，HEAD 就是"只要头不要正文的 GET"，很多链接检查器、探针、以及"先看这个地址存不存在"的写法用的就是它。在这个构建里问 HEAD，得到的是"这个地址不存在"。这不是缺陷，但它会让排查方向跑偏：接口明明在，探测说没有。

**第三，`OPTIONS` 也是 404**，也就是浏览器发起跨站预检时这里没有响应。同一条读数里 `有allow头的形状数:0`——整个方法谱里没有一支带 `allow` 头。`405` 原本的作用就是"这个地址在，但方法不对，能用的是 `Allow` 里那几个"；既然既拿不到 405 也拿不到 `Allow`，**客户端就没法用状态码区分"地址写错"和"方法用错"**，只能两种都按"地址不对"排查。

**第四，对照那两位证明这不是这一支的特例**：GET 打到 `.post` 那个文件回 404，POST 打到后台那条 `.delete` 也回 404。整个站的方法位都是这一套规则。

## 同一个 404 有两种形状，这才是最该记的一条

上面那张读数最后一行已经露出来了：大写那一条地址，`错误体回声的地址` 是 `(没有这一位)`。并排打一遍：

```
[两种404] {"小写":{"status":404,"type":"application/json","有data":true,"有url":true},"大写":{"status":404,"type":"text/html;charset=utf-8","正文长度":2246,"正文开头":"<!DOCTYPE html><html  lang=\"zh-CN\"><head"}}
```

同一个 404，小写那条回的是**错误体的 JSON**（有 `data`、有 `url`），大写那条回的是**一整页 HTML**（两千多字节，开头是 `<!DOCTYPE html>`）。为什么这样分不在本节的结论里，能钉住的是形状本身，以及它对客户端纪律的影响：第七条线立的规矩是"按 `data.code` 分支，不去匹配人话"，这一站给它补一句——**`data` 那一位不保证存在**，读之前必须判有。上一站那句被类型检查逼出来的 `json.data?.code` 不是洁癖，就是这个形状逼出来的。

判据里对应四条断言：小写那两条钉 `content-type` 含 `application/json`、`data` 那一位在；大写那两条钉 `content-type` 含 `text/html`、正文解析不成 JSON。

## 判据自己又红了一次：别用子串判形状

大写那一条我最初写的是 `expect(upperBody).not.toContain('"data"')`——想表达"这不是带 `data` 的错误体"。跑出来是红的：

```
Error: expect(received).not.toContain(expected) // indexOf
```

那两千多字节的 HTML 里**当然有 `"data"` 这串字**（页面自带的负载脚本里就有）。用文本搜索判形状，判的是"这串字符出没出现过"，不是"这是什么形状"。改成判能不能解析成 JSON：

```ts
let upperJson: unknown
try {
  upperJson = JSON.parse(upperBody) as unknown
} catch {
  upperJson = null
}
expect(upperJson, '大写那一条回的不是 JSON 错误体，而是错误页 HTML').toBeNull()
```

这与上一线那条"子串断言挡不住改值"（`toContain('Path=/')` 在 `Path=/app` 下照绿）是同族的错：**断言要打在结构上，不要打在一串字符是否出现上**。

## 尾斜杠是同一支 handler，回声是两个不同字符串

`地址形状` 那一段读数里，`/api/console/metrics` 与 `/api/console/metrics/` **都是 401**——多一个斜杠照样命中这一支；而错误体 `url` 那一位回声的是各自原样的地址（一个带斜杠、一个不带）。

这条对鉴权没有影响（两种写法都要过 `requireUser`），但它意味着：任何按"地址字符串"做的判断，都会把它们看成两个东西——限流按 key 计数、白名单/黑名单精确匹配、缓存 key、按路径统计的埋点，全都会分裂成两条。这个站今天按地址字符串做的判断只有两处：日志里的 `pathname`（只作观测）与 robots 清单里的 `Disallow: /api/`（前缀匹配，两种写法都盖得住），后者也有判据盯着：

```
[挡与收对账] {"disallow":["/api/"],"noIndexPaths":["/console","/me"],"两边都挡的":[]}
```

所以今天没有洞，但这是一张"今天的清单"，不是永久保证：将来谁加一条按路径精确匹配的规则，尾斜杠就是它的第一颗石子。

## `since` 那位现在归谁

上一站读到不传时间窗时那句 SQL 里没有 `occurred_at` 的条件，而传了就多一位 `>= $2`。接口这一侧**没有**任何时间窗参数，也不该顺手加一个"看起来无害"的：上一站的规矩不是"参数都危险"，而是**身份不许从请求里来**。真要加"这周登录几次"，加的是有界的、只收窄这个人自己数据的参数（值域要校验：几天到几周，不许负数、不许 `Infinity`），并且它进的是服务层那个 `since`，不是查询里新加的一位用户编号。

## 复跑与排错

| 撞上的现象 | 现量的形状是 | 先做什么 |
| --- | --- | --- |
| 按 405 写的分支从来没进过 | 方法不匹配回 404、无 `allow` 头 | 别按 405 写分支；要区分就自己判 `data.code` |
| 探针说接口不存在，但浏览器能用 | HEAD 与 GET 不是一回事（HEAD 404） | 探测改用 GET 看状态码，或按 `data.code` 判 |
| 客户端读 `data.code` 崩了 | 404 有两种形状：JSON 与整页 HTML | 读之前判有；`content-type` 先判 JSON |
| 同一接口在日志里出现两个地址 | 尾斜杠命中同一支、回声原样字符串 | 按地址字符串做的判断要先归一 |
| 跨站调用拿不到预检响应 | OPTIONS 404 | 这一站不提供跨源接口；要对外就得单独设计 |

## 交付前自查

- 七个方法、四个地址形状、两个对照接口，一次跑完全部现打，判据钉的是量到的号而不是文档措辞里的号
- 接口自己那行注释按现量改了（并留着"哪天升级到 405 会让这条判据红"的护栏）
- 同一个 404 的两种形状写成四条断言，其中一条是我自己先用子串判错、再改成解析判的
- 尾斜杠那条只报"今天没有洞"，并把按地址字符串的两处位置点名，不写成永久保证
- 依旧没有连库：带库那 3 条仍 `3 skipped`，本节没有一句"真会话下回什么码"的结论
