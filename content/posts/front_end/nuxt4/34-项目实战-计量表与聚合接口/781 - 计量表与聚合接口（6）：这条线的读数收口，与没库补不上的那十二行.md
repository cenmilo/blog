## 一次跑完，屏幕上 4 条绿、12 条跳过

把这条线碰到的端到端规格一次跑完（产物服务、没有数据库、没有邮件服务）：

```
E2E_PORT=3245 npx playwright test --project=site \
  test/e2e/metrics-endpoint.spec.ts test/e2e/cascade.spec.ts \
  test/e2e/async-data-count.spec.ts test/e2e/fetch-parity.spec.ts \
  test/e2e/full-login.spec.ts
```

```
Running 16 tests using 5 workers
  4 passed / 12 skipped (24.4s)
```

零失败，而这一站的结论全在被跳过的 12 条上：绿的那 4 条钉的是"**没有库也守得住**"的那一半。端口这一趟用的是 3245——这一段端口在这台机器上时不时会被出站连接先占掉（前几站撞过 `listen EADDRINUSE` 而 `netstat` 里没有监听条目），换一位数重跑就行，别去动别人的进程。

## 五步各留一句

| 哪一步 | 一句结论 | 复跑它的读数 |
| --- | --- | --- |
| 776 数字从哪张表来 | 表里只有四列、没有任何计数列，所以那个数字是查出来的 | `[计量表的列] {"列":["id","user_id","kind","occurred_at"],"计数类列":[]}` |
| 777 写入口只有一处 | 动作种类是普通文本，改一个字母写照样成功，只有判据看得见 | `[名字对账] {"对上的文件数":2,"分家的":[]}` |
| 778 聚合是纯函数 | 总数只来自那一条语句，不靠第二次查询 | `[读·一条语句] {"发出几条":1,"total":7,"各行相加":7}` |
| 779 先确认是谁在问 | 取数用的是守卫给的那个人；顺序判据绿着也挡不住换成查询串 | `[取数的那一位] {"实参":"user.id","守卫给的变量":"user"}` |
| 780 接口该回哪个码 | 方法不匹配一律 404，`405` 那一支在这个站里不会出现 | `{"GET":"401","HEAD":"404","OPTIONS":"404","POST":"404","PUT":"404","PATCH":"404","DELETE":"404"}` |

三条表外读数，是这一站反复要用的锚：

```
[两种 ON DELETE] {"计量":"cascade","审计":"set null","相反":true}
[计量·写失败(Error)] {"返回值":false,"日志条数":1,"那一行":"{\"ts\":\"2026-10-18T03:57:15.596Z\",\"level\":\"error\",\"msg\":\"meter_write_failed\",\"requestId\":\"req-meter-1\",\"kind\":\"login\",\"reason\":\"duplicate key value violates unique constraint\"}"}
[两种404] {"小写":{"status":404,"type":"application/json","有data":true,"有url":true},"大写":{"status":404,"type":"text/html;charset=utf-8","正文长度":2246,"正文开头":"<!DOCTYPE html><html  lang=\"zh-CN\"><head"}}
```

第一行是两张表的方向（同一个词 `count` 在两张表里是两个意思）；第二行是"落表失败不阻断业务"这句话的形状（回 `false`、日志里留的是真原因）；第三行是这一层给客户端立的规矩——**同样是 404，两种响应形状**，所以读 `data.code` 之前必须判有。

## 没库补不上的那十二行

跳过不是通过。这一站把它们逐条列出来，每条后面是它缺的东西：

| 规格与行号 | 那一条要的是什么 |
| --- | --- |
| `async-data-count.spec.ts:20` | 一条真会话：三种进页面方式各跑一次，数浏览器真发了几趟取数请求 |
| `fetch-parity.spec.ts:17` | 一条真会话：客户端导航进会员区，两种写法各发几趟、两块数是否一致 |
| `fetch-parity.spec.ts:66` | 一条真会话：整页加载进会员区，服务端 HTML 里两块是否都带着数字 |
| `full-login.spec.ts:120` | 库**加**邮件服务：申请链接、收到信、点进去、页面上看得见邮箱、登出 |
| `full-login.spec.ts:188` | 库**加**邮件服务：同一枚券点第二次必须 401，且不给任何"它曾经有效"的暗示 |
| `metrics-endpoint.spec.ts:144` | 一条真会话：带会话打这个接口，返回的就是这个人在库里的行数 |
| `metrics-endpoint.spec.ts:193` | 一条真会话：换一个人问同一个接口，拿到的是他自己的那份数 |
| `metrics-endpoint.spec.ts:217` | 真写库：删掉用户，他的计量行跟着没（与审计那行的选择相反） |
| `cascade.spec.ts:82` | 真写库：删用户后会话归零、审计一行不减、券原封不动 |
| `cascade.spec.ts:117` | 真写库：那张没外键的表能把刚删的账号复活——一张没用过的旧券仍能登录 |
| `cascade.spec.ts:143` | 真写库：控制实验，同样两张表把外键写成 cascade，券就跟着没（临时表） |
| `cascade.spec.ts:174` | 真写库：对照，全端下线只删会话行，用户、券、别的痕迹都不动 |

七条缺"一条真会话"，三条缺"真往库里写"，两条缺"库加邮件服务"——最后这两类都不该由假件冒充：内存里的假库不会替数据库做级联删除，也不会把一行真的计数留给你数。**要跑它们只需要一个你自己的库**：连接串放进 `.env`，用带库那一档跑（`NUXT_E2E_DB=1 npm run test:e2e -- …`）；别把它写进任何会被渲染或提交的文件。

这一节也是这一条线最大的缺口所在：这一层要交付的那句验收是"**页面上的数字与库里手工数出来的一致**"。判据已经齐了（接口只发一条语句、`total` 由各行相加、取数用的是本人），但"与库里数出来的对一遍"这半步从来没跑过——它就在上面第 6 行。

## 按文件算会算错

同一份规格里一条绿一条跳过是常态，报数要按用例：

| 规格 | 用例 | 这一档跑到几条 |
| --- | --- | --- |
| `metrics-endpoint.spec.ts` | 7 | 4 绿、3 跳过 |
| `cascade.spec.ts` | 4 | 0 绿、4 跳过 |
| `async-data-count.spec.ts` | 1 | 0 绿、1 跳过 |
| `fetch-parity.spec.ts` | 2 | 0 绿、2 跳过 |
| `full-login.spec.ts` | 2 | 0 绿、2 跳过 |

按文件看，"跑了五份规格"；按用例看，16 条里只跑到 4 条。`cascade.spec.ts` 会被算成"跑过"，而它一条都没跑到——**这份表为什么按用例数报，理由就在这里**（同一个坑在门后页那条线也踩过一次）。

单位层这一层的现值一起放这儿，因为这一条线的三条结论本来就不长在端到端那一层。八份判据合跑 `Test Files 8 passed (8)`／`Tests 42 passed (42)`，逐份是：

```
meter-shape -> Tests  6 passed (6)
meter-sql -> Tests  6 passed (6)
meter-write-surface -> Tests  5 passed (5)
meter-write-failure -> Tests  3 passed (3)
metrics-read -> Tests  6 passed (6)
metrics-summary -> Tests  5 passed (5)
metrics-boundary -> Tests  6 passed (6)
api-guard-surface -> Tests  5 passed (5)
```

最后那份是上一条线补的（管"守卫挂没挂、在不在读参数前面"），这一条线的 779 把"取数用的是谁"补在它旁边——两份合起来才把接口那道边界说完整。整层现在的数是**单位层 41 文件／268 条、运行时层 6 文件／20 条**。**凡是"只在没有负载时才生效"的逻辑、"顺序与来源"这类结构规矩、以及"改一个字母库照样收"这种静默失效，端到端那一层都量不到**——这条线里 777 那处日志的错、778 那句多余的数值转换、779 那个换成查询串的取数，红的全在单位层。

## 交付前自查

- 五步每一步都指得出"哪条用例打印哪一行"，没有哪句结论是靠回忆写的
- 十二行跳过各自带原因，原因写的是缺哪一样环境（库／邮件服务），不是"暂时不便跑"
- 按文件与按用例两种报法并排放着，差值就是那条最容易犯的错
- 三处"本轮改的"都能被自己的变异打回：777 的日志（三种故障同一句话）、778 的删除（字符串形状会撞红）、780 的注释（404 全程无 `allow`）
- 验收那句"与库里数出来的一致"只写到"判据齐了、缺一次真读数"，没写成通过

## 这条线没闭合的账

六步能收，账收不干净：需要真会话的七行与需要真写库的五行**一行都没跑过**（上一节那张表就是清单）；`server/services/audit.ts` 里 `audit_write_failed` 那一处与 777 修掉的完全同形，本轮没测它也没改，留给审计那条线；尾斜杠与不带斜杠命中同一支 handler，今天按地址字符串做的判断没有会漏的，**但"先归一再比较"这条规矩还没人写**；`/api/console/metrics` 只有一个接口，会员区那一页还没真读过它（读它要 `useAsyncData` 那一站）；`since` 那个时间窗在服务层可用、接口没接，接的时候要加范围校验；取数失败时页面上显示什么（骨架、空态、还是错误块）这一层管不到，属错误边界那条线；`npm run check` 里没有一条"这条线的判据都还在"的自检——它靠的是每次跑数。
