335 讲了 .env 到 runtimeConfig 的链路。这一篇专讲**密钥**这一面——.env 该怎么放、哪些是它的边界。

## 边界一：.env 要进 .gitignore

env 页开头一条 important：

> This file should be added to your `.gitignore` file to avoid pushing secrets to your repository.

密钥进了 Git 历史就很难彻底清除。`.env` 不进仓库——这是 077 那条 .gitignore 清单里 `.env`/`.env.*` + `!.env.example` 的由来：真实 `.env` 不提交，交一份不含值的 `.env.example` 模板。

## 边界二：应用代码别裸读 process.env

env 页的 important：

> In your application code, you should use Runtime Config instead of plain env variables.

密钥从 .env → nuxt.config 的 runtimeConfig（私有键）→ `useRuntimeConfig()` 读。不是满项目 `process.env.XXX`。334 的安全基线也建在这：只服务端读、不下发前端。

## 边界三：生产不读 .env，别把它当生产密钥方案

335 反复讲的那条，从密钥角度再看：

> Your `.env` files will not be read at this point [production].

所以 `.env` 是**开发/构建期的本地工具**，生产的密钥必须由部署平台设环境变量（命令行/shell/云平台面板）。把生产密钥指望在服务器上放一个 `.env`，是对这套机制的误用。

而生产覆盖 runtimeConfig 只认 `NUXT_` 前缀（important，见 342）：

> `runtimeConfig` won't pick up environment variables that don't start with `NUXT_` in production.

## 边界四：几个容易忽略的行为

- **改 .env 会重启**："When updating `.env` in development mode, the Nuxt instance is automatically restarted to apply new values to the `process.env`."
- **删变量不会取消**：note "removing a variable from `.env` or removing the `.env` file entirely will not unset values that have already been set."——删了 `.env` 里一行，那个值可能还在（从别处或缓存设过），别以为删了就没了。
- **换文件用 --dotenv**：`npx nuxt dev --dotenv .env.local` 用别的文件。
- **值会被转类型**：destr 那坑（342），一个纯数字或 `4848e0` 的密钥可能变成 number；要当字符串处理得把引号包进值里。327 那句 appSecret "made only of digits arrives as a number" 就是它。

## 边界五：nuxt preview 是本地预览的便利

Production Preview 节：

> we recommend using `nuxt preview` since using this command, the `.env` file will be loaded into `process.env` for convenience. Note that this command requires dependencies to be installed in the package directory.

本地想验生产行为时，`nuxt preview` 会读 `.env`（便利）。但它是"预览"，不代表线上也这样。且纯静态站预渲染后设不了 runtime config（335）。

## 一张密钥处理清单

| 做什么 | 怎么做 |
| --- | --- |
| 本地开发放密钥 | `.env`（且进 .gitignore） |
| 交给应用读 | nuxt.config 的 runtimeConfig 私有键 + `useRuntimeConfig()` |
| 生产设密钥 | 部署平台的环境变量，用 `NUXT_` 前缀命名 |
| 别提交密钥 | `.env` 进 .gitignore，交 `.env.example` |
| 本地验生产 | `nuxt preview`（会读 .env，是例外） |

## 自查

- `.env` 提交了吗？务必进 .gitignore，只交 `.env.example`。
- 生产是不是还在指望 `.env`？生产靠部署平台的 `NUXT_` 环境变量。
- 应用代码在裸读 process.env？改走 runtimeConfig。
- 数字型/`4848e0` 型密钥要当字符串，用引号包值防 destr 转类型。
