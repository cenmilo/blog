342 讲了 `NUXT_` 前缀怎么映射到 runtimeConfig 键。这一篇讲它的反面——一个很多人会先犯的写法，以及为什么它"看着能用、上线才炸"。

## 那个会坏在运行期的写法

你可能想："我这个第三方服务给的变量名就叫 `DATABASE_URL`，我在 runtimeConfig 里读它总行吧"，于是写：

```ts
// 危险：只在构建期有效
export default defineNuxtConfig({
  runtimeConfig: {
    dbUrl: process.env.DATABASE_URL,
  },
})
```

官方把这条写成 warning：

> Setting the default of `runtimeConfig` values to differently named environment variables (for example setting `myVar` to `process.env.OTHER_VARIABLE`) will only work during build-time and will break on runtime. It is advised to use environment variables that match the structure of your `runtimeConfig` object.

关键就一句：**"only work during build-time and will break on runtime"**。开发、`nuxt build`、`nuxt generate` 时 `.env` 被读进来了、`process.env.DATABASE_URL` 有值，所以默认值填上了，看着一切正常。但部署后运行生产服务时——

## 为什么运行期会断

两条已讲过的事拼起来就明白：

- `.env` 文件在生产运行阶段**不被读**（335："After your server is built ... Your `.env` files will not be read at this point."）。
- `nuxt.config` 里的这段代码是**构建期**跑一次、算出 runtimeConfig 的默认值的。构建期 `process.env.DATABASE_URL` 若没设（生产服务器上不读 .env），这个默认值就是 `undefined`，并被固化进产物。

也就是说你把一个"只在构建那一刻存在的东西"读进了"会写死进产物的默认值"。运行时想覆盖它，靠的又必须是"命名对得上的 `NUXT_` 变量"——`DATABASE_URL` 不匹配 `dbUrl` 的映射规则（那应是 `NUXT_DB_URL`），所以运行时也覆盖不上。两头落空 → 生产读到空值。

## 正确写法：让变量名对上结构

官方建议 "use environment variables that match the structure of your `runtimeConfig` object."。做法是：

1. runtimeConfig 里给个默认值（可以是空串，别用 `process.env.异名`）；
2. 用**映射规则对得上的** `NUXT_` 环境变量在运行时覆盖。

```ts
// nuxt.config：给默认值，不在这里读 process.env 的异名变量
export default defineNuxtConfig({
  runtimeConfig: {
    dbUrl: '',
  },
})
```

```ini
# 部署环境（或本地 .env）里设这个键，命名和结构对上
NUXT_DB_URL=postgres://...
```

这样：`dbUrl` 键对应 `NUXT_DB_URL`（342 的映射），运行时读的是**当前进程**的环境变量（341 里服务端 `useRuntimeConfig(event)` 拿的就是运行时覆盖过的值），生产设了 `NUXT_DB_URL` 就生效。如果你的上游只给你 `DATABASE_URL` 这个名字，让部署平台把它映射/改名成 `NUXT_DB_URL`，而不是在 nuxt.config 里读 `process.env.DATABASE_URL`。

## 一句话记住分界

- **构建期才有的东西**（.env 在 dev/build 被读进来的 process.env）：可以用来填 runtimeConfig 的**默认值**，但别指望它在运行时还在。
- **运行时要覆盖**：只有名字对得上的 `NUXT_*` 环境变量算数（335/341/342）。

## 自查

- 有没有写 `key: process.env.某个不同名的变量` 当 runtimeConfig 默认值？那是"构建期能过、运行期会坏"。
- 改成：runtimeConfig 给普通默认值，靠 `NUXT_<对得上的名字>` 在运行时覆盖。
- 上游只给异名变量时，在部署平台改名/映射成 `NUXT_` 形式，而不是在 nuxt.config 里读 process.env 异名。
- 记住 `.env` 只在 dev/build/generate 被读、生产运行不读。
