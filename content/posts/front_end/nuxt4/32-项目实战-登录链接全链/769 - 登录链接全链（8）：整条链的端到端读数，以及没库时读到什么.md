## 一趟跑完，屏幕上只有三种回执

把这条链的端到端规格一次跑完（不带库、不带 SMTP）：

```
Running 16 tests using 6 workers
10 passed
6 skipped (27.7s)
```

没有 failed。这既是好消息也是这一站要说的话：**16 条里有 6 条根本没跑**。跳过的那六条不是"通过得轻松"，它们是这条链上最需要真环境的部分——全链走通、重放必须 401、换号要回两条 `Set-Cookie`、以及"配了库但连不上"那一档的三条。所以这一站不做新机制，只交两张表：八步各留一句，和"没库读得到什么"。

## 八步各留一句

| 步骤 | 一句结论 | 复跑它的那条读数 |
| --- | --- | --- |
| 一条链五个落脚点 | 明文只在两处活着：函数返回的那一刻、邮件正文里 | `[同一条路]` 里状态 503、`code` 是 `MAIL_NOT_CONFIGURED` |
| 邮箱契约放 `shared/` | 契约写两遍迟早一份松一份紧；换个大小写曾经能绕过限流 | `[桶键]` 两种写法同一个键、剩余额度 `[9,8]` 单调降 |
| 入口那三步的顺序 | 格式闸在令牌桶前面，否则非法邮箱能把同机额度掏空 | `[码序]` 十条 503 之后一条 429、`retry-after` 360 |
| 券怎么生成 | 发给库的那句话里只有摘要，`id` 与 `used_at` 走 `default` | `[发券 SQL]` 的 `params` 第二位是 64 位摘要 |
| 发信的两种失败 | 没配置就 503，不"看起来成功"；超时要自己设，默认值给人两分钟 | `[超时对照]` 里"没给时"三个键都不存在 |
| 占券那条 UPDATE | 查、判、占压成一条语句，三种失败同一个 401 同一句人话 | `[占券 SQL]` 的 `"expires_at" > $3` |
| 落地与换号 | 落地地址靠 origin 等式收敛，登录必换号且两条语句同事务 | `[读 redirect 的文件]` 点名两处调用点 |
| 本收口 | 链上每一环都有回执，回执缺席的那些环要按档跑 | 本页那三张表 |

表里最后那一列写的是**用例自己打印出来的行**，不是"我验过了"。这些行都从本轮的跑动里抄下来，端口、编号、时刻都是这一次的。

## 没库能读到什么，带库才读到什么

| 环 | 没库没 SMTP 时读到 | 带库（加 SMTP）才读得到 |
| --- | --- | --- |
| 申请链接 | 503 `MAIL_NOT_CONFIGURED`，且存在与不存在的邮箱逐字节同形 | 200 `{"ok": true}`，邮件里那条链接 |
| 令牌桶 | 打得动，越界给 429 ＋ `retry-after` | 一样（这一位不碰库） |
| 占券 | 503 `DB_NOT_CONFIGURED`（形状对但没配库） | 302 落地、两条 `Set-Cookie` |
| 库连不上 | 读不到——这一档必须显式带一个死连接串 | 503 `DB_UNREACHABLE`，`url` 只到路径 |
| 重放同一枚券 | 读不到 | 401，且库里那一行仍是已用 |
| 会话轮换 | `/me` 有 `x-request-id`、预渲染的首页没有 | 登录前后 sid 不同、旧号查不到行 |

一句判据：**"没配就不发、也不假装发了"这一条在降级档里是可测的，而"发出去了"不可测**。跳过的那六条各自带着原因串，例如"需要配了 `NUXT_DATABASE_URL` 的产物实例"与"需要 `E2E_DB_DOWN=1` 与一个连不上的 `NUXT_DATABASE_URL` 一起跑"——**原因串是写给下一个人的：它说明这一条不是没写完，是缺环境**。

## 为什么要分成四档跑，而不是并成一趟

| 档位 | 命令 | 为什么单独一档 |
| --- | --- | --- |
| 默认（无库无 SMTP） | `npm run test:e2e` | 降级形状：400／401／503 这些码都在这档钉 |
| 打空额度 | `npm run test:e2e:drain` | 桶是一个进程共享的 Map，掏空之后同趟里别的规格全是 429 |
| 库连不上 | 带死连接串点名单跑那一份文件 | 整趟带上连接串，"没配库 ⇒ 503 `DB_NOT_CONFIGURED`"那条读数就换了意思 |
| 带库带本地 SMTP | `NUXT_E2E_DB=1` ＋ 指向本机 2525 的 `NUXT_SMTP_URL` | 真发信、重放、轮换、审计与计量都要落库 |

前两档本轮各跑了一次，都是绿的：打空额度那一趟 `2 passed (26.9s)`，读数 `[码序] {"放行次数":10,"码":[503,503,503,503,503,503,503,503,503,503,429],"retry-after":"360"}`、`[429 headers] {"x-request-id":"c97be094-4b4f-4d29-927b-1a5f4a818e41","retry-after":"360","code":"RATE_LIMITED"}`、`[掏空之后] {"合法形状的码":429,"非法邮箱的码":400,"code":"EMAIL_INVALID","人话":"邮箱地址格式不对，检查有没有 @ 和域名结尾。"}`；库连不上那一档 `3 passed (27.4s)`，读数 `[库连不上] {"状态":503,"code":"DB_UNREACHABLE","url":"/api/auth/verify","框架指纹头":"没有"}`、`[凭据回声] {"命中字段":[],"url":"/api/auth/verify"}`。

分档这件事的代价要说清楚：**一次 `npm run test:e2e` 通绿不等于整条链验过**。这条链上"人真的收到邮件并登进去"那半段，只有第四档能回答，而它需要一台真库——本站到这里为止没拿到连库授权，所以那张表右列的六行全都是读者自己跑一遍的产物。

## 带库那一档怎么造一枚券

值得单独看一眼，因为它绕开了整条发信链路：那两条要真库的用例不发邮件，而是**直接往库里写一行摘要**：

```ts [test/e2e/session-rotation.spec.ts]
await client.query(
  `insert into login_tokens (email, token_hash, expires_at, created_ip)
   values ($1, $2, now() + interval '15 minutes', '::1')`,
  [PROBE_EMAIL, tokenHash],
)
```

两个细节：写进去的是 `hashToken(token)` 而不是明文，所以这张表在库里长什么样、兑换那一步查的是哪一位，全都不变；而 `expires_at` 用的是数据库的 `now()`，**不是应用算的时刻**——这正好是"同一行里两种时钟并存"的反面教材：能兑换是因为两边都是绝对时刻（列是 `timestamp with time zone`），不是因为两边同一把尺子。测试里造数据可以走这条路，生产代码不行：生产要的是"这张券是谁在什么地址上申请的"，那一位 `created_ip` 也必须是真值。

## 撞上这些症状的时候

| 症状 | 先问一句 | 为什么 |
| --- | --- | --- |
| 全绿了，但你还是不确定登录能不能用 | 有没有跑过带库那一档 | 16 条里 6 条 skip，绿的都不碰真发信 |
| 一条用例带库就红 | 是不是默认档的形状被连接串换掉了意思 | `DB_NOT_CONFIGURED` 需要的是空值，不是假值 |
| 429 来得比预期早 | 同一趟里有没有别的规格在打额度 | 桶是进程级共享的，不是每份文件一只 |
| 库里造了券却兑换不了 | 那行摘要对得上你要点的明文吗 | 兑换查的是 sha256 之后的那一位 |
| 邮件里的链接点不开 | `token` 被软换行切断了没 | 收件端要先解 quoted-printable |

## 交付前自查

- 八步每一步都能在仓库里指出"哪条用例打印哪一行"，没有哪一句是靠回忆写的
- 六条跳过的用例各自带原因串，原因串里写的是缺哪一样环境
- 四档跑法都写清命令，且**没有把任何一档的绿当成整条链的绿**
- 降级形状（400／401／503 的分工、`code` 的集合、不泄露账号信息）在默认档全绿

这条线收到这里，还挂着这些没闭合的账，都是明面上的：**真库那一档的六个读数这一站一次都没跑过**（要一套你自己的数据库，连接串放在 `.env` 里）；`server/api/token-demo.post.ts` 那条探针地址要不要撤（它现在带着令牌桶，但仍会回行号、摘要与精确过期时刻）；占券与认人之间没有跨语句事务，那一瞬间失败会白烧一张券；发信失败与库失败的次数没进计量表；`Location` 头最终形态要真成功一趟才知道。八步里第七步的"落地"那一半还有个产品决定没做：`/console` 要不要允许带 `redirect`。


仓库这一轮没有代码改动：本轮的产出是这两张表和上面那段账。默认档 `Running 16 tests using 6 workers`／`10 passed`／`6 skipped` (27.7s)，打空额度档 `2 passed (26.9s)`，库连不上档 `3 passed (27.4s)`；单位层 28 文件／202 条、运行时层 5 文件／14 条，`npm run check` 八项全 ok。
