## 六篇文章读完，手边应该留下这六行数字

前每一站都在加判据、改页面，读数是散着的。这一站不散着放：把这条线新增的二十一条判据重新跑一遍，六步各留一句结论，再把"到今天还量不到的"单列一栏。**下面每一个数字都是这一趟重新打出来的**，不是从前某一站的存档值。

先摆盘子。三层各自的总量与本线的份额：

```text
单位层  Test Files 43 passed (43)   Tests 278 passed (278)     本线占 1 份 4 条
运行时层 Test Files 16 passed (16)   Tests  67 passed (67)      本线占 4 份 10 条
端到端  Running 7 tests using 3 workers → 7 passed (27.6s)      本线 3 份 7 条，0 跳过
端到端全量 Running 209 tests using 10 workers → 152 passed / 57 skipped (33.1s)
```

`7 passed` 那一趟是本线三份端到端规格单独跑的，一条都没跳过——**这条线的端到端判据一个都不需要数据库**。上一批（页面取数与键）的收口篇里，同一张表是 3 条跑 3 条跳过，缺的就是"得有一条真会话"。这一批换了量法：探针只问"这一次请求里有没有会话号"，那条会话号由本站的演示接口发，不进库。

## 六步各一句，挂着本轮的读数

**第一步**：两条口子都有键，位置不同——`useFetch` 的键写在选项对象里，`useAsyncData` 的键是第一位；不写键时两处调用各发一趟，写同一个键时只剩一趟。

```text
[两口子·带键] {"跑了几次":1,"每趟":["甲调用点#1"]}
[两口子·不写键] {"跑了几次":2,"每趟":["甲#1","乙#2"]}
[两口子·同一调用点] {"跑了几次":1,"每趟":["同一点#1"]}
```

**第二步**：把口子从 `useAsyncData` 换成 `useFetch`，两条路的读数一字不变；改得出"直接进有没有内容"的是**服务端取不取**，不是选哪个函数。

```text
[两路·A 直接进] {"html有标题":true,"html里链接数":2,"页面发的取数":[]}
[两路·B 点进来] {"页面发的取数":["/api/docs"],"列表条数":2}
```

**第三步**：类型认地址——地址是本站的，`useFetch` 与 `$fetch` 都推得出形状；写了显式泛型就以你写的为准（错误体那一支不再进来）；**地址写错不会报错，只是塌成 `unknown`**。这一位的判据是编译期断言，本轮跑过：`✓ test/nuxt/fetch-type-sources.test.ts (1 test)`。当年那五行原样打在 `.series/R67-791.md` 里，本文不重打，因为重打要先把代码改坏一次。

**第四步**：服务端那一趟带不带浏览器的 cookie，**开关是地址形状**——相对路径的 `useFetch` 带，绝对地址不带，裸 `$fetch` 什么都不带。

```text
[cookie两口子·档二 带会话号直接进] {"浏览器存的":["csrf","sid"],"转发那条":"带上了（这一趟由服务端发）","裸调那条":"没带上（这一趟由服务端发）"}
[cookie两口子·档三 点进来] {"页面发的取数":["/api/session-state","/api/session-state","/api/session-state"],"转发那条":"带上了（这一趟由浏览器发）","裸调那条":"带上了（这一趟由浏览器发）","水合告警数":0}
```

**第五步**：`lazy`、`pick`、`transform`、`default` 在两条口子上都叫同一个名字，但**名字档与选项档这一刻不等价**；`pick` 收的是负载不是请求；`transform` 与 `pick` 是顺序不是互斥。

```text
[lazy的名字] {"名字档":{"那一刻":"(没值)","status":"idle","趟数":0},"选项档":{"那一刻":"byKind,metrics,note","status":"success","趟数":1},"另一条口的名字档":{"那一刻":"byKind,metrics,note","status":"success","趟数":1},"名字档关掉watch":{"那一刻":"byKind,metrics,note","status":"success","趟数":1}}
[pick的负载] {"负载里键名数":{"hasSid":3,"sidPrefix":2,"hasCsrf":2,"csrfLength":2},"界面读到":"hasSid","字节数":3160}
[pick的请求] {"接口回的键":["csrfLength","hasCsrf","hasSid","sidPrefix"],"界面读到":"hasSid"}
```

**第六步**就是本篇：读数摊平，账摊开。

## 这条线立住了什么，写在页面上而不是写在记忆里

三样东西留在了仓库里，作用是让后面的人改坏了能立刻红：

- `test/unit/data-fetch-surface.test.ts`（4 条）把两条口子在 `app/` 里的现状钉成清单：谁走出口、谁就地取数、`useAsyncData` 的第一位是不是写死的键、认人地址每一处靠谁把请求头带过去、那六个编译器保留名有没有被自己导出。本轮读数：`[口子清单] {"就地Fetch":["app/pages/me.vue"],…}`、`[认人地址的取数点]` 三项、`[保留名的导出] {"扫到":[],"扫过的文件数":15}`。
- `app/pages/me.vue` 上的三位探针（两位问 cookie、一位问 `pick`）。差别不用改代码比，一份 HTML 里同时读得出来。
- 四条被推翻或收窄的说法，都写进了对应那一站的正文：`useAsyncData` 包住 `$fetch` 不是"两条路都通"的理由（第二步）、地址写错不报类型错（第三步）、`useLazyFetch` 与 `{ lazy: true }` 这一刻不等价（第五步）、`pick` 不会让接口少回东西（第五步）。

## 还量不到的那几行

这条线自己新增的判据里没有跳过的行，但欠着的账有四处，得说明白：

| 欠的那一位 | 现在有什么 | 缺什么 |
| --- | --- | --- |
| 真会话下两条口子各发几趟、页面两块数字是否一致 | 判据已写好：`test/e2e/fetch-parity.spec.ts` 两条、`test/e2e/async-data-count.spec.ts` 一条，默认档跳过 | 一条能用的真会话，而发会话要写库 |
| 带上的 cookie 真能换回用户 | 第四步只证明"请求头带过去了"（`hasSid` 变真） | 换回用户要查会话表 |
| `error` 那一种形状怎么分支 | 类型里带着那一支（第三步） | 分支写法与提示话术，交给错误边界那条线 |
| 名字档"这一刻不发"的根因 | 关 `watch` 就同形，位置指向包内 `fetch.js:88` | 再往下的调用链没追，正文只报形状 |

另外两处是本批之前的旧账，跟这条线无关但别丢：接口地址"先归一再比较"没人写；审计写失败那种同形串还没扫。

## 这条线自己打红过一次旧判据

第五站给账户页加了第三位探针，它问的也是 `/api/session-state`。当时只跑了新加的那两份端到端规格，全绿；收尾跑全量时才看到第四站那条"点进来时页面发的取数是两条"红了——现在它是三条。

这不是判据写错，是它把"这一页有几处取数"钉成了实现细节。改法是让它认集合而不认条数：那一份规格里现在写的是"出现的地址只有 `/api/session-state` 这一种，长度等于这一页上的探针数"。同时留一条流程规矩：**改过共享页面的取数之后，端到端要跑全量，不能只跑新增那几份**。这一趟的全量是 `152 passed / 57 skipped`，那条曾经红的已经绿了；本线三份单跑是 `7 passed`。

## 这张表怎么用

搬到自己站里时不用一次全跑。顺序建议是三段：先跑那份静态清单（`npm run test:unit -- test/unit/data-fetch-surface.test.ts`），它只读源码、一秒出结果，能立刻告诉你站里有几处认人地址是靠裸调用取的、有没有人把保留名自己导出了；再跑运行时层那四份（`npm run test:nuxt` 里挑 `two-doors-key-position`、`fetch-type-sources`、`request-leg-client`、`fetch-option-names`），这一层不需要接口真的能用，靠的是注入进去的假脚；最后才动端到端那三份，它要先构建再起发布物服务，一趟半分钟。

三段各管一件事：清单管"形状有没有变"，运行时层管"机制按不按文档说的那样动"，端到端管"浏览器和真 HTML 上到底是什么"。把结论从第一段推到第三段是不行的——第二段那四份全绿也说明不了首屏 HTML 里有没有数字，这正是 785 那一趟单独去读响应体的原因。

## 补那三行之前，别把默认档改绿

那三份端到端规格的跳过条件是文件头一句 `test.skip(DATABASE_URL === '', …)`。别为了让表上多几个 `passed` 就带上库连接串跑默认档——那三行读的是"有会话时怎样"，而其他一百五十几条读的是"没库时怎样"，混在一趟里跑，两边意思都被改了。要补就单独跑，命令与预期写在该站正文里。
