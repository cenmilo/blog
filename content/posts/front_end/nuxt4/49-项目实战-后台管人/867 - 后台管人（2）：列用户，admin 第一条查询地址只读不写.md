## 第三栏只有字，一个按钮都没有

上一站的结论是"那一列在，没人动它"。这一站先把"有哪些账号"读到屏幕上。

新开的这一栏只有一句状态词、一句话，加一份名单，**没有任何按钮**。这不是偷懒：封禁那个动作要等下一站带着"生效路径"一起做。今天在这里放一个会改 `banned_at` 的按钮，而门那一路还不读它，做的就是"看起来能用、实际什么都不挡"的东西。

这条地址是 `server/api/admin/users.get.ts`，目录名到路由的映射由框架负责。要做的设计决定是另外三件：按什么顺序给、给几行、以及"读不出来"的时候怎么说不。

## 四种"没有"必须是四个形状

同一句"没有"，在这一栏里至少有五种情况，而它们要让人做的动作不一样：

| 情形 | 状态码 | 机器码 | 屏幕上那句话 |
| --- | --- | --- | --- |
| 会话里没有号 | 401 | `UNAUTHENTICATED` | 先登录再看这一栏 |
| 登录了但不是管理员 | 403 | `FORBIDDEN` | 这一栏只有管理员能看 |
| 分页或角色参数写错 | 400 | `LIMIT_INVALID`／`OFFSET_INVALID`／`ROLE_INVALID` | （这一格不念句子） |
| 没配库或那句 SQL 没跑成 | 503 | `ADMIN_USERS_UNAVAILABLE` | 这一栏现在读不出来 |
| 库里真没符合条件的人 | 200 且 `users: []`、`total: 0` | — | 库里还没有账号 |
| 页码翻过头 | 200 且 `users: []`、`total > 0` | — | 这一页往后没有账号了，符合条件的还有 N 个 |

前两行必须是两个码。这条地址的第一句就是那道门，参数校验全排在它后面——反过来的代价上一线量过一次：没权限的人靠 400 与 403 的差别，能把"这条地址认哪些参数"试出来。

最后一行是这一栏最贵的两格。**"翻过头"和"没人注册"在接口上都是 `users: []`**，只差 `total` 那一位。折成一句的后果很具体：管理员点到第三页，屏幕上告诉他这站没人注册。

还有一格容易漏：`total` 与名单必须是**同一个问法**。写成"名单按角色筛、总数不带条件"，接口就同时回"筛出 3 个"与"全站共 120 个"，屏幕上那句"共 120 个"当场成假话。所以这一层的两条语句共用同一份条件对象：

```ts [server/services/admin-users-read.ts]
const 条件 = 角色 === null ? undefined : eq(users.role, 角色)

const 行 = await useDb().select({ /* 五列 */ }).from(users)
  .where(条件).orderBy(desc(users.createdAt), desc(users.id)).limit(限制).offset(偏移)

const 计数 = await useDb().select({ 条数: sql<number>`count(*)::int` })
  .from(users).where(条件)
```

排序带两把键不是装饰。同一秒注册两个人是可能的（批量导入），只有一把键时库可以任意挑谁在前，症状是"刷新一次顺序变了"。这里与上一线有个真差别：`task_runs` 的 `id` 是自增整数，平手时"后写的在前"有含义；这里的 `id` 是 uuid，平手时顺序**确定但任意**。所以这一栏念的是"同一刻注册的这几个"，不许读成"最新注册的人在第一个"。

## 一行时刻读不出来，为什么会变成整栏 500

`created_at` 那一列在库里是 `notNull`，看起来不可能读空。它确实读得出来——问题在**读回来的是什么类型**。这一列允许被手工写成 `'infinity'`，驱动对它就交回一个数字 `Infinity` 而不是日期对象。第一版照最顺手的写法来：

```ts
createdAtMs: 一.createdAt.getTime()
```

新写的判据当场撞出 `TypeError: 一.createdAt.getTime is not a function`。往下走的样子是：SQL 本身没失败，`catch` 把它兜成 `null`，接口回 503——**一行坏数据把整栏变成"读不出来"**。

修法不是给他补一个日期，也不是兜成 `0`（那屏幕上会念出 1970-01-01，那是替库里编一个读数）。只认日期对象，其它一律交 `NaN`，让念法那一层说人话：

```ts
function 时刻成毫秒 (值: unknown): number {
  return 值 instanceof Date ? 值.getTime() : Number.NaN
}
```

词表里因此多出「时刻可疑」那一支，念"这一页有 N 个账号，但其中有一行的注册时刻读不出来"。它不并进"有人"那一支，也不丢掉那一行——丢掉就把 3 行读成 2 行。

## 那句话只有一份，所以判据读的是状态词

`shared/copy/admin-users.ts` 里九种形状各有一句，行内三位的兜底也全收在这份文件里：名字空着念"（没填名字）"，而空串就原样是空串——**"没填"与"填了个空的"是两件事**；角色遇到词表外的值念"没列出的角色（staff）"并把原值带上。

角色清单只有一份，且**从库里那个枚举定义本身读**（`userRole.enumValues`）。另抄一份字面量的后果是加值那天筛不出来、还回 400 说参数非法。

组件里两个位置分开：`users-state` 给判据读，`users-sentence` 给人读，改文案不会把断言的位置带崩。

取数走那条把键烤死的出口。框架那份工厂宏有两种写法：传对象是**默认模式**，调用方能顶掉它；传函数是**覆盖模式**，工厂算出来的压过调用方的。本站一律用后一种，因为这一栏念的"全站共 N 个"绝不允许两个调用点各念一份。

## 删掉那句 await，带库端到端六档全绿

这一栏组件的第一句是 `await useAdminUsers(...)`，注释里那句"服务端那一趟由 SSR 发"看着就是在为这个 `await` 背书。做变异取证时把 `await` 删掉，跑带库那一趟：**六档全绿**，屏幕上照样念出"这一页 20 个账号（全站共 244 个）"。

这不是判据漏了，是那句背书本来不成立。文档在取数那两节里各写了同一句：不 await 也没关系，SSR 会等请求跑完再把结果发给客户端。所以 `await` 管的是这一段代码往下走时 `data` 落没落定，不管服务端那份 HTML 里有没有数字。于是补一档形状判据：后台那三栏各自 `await` 自己的出口。同一条变异再跑，这次红了——这件事端到端看不见，只能钉在源码形状上。**绿灯不等于对**。

## 共享库里只判自己那几行

带库那一份规格问的是真页面上那条地址。这条线第三次撞上同一个约束：这条地址读的是**全库**的账号，别的规格留着的行也在里面。所以 `total` 只判"大于等于我自己那几个"，绝不判等于几；名单里有没有我这几行，按自己插入的邮箱筛。

这一档还会插一个 `member` 探针——那是降级任务会动的人，必须占会话级那把锁，等不到就让路。入场按前缀自清，退场再删一次。

四份新判据文件一共 16 档，每档都要能撞红：

| 变异 | 红在哪一档 |
| --- | --- |
| 没配库那一格兜成空页 | 单测 ① |
| 时刻不是日期时兜成 `0` | 单测 ② |
| 计数语句不带筛选条件 | 单测 ③ |
| 读不到计数行当 0 | 单测 ④ |
| 排序少一把平手键 | 单测 ⑤ |
| 这一层开始读封禁列 | 单测 ⑥ |
| "翻过头"念成"没人符合" | 词表 ① |
| 名字空值兜成空串 | 词表 ② |
| 失败那句念成"还没账号" | 组件 ① |
| 空名单也渲出列表 | 组件 ① |
| 这一栏长出按钮 | 组件 ② |
| 接口不读那道门 | 端到端 ①：匿名读到 200 |
| 偏移没进 SQL | 端到端 ④：翻过头还给行 |

## 这一趟的读数

聚合检查八项全过：单测 475 条／72 文件，组件档 73 条／19 文件，静态检查 0 error（1 条历史警告与本站无关）。不带库端到端（端口 4231）260 passed／170 skipped／0 failed，这一站那份规格 6 档全在"要库"那一群里被跳过。

带库那一趟要分两件事说。单独跑这一站那六档（4207）是 6 passed，真库回读到的句子是"这一页 20 个账号（全站共 244 个）"，第一栏仍是"还没跑过"、第二栏"没人卡着"。带库全量那一趟（4232）是 323 passed／52 failed／3 did not run，52 条红的报错逐字相同，都是连不上远程数据库，一条断言红都没有；换端口重跑（4240）是 342 passed／28 failed／58 skipped／2 did not run，其中 26 条仍是连接超时或域名解析失败，另两条一是首页预取那格的历史闪红（第 11 次），二是"查不到的会话号仍回 401"读到了 500，而那一格单独跑（4241）是 3 passed——红的原因是拿会话号问库时库连不上、那条查询抛了出来。

结论照实写：这一站的带库证据是"本档六档绿"，全量带库绿灯本轮没取到，记为待补，不写成本站回归。

四帐为"形状变了"而红的老判据都按登记改期望值，一条没删：读 `role` 的名单 6→9 位（新增那三家分别只是走门、当筛选条件、念给人听，按 `role` 判权限的仍只有那两道门）、admin 档的读者 3→4、取数出口 4→5、后台端点清单 3→4，加上上一线那份基线档案 8→9 档。
