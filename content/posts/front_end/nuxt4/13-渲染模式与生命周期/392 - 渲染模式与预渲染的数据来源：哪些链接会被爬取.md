预渲染漏页最常见的一句解释是"这页没被链到"。但"被链到"到底指什么——是代码里写了 `<NuxtLink>` 就行，还是要满足别的条件？392 把这一层抠到最具体：爬虫眼里"链接"长什么样。

## 爬虫认的"链接"是 `<a href>`

回到 380 那段爬虫四步，关键是第 3、4 步：

> 3. Find all anchor tags (`<a href="...">`) in the HTML to navigate to other routes.
> 4. Repeat steps 1-3 for each anchor tag found until there are no more anchor tags to crawl.

爬虫找的是**服务端渲染出来的那段 HTML 里的 `<a href="...">` 锚点**。它不是解析你的 Vue 源码、也不是跑一遍客户端 JS——它看的是已经拼好、存下来的 HTML。一条链能不能被发现，取决于**它在构建期那份 HTML 里是不是已经是一个真 `<a href>`**。

## 由此几条实际边界

**① 只在客户端才出现的跳转，爬不到。** 如果某个入口是靠点击后才 `navigateTo`、或路由跳转由客户端逻辑拼出来，服务端 HTML 里根本没有对应 `<a href>`，爬虫就看不见它。声明式的 `<NuxtLink to="...">` 渲染成 `<a href="...">` 才是可发现的形态。

**② 数据里带的链接要构建期已就位。** 若某页的正文链接要靠水合后 `$fetch` 回来再渲染（389 那种二次请求场景），预渲染构建期那一趟这段还没内容、锚点就不在 HTML 里，下游页因此爬不到。首屏就把链接渲出来（走 SSR/取数进 payload，387），下游才可被发现。

**③ `noScripts` 路由不影响它被爬。** 381/365 说过 `noScripts` 页里链接仍"作为普通 `<a>` 标签工作"——只要 HTML 里有 `<a href>`，爬虫照样顺着发现，脚本禁不禁和被不被爬是两码事。

## 爬虫的固定起点

380 列过路由来源，这里只挑"起点"这条：爬虫从这三类开始读 `<a href>`——

1. 根路由 `/`；
2. `~/pages` 里的**非动态**页面；
3. `prerender.routes` 数组里显式列的。

从这些起点出发，再顺着每页 HTML 里的锚点滚雪球。所以动态页、或压根没被起点链到的页，得靠下面两招补。

## 发现不了的两条补法

**`crawlLinks`**：让爬虫开足马力顺锚点抓，并把发现不了的固定路由一起塞进 `routes` 当起点：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  prerender: {
    crawlLinks: true,
    routes: ['/sitemap.xml', '/robots.txt'],
  },
})
```

**`prerenderRoutes()` / `prerender:routes` 钩子**：当链接没法静态地出现在 HTML 里（比如全部路径要查 CMS），就别指望爬了，直接登记。380 给的钩子形态：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  hooks: {
    async 'prerender:routes' (ctx) {
      const { pages } = await fetch('https://api.some-cms.com/pages').then(res => res.json())
      for (const page of pages) ctx.routes.add(`/${page.name}`)
    },
  },
})
```

## 自查

- 爬虫认的"链接"＝服务端渲出的 HTML 里的 `<a href>` 锚点，不是 Vue 源码、也不是客户端 JS 跑出来的跳转。
- 三条边界：只在客户端出现的导航爬不到；正文链接要构建期已在 HTML；`noScripts` 不影响被爬（照有 `<a href>`）。
- 固定起点三类：`/`、`~/pages` 非动态页、`prerender.routes`；从此起点顺锚点滚。
- 静态链不进 HTML 的（CMS 全量页），用 `crawlLinks` 补起点、或 `prerenderRoutes()`/`prerender:routes` 钩子手动登记。
