Nuxt 官方入门最佳实践那一页，开头一句话很直接："When developing, you may face hydration issues. Don't ignore those warnings."（开发中你会碰到水合问题，别忽略那些警告）。要明白为什么不能忽略，先得搞清楚"水合"到底在合并哪两样东西。

## 为什么会有两套 DOM

365 讲过 universal 渲染的机制：服务器先跑一遍 Vue 的 JS，把组件拼成一整段 HTML 发过来；浏览器下载后，同一份 JS **再跑一遍**，把事件挂上去，让页面能交互——第二步就叫 **水合（Hydration）**。

于是同一个页面此刻有两份"表示"：

1. **服务器给的那段 HTML**：已经是浏览器里实实在在显示的 DOM，但它是"死"的——369 说过服务端没有响应式、`onMounted` 那套也不跑，所以这段 HTML 里没绑任何监听。
2. **浏览器里 Vue 要建的组件树**：Vue 拿着同一份组件代码，在脑子里算"如果我渲染，应该出什么 DOM"。

水合干的事，就是让这二者对上：Vue 把服务器已经给出的真实 DOM 节点，逐个认领成自己组件树的对应节点，然后只补上事件监听，而不是重新创建 DOM。对上了，页面既保留了首屏 HTML、又变活了。

## 对不上，就是 mismatch

如果"Vue 在浏览器算出来的样子"和"服务器给的那段 HTML"不一样——比如服务器那趟和客户端那趟读到的值不同、或者客户端渲染出了服务器根本没有的节点——Vue 就发现认领失败，报一个 **hydration mismatch**。365 那页引 Vue 文档时也提过这个概念（tip 直接链到 Vue 的 "hydration mismatch" 一节）。

## 为什么不只是个警告

官方那页专门反驳"这只是 warning"的想法：

> Hydration mismatches are not just warnings - they are indicators of serious problems that can break your application.

它把后果分两类列了出来。

**性能层面：**

- **可交互时间变长**：水合错误会**逼 Vue 把整个组件树重新渲染一遍**（"force Vue to re-render the entire component tree"），你的应用要更久才能交互。
- **体验差**：用户可能看到内容闪一下，或布局意外跳动。

**功能层面：**

- **交互坏掉**：事件监听可能挂不上，按钮和表单点了没反应。
- **状态不一致**：应用状态和用户看到的会不同步（"what the user sees and what the application thinks is rendered"）。
- **SEO 问题**：搜索引擎索引到的内容，可能和用户实际看到的不一样。

注意第一条的因果：正因为水合的前提是"复用服务器那段 DOM"，一旦对不上、Vue 只能整树重渲染，SSR 省下的那点首屏优势当场就还回去了。

## 怎么发现它

最直接的途径，官方写的是**开发期控制台**：

> Vue will log hydration mismatch warnings in the browser console during development.

也就是在 `nuxt dev` 下打开浏览器控制台，Vue 会把水合不匹配的警告打出来。生产构建默认不带这些警告，所以别等线上——开发期看到就别放过，这正是那句话的意思。

## 自查

- SSR 下同一页有两套表示：服务器拼的死 HTML（无响应式无监听）＋浏览器里 Vue 要建的组件树；水合让二者逐节点对上并补挂监听。
- 两边算出来的 DOM 不一致 = hydration mismatch。
- 后果不只是警告：会逼 Vue 重渲染整树（可交互变慢）、事件挂不上、状态不同步、SEO 索引到错内容。
- 发现途径＝开发期浏览器控制台，Vue 会打 warning。
