365 认全了名字，这一篇解决"我的站该选哪个"。答案不在技术先进不先进，在你愿意拿什么换什么。官方把两种主线的优缺点都摊开了。

## Universal（SSR）：好处

- **性能**：用户能立刻看到内容，因为浏览器渲染静态 HTML 比先下 JS 再拼快得多；同时水合过程又保留了应用的交互性。
- **SEO**：像传统服务端程序一样，整页 HTML 一次性送到浏览器，爬虫能直接索引内容——官方说这是"任何你想快速被索引的内容"的好选择。

## Universal（SSR）：代价

- **开发约束**：服务端和浏览器环境提供的 API 不一样，要写一份两边都能无缝跑的代码有时会棘手（Nuxt 给了指南和专门的变量帮你判断某段代码在哪执行——就是 365 那张"谁在哪跑"表）。
- **成本**：要实时渲染页面，就得有一台服务器一直跑着，像传统服务器那样有月成本。不过好在水合之后，客户端内导航由浏览器接管，服务器调用大幅减少；还能靠 edge-side rendering 进一步省（365 第四节）。

**官方点名适合 universal 的**：内容为主的网站——**博客、营销站、作品集、电商站、市场类站点**。

## Client-Side（CSR）：好处

- **开发速度**：纯客户端不用操心代码和服务端兼不兼容，比如可以放心用 `window` 这种只在浏览器有的 API。
- **便宜**：不用跑在支持 JS 的平台上，HTML/CSS/JS 文件能丢在任何静态服务器上托管。
- **离线**：代码全在浏览器里跑，断网也能继续工作。

## Client-Side（CSR）：代价

- **性能**：用户要等浏览器把 JS 下完、解析完、跑起来才看到内容，快慢取决于网络（下载）和用户设备（解析执行）。
- **SEO**：客户端渲染出来的内容，索引和更新都比服务端拼好的 HTML 慢——因为爬虫第一次来抓时不会等你界面渲染完。

**官方点名适合 CSR 的**：不需要被索引、或用户会频繁回访的**重交互应用**，能靠浏览器缓存跳过后续访问的下载阶段——**SaaS、后台管理系统、在线游戏**。

## 一张对照表

| | Universal（SSR） | Client-Side（CSR） |
| --- | --- | --- |
| 首屏 | 快（直接给 HTML） | 慢（等 JS 下载执行） |
| SEO | 爬虫直接索引 | 索引/更新慢 |
| 开发省心度 | 两端 API 要对齐 | 可随便用 `window` |
| 服务器成本 | 要一台一直跑的服务器 | 任意静态托管即可 |
| 离线 | 否 | 可以 |
| 官方建议场景 | 博客/营销/作品集/电商/市场 | SaaS/后台/游戏 |

## 一条别忽略的硬提醒

选 SSR 时最容易踩的坑，官方用 `::important` 单独框了出来：

> When importing a library that relies on browser APIs and has side effects, make sure the component importing it is only called client-side. Bundlers do not treeshake imports of modules containing side effects.

拆开说：一个库**依赖浏览器 API**、又**带副作用**，导入它的那个组件必须保证只在客户端跑。原因是打包器**不会**对"含副作用的模块"做 tree-shaking——你以为是客户端才用到的东西，服务端阶段也照样被打进去、照跑，于是撞上"服务端没有 `window`"之类的错。这类组件怎么强制只在客户端，用 376 的 `ClientOnly`（365 也提过"组件可强制只在客户端运行"）。

## 怎么选（场景题）

- 内容站、要做 SEO、首屏要快 → universal（默认就是它，不用动）。
- 登录后的重交互工具/后台、几乎不需要被搜索引擎收录、用户会反复来 → `ssr: false`。
- 一个站里既有营销页又有后台 → 别整站一刀切，用 hybrid 按路由分：营销页走 universal/预渲染、后台 `/admin/**` 走 `ssr: false`（367）。
- 引入了带副作用且依赖浏览器 API 的库 → 包它的组件锁客户端（上面的 `::important`）。

## 自查

- SSR 用开发约束和服务器成本，换首屏快 + SEO 好；适合内容站。
- CSR 用首屏慢 + SEO 弱，换开发省心 + 托管便宜 + 可离线；适合重交互、高频回访的应用。
- Nuxt 默认 universal，切 CSR 一行 `ssr: false`，两者混合走 route rules（367）。
- 带浏览器 API + 副作用的库，导入它的组件必须只在客户端——因为打包器不 tree-shake 有副作用的模块。
