373 说清了两套 DOM 对不上就叫 mismatch。这一篇把"什么操作会让它们对不上"列全——官方 `guide/best-practices/hydration` 那一节在 Common Reasons 下给了五个，每个都配了坏例（Problem）和修法（Solution），逐个落地。

## 成因一：服务端用了浏览器专属 API

问题代码：

```vue
<script setup>
// localStorage 在服务端不存在，会引发水合不匹配
const userTheme = localStorage.getItem('theme') || 'light'
</script>
```

`localStorage` 只在浏览器有，服务端那趟要么直接抛错、要么取到 `undefined`，于是服务器拼出的值和浏览器算出的值不同。

修法——用 `useCookie`，它在两端都能读、且服务端能把 cookie 带过去：

```vue
<script setup>
// 服务端和客户端都能用
const userTheme = useCookie('theme', { default: () => 'light' })
</script>
```

## 成因二：两端数据不一致

问题代码：

```vue
<template>
  <div>{{ Math.random() }}</div>
</template>
```

`Math.random()` 服务端跑一次得一个值、客户端水合时又跑一次得另一个值，两边必然不同。

修法——把这种值放进 SSR 友好的状态。`useState` 服务端算一次、结果写进 payload 带给水合端的客户端复用，不再重算：

```vue
<script setup>
const state = useState('random', () => Math.random())
</script>
```

这正对上取数那一节"服务端取的数据转发进 payload、水合时别再取"的思路（372、262）。

## 成因三：按客户端状态做条件渲染

问题代码：

```vue
<template>
  <div v-if="window?.innerWidth > 768">Desktop content</div>
</template>
```

`window` 服务端没有，`v-if` 条件在两端算出不同结果，服务器可能压根没渲染这块、客户端却渲染了。

修法——用 CSS 媒体查询做响应式，而不是用 JS 在模板里判窗口：

```vue
<template>
  <div class="responsive-content">
    <div class="hidden md:block">Desktop content</div>
    <div class="md:hidden">Mobile content</div>
  </div>
</template>
```

## 成因四：带副作用的第三方库

问题代码：

```vue
<script setup>
if (import.meta.client) {
  const { default: SomeBrowserLibrary } = await import('browser-only-lib')
  SomeBrowserLibrary.init()
}
</script>
```

官方括号里点了一句这最常见于 tag manager："this happens a LOT with tag managers"。库会改 DOM 或依赖浏览器环境。

修法——等到水合完成后再初始化，放进 `onMounted`（`onMounted` 只在浏览器跑，见 369）：

```vue
<script setup>
onMounted(async () => {
  const { default: SomeBrowserLibrary } = await import('browser-only-lib')
  SomeBrowserLibrary.init()
})
</script>
```

这和 366 那条"带副作用的库导入它的组件要只在客户端"、370"副作用挪进 `onMounted`"是同一条线。

## 成因五：依赖当前时间的内容

问题代码：

```vue
<script setup>
const hour = new Date().getHours()
const greeting = hour < 12 ? 'Good morning' : 'Good afternoon'
</script>
```

服务器渲染的时刻和用户浏览器打开的时刻可能不同（尤其有缓存时），问候语就两边不一致。

修法有两道：

- 用 `<NuxtTime>` 组件（服务端渲染安全的时间显示，本系列 099）：

  ```vue
  <template>
    <NuxtTime :datetime="new Date()" format="HH:mm" />
  </template>
  ```

- 或包进 `<ClientOnly>`，服务端先给个占位、水合后再算：

  ```vue
  <template>
    <ClientOnly>
      {{ greeting }}
      <template #fallback>Hello!</template>
    </ClientOnly>
  </template>

  <script setup>
  const greeting = ref('Hello!')
  onMounted(() => {
    const hour = new Date().getHours()
    greeting.value = hour < 12 ? 'Good morning' : 'Good afternoon'
  })
  </script>
  ```

`ClientOnly` 的用法见 376。

## 五条成因速查

| 成因 | 触发点 | 官方修法 |
| --- | --- | --- |
| 浏览器专属 API | `localStorage.getItem(...)` | `useCookie(...)` |
| 两端数据不一致 | 模板里 `Math.random()` | `useState('key', () => Math.random())` |
| 按客户端状态条件渲染 | `v-if="window?.innerWidth"` | CSS 媒体查询（`hidden md:block`） |
| 带副作用的第三方库 | setup 里 `import.meta.client` + `init()` | 到 `onMounted` 里再 `init()` |
| 依赖当前时间 | `new Date().getHours()` 拼文案 | `<NuxtTime>` 或 `<ClientOnly>`+`onMounted` |

## In Summary：官方四条总则

那一节最后用 "In Summary" 收口，是上面五例的共性：

1. **用 SSR 友好的组合式**：`useFetch`、`useAsyncData`、`useState`。
2. **包起只客户端的代码**：浏览器专属内容用 `<ClientOnly>`。
3. **保证数据源一致**：服务端和客户端用同一份数据。
4. **别在 setup 里造副作用**：依赖浏览器的代码挪进 `onMounted`。

官方再补一条延伸阅读，指向 Vue 自己的 "SSR hydration mismatch" 文档。

## 自查

- 五类成因同一个根子：服务端算出的 HTML 和客户端算出的不一样。
- 记五组替换：localStorage→useCookie、Math.random→useState、window 条件→媒体查询、库 init→onMounted、时间文案→NuxtTime/ClientOnly。
- 四条总则＝SSR 友好组合式、ClientOnly 包客户端内容、两端数据一致、副作用挪进 onMounted。
