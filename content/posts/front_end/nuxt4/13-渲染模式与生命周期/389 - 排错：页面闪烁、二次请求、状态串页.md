## 现象一：页面闪烁、布局跳动

**你看到的**：首屏内容出现后又闪一下、或布局突然错位。这正是 373 列的症状之一（"Users may see content flashing or unexpected layout shifts"）。

**成因**：水合不匹配。服务端那段 HTML 和客户端 Vue 算出的不一样，Vue 只能把整棵树重渲（"force Vue to re-render the entire component tree"），重渲那一下就是"闪"。

**怎么排**：去 `nuxt dev` 的浏览器控制台找 Vue 打的 hydration mismatch warning（373），顺着 374 那五类成因逐项查——
`localStorage` 在 setup、`Math.random()` 直接进模板、`window.innerWidth` 条件渲染、带副作用的库没放 `onMounted`、`new Date()` 拼时间文案。每类都有对应修法（useCookie/useState/媒体查询/onMounted/NuxtTime 或 ClientOnly）。

## 现象二：同一接口被请求了两次

**你看到的**：网络面板里一个接口出现两次——服务端一次、浏览器又一次。

**成因**：在 setup 里用了裸 `$fetch` 取首屏数据。取数那页写得很清楚，`$fetch` 在 setup 里取数会"cause data to be fetched twice, once on the server ... and once again on the client"，而且"This can cause hydration issues, increase the time to interactivity and cause unpredictable behavior."

**根因回到 387**：`$fetch` 不往 payload 转发、客户端复用不了，所以水合时又取一次。`useFetch`/`useAsyncData` 的本职就是"if an API call is made on the server, the data is forwarded to the client in the payload instead of being fetched again"。

**怎么排**：首屏要进 HTML 的数据一律 `useFetch`/`useAsyncData`；`$fetch` 只留给"纯浏览器里的事件触发请求"（点了按钮才发那种）。注意别把 `server: false` 当成省请求的手段——那种数据首屏根本不在服务端取、水合完才取，是另一回事（372）。

## 现象三：状态串页、甚至串用户

**你看到的**：上一个页面改的值跑到下一个页面上；更糟的是生产环境里，A 用户看到了 B 用户的数据。

**成因**：把 `ref(...)`、可变对象建在**模块作用域**或 setup 之外的共享位置。服务端每个请求**不新建一份**、而是复用同一份模块状态——这正是 250 记的那条硬警告（`export myState = ref({})` "would result in state shared across requests on the server and can lead to memory leaks"），也是 370 "全局态"那条视频 callout 讲的同一件事。

**怎么排**：
- 跨组件/跨请求要共享的响应式状态，用 `useState`（每请求一份、进 payload 水合复用，387），别用模块级 `ref`。
- 只跑一次的初始化副作用用 `callOnce`。
- 这类串用户问题 dev 常复现不了（本地就你一个用户、状态看着没事），要在生产多请求下才暴露——**别用 dev 的正常表现来证明它没问题**。

## 排查工具

看不清就上 debugging 那页给的三件（细节见 383/384 之前的 338）：

- **dev 控制台**：水合警告只在开发期打（现象一的入口）。
- **sourcemaps**：服务端构建默认开、客户端 dev 开；`sourcemap: { server: true, client: true }` 精确控制。
- **`nuxt dev --inspect`**：接 Chrome DevTools 调服务端；官方限制——Node 与 Chrome 要同平台、**Docker 里不行**。

## 三类症状对照

| 症状 | 根因 | 正解 |
| --- | --- | --- |
| 闪烁 / 布局跳动 | 水合不匹配 | 按 374 五成因对齐两端 |
| 接口请求两次 | setup 里裸 `$fetch` | `useFetch`/`useAsyncData` 经 payload 转发 |
| 状态串页/串用户 | 模块级共享状态 | `useState`（每请求一份）、`callOnce` |

## 自查

- 闪烁＝mismatch，先开 dev 控制台看 warning、对 374 五成因。
- 二次请求＝setup 裸 `$fetch`；首屏数据用 useFetch/useAsyncData，`$fetch` 只留给纯客户端事件。
- 状态串页＝模块作用域 `ref`；共享状态改 `useState`，且这类问题 dev 常看不出来、要在生产判。
- 看不清用 dev 控制台 / sourcemap / `--inspect`（Docker 不能用）。
