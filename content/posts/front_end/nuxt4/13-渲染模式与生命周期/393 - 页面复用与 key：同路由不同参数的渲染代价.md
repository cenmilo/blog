列表页点进详情，再点"下一个"，URL 从 `/user/1` 变成 `/user/2`，但页面里你手动改过的表单、滚到的位置都还在，取数好像也没重跑——这是 Vue Router 的同组件复用，不是 bug。要精确控制"什么时候真的重建页面"，靠的是 `key`。

## 默认行为：同路由换参数会复用

一个动态页 `pages/user/[id].vue` 对应一条路由记录。参数从 1 换到 2，命中的还是**同一个组件**，所以 Vue 复用实例：组件不卸载重挂、`setup` 不重跑、`onMounted` 那套客户端生命周期不再走一遍、组件内部状态保留。要感知参数变化，得自己 `watch(() => route.params.id, ...)`，或者用下面的 `key` 强制重建。

这也是为什么"参数变了数据没刷新"常见——复用意味着 `useFetch` 若没在 `watch` 里挂上那个参数，就不会重取（取数那侧的机制见 239）。

## `key` 是官方的控制点

`definePageMeta` 的参数表里这一行就是干这个的：

> **`key`** — **Type**: `false | string | ((route: RouteLocationNormalizedLoaded) => string)` — Set `key` value when you need more control over when the `<NuxtPage>` component is re-rendered.

`nuxt-page` 那页给的 `pageKey` prop 是同一件事的另一半：

> `pageKey`: control when the `NuxtPage` component is re-rendered.

官方举例说得很直白：

> For example, if you pass a key that never changes, the `<NuxtPage>` component will be rendered only once - when it is first mounted.

**给一个永远不变的 key，页面只在首次挂载时渲染一次。**

## 两种写法

在 `<NuxtPage>` 上设（影响该出口下所有页）：

```vue
<!-- 静态：整片复用，只渲一次 -->
<NuxtPage page-key="static" />

<!-- 动态：按当前路径决定 key -->
<NuxtPage :page-key="route => route.fullPath" />
```

或在页面自己内部就近设（`definePageMeta` 的 `key` 等价于 `pageKey`）：

```vue
<script setup lang="ts">
definePageMeta({
  key: route => route.fullPath,
})
</script>
```

`route => route.fullPath` 的含义是：只要完整路径（含参数、query）变了，key 就变，组件重建——于是 `onMounted`、setup 初始化都会重新走一遍。

`nuxt-page` 那页有一条 `::warning` 级别提醒：动态 key 的写法里**不要用 `$route` 对象**，会和 `<NuxtPage>` 用 `<Suspense>` 渲染页面的方式冲突。要用回调里的 `route` 形参。

## 三种取值怎么选

| 想要的效果 | 怎么写 | 结果 |
| --- | --- | --- |
| 同组件复用、状态留住 | 不设 key（默认） | 换参数只更新参数，不重建 |
| 路径一变就完全重建 | `key: route => route.fullPath` | 每次导航都重挂、setup 重跑 |
| 整片只渲一次 | `page-key="static"` | 组件只首次挂载渲染 |
| 关掉 key 控制 | `key: false` | 类型允许 `false`（不设定自定义 key） |

`key` 类型里的 `false` 是"不给自定义 key"这一档；`string` 是固定值；函数是动态值。

## 别把 keepalive 当 key 用

`definePageMeta` 里紧挨着的 `keepalive` 是另一件事——"preserve page state across route changes"，走 Vue 的 `<KeepAlive>`，管的是**离开页面后状态留不留**；`key` 管的是**同一路由换参数时组不重组**。官方 Basic Usage 那个例子把两个一起用了：

```vue
<script setup lang="ts">
definePageMeta({
  key: route => route.fullPath,
  keepalive: {
    exclude: ['modal'],
  },
  pageType: 'Checkout',
})
</script>
```

## 一条容易忽略的连带行为

`scrollToTop` 的说明专门点了 key：

> Navigation is independent from rendering, so scroll behavior is always triggered even when the page doesn't re-render (e.g. when using a fixed `key`). Set `scrollToTop: false` to disable scrolling in such cases.

也就是说：即便 `key` 固定导致页面不重渲，**滚动到顶照样发生**——导航和渲染是两回事。想让复用时别滚回顶部，显式设 `scrollToTop: false`。

## 自查

- 同路由换参数默认**复用组件**：不重挂、setup 不重跑、内部状态保留、`onMounted` 不再走。
- `key`（`definePageMeta` 的 `key` / `<NuxtPage>` 的 `pageKey`）控制何时重渲；固定 key 只渲一次，`route => route.fullPath` 一变就重建。
- 动态 key 里别用 `$route` 对象（和 Suspense 渲染冲突），用回调形参。
- `keepalive` 管"离开页面状态留不留"，`key` 管"换参重组不重组"，别混。
- 复用时 `scrollToTop` 默认仍触发，需要就设 `scrollToTop: false`。
