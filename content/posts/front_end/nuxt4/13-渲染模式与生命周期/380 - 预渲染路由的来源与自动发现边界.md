预渲染上线后最常听到的一句抱怨："这个页面明明在 `pages/` 里，怎么生成出来是空的 / 根本没生成？"多半是它没被爬虫发现。要弄清哪些页会被渲，得看 Nitro 爬虫到底怎么找路由。

## 爬虫的四步

官方 "How the Nitro crawler works" 把过程拆成四步：

1. 加载这些页的 HTML：应用根路由 `/`、`~/pages` 里的**非动态**页面、以及 `prerender.routes` 数组里列的任何其它路由。
2. 把 HTML 和 `_payload.json` 存进 `.output/public/` 供静态服务。
3. 在 HTML 里找所有锚点标签（`<a href="...">`），据此跳到别的路由。
4. 对每个找到的锚点标签重复第 1-3 步，直到没有更多可爬的链接。

## 由此得到的硬边界

官方在四步后面直接点破了：

> This is important to understand since pages that are not linked to a discoverable page can't be pre-rendered automatically.

**没被某个"可发现的页面"链接指向的页面，没法被自动预渲染。** 这就是漏网页的根因——比如只从搜索、外链、或 JS 拼出来的地址进入的页面，首页里没有任何 `<a href>` 指向它，爬虫第 3 步就找不到它。

## 路由一共有几个来源

把四步和 379 的配置合起来，被预渲染的路由来自这几处：

| 来源 | 怎么进爬虫 |
| --- | --- |
| 根页 `/` | 爬虫起点（第 1 步固定读） |
| `~/pages` 里的非动态页 | 第 1 步固定读 |
| `prerender.routes` | 第 1 步显式列出（sitemap/robots 这类） |
| 上面这些页里的 `<a href>` | 第 3-4 步顺链接发现 |
| `routeRules` 的 `prerender: true` | 按路由配（379/367） |
| 运行时 `prerenderRoutes()` | 见下 |
| `prerender:routes` 钩子 | 见下 |

动态页（如 `pages/blog/[slug].vue`）本身不在这几个自动来源里——它得被某页链接到、或被下面两个运行时入口加进来。

## 运行时补漏的三个入口

官方 "Runtime Prerender Configuration" 给了三个。

**1. `prerenderRoutes()`**（在 Nuxt 上下文里、预渲染执行期调用，见 323）：给 Nitro 再加要预渲染的路由。

```vue
<script setup>
prerenderRoutes(['/some/other/url'])
prerenderRoutes('/api/content/article/my-article')
</script>
```

连 API 路由也能登记去预渲染。

**2. `prerender:routes` Nuxt 钩子**：预渲染前调用，用来追加路由——典型是去 CMS 拉全部页面再 `ctx.routes.add(...)`。

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  hooks: {
    async 'prerender:routes' (ctx) {
      const { pages } = await fetch('https://api.some-cms.com/pages').then(res => res.json())
      for (const page of pages) {
        ctx.routes.add(`/${page.name}`)
      }
    },
  },
})
```

这是把"没链接指向的 CMS 页"批量喂给爬虫的正解。

**3. `prerender:generate` Nitro 钩子**：每个路由预渲染时都调用，做逐路由细控——比如把带 private 的跳过。

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  nitro: {
    hooks: {
      'prerender:generate' (route) {
        if (route.route?.includes('private')) {
          route.skip = true
        }
      },
    },
  },
})
```

`prerender:routes` 负责"加路由进来"，`prerender:generate` 负责"逐个决定渲不渲"，一前一后。

## `_payload.json`：预渲染顺带产出的水合数据

第 2 步存 HTML 的同时还存 `_payload.json`。Payload Extraction 那节说：预渲染路由在**构建期**生成 payload 文件；客户端导航时读它、复用里面数据而不是在浏览器重新取数。后果是官方点明的——"在完全静态的站点上，客户端导航复用构建期捕获的数据，所以数据会一直是旧的直到下一次重新构建"。这条决定了纯静态站的数据新鲜度上限。

## 自查

- 爬虫四步：读 `/`+非动态页+`prerender.routes` → 存 HTML 与 `_payload.json` → 找 `<a href>` → 重复到没有新链接。
- 硬边界：没被可发现页链接指向的页不能自动预渲染。
- 补漏三入口：`prerenderRoutes()`（上下文+预渲染期）、`prerender:routes` 钩子（预渲染前批量加）、`prerender:generate` 钩子（逐路由 skip）。
- 预渲染同时写 `_payload.json`；纯静态站数据会陈旧到下次重建。
