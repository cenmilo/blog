365-389 分别讲了渲染形态、生命周期、水合、预渲染、取数和 payload。这一篇把它们按时间排成一条线——一次首屏请求从点进去到能交互，到底先后发生了什么。后面每篇都在这张图的某一段上。

## 服务端那一趟（每个初始请求）

浏览器请求一个 URL，服务器先走七步（368 的 Server Lifecycle）：

1. **Nitro 插件**（`server/plugins`）：只在服务启动跑一次（serverless 则每请求 boot、但不 await）。
2. **服务端中间件**（`server/middleware`）：每请求执行；注意从这里 return 值会终止请求（368 的 `::warning`）。
3. **建实例 + 应用插件**：创建 Vue/Nuxt 实例、跑 `app/plugins`（含 `.server` 后缀）→ 触发 **`app:created`**（371）。
4. **validate**：跑 `definePageMeta` 里的 `validate`（早于中间件）。
5. **路由中间件**：全局中间件两端都跑；服务端重定向会重置应用状态（除 cookie）。
6. **渲染 + 取数**：`useFetch`/`useAsyncData`/`useState` 在此跑，结果**序列化进 payload**（387）。**这一步 Vue 生命周期钩子一个都不执行**（369），也没有响应式——因为服务端只把页面自上而下拼成静态 HTML。
7. **出 HTML**：渲染完触发 **`app:rendered`**，Nuxt 把组件结果与 unhead 的 head 设置合成完整 HTML；发出前 Nitro 触发 **`render:html`**（371）。

到这儿，浏览器收到的是：带内容、带 meta、带 payload 的一整份 HTML。

## 客户端那一趟（任何模式都走）

浏览器拿到 HTML 后走五步（368 的 Client Lifecycle）：

1. **应用插件**：跑内置 + `app/plugins`（含 `.client` 后缀）→ 又触发 **`app:created`**。
2. **validate**：和服务端一样。
3. **路由中间件**：两端都会跑的逻辑；要分环境用 `import.meta.client`/`import.meta.server`。
4. **挂载 + 水合**：`app.mount('#__nuxt')`；SSR/SSG 下 Vue 做**水合**——把已有的服务端 DOM 逐节点认领、补挂事件监听，**读 payload 复用数据、不再重取**（373、387）。挂载前 `app:beforeMount`、挂载后 `app:mounted`（371）。
5. **Vue 生命周期**：从这里开始才跑完整的 Vue 钩子（`onMounted` 等）——也就是 369/370 说的副作用该放的地方。

之后若配了页面动画，`<Transition>` 播进出场、结束触发 `page:transition:finish`（383/371）。

## 一张时间轴

| 段 | 步 | 关键事 | 钩子 |
| --- | --- | --- | --- |
| 服务端 | 插件/中间件 | Nitro 插件一次、每请求中间件 | — |
| 服务端 | 建实例 | Vue/Nuxt 实例、应用插件 | `app:created` |
| 服务端 | validate→中间件 | 校验、鉴权/重定向 | — |
| 服务端 | 渲染+取数 | useFetch/useAsyncData/useState→payload；Vue 钩子不跑 | — |
| 服务端 | 出 HTML | 合 unhead、发 HTML | `app:rendered`→`render:html` |
| 客户端 | 插件 | 应用插件（含 `.client`） | `app:created` |
| 客户端 | 挂载+水合 | 认领 DOM、补监听、读 payload 不重取 | `app:beforeMount`→`app:mounted` |
| 客户端 | Vue 生命周期 | 完整钩子从此才跑 | onMounted 等 |
| 客户端 | 动画（可选） | `<Transition>` 进出场 | `page:transition:finish` |

## 把它对上渲染模式

- **SSR（默认）**：上面两趟完整走——服务端出带内容的 HTML、客户端水合。SEO 与首屏都快。
- **预渲染**：服务端那趟挪到**构建期**跑一次、产物存成静态 HTML；客户端仍是五步（382）。数据进 payload 也发生在构建期（380：静态站数据会陈旧到下次重建）。
- **`ssr: false`（纯 CSR）**：**跳过整个服务端那一趟**，`#__nuxt` 是空的（386），客户端才建内容——代价是首屏等 JS、SEO 弱（388）。
- **Hybrid**：不同路由按 routeRules 各走各的那趟（367）。

## 自查

- 一条线：服务端(插件→中间件→建实例 app:created→validate→中间件→渲染取数进 payload→出 HTML app:rendered/render:html) ＋ 客户端(插件 app:created→validate→中间件→挂载水合 beforeMount/mounted→完整 Vue 生命周期→可选动画)。
- 服务端那趟 Vue 钩子不跑、无响应式；副作用只在客户端 `onMounted` 起。
- 水合读 payload 复用数据，是"不二次请求"的机制（387/389）。
- 渲染模式决定这条线走几段：CSR 跳服务端整趟、预渲染把服务端那趟搬到构建期、hybrid 按路由分。
