先说症状：报错信息通常是 "A composable that needs the Nuxt instance ... ran outside ..." 或者更含糊的 "injection ... not provided"。这类问题的原因几乎都不在函数本身，而在**你是在哪一刻、哪个位置调用它的**。

## 文档明写的四个调用点

| 位置 | 依据原文 | 出自哪页 |
| --- | --- | --- |
| 页面/组件的 `setup` | "meant to be called directly in a setup function, plugin, or route middleware" | `useFetch` |
| 插件 | 同上一句 | `useFetch` |
| 路由中间件 | 同上一句 | `useFetch` |
| 生命周期钩子回调的**顶层** | "invoked in setup method or called directly at the top level of a function in lifecycle hooks, otherwise you should use `$fetch` method" | data-fetching |

第四行那句常被略过，但它的实用价值最高：**钩子函数里可以调，前提是"直接写在函数顶层"**。比如 `onMounted(async () => { await useFetch(...) })` 属于允许的位置；而在 `onMounted` 里再套一层普通函数、或者放进 `setTimeout`，就落到 E1001 那一类了。

`useAsyncData` 那页的措辞更抽象："meant to be called directly in the Nuxt context"——**什么算 Nuxt 上下文，错误码页写得比它清楚**。

## E1001 把"上下文"这个词落地了

> A composable that needs the Nuxt instance (`useNuxtApp()`, `useRoute()`, `useFetch()`, …) ran outside a plugin, Nuxt hook, route middleware, or Vue `setup()`. The most common trigger is calling it inside an async callback (`setTimeout`, `.then()`, after an `await`) where the context has been lost.

官方给的解法一句两半：

> Call the composable synchronously at the top of `setup()` / a plugin / middleware and reuse the captured result later. For server-side async work, wrap the call with `nuxtApp.runWithContext()`.

我把这两半拆成两种修法：

```ts
// 修法一：先同步取，再在回调里用
const nuxtApp = useNuxtApp()
setTimeout(() => {
  console.log(nuxtApp.payload)   // 复用已经拿到的实例
}, 100)

// 修法二：服务端异步链里把上下文重新包上
await nuxtApp.runWithContext(() => navigateTo('/login'))
```

第二个写法不是我编的：官方自定义 `$fetch` 配方里就在 `onResponseError` 中用了 `nuxtApp.runWithContext(() => navigateTo('/login'))`（238 会看到整段），原因是**拦截器回调不在 setup 的同步执行流里**。

## 中间件里能取数，但拿不到"当前路由"

这两件事互相纠缠，所以单独说。允许调用取数函数这一点来自 `useFetch` 那句（route middleware 被点名）。但同一时间，路由那一头有一条禁令：

> Always use the `to` and `from` parameters in your middleware to access the next and previous routes. Avoid using the [`useRoute()`] composable in this context altogether.
> There is **no concept of a "current route" in middleware**, as middleware can abort a navigation or redirect to a different route. The `useRoute()` composable will always be inaccurate in this context.

违反的官方后果是一条错误码：E2005（`useRoute()` was called inside a route middleware (directly or via another composable)）。**"via another composable" 这几个字很重要**——你封装的函数内部用了 `useRoute()`，同样触发。

所以中间件里正确的取数形状是把 `to` 当参数传进去：

```ts
export default defineNuxtRouteMiddleware(async (to) => {
  const { error } = await useFetch('/api/check', { query: { id: to.params.id } })
})
```

**这个例子是我按两条规则拼的**（middleware 是允许的调用点 + 路由信息必须来自 `to`），官方没给"中间件里取数"的示例。用之前值得确认一件事：中间件里取的数**不会自动进页面组件**（页面得自己再取一次，或者两边用同一个显式 `key` 共享——215 那张共享表就是为这种情况准备的）。

顺带另一条同源限制在错误页那侧（185 引过）：初始页中间件在服务端与客户端各跑一趟，所以**中间件里的取数也可能跑两次**，官方给的分流办法是 `import.meta.server` / `import.meta.client`。

## 布局：文档从没在这里写取数

布局页与取数相关的记载是零。我能给的只有两条相邻事实：

1. 布局是一个 Vue 组件，官方示例里它直接用了 `useRoute()` 与 `useHead()`（185 抄过那个 `layouts/default.vue`），说明**布局的 `setup` 里有 Nuxt 上下文**。
2. 取数函数的合法调用点写的是 "setup function"（没限定是页面还是组件）。

按这两条推，**布局的 setup 里调取数是允许的**。但有一件事布局与页面根本不同，直接决定这么做值不值：官方给布局的定位是"包含多个页面共用的界面、**避免在页面之间重新渲染**"（"avoid re-rendering between pages"，103 抄过）。**布局不重新挂载，那么它的 setup 也只跑一次**——把"随页面变的取数"写在布局里，拿到的是第一次那份数据，之后不会跟着路由更新。

所以我的分工是：

- 全站一份、路由不变的数据（比如导航菜单要用的分类列表）⇒ 放布局，正好只取一次。
- 每个页不同的数据 ⇒ 放页面，别放布局。
- 想跨页共享同一份 ⇒ 用显式 `key`（215）或 `useNuxtData` 读缓存（228），而不是把它挪进布局。

## 一张速查表

| 我想调用的位置 | 结论 | 依据 |
| --- | --- | --- |
| 页面/组件 `<script setup>` 顶层 | 可以 | `useFetch` note |
| 插件顶层 | 可以 | 同上 |
| 路由中间件 | 可以，但路由信息只能用 `to`/`from` | `useFetch` note + 中间件那两条 + E2005 |
| `onMounted` 等钩子回调的顶层 | 可以 | data-fetching 第 357 行那句 |
| `setTimeout` / `.then()` / `await` 之后 | 不行（E1001），要 `runWithContext` | E1001 原文 |
| 布局的 setup | 文档未点名，按"组件 setup"推为可以；**但只跑一次** | 185 的布局示例 + 定位句 |
| Nitro 服务端路由里 | 不是这个上下文，改用服务端 API（`event` 那套） | 133 讲的两侧分工 |

## 自查

1. 文档一共点名了哪四类合法调用位置？（答：`setup`、插件、路由中间件、生命周期钩子回调的顶层。）
2. 最常见的上下文丢失是怎么发生的，两种修法是什么？（答：在异步回调里调用（`setTimeout`、`.then()`、`await` 之后）；修法是提前同步取出实例复用，或用 `nuxtApp.runWithContext()` 包。）
3. 为什么"把取数写在布局里"通常不是好主意？（答：布局避免在页面间重新渲染，setup 只跑一次，随页变化的数据不会更新；共享数据应该用显式 key 或 `useNuxtData`。）
