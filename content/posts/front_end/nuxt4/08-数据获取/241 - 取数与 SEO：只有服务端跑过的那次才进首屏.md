先给一个我实测出问题的形状：文章详情页在 `onMounted` 里取数据，浏览器里一切正常，`curl` 出来的 HTML 却是空的。**内容没进首屏，不是标签写错了。**

## 首屏 HTML 是在什么时候拼出来的

生命周期那页第 7 步把顺序写死了：

> After all required data is fetched and the components are rendered, Nuxt combines the rendered components with settings from `unhead` to generate a complete HTML document. This HTML, along with the associated data, is then sent back to the client to complete the SSR process.

这句给了两个结论：**取数在渲染之前完成**，而 `unhead` 的设置与组件渲染结果一起被合并。所以"内容 + 标题 + meta"是同一份产物。

再看第 6 步（取数那步）为什么必须在服务端：官方写 "Vue lifecycle hooks such as `onBeforeMount`, `onMounted`, and subsequent hooks are **NOT** executed during SSR"（232 逐句引过）。**把取数放 `onMounted`，服务端那一趟就没有它**，首屏自然空。

## 官方自己给 SEO 划的那条线

`server: false` 那一节里，官方在讲 lazy + 客户端取数之后补了一句定位：

> Combined with the `lazy` option, this can be useful for data that is not needed on the first render (for example, non-SEO sensitive data).

**"non-SEO sensitive"（非 SEO 敏感）这个词就是官方给的边界**：`server: false` + `lazy` 是给"不重要出现在首屏"的数据用的。同段还有那句关于时机的描述：

> By default, data fetching composables will perform their asynchronous function on both client and server environments. Set the `server` option to `false` to only perform the call on the client-side. On initial load, the data will not be fetched before hydration is complete so you have to handle a pending state, though on subsequent client-side navigation the data will be awaited before loading the page.

这句话里有个容易被忽略的不对称：**首屏（初始加载）不等，后续客户端导航会等**。也就是说 `server: false` 的代价主要落在第一次访问——而那一次往往就是搜索引擎来的那一次。

官方示例把两种调用并排写了出来：

```ts
/* This call is performed before hydration */
const articles = await useFetch('/api/article')

/* This call will only be performed on the client */
const { status, data: comments } = useFetch('/api/comments', {
  lazy: true,
  server: false,
})
```

这个形状很实用：**正文（SEO 敏感）服务端取，评论（非敏感）客户端取**。文章的"评论区不需要被索引"是假设场景，官方只给了 "for example, non-SEO sensitive data" 这个措辞，不担保评论一定属于该类。

## `await` 不改变首屏，`server` 才改变

210 抄过的那句在这里正好用来消误解：

> The `await` does **not** change the server-rendered HTML. During server rendering, Nuxt waits for the request to resolve before serializing the page either way (`<Suspense>`, and `onServerPrefetch` under the hood), so the fully populated result is always sent to the browser.

**`await` 决定的是"后面的代码什么时候跑"**，不决定"服务端有没有取"。所以我见过的一种错误诊断是"我 await 了怎么还没内容"——要看的是 `server` 选项和这条路由的渲染模式，不是 `await`。

反过来那条 note 就是症状本身：

> If you have not fetched data on the server (for example, with `server: false`), then the data *will not* be fetched until hydration completes. This means even if you await `useFetch` on client-side, `data` will remain undefined within `<script setup>`.

## head 那一侧：同一个前提，两个额外条件

190 引过的那句在这里是前提：

> In most instances, SEO meta tags don't need to be reactive as search engine robots primarily scan the initial page load.

**搜索引擎读的是首屏那一次**——那么当 meta 内容来自取数结果时（`title: () => article.value?.title`），它必须首屏就有。文档给的对应写法是"静态部分包 `if (import.meta.server)`"，而随数据变化的部分保留反应式：

```vue [app/app.vue]
<script setup lang="ts">
const dynamicTitle = ref('My title')
// Only use reactive meta tags outside the condition when necessary
useSeoMeta({
  title: () => dynamicTitle.value,
  ogTitle: () => dynamicTitle.value,
})
</script>
```

两个额外条件都来自流式渲染那一节（193/204 逐句引过）：

- **注册时机**："`useHead`/`useSeoMeta` called synchronously in `<script setup>` (before any `await`), in plugins, or in middleware render into the shell `<head>` as usual."，晚注册的变成客户端补丁。
- **谁能看到补丁**："Anything else (a crawler your `botRegex` does not list, a link unfurler, `curl`) will not see those tags at all."

所以"取数 → 用结果设 meta"这个顺序，在开了流式的路由上是**天然危险**的：取数是异步的，之后的 `useSeoMeta` 就落在 `await` 之后。官方给的两种化解我都记过——把 SEO 关键标签保持同步，或者给该路由退出流式（`routeRules: { '/path': { streaming: false } }`）。

## 别忘了 ssr: false 会让这一切失效

路由级或全局 `ssr: false` 时，首屏 HTML 里没有内容（232/237 都碰过），而且 235 那条链在这里成立：**`ssr: false` 强制 `payloadExtraction: false`**。所以"后台管理页"这类不需要 SEO 的路由开 `ssr: false` 没问题，"内容页"开它就是自断首屏。

## 一张判据表

| 情形 | 首屏 HTML 里有没有 | 依据 |
| --- | --- | --- |
| `useFetch`/`useAsyncData` 在 setup 顶层，`server` 默认 `true` | 有 | 第 7 步在取数之后拼 HTML |
| `onMounted` 里取数 | **没有** | 服务端不执行挂载钩子 |
| `server: false` | **首屏没有**（水合后才有） | 那句 note |
| `ssr: false`（路由或全局） | 没有，且 payload 被强制关 | 渲染模式定义 + `payloadExtraction` 限定 |
| meta 在 `await` 之后注册 + 路由流式 | 抓取者可能完全看不到 | 流式那节两句 |
| `swr`/`isr` 命中缓存 | 有，但内容是缓存期那份 | 237 两句 |

## 自查

1. 内容进不进首屏，取决于哪个选项而不是哪个写法？（答：取决于 `server` 与这条路由的渲染模式；`await` 不改变服务端 HTML。）
2. 官方给 `server: false` + `lazy` 划的用途是什么？原话是哪个词？（答：给"第一次渲染不需要"的数据用；词是 "non-SEO sensitive data"。）
3. 开了流式的路由上，"取完数再设 meta"为什么危险？两种化解是什么？（答：晚注册的标签到不了已发出的 shell `<head>`，变成客户端补丁，不跑 JS 的一方读不到；化解是保持同步注册，或给该路由 `streaming: false`。）
