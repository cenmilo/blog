需求很常见：一个外部 API，每个请求都要带 token，token 过期要跳登录。**先别去找"全局配置 $fetch 的地方"——官方明确说那个口子是有意关掉的。**

## 起点：为什么没有全局配置

> When working with Nuxt, you might be making the frontend and fetching an external API, and you might want to set some default options for fetching from your API.
>
> The `$fetch` utility function (used by the `useFetch` composable) is intentionally not globally configurable. This is important so that fetching behavior throughout your application remains consistent, and other integrations (like modules) can rely on the behavior of core utilities like `$fetch`.

我给这句话的实用解读是：**别的模块也依赖 `$fetch` 的默认行为**，所以它不能被你的项目改。要改就造自己的客户端——这也解释了 226 那次我踩的事（`createUseFetch` 存在的理由）。

## 配方一：一个组合式搞定 baseURL + 鉴权 + 401

官方设定的场景（照抄）："Let's say you have an external API at `https://api.nuxt.com` that requires JWT authentication via nuxt-auth-utils, and you want to redirect to `/login` on `401` responses."

```ts [app/composables/useAPI.ts]
export const useAPI = createUseFetch({
  baseURL: 'https://api.nuxt.com',
  onRequest ({ options }) {
    const { session } = useUserSession()
    if (session.value?.token) {
      options.headers.set('Authorization', `Bearer ${session.value.token}`)
    }
  },
  async onResponseError ({ response }) {
    if (response.status === 401) {
      await navigateTo('/login')
    }
  },
})
```

调用侧从此只写路径：

```vue [app/pages/dashboard.vue]
<script setup lang="ts">
const { data: profile } = await useAPI('/me')
const { data: orders } = await useAPI('/orders')
</script>
```

官方的总结句是 "Now every call to `useAPI` automatically includes the auth header and handles 401 redirects."

这一段里有三处我认为是"设计而非随手写"的：

1. **`createUseFetch` 落在 `app/composables/` 里**，因为它必须是被扫描目录下的导出声明（233 那条约束、226 的宏 note）。
2. **`options.headers.set(...)` 是方法调用**，不是给对象赋一个键——221 也标过这一点（依赖 ofetch 1.4+）。
3. **鉴权逻辑写在 `onRequest` 里**，而不是 `createUseFetch` 的顶层选项。原因是取会话需要 Nuxt 上下文，而 `onRequest` 在每次请求时执行，那时上下文是在的。

顺带一条：`headers` 选项本身也能直接传值（220 那张表），但它适合固定头；**"每次请求现算"的头要走拦截器**。

## 配方二：需要更低层时，造实例放插件

> If you need lower-level control, you can create a custom `$fetch` instance with a Nuxt plugin and either use it with `useAsyncData` directly or pass it to `createUseFetch`.

官方先给了一条 note 说明这个实例能干什么：

> `$fetch` is a configured instance of ofetch which supports adding the base URL of your Nuxt server as well as **direct function calls during SSR (avoiding HTTP roundtrips)**.

那句 "direct function calls during SSR" 就是 211 那条 tip（打内部 API 路由时直接调函数、省一次请求）在同一件事上的第二处记载。

```ts [app/plugins/api.ts]
export default defineNuxtPlugin((nuxtApp) => {
  const { session } = useUserSession()

  const api = $fetch.create({
    baseURL: 'https://api.nuxt.com',
    onRequest ({ request, options, error }) {
      if (session.value?.token) {
        options.headers.set('Authorization', `Bearer ${session.value?.token}`)
      }
    },
    async onResponseError ({ response }) {
      if (response.status === 401) {
        await nuxtApp.runWithContext(() => navigateTo('/login'))
      }
    },
  })

  return {
    provide: {
      api,
    },
  }
})
```

**请注意 `runWithContext` 那一行**：配方一里 `navigateTo` 是裸调的，配方二里被包了一层。这正是 233 那条 E1001 规则的实践——**拦截器回调不在 setup 的同步执行流里，所以要显式把上下文包回来**。这个差别官方没有用文字解释，我是从两处写法对比推出来的；两处都在同一个"401 跳登录"的语义下，所以我的读法是"插件场景必须包"。

使用形态（官方给的两行）：

```vue [app/app.vue]
<script setup>
const { $api } = useNuxtApp()
const { data: modules } = await useAsyncData('modules', () => $api('/modules'))
</script>
```

配套那条 callout 补上"为什么不裸调 `$api`"：

> Wrapping with `useAsyncData` **avoids double data fetching when doing server-side rendering** (server & client on hydration).

这就是 210 那套机制在用自定义客户端时的表现：**换掉取数实现不影响防双跑，前提是你仍然把调用包在 `useAsyncData` 里**。注意它这里用的是显式 key（`'modules'`）——215 说过，能起去重与共享作用的正是这个 key。

## 两条配方怎么选

| 我要的 | 用哪个 |
| --- | --- |
| 一个 API、统一 baseURL/头/错误处理 | 配方一（`createUseFetch`），保持 `useFetch` 的签名与响应类型推断 |
| 需要复用一个 `$fetch` 实例给非取数场景（比如 store、服务端 handler 之外的应用代码） | 配方二（插件 + `$fetch.create` + provide） |
| 两者都要 | 官方允许把实例传进 `createUseFetch`（`$fetch` 选项 + 函数形态），见 226 |

**`createUseFetch` 还能接受自定义 `$fetch` 实例**这一点，226 已经用官方示例演过（`$fetch: useNuxtApp().$api as typeof $fetch`，且必须用函数形态）。

## 自查

1. 为什么没有"全局配置 `$fetch`"的开关？（答：官方明写是 intentional，为了让全应用取数行为一致、模块可依赖核心工具的行为。）
2. 配方二的 `navigateTo` 为什么要包 `runWithContext`？（答：拦截器回调不在 setup 同步流里，直接调用会丢 Nuxt 上下文——对应 E1001。）
3. 用了自定义实例为什么还要包 `useAsyncData`？（答：官方 callout 说明包起来才避免 SSR 下的双取数。）
