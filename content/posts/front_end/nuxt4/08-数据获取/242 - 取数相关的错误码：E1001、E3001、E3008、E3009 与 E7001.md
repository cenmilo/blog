## E1001：上下文丢了（最常见）

> A composable that needs the Nuxt instance (`useNuxtApp()`, `useRoute()`, `useFetch()`, …) ran outside a plugin, Nuxt hook, route middleware, or Vue `setup()`. The most common trigger is calling it inside an async callback (`setTimeout`, `.then()`, after an `await`) where the context has been lost.

解法原文两句：

> Call the composable synchronously at the top of `setup()` / a plugin / middleware and reuse the captured result later. For server-side async work, wrap the call with `nuxtApp.runWithContext()`.

这条对取数的意义有两层：**位置不对**（233 那张表）与**时机不对**（`await` 之后）。第二层更隐蔽——比如你在 `useFetch` 之后接一个 `.then()`，在里面再调一个 composable，就会命中。

我在 238 里已经见过官方自己用第二句的例子：插件里造的 `$fetch` 实例，在 `onResponseError` 里写的是 `nuxtApp.runWithContext(() => navigateTo('/login'))`。

## E3001：URL 以 // 开头

> The URL passed to `useFetch()` starts with `//`. A protocol-relative URL like this resolves to an external host, which is almost never intended and is rejected to avoid leaking requests to a different origin.

官方解法就给两行：

```ts
useFetch('/api/data')
useFetch('https://api.example.com/data')
```

**为什么我要专门记它**：这类写法常常是拼接出来的。`'//' + path` 或者 `baseURL` 尾部带斜杠再拼一个以斜杠开头的路径，结果就是 `//api/data`。**它不是本地能看出来的错误**——本机如果 `baseURL` 配得刚好，可能一直不触发。这一条与 126 讲的"`//evil.com` 属于绝对链接"是同一个形状的风险，只不过这里发生在取数。

## E3008 与 E3009：两个参数校验

```ts
const { data } = useAsyncData('users', () => $fetch('/api/users'))
```

两页给的解法是同一行代码，因为两条错误各管一个参数：

| 码 | 官方描述 | 校验对象 |
| --- | --- | --- |
| E3008 | "The first argument must be a non-empty string so Nuxt can cache and deduplicate the request across components." | key |
| E3009 | "The handler is the function that performs the fetch and returns the data, so it cannot be omitted or of another type." | handler |

**这里有一处文档之间不一致，必须点出来**：E3008 的措辞是"第一个参数必须是非空字符串"，而 `api/composables/use-async-data` 那页明确给了**两条重载**，第一条是 `(handler, options?)`——**省略 key、由框架按文件名与行号自动生成**（212/215 抄过）。

这两句话不能同时按字面成立。我的读法是：**错误码页描述的是"你显式给 key 时它必须是非空字符串"**，而不是"必须给 key"——因为同族的 E3009 也只在"给了但不是函数"时才谈类型。但这是解释性的推论，文档没有明说。**所以我把 E3008 当作"key 给了就给它真值"的提醒，而不是"必须写 key"**；真要确认，就写一次 `useAsyncData('', () => ...)`（空串）看是否报 E3008，以及省略 key 时是否报——两次各一分钟。

顺带把 215 那条官方建议再贴一次，因为它比错误码更值得遵守：**自动生成的 key 只算调用位置，所以封装函数里一定自己给 key。**

## E7001：payload 地址带了域名

> A payload URL was requested with a full URL that includes a hostname. Payloads are always served from the same origin as the app, so a URL with a hostname points outside the app and is rejected.

解法一行，函数也顺带暴露出来了：

```ts
loadPayload('/some-page')
```

这条属于 `useNuxtApp().payload` 那一族（210/235 讲的那个 payload）。我平时不直接调 `loadPayload`，但**在 CDN/子路径部署下它会找上门**：如果应用挂在 `/prefix/`（222 那个 `app.baseURL` 的例子），传进去的相对路径该怎么算文档没说——**这类问题我先怀疑自己传的是绝对地址**。

顺带一条相邻的：E5001 说"依赖 app manifest 的代码在 `experimental.appManifest` 关闭时会报"，而它的描述里点名了一个与取数相关的用途："The manifest powers features such as route rules matching and **prerendered-payload detection** on the client"——**静态站的 payload 探测就依赖它**，这条我在 235 那张排查表旁边补上。

## E7007 与 E7009：状态族，症状很像取数

这两条属于 `useState`（230 里 `callOnce` 的官方示例就用了它），但报错形状与取数很像，所以放在一起：

| 码 | 官方描述要点 |
| --- | --- |
| E7007 | "`useState()` received a non-function initial value. **The initializer must be a function so that it only runs once, on the server, and its result can be serialized into the payload for hydration.**" |
| E7009 | "`useState()` was called with a key that is not a string. The key identifies the shared state across the app and **in the hydration payload**, so it must be a non-empty string." |

E7007 那句理由我认为值得抄进日常写法：**初值必须是函数，因为它只在服务端跑一次、结果要序列化进水合用的 payload**。把 `useState('key', 0)` 写成字面量而不是 `useState('key', () => 0)` 就会撞它——这跟 `useAsyncData` 的 `default` 是工厂函数（218）是同一个设计。

## 一张对照表

| 我看到的现象 | 先查哪条 |
| --- | --- |
| 报 "outside Nuxt context" 或注入失败 | E1001（位置/时机） |
| 取数请求跑到别的域名去了 | E3001（`//` 开头） |
| `useAsyncData` 直接抛参数错误 | E3008（key 给了空值）／E3009（handler 不是函数） |
| 静态站上 payload 请求失败、带主机名 | E7001；同时看 `appManifest`（E5001） |
| `useState` 初值写法被拒 | E7007（要函数）／E7009（key 要字符串） |
| 页面能跑但导航后数据不更新 | 不是错误码，回去看 239 的"watch 不改 URL" |

## 自查

1. E1001 描述的两种触发分别是什么？（答：在没有 Nuxt 实例的位置调用（插件/Nuxt 钩子/路由中间件/`setup` 之外），以及最常见的——在异步回调里调用（`setTimeout`、`.then()`、`await` 之后）。）
2. E3008 与 API 页那条重载有什么冲突？我怎么处理？（答：错误码说"第一个参数必须是非空字符串"，API 页给了"handler 优先、key 自动生成"的重载；我按"给了 key 就必须有效"来理解，并用两次最小实验确认。）
3. 为什么 `useState` 的初值必须是函数？（答：官方理由是它只在服务端跑一次，结果要序列化进水合用的 payload。）
