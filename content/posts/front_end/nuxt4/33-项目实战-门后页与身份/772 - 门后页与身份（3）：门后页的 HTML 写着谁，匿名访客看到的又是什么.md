## 同一个站里三种相反的话

匿名访客（没有会话的人）在你站上会拿到三种东西，每种都是一个数字：

```
[console gate ssr] {"status":302,"location":"/me","bytes":89,"hasMarker":false,"hasRequestId":true}
[账户页的 HTML] {"status":200,"robots":"noindex","未登录":true,"会员区入口":false,"登出按钮":false,"标题":"账户 · Substrate","字节数":2359}
[robots 清单] {"disallow":["/api/"],"含me":false,"含console":false}
```

- 会员区那一页：一条 302，正文 89 字节——门挡得住，正文连一个字都没发。
- 账户页：200、2359 字节，里面写着"未登录"，还有一行 `<meta name="robots" content="noindex">`。
- robots.txt：一份文本，清单里只有接口那一条，账户页与会员区都不在。

再加上首页：

```
[首页负载] {"含currentUser":true,"会员区入口":false,"首页robots元标签":"index, follow","响应与磁盘文件同长":true,"磁盘文件存在":true}
```

首页发的是 `index, follow`，账户页发的是 `noindex`——两份文件、两句相反的话。这一站要说的就是这些话各自的**位置**、它们能不能被同一份判据核对，以及为什么"多挡一层"的那种改法反而把保护删掉了。

## 这一位为什么必须在服务端发

讲 `useSeoMeta` 的那一节有两句直接相关的话。第一句是性能那段：「In most instances, SEO meta tags don't need to be reactive as search engine robots primarily scan the initial page load.」——来看你页面的程序主要读**第一次发出去的那段 HTML**。第二句给了写法：「For better performance, you can wrap your `useSeoMeta` calls in a server-only condition」，例子写的正是 `robots: 'index, follow'`。

而 `useServerSeoMeta` 那一节开头就是：「`useServerSeoMeta` is deprecated. Wrap `useSeoMeta` in an `if (import.meta.server)` block instead. The auto-import is removed under `future.compatibilityVersion: 5`.」

所以本站这一位的写法是这个形状（`app/pages/me.vue`、`app/pages/console/index.vue` 两处一样）：

```ts
if (import.meta.server) {
  useSeoMeta({ robots: 'noindex' })
}
```

至于 `noindex` 这三个字本身，要说清楚一件事：**它不是 Nuxt 文档规定的取值**，是 robots 元标签这个约定的取值之一。文档只给到"怎么写这一位"，值的内容属于那个约定自己那一层。

## 门后页的 HTML 写着谁

这一问要等一条真会话才能答：登录之后那 2359 字节换成多少、`<p data-testid="console-email">` 里写着谁的邮箱、正文里那句只有登录用户才该看见的话出没出现。`test/e2e/console-gate.spec.ts` 第四条钉的就是这一串，它在默认那一趟里是跳过的那一条。

不过"匿名那一趟里写着谁"是可以直接量的，而且量出来的东西比"什么都没写"更有意思：**首页里烤着一个 `null`**。

首页是预渲染的（`routeRules` 里 `'/': { prerender: true }`）。上一站量的那条规则在这里反过来用：构建那一刻服务端跑了插件，`useUser()` 那一位写进去的是 `null`（构建机上没有会话，中间件那条降级也不会去查库），于是这个 `null` 被连同 HTML 一起烤进磁盘文件。读数是 `[首页负载] {"含currentUser":true,...}`——那位确实在负载里；`会员区入口:false`——那条入口包在 `v-if="user"` 里，匿名那一趟连节点都不存在。

结果就是**预渲染帮了这道门**：爬虫从首页那份静态 HTML 里看不到任何指向会员区的链接，走不进去；而首页自己发的是 `index, follow`，公开面该收的照常收。

这里有一个容易被误读的点要钉住：入口不在 HTML 里**不是**保护。会员区那条地址挡得住人靠的是 770 量的那道门与接口那道 `requireUser`，把地址猜出来直接访问，拿到的还是 302 与 401。上一站说过"门挡的是导航不是数据"，这一站补一句：入口藏不藏得住，更不是数据边界。

## "别来"和"别收"不能同时用一个地址

规矩写在两份文件的注释里：`Disallow` 挡的是**来不来**（爬虫读不到这一页），`robots: 'noindex'` 挡的是**收不收**（读到了也标成别收）。两者一起用的时候，第二条会失效——来都进不来，那句"别收"就没人读到；而这一页如果被别的页面链接指着，地址仍然可能凭链接进索引，只是没有摘要。

本站真在这条上摔过一次：`/me` 原先就在清单里，后来才从那里挪走，改成页面自己发 `noindex`（`server/services/public-files/robots.ts` 与 `app/pages/me.vue` 两边注释都记着这件事）。

挪走之后，**没有任何判据守着这个决定**。最容易被写回来的形式听起来还特别合理："门后页再加一条 `Disallow` 更保险。" 所以这一站补了一份对账判据（`test/unit/indexing-surface.test.ts`，5 条），基线打印：

```
[表态清单] [{"地址":"/console","发的值":"noindex"},{"地址":"/docs","发的值":"index, follow"},
  {"地址":"/docs","发的值":"index, follow"},{"地址":"/","发的值":"index, follow"},{"地址":"/me","发的值":"noindex"}]
[两类页] {"门后":[{"地址":"/console","值":"noindex"},{"地址":"/me","值":"noindex"}],
  "公开":[{"地址":"/docs","值":"index, follow"},{"地址":"/docs","值":"index, follow"},{"地址":"/","值":"index, follow"}]}
[挡与收对账] {"disallow":["/api/"],"noIndexPaths":["/console","/me"],"两边都挡的":[]}
```

五条判据分别是：每条页面路由都要**显式**发这一位（不发就跟着默认值走，而默认是收）；取值只许 `index, follow` 与 `noindex` 两种；门后目录与账户页必须是 `noindex`、其余页面必须是要收；发了 `noindex` 的地址一个都不许出现在清单里；错误页也发 `noindex`，但它不是一个地址、不参与上一条对账。

对账那一条的两个集合是从两处独立取的：noindex 那边扫 `app/pages/**` 的源码，清单那边 `import` 服务里那份常量。期望值不从同一处抄，改坏任何一边都会红。

四条变异读数（先改坏再跑）：

- 往清单里加一条 `'/console'` → 静态这条打印 `[挡与收对账] {"disallow":["/api/","/console"],"noIndexPaths":["/console","/me"],"两边都挡的":["/console"]}`、`expected [ '/console' ] to deeply equal []`，1 条红；同一份改动跑端到端，`[robots 清单] {"disallow":["/api/","/console"],"含me":false,"含console":true}` 也红，加上 robots 自己那份正文判据一共 `3 failed / 6 passed (28.3s)`。**同一处改动，两层各查各的**。
- 把这一位写成 `no-index`（多一个连字符）→ `[取值集合] {"出现过的值":["no-index","index, follow","noindex"],"第三种":["app/pages/console/index.vue → no-index"]}`，2 条红。这个值到底被来看页面的程序怎么解释，与本站无关也无处可验——能确定的是：它不再等于本站承诺过的那两种之一，而界面上一个报错都看不见。
- 把账户页那句删掉 → `[表态清单]` 里变成 `{"地址":"/me","发的值":"(没发)"}`，报 `这些页面没表态，会跟着默认值走：["app/pages/me.vue"]`，3 条红。
- 把文档列表页改成 `noindex` → `[两类页]` 的公开那组里 `/docs` 一次是 `noindex`、一次是 `index, follow`（列表页与详情页两份文件各说各话），红。这一条最像"顺手加的保险"，实际是把刚做出来的收录面自己关掉。

## 判据自己先红了两次

这两处都不是被测代码的问题，是判据写得不对，值得单记。

第一次：那条 `prerender: false` 的核对原本先过了一遍"剥注释"再找 `'/console`，跑出来 `expected undefined to be defined`。原因是 `routeRules` 里写的是通配形式 `'/console/**'`，而剥块注释的正则把里面的 `/*` 当成注释开头，一路吃到下一个 `*/`，把那张表剩下的部分整段吞掉了。改法是这一位读原文，不剥注释——**剥注释的判据要先想清楚：被剥的那个形状会不会出现在字符串字面量里**。

第二次在类型检查上：

```
test/unit/indexing-surface.test.ts(99,65): error TS2367: This comparison appears to be
unintentional because the types '"/api/"' and '"/"' have no overlap.
```

`DISALLOW_PATHS` 是 `as const` 的字面量元组，所以 `p !== '/'` 在类型眼里是"两个永不相等的字面量在比"。逻辑没错，是类型太精确。修法是把局部副本标成 `string[]`。这是连着第二次撞在同一件事上：**跑起来了不等于类型也过**（上一站那条是 `TS2352`），所以 `npm run check` 里那一项不能跳。

## 出问题时按这个顺序找

| 想知道的事 | 看哪里 | 现成的读数 |
| --- | --- | --- |
| 这一页会不会被收进索引 | 服务端发的那一行元标签 | `[账户页的 HTML]` 的 `robots` |
| 爬虫会不会被挡在门外 | `/robots.txt` 正文的清单 | `[robots 清单]` 的 `disallow` |
| 两条有没有互相抵消 | 对账判据 | `[挡与收对账]` 的 `两边都挡的` |
| 匿名拿到会员区几个字 | 响应状态与字节数 | `[console gate ssr]` 的 `bytes` |
| 首页替谁作了保 | 预渲染那份磁盘文件 | `[首页负载]` 的 `会员区入口` |

## 你自己站上跑一遍

```
npm run test:unit -- test/unit/indexing-surface.test.ts
E2E_PORT=3224 npm run test:e2e -- --project=site \
  test/e2e/gated-page-markup.spec.ts test/e2e/console-gate.spec.ts test/e2e/robots.spec.ts
```

预期 `Tests 5 passed (5)` 与 `12 passed`／`2 skipped`。跳过的两条都要库：一条是"带上一枚有效会话回 200、正文里才有那一段"，一条是账户页在会话下的形状。**门后页的 HTML 到底写着谁的邮箱，本站没量到**——连接串放在 `.env` 里，用你自己的库跑，别把它写进任何会被渲染或提交的文件。

本轮之后单位层是 33 文件／227 条，运行时层 6 文件／20 条，`npm run check` 八项全 ok。永久改动是两份判据文件（`test/e2e/gated-page-markup.spec.ts`、`test/unit/indexing-surface.test.ts`）；除了上面那四处变异和判据自己那两处错，应用代码一行没动。
