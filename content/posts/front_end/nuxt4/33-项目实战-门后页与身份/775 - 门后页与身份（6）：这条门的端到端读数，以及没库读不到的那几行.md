## 一次跑完，屏幕上是两种回执

把这条线涉及的十份规格一次跑完（产物服务、没有数据库、没有 SMTP）：

```
E2E_PORT=3241 npm run test:e2e -- --project=site \
  test/e2e/console-gate.spec.ts test/e2e/console-baseline.spec.ts \
  test/e2e/identity-payload.spec.ts test/e2e/gated-page-markup.spec.ts \
  test/e2e/api-guard.spec.ts test/e2e/logout.spec.ts \
  test/e2e/session-cookie.spec.ts test/e2e/metrics-endpoint.spec.ts \
  test/e2e/cascade.spec.ts test/e2e/session-rotation.spec.ts
```

```
Running 36 tests using 10 workers
  24 passed / 12 skipped (28.1s)
```

零失败，而这一站的结论全在那被跳过的 12 条上：**这 24 条绿的是"没库也守得住"的那一半，剩下 12 条一条都没跑**。端口这里换过一次：3235 起不来，报 `listen EADDRINUSE :::3235`，而 `netstat` 里没有任何 LISTENING——这台机器把这一段端口先发给出站连接了，换一位数重跑就行，别去动别人的进程。

还有一行值得单看：想按"其它方法回 405"写的那条判据，量到的其实是 404——`[metrics method]` 三种形状（嵌套目录的 `.get`、顶层的 `.get`、`.post` 那一位）全部是 `{"status":404,"type":"application/json"}`。所以那条判据钉的是"不是 200"这一硬事实，方法不匹配就不执行那个 handler，至于回 404 还是 405 留给路由实现，不锁死。**文档给的是措辞，判据钉的必须是自家量到的形状。**

## 没库读不到的那十二行

skip 不是通过。这一站把它们逐条列出来，每条后面是它缺的东西：

| 规格与行号 | 那一条判据要的是什么 |
| --- | --- |
| `console-gate.spec.ts:61` | 一枚有效会话：同一地址回 200、正文里才有那一段、`noindex` 在 |
| `session-rotation.spec.ts:34` | 登录成功即换会话号：旧号当场作废、新号进库 |
| `logout.spec.ts:90` | 登出只关自己这一台，别处的会话不受影响 |
| `logout.spec.ts:122` | 全端下线一删就是这个人的全部会话，权限与参数的先后同时钉住 |
| `logout.spec.ts:200` | 浏览器里点登出：请求真发出去、页面立刻回到未登录、刷新后仍然是 |
| `metrics-endpoint.spec.ts:48` | 带会话打接口：返回的就是这个人在库里的行数 |
| `metrics-endpoint.spec.ts:97` | 换一个人问同一接口：拿到的是他自己的那份数 |
| `metrics-endpoint.spec.ts:121` | 删掉用户：他的计量行跟着没（与审计那行的选择相反） |
| `cascade.spec.ts:82` | 删用户后：会话归零、审计一行不减（`actor` 变 null）、券原封不动 |
| `cascade.spec.ts:117` | 那张没外键的表能把刚删的账号复活：一张没用过的旧券仍能登录 |
| `cascade.spec.ts:143` | 控制实验：同样两张表把外键写成 cascade，券就跟着没（临时表） |
| `cascade.spec.ts:174` | 对照：全端下线只删会话行，用户、券、别的动作的痕迹都不动 |

前七条缺的是"一条真会话"，后五条缺的是"真往库里写"。两类都不该由假件冒充：内存里的假库不会替数据库做条件删除，也不会把外键级联跑一遍。**要跑它们只需要一个你自己的库**：连接串放进 `.env`，然后用带库的那一档跑（`NUXT_E2E_DB=1 npm run test:e2e -- …`）；不要把它写进任何会被渲染或提交的文件。

带库那一档跑出来的东西本站一次都没有，所以这条线的所有结论都只覆盖到"没库也守得住"那一半。

## 按文件算会算错

同一份规格里，一条绿一条跳过是常态，报覆盖要按用例数：

| 规格 | 用例 | 这一档跑到几条 |
| --- | --- | --- |
| `console-gate.spec.ts` | 4 | 3 绿、1 跳过 |
| `console-baseline.spec.ts` | 4 | 4 全绿 |
| `identity-payload.spec.ts` | 2 | 2 全绿 |
| `gated-page-markup.spec.ts` | 3 | 3 全绿 |
| `api-guard.spec.ts` | 3 | 3 全绿 |
| `session-cookie.spec.ts` | 4 | 4 全绿 |
| `logout.spec.ts` | 5 | 2 绿、3 跳过 |
| `metrics-endpoint.spec.ts` | 5 | 2 绿、3 跳过 |
| `cascade.spec.ts` | 4 | 0 绿、4 跳过 |
| `session-rotation.spec.ts` | 2 | 1 绿、1 跳过 |

合计 24 绿、12 跳过。要是只看"哪几份文件跑过了"，`cascade.spec.ts` 会被算成"跑过"，而它一条都没跑到；`session-rotation.spec.ts` 看起来"跑过"，实际只跑到一半。**同一份文件里绿与跳过并存，这件事每档都会发生**——所以这一站报覆盖只报用例数。

另外两层的现值一起放这儿，因为这一站的三条结论本来就不长在端到端那一层：单位层 35 文件／236 条，运行时层 6 文件／20 条。**凡是"只在没有负载时才生效"的逻辑（初值工厂、降级分支、默认形状）和"顺序与同源"这类结构规矩，端到端那一层量不到**——771 改初值工厂时端到端全绿、772 与 774 那两处"抄第二遍"也是静态判据先红。

## 另一种跳过：缺的不是环境，是另一趟开关

`caching.spec.ts` 不在开头那条命令里——它讲的是缓存，不属于这条门。但"门后页会不会被缓存住"是这条线留下的一笔账，所以单跑了一趟生产形态那一档（`E2E_PORT=3242`）：

```
Running 8 tests using 1 worker
  3 passed / 5 skipped (31.5s)
```

那 5 条跳过跟库一点关系都没有。这份规格按开关分四档跑（两个开关都关、只给注册路由开、给 `/**` 开、给 `isr` 开），每一档只跑属于那一档的那几条，其余在函数体第一行就 `test.skip` 掉，理由直接写在那一行里：

```
test.skip(TTL_API === 0, '需要 NUXT_SWR_API=4 那一趟')
```

这一档打印出来的两行：

```
[swr pages off] {"cacheControl":"(没有这一位)","modified":"(没有这一位)","ids":["04b99601-344f-4cc2-8bea-983d726b6d9d","30208668-3e53-4b02-afaa-5627f7e23f11"],"ms":[143,5]}
[swr uncached] {"/robots.txt":{"hasMarker":false,"cacheControl":"(没有这一位)"},"/sitemap.xml":{"hasMarker":false,"cacheControl":"(没有这一位)"},"/llms.txt":{"hasMarker":false,"cacheControl":"(没有这一位)"},"/me":{"hasMarker":false,"cacheControl":"(没有这一位)"}}
```

`/me` 那一位是这条线要的读数：**门后页在生产形态下不在缓存里**，头里没有 `cache-control`，正文也不是从一份缓存条目重放出来的。至于第一行里那两个不同的 `ids`，它证明不了任何事——那个响应编号是服务端中间件写在真实响应上的，而缓存接管的是包装内部那个代理响应，所以哪怕每次命中缓存，来一个请求还是新发一个号。这一档的断言落在 `last-modified` 那一位：它只在生成缓存条目时算一次，命中时原样重放，所以"没有这一位"才等于没被缓存过。**顺手打的读数与断言用的读数要分开，前者能骗人。**

于是这份表里的"跳过"其实有两种：`console-gate.spec.ts:61` 那种缺的是环境里的一样东西，补上就能跑；`caching.spec.ts:53` 那种缺的是另一趟开关，同一次跑永远补不上。混在一列里就看不出哪个洞能填、哪个只是没切档，所以报覆盖的时候必须把 skip 那句理由一起带出来。

## 交付前自查

- 五步的每一步都能指出"哪条用例打印哪一行"，没有哪句结论是靠回忆写的
- 十二行跳过各自带原因，原因写的是缺哪一样环境，不是"暂时不便跑"；另一份规格那五种跳过单独一节交代，因为它们缺的是档不是环境
- 端口冲突、方法后缀量到 404 而不是 405、子串断言在改值时照绿——三处都按现量结果写，没有按文档措辞猜
- 降级形状（302 与 401 的分工、`code` 的集合、失败不发 cookie）在这一档全绿

## 这条线没闭合的账

六步能收，账收不干净，都摆在明面上：**要一条真会话的读数一条都没跑过**（上表前七行）；要真写库的对照也没跑（后五行）；`requireAdmin` 的第二道（登录但角色不对）只由单位层钉住形状；SSR 站点的初始页中间件服务端与浏览器各跑一次，这条还没有一条打印"跑了几次"的判据；`/console` 要不要允许带 `redirect` 是个没做的产品决定；占券与认人之间没有跨语句事务，那一瞬间失败会白烧一张券；发信失败与库失败的次数没进计量表；`server/api/token-demo.post.ts` 那条探针地址要不要撤还没定（它现在也走 `clearSessionCookies`，path 已经一并受同源约束）。

还有一条是这一站新添的：cookie 的 `path` 现在只有一个来源，**但它对的是"同一个站内部自洽"**。真要把站点装到子路径下（反代后面挂 `/app`），发与删会一起变、判据不会红——那时要重量的是浏览器与反代之间那一段，不在这六步的覆盖里。
