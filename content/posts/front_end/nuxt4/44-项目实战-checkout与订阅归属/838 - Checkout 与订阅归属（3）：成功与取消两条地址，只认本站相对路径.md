## 先说清楚：这一站不是在修漏洞

上一站闭上归属之后，那张单子里还剩两格值得看：

```text
success_url  →  付完款浏览器跳哪儿
cancel_url   →  取消跳哪儿
```

它们长在哪儿？请求体里根本没有这一位——`parseCheckout` 只认 `planId` 一个键，多余的字段会被剥掉（上一站那档"塞一个别人的 id"读的就是这个行为）。所以"别人能改这两条地址"这句话现在不成立，写成一篇文章假装发现了它、再补一个校验，是自我欺骗。

真正能改这两条地址的入口只有一个：`public.siteUrl` 那个配置值。它是裸拼进去的：

```ts
success_url: `${输入.站点地址}/console`,
cancel_url: `${输入.站点地址}/`,
```

于是这一站做两件更小的事：**把"改不了"变成一条会红的防线**，以及**把那个唯一的输入归一掉**。

## 尾斜杠这件事是真的会拼坏

把归一去掉（就是上面那两行裸拼的样子），一份带尾斜杠的配置给出的是：

```text
[结账·两条地址] {"默认":{"success_url":"http://localhost:3000/console","cancel_url":"http://localhost:3000/"},
"尾斜杠":{"success_url":"http://localhost:3000//console","cancel_url":"http://localhost:3000//"},
"子路径":{"success_url":"https://example.com/app//console","cancel_url":"https://example.com/app//"}}
```

`http://localhost:3000//console` 这种地址多数服务器还能忍，`cancel_url` 变成 `//` 就有讲究了：以两个斜杠开头的串在 URL 语境里是协议相对地址，`//` 后面那段会被当成主机名。默认配置（`.env` 里那位不带尾斜杠）读不到这一行——**这条症状是把归一去掉之后读到的**，不是"运维已经配坏了"。

## 归一这一步只认一件事：它像个站点根

新增的纯函数 `本站地址根(值)`：像就给出去，不像就 `null`。十条输入一次读全：

```text
[结账·站点根] {"默认":"http://localhost:3000","带尾斜杠":"http://localhost:3000",
"带两条尾斜杠":"https://example.com/app","带查询串":"https://example.com","带片段":"https://example.com",
"没有协议":null,"协议是脚本":null,"只到协议":null,"空串":null,"不是字符串":null}
```

四条判断各有各的理由：

- **尾斜杠剥掉**（连续多条也一次剥完）；查询串与片段剥掉——配置值里写 `?debug=1` 这种事一旦发生，拼出来的地址会带着一份诊断参数跳回会员区。
- **必须真以 `http://` 或 `https://` 开头**。`localhost:3000` 这种漏了协议的写法要挡掉：它拼出来是 `localhost:3000:80/console` 一类没人能跳的东西。
- **`javascript:alert(1)` 挡掉**。这是这一站唯一一次提"跳转能执行脚本"这件事，理由很实在：拼完的地址是**要交给别人去跳的**——渠道在它的页面上把浏览器送到那儿，脚本协议在那条路上就是执行代码。
- **允许带子路径**（`https://example.com/app`）。站点挂在子目录是常见部署，`/app/console` 是对的，不该被"只准是根"这种想当然挡掉。

## 配置那一步现在管两件事，但仍只有一处判断

```ts
const 站点 = 本站地址根(配置.public.siteUrl)
// …可售性判断之后…
if (!密钥 || 站点 === null) { throw 503 CHECKOUT_NOT_CONFIGURED }
```

两件事合成一个码是有意的：对调用方来说动作完全相同（等本站配好），运维要看的是"没配好"，不是"请求不对"。而它仍留在可售性之后——上一站钉死的那串顺序（门 → CSRF → 形状 → 可售 → 有没有配置 → 才交出去）不能因为多了一位检查就变形。

上一站那条静态判据找的字串因此从 `if (!密钥)` 换成 `if (!密钥 ||`。这一处要交代清楚，因为它长得像"改判据迁就实现"：**换掉的只是被找的写法，那条"配置检查只能有一处"的计数判据照旧钉着**（它防的是 836 撞过的形状——再加一处而不挪走原来那处，位置就读不出真实顺序）。

## 防线那一档：四种写法，四条读数一模一样

请求体里分别塞 `successUrl`、`cancel_url`、`redirect_uri`、以及 `success_url: 'javascript:alert(1)'` 四种写法，各发一单，再从本机假 provider 记下的正文里把那两位解出来：

```text
[结账·防线] {"发数":"4","第一条的成交后":"http://localhost:3000/console",
"四条全是同一对":"true","外站出现在正文里":"false"}
```

四发都回 200（没被挡——这些字段不存在于契约里，剥掉了就不是错误），交出去的仍是本站那两条。这一档要红的时机是将来：谁给请求契约加一位地址、接口去读它，它立刻红。

它真的会红。把接口改成听请求体的那一位：

```text
[结账·防线] {"发数":"4","第一条的成交后":"https://evil.example.com/steal/console",
"四条全是同一对":"false","外站出现在正文里":"true"}
1 failed / 2 passed / 1 skipped
```

注意那一发**红一档、另两档照绿**：另一档没塞这个字段，走的是原来的路。红几档不是运气，是判据定位准不准的读数。

## 那两条地址落到的地方，量一次

```text
[结账·落地] {"无会话成交页":302,"落地到":"/me","有会话成交页":200,"有会话取消页":200}
```

会员区那一栏在无会话时是 **302 到 `/me`**（`app/middleware/console-auth.ts` 那句 `navigateTo('/me')` 在服务端那一趟顺带把状态码定成 302）。这对"付完款跳回来"没有影响：渠道跳回来时浏览器带着刚才那个用户的会话，走的是 200 那一条。而 `cancel_url` 指的首页对任何人都能读——取消之后什么都不变，正好。

**这一站没往那一栏里加任何订阅信息**。它现在读的是计量数字；订阅状态真显示出来是 840 的活。

## 坏配置那一趟：一个字节都不往外发

`success_url` 一旦被拼成畸形串，就是一份要交给渠道去跳的东西。所以这一趟把配置配坏，读接口在递出去之前停不停：

```text
[结账·坏站点] {"站点根归一结果":"null","状态":503,"码":"CHECKOUT_NOT_CONFIGURED","假provider收过几发":"0"}
1 passed / 3 skipped
```

`假provider收过几发:0` 是这一档的重点：状态码 503 只说明"挡下了"，**零外发才说明没递出去**。

这一档必须单独一趟跑（`NUXT_PUBLIC_SITE_URL=javascript:alert(1)`），于是它顺带撞出一条判据写法上的规矩：一条测试里多个 `skip` 条件时，**第一条决定它在分档表里落哪一族**。这一档第一条本来写的是"要配密钥"，结果整条落进"没归类"；把 `NUXT_PUBLIC_SITE_URL` 那句挪到第一条之后，分档表就没有归不进类的了。

## 各趟读到几档

| 这一趟 | 两个文件合计 | skip |
| --- | --- | --- |
| 带库、配下单密钥、渠道指本机假 provider（各文件自己一个端口） | 8 passed 加 3 passed | 各 1（"没配密钥"那一档、坏站点那一档） |
| 两个文件并跑、`NUXT_STRIPE_API_URL` 只能指一头 | 7 passed | 6 skipped |
| 带库、不配密钥 | 6 passed | 7 skipped |
| 不带库也不配密钥 | 2 passed | 11 skipped |

并跑那一行是本轮才看明白的：两个判据文件各起一个假 provider（3411 与 3412），环境变量只能指其中一个，另一头的档全自己 skip。skip 的原因写在环境上，不是写在代码上，读表时要能分开这两件事。全站这一趟是 257 passed／102 skipped，分档 要库 47／要外部服务变量 30／内容目录读得到 14／要另一趟构建的开关 11，没有一条归不进类。

## 撞上的三件事

| 症状 | 为什么 | 怎么办 |
| --- | --- | --- |
| `npm run lint` 报 `Unnecessary escape character` | 断言里为了匹配一个反引号写了 `` \` ``，在普通字符串里那个反斜杠是多余的 | 正则在字符类里用 `\x60` 表这个字符；别拿反斜杠去骗字符串 |
| 命令行里 `NUXT_PUBLIC_SITE_URL=javascript:alert(1)` 报语法错 | 括号是 shell 的元字符 | 整个值加单引号 |
| 两个文件并跑时假 provider 的档全 skip | `NUXT_STRIPE_API_URL` 只能指一个端口 | 各文件单独一趟跑；并跑那一趟的 skip 数要单独说明 |

## 下一站

下一站处理那条已经在未闭合里躺着的东西：渠道送回来一个本站不认得的用户编号时，入账那一路现在会抛未处理错误（上一站读出来的）。它正好落在"同一条订阅在两处都能拿到 id，谁是建行那位"这一站里——先认人，再决定建不建行，并把这件事判住。
