## 库里已经有那一行，页面上一个字都没有

前四站把这条链修到了这里：下单时交出去一张单子，渠道付完款送回一条事件，事件入账时先认人再建那一行。`subscriptions` 里有 `status` 与 `current_period_end` 两列，而 `status` 用的是站内那五个词，不是渠道那八个名字。

而 `app/pages/console/index.vue` 上关于订阅的字是零。这一屏只有计量那一份数。所以这一站的第一个动作不是写接口，是把"页面上该出现什么"这个问题问完：一个人有几行时读哪一行、一行都没有时说什么、那句话由哪一层来说。

## 造那一行要用应用自己的口子

第十八线那几档判据是测试直接往库里插行再读回来。这一站不能照抄：**要让渠道事件打进 `/api/billing/webhook`，由 `ingest.ts` 去建那一行**，否则读的那一路接上的是一段被测试代写的假数据。发进去的事件用本机密钥自签，多行 JSON 走 `text/plain`（带上 `application/json` 时发探针那一侧会把体再编一次，签出去的字节与收到的字节就不是同一份）。

```text
[订阅栏·生效] {"入账状态":200,
"库里":{"status":"active","end_ms":"1795048116000.000000"},
"接口":{"状态":200,"体":{"subscription":{"status":"active","currentPeriodEnd":1795048116000,"updatedAt":1792456116000}}},
"页":{"状态":200,"状态词":"active","句子":"生效中","到期":"2026-11-19（按 UTC 记）"}}
```

这一条里四位要同时对上：应用那一路回 200、库里那一行是 `active`、接口把同一格发出来、页面渲出"生效中"。任何一位单独看都不算——库里对而页面不对，是读的那一段没接上；页面对而库里没有，是写了死字。

## 一个人两行时读哪一行

`subscriptions` 上只有主键唯一，没有"每人一行"的约束，所以一个人可以多份订阅，而那一栏只有一个位置。读的那一层挑的是 **`updated_at` 最新的那一行**，与状态机比时间的那一位同一个口径：

```text
[订阅栏·两行] {"库里几行":2,
"库里顺序":["sub_w840_two_new_1792455178:active:1792455178000.000000","sub_w840_two_old_1792455178:inactive:1792368778000.000000"],
"接口体":{"subscription":{"status":"active","currentPeriodEnd":1792541578000,"updatedAt":1792455178000}},"页面那句":"生效中"}
```

排序还要再挂一个 `id` 当平手键：两条事件同一秒到达时 `updated_at` 相同，没有第二排序键就是让库随便挑一行，症状是"这一栏隔一次刷新换了个计划"。这一位在静态档里被读出来：

```text
[订阅栏·读口子] {"门":123,"读订阅":178,"读订阅次数":1,"服务里查表次数":1,"排序有平手键":true,
"空行不兜成none":true,"接口编句子":false,"页面出口次数":1,"页面念词表":true}
```

同一份静态档还钉着两件事：`requireUser` 的位置在读订阅**之前**（那两个数字就是源码里的位置），以及读的一方**不许**把"没有行"兜成 `status: 'none'`。

## 一行都没有的时候说什么

接口在没有行时回 `{"subscription":null}`。这一位看着多余，其实是最容易写错的一处：在服务层兜成 `none`，页面就只会显示"还没有过订阅"，而"这条记录存在且值是 none"与"根本没听说过这个人付过款"是两件事。前者是状态机留在库里的痕迹，后者是空档。两句话也故意不同：

```text
[订阅栏·空档] {"接口":{"状态":200,"体":{"subscription":null}},
"页":{"状态":200,"状态词":"(空档)","句子":"还没有开通这个会员","有到期栏":false},"是会员区":true}
[订阅栏·终态] {"入账":200,"生效中":"生效中","停了":"已停止","到期栏":"2026-10-21（按 UTC 记）",
"接口":{"subscription":{"status":"inactive","currentPeriodEnd":1792541570000,"updatedAt":1792455290000}}}
```

"已停止"与"还没有开通"必须能分出来：付过款而已经取消的人，看到"还没有开通这个会员"会以为自己那笔钱没进账。还有一件顺手做的事——空档时**那一行到期日根本不出现**，不是显示一个空日期：一行都没有，日期是编出来的。

## 那句人话由谁说

词表放在 `shared/copy/subscription.ts`，接口只发状态词，页面负责念。这样分有两个好处：改文案不会把判据带崩（判据读的是状态词那一位），而"这个状态该说什么"只有一份。

```text
[订阅栏·词表] {"格子数":5,"五种都在":true,
"每格":["none=还没有过订阅","active=生效中","past_due=逾期未付","cancellation_scheduled=到期后停止","inactive=已停止"],
"句子有重复":false,"空档那句":"还没有开通这个会员","空档与none同句":false}
[订阅栏·兜底] {"站内词":"生效中","各输入":{"渠道词":"这一栏读不出来，请稍后再看","空":"这一栏读不出来，请稍后再看",
"没给":"这一栏读不出来，请稍后再看","数字":"这一栏读不出来，请稍后再看"},"混进好消息":false}
```

兜底那一句值得多说两句。`status` 那一列是 text 不是 enum，库里躺着一个词表外的名字是可能的（人工修过数、旧版本写进去的）。最贵的写法是把它兜成 `none`——已经付费的人看到"还没有过订阅"。兜底句只说读不出来。

## 周期末为什么按 UTC 出字

那一格如果按访问者的习惯写法来排，服务端与浏览器会各算一次同一个数：本机时区是 `Asia/Shanghai`，同一个毫秒数两种写法给出两个日子。

```text
[订阅栏·周期末] {"有值":"2026-11-30（按 UTC 记）","空":"没有到期记录","没给":"没有到期记录","不是数":"没有到期记录",
"本机时区":"Asia/Shanghai","本地串":"2026年12月1日","两种写法同不同":false}
```

`16:00Z` 在东八区已经是第二天。服务端渲出来的那一份与浏览器接手后算出来的那一份不是同一个字，控制台就报水合不匹配。本站现在挑的是两边一定一致的那种写法，代价写在明处：**对处在跨天边缘的访问者，页面上那一天可能与他心里的到期日差一天**。要按访问者时区显示，得先决定时区从哪里来（会话里没有这一位），那是另一件事。

## 为什么不并进计量那个接口

会员区已经有一个 `/api/console/metrics`。再开一个地址看起来是多余的，但两件事的"没有"不一样：计量没有行是 `0`（一个数），订阅没有行是 `null`（一份还没开始的事实）。并成一个回体就得让页面分辨"这一位是 0 还是没读到"——那正是错误契约那一站反复挡的写法。

加第二个出口之后，负载里那位确实多了一个：

```text
[对账·键] {"接口体顶层键":["metrics"],"负载data键":["console:metrics","console:subscription"],
"那一位的键":["metrics"],"键名出现次数":2,"错误槽键":["console:metrics","console:subscription"]}
```

这条判据原来期望 `payload.data` 里只有一位。改它不是把标准放宽：它守的一直是"别多出一位**自动生成的**键"，两处调用各取各的时候第二处会带一个哈希样的键进来。所以期望值从一位改成两位，判据内容一个字没动——谁把这一栏改成就地取数，这里照样红。

## 上一站那个读不出东西的 200，这一站有了名字

839 收尾时留着一档说不清的读数：会员区那页回的是 200，可两个标记都读不出内容。这一站用一条对照把它问出来了：把探针的会话行删掉，再问一次同样的地址。

```text
[订阅栏·失效会话] {"活着":200,"死后":{"状态":401,"码":"UNAUTHENTICATED"},
"门后页":{"状态":200,"标题":"账户 · Substrate","是会员区":false,"是账户页":true,"订阅栏":"(读不到)","字节数":4301}}
```

标题是 `账户 · Substrate`。**门挡下来的时候发出去的是一份 200 的别的页**，不是 3xx：读 HTML 的判据只看状态码就会以为自己读到了会员区。那个"隔一次能读到、隔一次读不到"的根因也在这里现形——对账那一档挑的是"此刻库里行最多的那个人"，那是全站第一名，行其实属于隔壁那份判据的探针；并跑时隔壁删掉它自己的用户，级联把这一档刚插的会话一起带走。对账要的是"同一个人的三处读数对平"，行是谁写的与它算得对不对无关，所以那一档改成自建用户、自己写三行：

```text
[对账·三段] {"用户行":{"user_id":"025a857a-…","n":3},
"库里的分组":[{"kind":"r825_alpha","n":1},{"kind":"r825_beta","n":2}],"库里的总数":3,
"接口状态":200,"接口总":3,"页面状态":"success","页面总数":"3","页面响应状态":200,
"页面原文头":"<!DOCTYPE html><html lang=\"zh-CN\"><head>…<title>会员区 · Substrate</title>…","页面原文字节数":4997}
```

现在期望值能手敲了：三行两种 `kind`，合并成两格、总数是三。上一站那种"从库里抄一个数当期望值"的写法就没有这个余地。

## 三次改动，各红了哪几档

| 改坏的那一处 | 端到端 | 单测（静态） |
| --- | --- | --- |
| 让归属从查询串里取（`?user=…`） | `840⑦` 一档红：`乙带参数` 读到 `{"status":"active"}`，正是甲那一行 | — |
| 页面直接打状态词、不念词表 | `840②③④⑤` 四档红：`"句子":"active"` | ④ 红在 `页面念词表:false` |
| 排序去掉平手键 | — | ④ 红在 `排序有平手键:false` |

第一条里那句"只红一档"很值钱：`乙什么也没传`那一读照样对，只有把甲的编号明写进查询串那一发才暴露问题。所以判归属这件事，光测"默认读到的是自己的"不够，得**把别人的编号明写进去问一次**。

## 撞上的四件事

| 症状 | 为什么 | 怎么办 |
| --- | --- | --- |
| `Invalid regular expression flag` | `/<title>/exec(原文)` 里紧跟斜杠的 `exec` 被当成标志位 | 判空那一发用 `indexOf` 自己截，或者把正则收进变量再调用 |
| `expect(读数.X)` 报"读不到"，而库里明明有行 | 读 HTML 的判据只看状态码：门挡下来时发的是 200 的另一份页 | 判据里同时读"这是不是那一页"的标记（标题或页内独有的一个名字） |
| 加第二个出口后两处老判据红 | 一条钉"负载里只有一位"，一条钉"那个宏只出现在一处"；它们数的是数量，不是它们说要守的东西 | 期望值改成两位，判据内容不动：守的仍是"别多出一位自动生成的键"；那份扫描按文件收集出现处，新出口要进名单并且都得是锁键写法 |
