025 从"第一屏是怎么拼出来的"角度讲过 `app.vue`，这一篇补上官方在 `app.vue` 目录页里给的另外三件事：三种写法、什么情况下可以不写，还有那条会影响包体的 note。

官方的定义就一句：`app.vue` 文件是你 Nuxt 应用的主组件。

025 抄的是 Views 页那句"入口点、为每一个路由渲染其内容"，这句是同一件事的另一面——它是组件树的根，所以它里面放的东西，每个页面都会拿到。

最简写法连路由都不要。官方第一个例子短到只有一行模板：

```vue [app/app.vue]
<template>
  <h1>Hello World!</h1>
</template>
```

紧跟着一句很有分量的说明：在 Nuxt 里，`app/pages/` 目录是可选的。如果它不存在，Nuxt 就不会包含 vue-router 依赖。这在构建落地页、或一个不需要路由的应用时很有用。

注意这是依赖级的差别，不是少写几个文件。024 那份最小 `package.json` 里 dependencies 明明有 `vue-router`，但按官方这句，`app/pages/` 不存在时它不会被打进应用。014 讲过 `vue-router` 是谁，这里是它的取舍条件。

所以做单页落地页时，别随手建一个空的 `app/pages/` 目录。

有了页面，`<NuxtPage />` 就是必须的。官方原话：当你有一个 `app/pages/` 目录时，你需要使用 `<NuxtPage>` 组件来显示当前页面。

```vue [app/app.vue]
<template>
  <NuxtPage />
</template>
```

想加公共结构，直接写在 `app.vue` 里也行。官方说这在你想要包含全局元素时很有用，比如页头、页脚：

```vue [app/app.vue]
<template>
  <header>
    Header content
  </header>
  <NuxtPage />
  <footer>
    Footer content
  </footer>
</template>
```

这个示例有个地方值得停下来：模板把 `<header>`、`<NuxtPage />`、`<footer>` 三个节点并列在根上。而 026 抄过的 layouts 要求写着"与其它组件不同，你的布局必须有单一根元素"，根元素还不能是 `<slot />`。

两边看着矛盾，但要求本来就是两份：`app.vue` 官方示例里就是三个并列节点，布局文件按官方要求用单一根元素包住 `<slot />`。没有把它们合并成一条统一规则的依据，各照各的文档写就好。

026 那条"只有一层布局时建议改用 app.vue"的建议，正好和这个写法对上：页头页脚直接写在 `app.vue` 里，连布局那一层都省了。

第三种写法是给多套布局用的。官方原话：当你的应用对不同页面需要不同布局时，可以用 `app/layouts/` 目录配合 `<NuxtLayout>` 组件，定义多个布局并按页面应用。

```vue [app/app.vue]
<template>
  <NuxtLayout>
    <NuxtPage />
  </NuxtLayout>
</template>
```

判据官方写得很明确：触发条件是"对不同页面需要不同布局"。全站一套页头页脚，用第二种；多套包装，用第三种。细节在 026、059。

什么时候可以不写 `app.vue`。这一页开头有条 tip，很容易被跳过：如果你有一个 `app/pages/` 目录，`app.vue` 文件是可选的。Nuxt 会自动包含一个默认的 `app.vue`，但你仍然可以加上你自己的，按需要自定义结构与内容。

对照 025 抄过的那半句"或者移除 app/app.vue，使用默认入口"，两处说的是同一件事：删掉它，框架替你补一个默认入口。

这样要不要写 `app.vue` 就好判断了。没有 `app/pages/` 的单页落地页，写一个最简的，还顺便省掉 vue-router；有 pages 又不需要全局结构，可以不写；要全局页头页脚，写，用第二种；要多套布局，写，用第三种。

最后是本篇分量最重的那条 note：请记住 `app.vue` 充当你 Nuxt 应用的主组件。你往它里面加的任何东西（JS 与 CSS）都会是全局的，并被包含进每一个页面。

括号里的"JS 与 CSS"是关键。它说的不是模板会显示在每个页面——模板本来就该只有一份——而是这个文件里的脚本与样式会进到每一个页面。

由此有两条实际约束。只属于一个页面的逻辑，别写在 `app.vue` 的 `<script setup>` 里，它会在每个页面都执行，而 013 讲过同构渲染下这些代码服务端与客户端各跑一次，等于每个页面每次访问都跑两遍。只该作用于某一块的样式也别写在这儿，按那句 note 它是全局的。

反过来，确实每个页面都要的东西就正该写在这儿，比如官方举的页头页脚。
