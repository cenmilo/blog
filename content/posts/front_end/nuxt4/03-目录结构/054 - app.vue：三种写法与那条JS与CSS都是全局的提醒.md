025 我从"第一屏是怎么拼出来的"角度讲过 `app.vue`。这一篇补上官方在 `app.vue` 目录页里给的另外三件事：**它的三种写法、它在什么情况下可以不写，以及那条会影响包体的 note。**

## 官方定义：主组件

> `app.vue` 文件是你 Nuxt 应用的**主组件**。

025 抄的是 Views 页那句"入口点（entrypoint）、为每一个路由渲染其内容"，这一句是同一件事的另一面说法：**它是组件树的根，所以它里面放的东西每个页面都会拿到。**

## 写法一：最简——而且**不需要路由**

官方给的第一个例子短到只有一行模板：

```vue [app/app.vue]
<template>
  <h1>Hello World!</h1>
</template>
```

紧跟着一句很有分量的说明：

> 在 Nuxt 里，[`app/pages/`](https://nuxt.com/docs/4.x/directory-structure/app/pages) 目录是**可选的**。**如果它不存在，Nuxt 就不会包含 vue-router 依赖。** 这在构建一个落地页、或一个不需要路由的应用时很有用。

**这一句值得记住，因为它是"依赖级"的差别，不是"少写几个文件"。** 024 那份最小 `package.json` 里 `dependencies` 明明有 `vue-router`——**但按官方这句，`app/pages/` 不存在时它不会被打进应用。**（014 讲过 `vue-router` 是谁，这里是它的取舍条件。）

**所以做单页落地页时，不要随手建一个空的 `app/pages/` 目录。**

## 写法二：有页面时，`<NuxtPage />` 是必须的

> 当你有一个 `app/pages/` 目录时，**你需要使用 `<NuxtPage>` 组件来显示当前页面**：

```vue [app/app.vue]
<template>
  <NuxtPage />
</template>
```

然后官方给了"把公共结构直接写在 `app.vue` 里"的版本：

> 你也可以直接在 `app.vue` 里定义你应用的公共结构。**这在你想要包含全局元素（例如页头或页脚）时很有用**：

```vue [app/app.vue]
<template>
  <header>
    Header content
  </header>
  <NuxtPage />
  <footer>
    Footer content
  </footer>
</template>
```

**这里有一个和 026 看起来矛盾的地方，值得说清楚：上面这个模板把 `<header>`、`<NuxtPage />`、`<footer>` 三个节点并列在根上。**

而 026 抄过的 layouts 那条要求是：

> 与其它组件不同，你的布局**必须有单一根元素**，以便 Nuxt 在布局之间应用过渡——并且这个根元素不能是 `<slot />`。

**两页的要求不一样，我没有把它们合并成一条统一规则的依据。** 可执行的做法就是各照各的文档：**`app.vue` 官方示例里就是三个并列节点；布局文件按官方要求用单一根元素包住 `<slot />`。**

（026 那条"只有一层布局时建议改用 `app.vue`"的建议，正好和这个写法对上——**把页头页脚直接写在 `app.vue` 里，就不需要布局那一层。**）

## 写法三：需要多种布局时

> 当你的应用**对不同页面需要不同布局**时，你可以使用 `app/layouts/` 目录配合 `<NuxtLayout>` 组件。**这让你定义多个布局并按页面应用它们**：

```vue [app/app.vue]
<template>
  <NuxtLayout>
    <NuxtPage />
  </NuxtLayout>
</template>
```

**判据官方写得很明确：触发条件是"对不同页面需要不同布局"。** 全站一套页头页脚 → 写法二；多套包装 → 写法三（细节在 026、059）。

## 那句 tip：什么时候可以不写 `app.vue`

这一页开头就有一条 tip，很容易被跳过：

> 如果你有一个 `app/pages/` 目录，**`app.vue` 文件是可选的**。Nuxt 会**自动包含一个默认的 `app.vue`**，但你仍然可以加上你自己的，以按需要自定义结构与内容。

对照 025 抄过的那半句"（或者移除 `app/app.vue`，使用默认入口）"——**两处说的正是同一件事**：删掉它，框架替你用一个默认入口。

于是"要不要写 `app.vue`"的判据就变得很简单：

| 你的情况 | 官方给出的做法 |
| --- | --- |
| 有 `app/pages/`、且不需要任何全局结构 | **可以不写**，Nuxt 自动包含默认的 `app.vue` |
| 需要全局页头/页脚 | 写 `app.vue`，用写法二 |
| 需要多种布局 | 写 `app.vue`，用写法三 |
| 没有 `app/pages/`（单页落地页） | 写 `app.vue`，用最简写法（此时也不会引入 vue-router） |

## 本篇最该记住的一条：它是全局的

官方用 note 块写的这句：

> **请记住 `app.vue` 充当你 Nuxt 应用的主组件。你往它里面加的任何东西（JS 与 CSS）都会是全局的，并被包含进每一个页面。**

括号里的 **JS 与 CSS** 是关键——它讲的不是"模板会显示在每个页面"，而是**这个文件里的脚本与样式会进到每一个页面**。

这条 note 的实际约束有两条（我从"全局且被包含进每个页面"这句直接读出来的）：

1. **别把只属于一个页面的逻辑写在 `app.vue` 的 `<script setup>` 里。** 它会在每个页面都执行——而 013 讲过同构渲染下这些代码服务端与客户端各跑一次，**等于每个页面每次访问都跑两遍**。
2. **别把只该作用于某块的样式写在这里。** 按这句它是全局的。

**反过来，"确实每个页面都要的东西"就正该写在这儿**——例如官方举的页头页脚。
