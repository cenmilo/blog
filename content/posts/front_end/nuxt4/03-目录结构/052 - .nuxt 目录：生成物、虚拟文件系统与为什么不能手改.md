050 那张目录地图上没有 .nuxt 的位置。它不是你的代码，是框架生成的，可你在报错里撞见它的次数，多半比任何一个目录都多。所以值得单独写一篇：它是什么时候生成的，里面有什么值得认识的，为什么官方要专门警告你别碰它。末尾还有一个容易忽略的事实——磁盘上看到的 .nuxt，未必是全部。

官方的定义就一句：Nuxt 在开发时使用 `.nuxt/` 目录来生成你的 Vue 应用。

注意"在开发时"。生产产物住在 `.output`，那是 053 的内容；两个目录一个管开发期，一个管发布期，别混。官方还专门用 important 块提醒：把它加进 `.gitignore`，别把开发构建产物推进仓库。

什么时候会有这份目录？Nuxt 项目依赖自动生成的类型才能正常工作，这些类型就放在 `.nuxt` 里，035 抄过这句判据。跑 `nuxt dev` 会生成，而且整个目录会被重新创建——这句后面还要用到。跑 `nuxt build` 也会生成。只想生成它、不干别的，用 `nuxt prepare`，CI 和 `postinstall` 场景靠的就是它。

脚手架 package.json 里那句 `postinstall: "nuxt prepare"` 干的就是这件事，024 讲过。装完依赖，.nuxt 就已经在那儿了。

目录里的文件不用一个个看，但有几样东西你迟早要主动去找。

先是四份 tsconfig：`.nuxt/tsconfig.app.json`、`.nuxt/tsconfig.node.json`、`.nuxt/tsconfig.server.json`、`.nuxt/tsconfig.shared.json`，四个上下文各管一份，清单来自 031。哪天编辑器没了类型提示，或者 typecheck 的结果看着不对劲，先去看这个目录还在不在、四份齐不齐。

然后是别名。051 那张默认别名表里，有两条直接指进 .nuxt：

```json
{
  "#build": "/<rootDir>/.nuxt",
  "#internal/nuxt/paths": "/<rootDir>/.nuxt/paths.mjs"
}
```

`#build` 是能写进 import 的真别名，不是文件夹管理器里看的那种摆设。031 从 TypeScript 那一节也提过同一件事：生成的 tsconfig 里就带着 `#imports`、`~/file`、`#build/file` 这些路径。

还有 `nuxt.lock`。033、034、041 都出现过它，官方的说法是 dev 服务器把自身记录进构建目录的这个文件里。它会出现在三个地方：第二个 `nuxt dev` 靠它发现"已经有一个在跑了"，不去抢端口，033 讲过；`nuxt curl` 靠它找到要请求的服务器，041 讲过；`nuxt task` 靠它找到要通信的服务器，041 也讲过。

040 的 `nuxt cleanup` 还牵出一个副作用：cleanup 把构建目录删了，锁也跟着没了。于是明明 dev 进程还活着，命令却说找不到——原因就在这儿。

然后是那句 warning：你不应当触碰里面的任何文件，因为运行 `nuxt dev` 时整个目录会被重新创建。

这不是"最好别改"的客气话。你改了，下一次 dev 就全被覆盖，等于白改。改出问题更麻烦——031 抄过另一页的同一立场，连根目录那份 `tsconfig.json` 都不建议直接改，因为它可能覆盖 Nuxt 或其它模块依赖的设置。.nuxt 里这些生成文件只会更敏感。

真要改，走配置：扩展类型用 `typescript.tsConfig` 和那四个按上下文的选项，036 逐条讲过例外规则；换目录位置用 `buildDir`，051 讲过。

记住一个判据就够了：.nuxt 是输出，不是输入。

还有一句容易被略过的：Nuxt 为模块提供了虚拟文件系统（VFS），模块可以把模板"添加到这个目录里"，而根本不写磁盘。

这句信息量很大。你翻 .nuxt 找不到某个文件，不代表它不存在——模块注入的东西可能只在 VFS 里，磁盘上没有，框架照样读得到。

怎么看到它们？开发模式打开 Nuxt DevTools，切到 Virtual Files 标签页。想知道某个模块到底给你生成了什么，这是官方指定的路。047 提过另一个标签 Payload tab，看的是取数转发到客户端的数据；这里的 Virtual Files 看的是构建期生成物，俩标签管的是两码事。

VFS 模块侧的写法在 067、630 到 699 那几篇，这里只说到"有这个机制、DevTools 看得到"为止。

最后提一下改名的事。051 抄过官方这句说明：许多工具假定 `.nuxt` 是个隐藏目录，因为它以 `.` 开头，如果这会造成问题，可以用 `buildDir` 换个位置：

```ts
export default defineNuxtConfig({
  buildDir: 'nuxt-build',
})
```

但这一改，前面说的所有 .nuxt 都要跟着换：.gitignore 里的条目——important 的本意是把"构建目录"加进去，不是死磕那个名字，040 那张清单里这一项就按 buildDir 的实际值走；还有 `#build` 别名指向的位置。
