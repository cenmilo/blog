072 我说过配置不止一份文件。这一篇讲第二份，`.nuxtrc`。它的价值很具体，你能在家目录里放一份，让你机器上所有 Nuxt 项目共享同一套默认设置。

它是什么，扁平语法。官方原话，`.nuxtrc` 文件允许你用扁平语法，flat syntax，定义 Nuxt 配置。它基于 `unjs/rc9`。

官方在 tip 里划了分工，更高级的配置，请使用 `nuxt.config`。

这两句给了一个清楚的分工。050 那句另一种配置 Nuxt 应用的语法，对全局配置有用，是同一个意思的另一处表述。

扁平是关键字，没有嵌套对象、没有 JS，只有一行行的 `键=值`。

四种写法，一张示例块。官方给的示例块很短，但四种语法各占一角。

```bash [.nuxtrc]
# Disable SSR
ssr=false

# Configuration for `@nuxt/devtools`
devtools.enabled=true

# Add Nuxt modules
modules[]=@nuxt/image
modules[]=nuxt-security

# Module setups (automatically added by Nuxt)
setups.@nuxt/test-utils="3.23.0"
```

逐条读，单层键值 `ssr=false` 直接对应 `nuxt.config` 的顶层选项，018 讲过 `ssr`。点号路径 `devtools.enabled=true` 表示嵌套对象里的一个键。方括号 `modules[]=@nuxt/image` 用方括号表示追加，两行各追加一项，所以 `modules` 最终有 `@nuxt/image` 与 `nuxt-security` 两项。带点加引号值 `setups.@nuxt/test-utils="3.23.0"` 键里可以带斜杠，值用引号包。

`[]=` 这一条是这一节最容易写错的地方，扁平语法里没法写数组字面量，官方给的就是这个追加运算符。

`setups` 那一节，Nuxt 自己的记账区。官方用 note 写的，Nuxt 会自动添加一个 `setups` 区，用来跟踪模块的安装与升级状态。它在内部用于模块生命周期钩子，不应该被手动修改。

这一句解释了为什么示例块里那行被注释成 automatically added by Nuxt。你要理解的就是两点，看见 `setups.*` 不要手删，那是框架的账本，它记的是模块装过、升到哪个版本，与 044 讲的 `nuxt upgrade`、045 讲的 `nuxt add` 属于同一套机制，官方在那里指的正是模块安装与升级生命周期钩子。

覆盖顺序，三层，官方分两处写。第一层与第二层，这一页正文直接给了，如果存在，`nuxt.config` 文件里的属性会覆盖 `.nuxtrc` 文件里的属性。

第三层来自家目录那份全局文件。官方原话，你也可以在你的家目录里创建一个全局 `.nuxtrc` 文件，以全局地应用配置。在 macOS 或 Linux 上，这个文件位于 `~/.nuxtrc`，在 Windows 上，它位于 `C:\Users\{username\}\.nuxtrc`。这个全局 `.nuxtrc` 文件允许你定义作用于你系统上所有 Nuxt 项目的默认设置。不过，项目级的 `.nuxtrc` 文件会覆盖这些全局设置，而 `nuxt.config` 优先于两者。

完整顺序，从最高到最低，项目的 `nuxt.config`，大于项目的 `.nuxtrc`，大于家目录的 `.nuxtrc`。

Windows 那条路径值得单独注意，它直接给了 `C:\Users\{username\}\.nuxtrc`。你在 macOS 上习惯 `~/.nuxtrc`，换到 Windows 就找不到了，023 那篇讲过 Windows 上还有些别的本地差异，如 HMR 与 DNS。

已经见过它的两次，047 与 048。这一系列里 `.nuxtrc` 已经被提到过两次，都指用户级那份。

一次是 047 的 devtools，运行 `nuxt devtools enable` 会把 Nuxt DevTools 全局安装，同时在当前项目里启用它。这一偏好会保存在你用户级的 `.nuxtrc` 里。

一次是 048 的更新检查，`latest` 这个 dist-tag 从你在 `.npmrc` 里配置的 registry 读取，并缓存进你的用户级 `.nuxtrc`，或者在你的用户级 `.nuxtrc` 里加 `updateCheck.enabled=false` 以永久退出。

合起来看，家目录那份 `.nuxtrc` 实际是你的个人 Nuxt 偏好面板，DevTools 开不开、要不要检查更新，都存在那儿。要重置个人环境、或者排查我同事没这问题，看的就是这个文件。前半句是官方事实，后半句是我给的使用建议。

与 `nuxt.config` 的取舍，一张判据表。

需要函数、条件逻辑、复杂嵌套，放 `nuxt.config`，依据是 tip 那句更高级的配置请用 `nuxt.config`。

一个布尔或字符串开关、跨所有项目共享，放家目录 `.nuxtrc`，依据是那句定义作用于系统上所有 Nuxt 项目的默认设置。

追加模块而非覆盖整个数组，用 `.nuxtrc` 的 `modules[]=`，依据是示例块与追加语义。

项目的正式配置，要进仓库、给同事看，放 `nuxt.config`，依据是它是三层里最高的一层，也是 072 那个完全重启的主配置文件。

注意进仓库这一列，053 抄的官方 `.gitignore` 清单里没有 `.nuxtrc`，说明它是可以随项目提交的。这一句是我按那份清单没列它得出的观察，官方没在这里明说。
