从旧项目抄过来的 `nuxt.config` 里，`head`、`buildModules`、`router.extendRoutes` 这些写法在新版本里都不认了。这一节就是处理这些的：六个章节，九步操作，三条"别再这么写"。

## 章节与步骤的分布

| 章节 | 编号步骤 | 其它内容 |
| --- | --- | --- |
| `nuxt.config` | **3 步** | 三个 `####` 规则（ESM / Async / Dotenv）＋ 一条 `::note` |
| Modules | **3 步** | 一句定性"Nuxt and Nuxt modules are now **build-time-only**"＋模块作者 tip |
| Directory Changes | 无编号 | `static/`→`public/`，或设 `dir.public` |
| TypeScript | **3 步** | `tsconfig.json` 四份 references ＋ `nuxt typecheck` 的 note |
| Vue Changes | 无编号 | 两个 Vue 3 文档链接 ＋ **不能用 Vue 3 migration build** |
| Vuex | 无编号 | pinia 方案、手动 Vuex 4 方案、社区模块兜底 |

3 ＋ 3 ＋ 3 ＝ **九步**，这是这一节可执行部分的全部。

**开头一句先记住**："The starting point for your Nuxt app remains your `nuxt.config` file."——配置文件本身还在；紧跟的 `::note` 说明它由 **`unjs/jiti` 与 `unjs/c12`** 加载，这就是下面 ESM 那条规则的来源。

## 配置文件的三步

**第一步**：迁到 `defineNuxtConfig`，它提供带类型的配置 schema。

```ts [Nuxt 3]
export default defineNuxtConfig({
  // ...
})
```

**第二步**：`router.extendRoutes` 换成 `pages:extend` 钩子。

```ts [Nuxt 3]
export default defineNuxtConfig({
  hooks: {
    'pages:extend' (routes) {
      //
    },
  },
})
```

**第三步是最需要动手的一步**：`router.routeNameSplitter` **没有对应的新配置键**，官方给的做法是在同一个 `pages:extend` 钩子里自己重算名字。示例里的逻辑是三行——取相对 `./pages` 的路径、去掉结尾 4 个字符（扩展名）、把结尾的 `/index` 去掉、再把分隔符换成你原来的 splitter：

```ts [Nuxt 3]
import { createResolver } from '@nuxt/kit'

export default defineNuxtConfig({
  hooks: {
    'pages:extend' (routes) {
      const routeNameSplitter = '/'
      const root = createResolver(import.meta.url).resolve('./pages')

      function updateName (routes) {
        if (!routes) {
          return
        }

        for (const route of routes) {
          const relativePath = route.file.substring(root.length + 1)
          route.name = relativePath.slice(0, -4).replace(/\/index$/, '').replace(/\//g, routeNameSplitter)

          updateName(route.children)
        }
      }
      updateName(routes)
    },
  },
})
```

这段有三点要照做：**用 `createResolver(import.meta.url).resolve('./pages')` 拿根路径而不是硬编码**、**递归处理 `route.children`**、**名字是 `route.file` 截出来的**（所以 `slice(0, -4)` 隐含"扩展名正好 4 个字符"，`.vue` 成立，其它扩展名要自己调整）。

## 三条禁用规则

**ESM Syntax。** 原文说 Nuxt 3 是 ESM 原生框架，虽然 `unjs/jiti` 在加载 `nuxt.config` 时提供了半兼容，但**要避免在这个文件里用 `require` 和 `module.exports`**，两个替换动作是：`module.exports` → `export default`；`const lib = require('lib')` → `import lib from 'lib'`。

**Async Configuration。** "In order to make Nuxt loading behavior more predictable, **async config syntax is deprecated**. Consider using Nuxt hooks for async operations." —— 异步配置函数不要了，异步的事交给钩子。

**Dotenv。** "Nuxt has built-in support for loading `.env` files. **Avoid directly importing it from `nuxt.config`.**" —— 框架自己读 `.env`，不要在配置里手动 import。

## 模块的三步

这一节的定性是 **"Nuxt and Nuxt modules are now build-time-only."**（只在构建期生效），三步是：

1. 把所有 `buildModules` 移进 `modules`。
2. 检查模块的 Nuxt 3 兼容性。
3. **本地模块如果指向目录，要改成指向入口文件**：

```diff
  export default defineNuxtConfig({
    modules: [
-     '~/modules/my-module'
+     '~/modules/my-module/index'
    ]
  })
```

第三条是典型的"不报错但没生效"位置——目录路径与入口文件路径在解析上是两个不同的 src。

末尾的 tip 把模块作者引向 `migration/module-authors` 与模块开发指南两节。

## 目录、TypeScript 与 Vue 三节

**Directory Changes** 只有一句实质内容：**`static/` 改名成 `public/`**，要么你直接重命名目录，要么保留旧名并在配置里设 `dir.public`。

**TypeScript** 先把目的说清楚："This does not mean you need to write your application in TypeScript, just that Nuxt will provide automatic type hints for your editor."。三步是：

1. 建一份 `tsconfig.json`，内容是 `"files": []` ＋ 四条 `references`：**`./.nuxt/tsconfig.app.json`、`tsconfig.server.json`、`tsconfig.shared.json`、`tsconfig.node.json`**。
2. 跑 `npx nuxt prepare` 生成这些 tsconfig 文件。
3. 按安装页的说明装 Volar。

另有一条 `::note`：**`nuxt typecheck` 命令用 `vue-tsc` 给应用做类型检查**。

**Vue Changes** 一节给的是两个必读链接（Vue 3 迁移指南与它的 breaking changes 列表），并明确一句：**目前无法在 Nuxt 3 里使用 Vue 3 的 migration build**。这一节没有步骤——它把 Vue 层面的改动全部推到 Vue 自己的文档去。

## Vuex 那一节的三条路

官方立场：**Nuxt 不再提供 Vuex 集成，推荐改用 pinia**（它有内置 Nuxt 支持，通过 `@pinia/nuxt` 模块）。三条路各给一段代码：

1. **走 pinia**：装包 → 配置里加 `modules: ['@pinia/nuxt']` → 在应用根目录建 `store/`（示例是 `store/index.ts` 用 `defineStore('main', { state: () => ({ counter: 0 }), actions: { increment () { this.counter++ } } })`）→ 写一个插件把 store 全局化（`defineNuxtPlugin(({ $pinia }) => ({ provide: { store: useMainStore($pinia) } }))`）。
2. **继续用 Vuex**：先按 Vuex 官方步骤升到 **Vuex 4**，再加一个插件 `defineNuxtPlugin((nuxtApp) => { nuxtApp.vueApp.use(store) })`。
3. **大应用的兜底**：官方明说这种迁移"can entail a lot of work"，此时可用社区模块 `nuxt3-vuex-module`，"should work out of the box"。

注意第 1 条里的位置：示例的 store 放在**应用根目录的 `store/`**，插件放在 `app/plugins/pinia.ts`——**两个目录的基准不一样**，这与本篇另一处（本地模块路径要写全）是同一类坑。

## 自查

- 九步分布：配置 3（`defineNuxtConfig`、`extendRoutes`→`pages:extend`、`routeNameSplitter` 手工重算）／模块 3（`buildModules`→`modules`、查兼容、目录改入口文件）／TypeScript 3（四份 references、`nuxt prepare`、装 Volar）。
- 三条禁用：不用 `require`／`module.exports`、异步配置语法废弃（改用钩子）、不在配置里 import `.env`。
- 目录只有一件事：`static/`→`public/` 或设 `dir.public`。
- 类型检查命令是 `nuxt typecheck`（走 `vue-tsc`）；**Vue 3 migration build 用不了**。
- Vuex 三条路，官方推荐 pinia；示例里 store 在根目录、插件在 `app/plugins/`。
