升完版本，图片优化策略变了、某个部署预设的产物结构变了、`<NuxtPage>` 的组件名也变了。你搜"兼容"，会搜到三个不同的东西：一个日期、一个数字、还有一堆各自独立的开关。**它们不是同一层的东西，文档也从不告诉你先动哪个。**

## 第一层：compatibilityDate，管的是别人的默认行为

配置参考里那两行是这个键的全部记载：

> Specify a compatibility date for your app.
>
> This is used to control the behavior of presets in Nitro, Nuxt Image and other modules that may change behavior without a major version bump.

范围划得很清楚：**它管的是 presets 与其他模块**，也就是**不是 Nuxt 自身的功能**。这一节**没有类型行、没有默认值行**。

另一个正面讲它的地方是报错页 B5001：没设这个日期时，"Nuxt uses this date to decide which behaviour defaults to apply, so your project stays stable across Nuxt and Nitro updates **instead of silently picking up new defaults**"，Resolution 是补上**当天日期**（示例里 `'YYYY-MM-DD'` 是占位符）。

**这里有一处必须点明的空档：升级那一页从头到尾没有出现 `compatibilityDate` 这个键名。** 它给的是 `future.compatibilityVersion`。也就是说，"我升 4 时要不要改日期"这件事，**升级指南里没有答案**；能确证的只有 B5001 那句——缺日期会静默采用新默认值。

## 第二层：compatibilityVersion，一次改十九项

升级页 Testing Nuxt 5 一节给的是配置而不是命令：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  future: {
    compatibilityVersion: 5,
  },
})
```

前提与范围都写在那一页：**Nuxt 5 "currently in development"**，"**From Nuxt 4.2+** you can test many of its breaking changes by setting `future.compatibilityVersion` to `5`"，随后是那句定性 "Defaults throughout your Nuxt configuration then change to opt in to Nuxt 5 behaviour. **On Nuxt 4 this covers:**" 与那份**十九项**清单。

末尾的 `::note` 把边界钉住：这清单只说 Nuxt 4 上这个 flag 改的东西，**Nuxt 5 自身的其它变更（例如升到 Nitro v3）不是任何 flag 能在 4 上开出来的**。

与第一层的对比是清楚的：**档位是"一次改一批 Nuxt 自己的默认值"，日期是"锁住 Nitro 与模块的行为集合"**。但**两者之间会不会互相影响（例如改了日期，这十九项是否受影响），文档没有写过。**

## 第三层：单项回退，升级页给了十处

这是实际迁移中最常用的一层。Migrating to Nuxt 4 那一节里，每个变更条目自带一段回退写法，`experimental: {` 这种块一共出现 **10 次**：

| 出现的开关写法 | 用途 |
| --- | --- |
| `experimental: { granularCachedData: false }` | 回退到旧的缓存数据行为 |
| `experimental: { normalizeComponentNames: false }` | 回退组件名归一化 |
| `experimental: { spaLoadingTemplateLocation: 'within' }` | 回退加载屏的渲染位置 |
| `experimental: { scanPageMeta: true }` | 回退 page meta 的扫描时机 |
| `experimental: { sharedPrerenderData: false }` | 回退预渲染数据共享 |
| `experimental: { defaults: { useState: { resetOnClear: false } } }` | 回退 `clearNuxtState` 的行为 |
| `experimental: { defaults: { useState: { resetOnClear: true } } }` | **不设档位也提前采用**该行为 |
| `experimental: { pendingWhenIdle: true }` | 回退 `pending` 值行为 |
| `experimental: { alwaysRunFetchOnKeyChange: true }` | 回退 key 变化时的执行时机 |
| `experimental: { normalizePageNames: false }` | 回退页面组件名归一化 |

第六、七行是同一个键的两个方向，官方配的句子也分得很清楚：一句是 "Alternatively, you can revert to the previous behavior with:"，另一句是 "**You can also opt in to this behavior today without setting `compatibilityVersion: 5`**:"——**这一项既能提前采用也能回退，是唯一被这样写成两个方向的**。

另外两句的措辞差异值得留意：升级页同时出现 "the previous **behaviour**"（英式，两处）与 "the previous **behavior**"（美式，多处），还有一处加了 "**temporarily**"（"you can temporarily revert to the previous behavior with"）——**加了 temporarily 的那一项，官方明说这个回退是暂时的**。

## 两处不在 experimental 里的回退

**目录结构可以整体退回旧布局。** 这一项的正文先说 "migration is *not required*"，然后给出强制 v3 结构的写法：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  // This reverts the new srcDir default from `app` back to your root directory
  srcDir: '.',
  // This specifies the directory prefix for `router.options.ts` and `spa-loading-template.html`
  dir: {
    app: 'app',
  },
})
```

**两句注释就是这两行的用途说明**：`srcDir: '.'` 把新的 `app` 默认退回根目录，`dir.app: 'app'` 则单独指定去哪个目录找 `router.options.ts` 与 `spa-loading-template.html`。

**还有两处按各自的配置键回退**：内联样式用 `features` 那一节的 `inlineStyles: true`（官方句子里写的是"设回 `true` 就同时内联全局 CSS 与组件 CSS"），head 的兼容用 `head.legacy`（升级页那句是 "revert to the v1 behavior by enabling the `head.legacy` config"）。

## 三层怎么选用

- **升级后"某个模块／部署预设的行为"变了** → 先查 `compatibilityDate` 有没有设、什么时候设的（这是唯一有专门报错码 B5001 的机制）。
- **想整体试 Nuxt 5** → `future.compatibilityVersion: 5`（**要 Nuxt 4.2+**），但它开不出 Nitro v3 那类变更。
- **只想退回某一项 4 的改动** → 用上面那十个 `experimental` 开关之一；**逐项对应关系在升级页每个变更条目里，不要凭名字猜。**
- **想保住旧的目录布局** → `srcDir: '.'` ＋ `dir.app`，这跟上面三层都无关。

三层之间没有优先级表，**同时设置时的相互影响文档未写**，这是本篇最需要提醒的位置。

## 自查

- `compatibilityDate`：**升级页零提及**，它的范围是 Nitro／Nuxt Image／其他模块的 presets，缺省后果由 B5001 说明。
- `future.compatibilityVersion: 5`：一次改**十九项**，**Nuxt 4.2+**，且官方声明它开不出 Nitro v3 这类变更。
- 单项回退：**`experimental: {` 块在升级页出现 10 次**，其中 `defaults.useState.resetOnClear` 写了**回退与提前两个方向**、有一处措辞带 "temporarily"。
- 两个非 experimental 的回退：`srcDir: '.'` ＋ `dir.app: 'app'`；`features.inlineStyles: true`；`head.legacy`。
- **三层的分工与相互影响，文档没有对照表。**
