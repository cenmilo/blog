`asyncData`、`fetch`、`validate`、`watchQuery`、`scrollToTop` 这些写在组件里的选项，升上来之后有的改名、有的搬家、有的直接没了。这一节十个条目，但**近七个只有一句"去看别处"或"不支持"**。

## 十个小节的分布

| `##` 小节 | 这一节给了什么 |
| --- | --- |
| `asyncData` and `fetch` | 实质内容：Isomorphic Fetch、Composables、Migration 两步 |
| `head` | **仅一条 read-more**（→ meta 那一节） |
| `key` | 一句话 ＋ 一个 diff |
| `layout` | **仅一条 read-more**（→ 页面与布局那一节） |
| `loading` | 一句 "This feature is not yet supported in Nuxt 3." |
| `middleware` | **仅一条 read-more**（→ 插件与中间件那一节） |
| `scrollToTop` | "not yet supported" ＋ 替代办法 ＋ **一个 `definePageMeta` diff（自相矛盾）** |
| `transition` | **仅一条 read-more**（→ 过渡那一节） |
| `validate` | 一段规则 ＋ 一个 diff |
| `watchQuery` | 一句 "This is not supported in Nuxt 3." ＋ 替代写法示例 |

**4 ＋ 3 ＋ 3 ＝ 10**：四个纯跳转、三个不支持、三个有实质内容。

## asyncData 与 fetch：换成两个组合式函数

`### Composables` 给的新选项是 [`useAsyncData`] 与 `useFetch`，并且各有一个 lazy 变体（`useLazyAsyncData`、`useLazyFetch`），**lazy 变体的作用是"不阻塞客户端导航"**。

旧写法（两种都在一个代码块里）：

```ts
export default {
  async asyncData ({ params, $http }) {
    const post = await $http.$get(`https://api.nuxtjs.dev/posts/${params.id}`)
    return { post }
  },
  // or alternatively
  fetch () {
    this.post = await $http.$get(`https://api.nuxtjs.dev/posts/${params.id}`)
  },
}
```

新写法搬进 `setup()` 或 `<script setup>`：

```vue
<script setup lang="ts">
// Define params wherever, through `defineProps()`, `useRoute()`, etc.
const { data: post, refresh } = await useAsyncData('post', () => $fetch(`https://api.nuxtjs.dev/posts/${params.id}`))
// Or instead - useFetch is a convenience wrapper around useAsyncData when you're just performing a simple fetch
const { data: post, refresh } = await useFetch(`https://api.nuxtjs.dev/posts/${params.id}`)
</script>
```

**这一节最关键的是那条 `::note`，它纠正一个常见误解**：

> Despite the names, `useFetch` is not a direct replacement of the `fetch()` hook. Rather, `useAsyncData` replaces both hooks and is more customizable; it can do more than simply fetching data from an endpoint. `useFetch` is a convenience wrapper around `useAsyncData` for simply fetching data from an endpoint.

也就是说：**别按名字对应**（`fetch()` ↛ `useFetch`）。**要替换旧的 `asyncData` 与 `fetch` 两个钩子，正解是 `useAsyncData`；`useFetch` 只是"单纯取一个端点"时的便捷包装。**

`### Isomorphic Fetch` 讲的是取数工具：旧版可能用 `@nuxtjs/axios` 或 `@nuxt/http`，或者直接用被 polyfill 的全局 `fetch`；新版有一个**与 Fetch API 同 API 的全局 `fetch` 方法**，或者用 `$fetch`（底层是 unjs/ofetch）。官方列了两条好处：

1. 它会"聪明地"在**服务端时直接调用 API**、在客户端时发起客户端调用，也能调第三方 API。
2. 附带便利特性：自动解析响应、自动序列化数据。

`### Migration` 两步很直白：把 `asyncData` 钩子换成 `useAsyncData` 或 `useFetch`；把 `fetch` 钩子换成同样的两者之一（写在页面／组件里）。

**这一节还留着两条未写的注释**（在页面上是 HTML 注释，渲染不出来，但源码里在）：`TODO: Intro to <script setup>` 与 `TODO: Mention about options compatibility with asyncData`。**第二项恰好是这一节最该讲的东西**（Options API 项目怎么对应 `asyncData`），官方自己标了没写。

## key 与 validate：搬进 definePageMeta

`key` 一节的实质就一句："You can now define a key within the `definePageMeta` compiler macro."，diff 里把组件选项式写法换成宏调用，并且**方法形式也一并保留**（`key: route => route.fullPath`）。

`validate` 一节的规则密度更高：

- Nuxt 3 的 validate 钩子**只接受一个参数，就是 `route`**（旧写法解构的是 `{ params }`）。
- 与 Nuxt 2 一样可以返回布尔值；**返回 false 且找不到其它匹配时就是 404**。
- **也可以直接返回带 `status`／`statusText` 的对象立即以错误响应，此时其它匹配不会再被检查。**

```diff [app/pages/users/[id\\].vue]
- <script>
- export default {
-   async validate({ params }) {
-     return /^\d+$/.test(params.id)
-   }
- }
+ <script setup>
+ definePageMeta({
+   validate: async (route) => {
+     const nuxtApp = useNuxtApp()
+     return /^\d+$/.test(route.params.id)
+   }
+ })
  </script>
```

顺带一句 4.x 侧的印证：`definePageMeta` 的类型里 `validate` 的签名正是 `(route: RouteLocationNormalized) => boolean | Promise<boolean> | Partial<NuxtError> | Promise<Partial<NuxtError>>`——**"返回对象"那一路对应的是 `NuxtError` 的部分字段**。

注意 diff 文件名 `[id\\]` 这种写法（页面里带反斜杠转义），复制路径时不要照抄成字面的双反斜杠。

## 三个"不支持"，其中一个自相矛盾

**`loading`：** "This feature is not yet supported in Nuxt 3." —— 一句完，无替代方案。

**`watchQuery`：** 措辞是 "**This is not supported** in Nuxt 3."（没有 yet），替代办法是自己用 watcher 触发重取：

```vue [app/pages/users/[id\\].vue]
<script setup lang="ts">
const route = useRoute()
const { data, refresh } = await useFetch('/api/user')
watch(() => route.query, () => refresh())
</script>
```

**`scrollToTop` 是这一节唯一前后打架的一节。** 它先说 "This feature is not yet supported in Nuxt 3."，接着给出覆盖默认滚动行为的路径（`~/router.options.ts`，并指向自定义路由那一节），然后又写 "Similar to `key`, specify it within the `definePageMeta` compiler macro." 并配了一个 diff：

```diff [app/pages/index.vue]
- <script>
- export default {
-   scrollToTop: false
- }
+ <script setup>
+ definePageMeta({
+   scrollToTop: false
+ })
+ </script>
```

**而 4.x 的 `definePageMeta` 文档里，`scrollToTop` 是被正式列进类型的**：`scrollToTop?: boolean | ((to, from) => boolean)`。三处放一起读，结论只能是：**这一节的"not yet supported"是迁移页没有随 4.x 更新的旧措辞**，实际能不能用、以及函数形式的生效时机，**按 `definePageMeta` 那一节与实测为准，不要按本节那句为准。**

## 自查

- 十个条目里**四个纯跳转**：`head`→meta 页、`layout`→页面与布局页、`middleware`→插件与中间件页、`transition`→过渡页。
- **`useFetch` 不是 `fetch()` 钩子的替代**；替换两个旧钩子的是 `useAsyncData`，`useFetch` 只是取端点的便捷包装。
- `key`、`validate`、`scrollToTop` 都搬进 `definePageMeta`；**validate 只有 `route` 一个参数**，可返回 `status`／`statusText` 对象立即出错且不再检查其它匹配。
- `loading` 无替代；`watchQuery` 用 `watch(() => route.query, () => refresh())` 自己实现。
- `scrollToTop` 一句"不支持"与一句"写进 definePageMeta"在同一节里并存，**以 definePageMeta 的类型记载为准**。
- 本节留着两条官方未写完的 TODO 注释（`<script setup>` 介绍、Options API 与 asyncData 的兼容性说明）。
