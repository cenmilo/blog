旧项目里 `export default (ctx, inject) => { inject('injected', …) }` 这种插件，新版跑不起来；`middleware` 里靠 `store.state` 判登录的写法也一样。这一节管这两件事，一共四步。

## 插件：形状变了，参数只剩一个

定性句："Plugins now have a different format, and take only one argument (`nuxtApp`)."

前后对照（官方 code-group 给的就是这两段）：

```ts [Nuxt 2]
export default (ctx, inject) => {
  inject('injected', () => 'my injected function')
}
```

```ts [Nuxt 3]
export default defineNuxtPlugin((nuxtApp) => {
  // now available on `nuxtApp.$injected`
  nuxtApp.provide('injected', () => 'my injected function')

  // You can alternatively use this format, which comes with automatic type support
  return {
    provide: {
      injected: () => 'my injected function',
    },
  }
})
```

新格式里注释写明了两件事：**`nuxtApp.provide(...)` 的结果挂在 `nuxtApp.$injected` 上**；以及**另一种"返回 `provide` 对象"的写法带自动类型支持**。想拿到编辑器提示就用第二种。

这一节还挂了两条 read-more，分别指向插件目录那一节与 `useNuxtApp` 的 API 参考条目（后者那句是 "Read more about the format of `nuxtApp`."）——**`nuxtApp` 上到底还有什么，这一节没有列。**

### Migration 两步

1. 把插件迁到 `defineNuxtPlugin` 助手函数。
2. **删掉配置 plugins 数组里那些其实位于 `app/plugins/` 的条目。** 原文给的自动注册范围很具体："All files in this directory **at the top level** (and **any index files in any subdirectories**) will be automatically registered. **Instead of setting `mode` to `client` or `server`, you can indicate this in the file name.** For example, `~/plugins/my-plugin.client.ts` will only be loaded on client-side."

括号里那句"顶层文件 ＋ 任意子目录的 index 文件"是范围，别理解成"目录里所有文件递归注册"；而**运行端靠文件名后缀 `.client`／`.server` 表达**，这是这一节给出的约定。

## 路由中间件：换成 defineNuxtRouteMiddleware ＋ navigateTo

前后对照：

```js [Nuxt 2]
export default function ({ store, redirect }) {
  // If the user is not authenticated
  if (!store.state.authenticated) {
    return redirect('/login')
  }
}
```

```ts [Nuxt 3]
export default defineNuxtRouteMiddleware((to, from) => {
  const auth = useState('auth')
  if (!auth.value.authenticated) {
    return navigateTo('/login')
  }
})
```

三处替换是同时发生的：**签名从解构 ctx 对象变成 `(to, from)`**、**`store.state` 变成 `useState('auth')`（注意取值要 `.value`）**、**`redirect()` 变成 `navigateTo()`**。

正文接着说注册方式与 Nuxt 2 相同之处与不同之处："Much like Nuxt 2, route middleware placed in your `~/middleware` folder is automatically registered. You can then specify it by name in a component. **However, this is done with `definePageMeta` rather than as a component option.**"

也就是说：**目录里放文件 → 自动按名字注册**这件事没变，变的是**引用它的地方**——不再是组件选项，而是 `definePageMeta`。

最后一句是 `"navigateTo" is one of a number of route helper functions.`——**它不是唯一的路由助手，但这一节没有列其余那几个**（要看得去中间件目录那一节或 API 页）。

### Migration 两步

1. 把路由中间件迁到 `defineNuxtRouteMiddleware`。
2. **全局中间件改用文件名后缀**："Any global middleware (such as in your `nuxt.config`) can be placed in your `~/middleware` folder with a `.global` extension, for example `~/middleware/auth.global.ts`."

原来写在配置里的全局列表，新版变成**放在 `~/middleware` 里、名字带 `.global`** 的文件。

## 四步与两种约定的位置

| 归属 | 步骤 | 关键变化 |
| --- | --- | --- |
| 插件 | 第 1 步 | `defineNuxtPlugin` 包住 |
| 插件 | 第 2 步 | 配置数组里删掉目录内的条目；**端靠 `.client`／`.server` 文件名** |
| 中间件 | 第 1 步 | `defineNuxtRouteMiddleware((to, from) => …)` ＋ `navigateTo()` |
| 中间件 | 第 2 步 | 全局中间件用 **`.global` 后缀**放进 `~/middleware` |

顺带一句与配置侧的关系：`nuxt.config` 里的 `plugins` 数组**仍然可用**，它接受字符串或 `{ src, mode }` 对象，并且**所有插件按 src 路径去重**（这两条是配置参考那一节给的）。**所以这一节"把目录内的条目删掉"是避免重复表述，而不是说数组写法被废了。**

## 自查

- 四步：两个 `defineNuxt*` 助手 ＋ 两个文件名约定（`.client`／`.server`、`.global`）。
- 插件里 `provide` 的两种写法等价，**返回 `{ provide: {...} }` 那种自带类型支持**。
- 自动注册范围是 `app/plugins/` **顶层文件 ＋ 子目录的 index 文件**，不是递归全部。
- 中间件按名字引用要靠 `definePageMeta`，不再是组件选项；`useState` 取值要 `.value`。
- `navigateTo` 只是"若干路由助手函数之一"，其余这一节未列。
- 配置的 `plugins` 数组仍有效、按 src 去重——这一节第 2 步是去冗余而非废弃数组。
