照着迁移文档改代码时，你会先愣一下：示例里的 `useRouter`、`computed`、`useFetch` 都没有 import 语句。是文档漏了吗？这一页专门回答了这个问题。

## 这一页的全部内容

页首定性句："Nuxt 3 adopts a minimal friction approach, meaning wherever possible components and composables are auto-imported."

然后是那条 `::note`，原文：

> In the rest of the migration documentation, you will notice that key Nuxt and Vue utilities do not have explicit imports. This is not a typo; Nuxt will automatically import them for you, and you should get full type hinting if you have followed [the instructions] to use Nuxt's TypeScript support.

三个信息点：

1. **不是笔误**——这是官方在这页专门澄清的。
2. 自动导入的是"key Nuxt and Vue utilities"。
3. **类型提示是有前提的**：得按 configuration 那一页的 TypeScript 一节做过（那三步是建 `tsconfig.json` 的四份 references、跑 `npx nuxt prepare`、装 Volar）。没做的话代码能跑、编辑器全是红。

再往下就一个链接（指向自动导入概念页）与 **Migration 一节的一步**：

> 1. If you have been using `@nuxt/components` in Nuxt 2, you can remove `components: true` in your `nuxt.config`. If you had a more complex setup, then note that the component options have changed somewhat. See the [components documentation] for more information.

这一步里其实是两个动作：**删掉 `components: true`**（因为新版的组件目录默认就会扫），以及**如果你原来配了前缀、路径这些选项，得去组件目录那一页重看**——因为选项形状变了。

末尾的 `::tip` 给自查办法：看那两个 `.d.ts` 文件，就能知道 Nuxt 把你的组件与组合式函数解析成了什么。

## 两份 .d.ts 的路径在两页里不一样

这一页的 tip 原文写的是：

> You can look at `.nuxt/types/components.d.ts` and `.nuxt/types/imports.d.ts` …

而 4.x 的组合式函数目录那页写的是另一条路径：**"Under the hood, Nuxt auto generates the file `.nuxt/imports.d.ts` to declare the types."**——**没有 `types/` 这一段。**

两处说法不一致，而**自动导入概念页压根没提任何 `.d.ts` 文件**，所以没有第三处可以仲裁。读法只能是：**迁移这一页的措辞沿用了旧版路径，没有随 4.x 更新**（这是从两处记载的差异直接读出来的，文档本身没有承认）。

实际要查的时候，**不要照抄路径**：直接列一下你的 `.nuxt` 目录，看 `imports.d.ts` 与 `components.d.ts` 落在哪一层，比按文档拼路径可靠。

## 这一页没讲、但迁移时会撞到的三件事

**第一，`components: true` 之外的旧键。** 这一页只提了 `@nuxt/components` 那一个开关；旧配置里常见的 `components.paths`、前缀策略等，它一律说"去组件目录那页看"，本页没给对照表。

**第二，自动导入的作用域边界。** 这一页说"wherever possible"，但哪些目录会被扫、嵌套目录算什么、`shared/` 与服务端各自只在自己上下文里可用——这些都在概念页与目录页里，**本页一句都没提**。迁移时"某个函数没被自动导入"通常是这个问题，而不是这一页的问题。

**第三，关掉自动导入的三个开关不在这一页。** 全局关、只停扫描、连组件目录一起清空，这三种是不同粒度，本页没有涉及。

## 自查

- 这一页只有：一句定性、一条 `::note`（不是笔误＋类型提示有前提）、一个概念页链接、**Migration 一步**、一条 `::tip`。
- 那一步的两个动作：**删 `components: true`**；**组件选项变了要另查目录那页**。
- **两处 `.d.ts` 路径不一致**（迁移页 `.nuxt/types/imports.d.ts` vs 目录页 `.nuxt/imports.d.ts`），概念页未提；以实际 `.nuxt` 目录为准。
- 类型提示的前提在 configuration 那页的 TypeScript 三步里，不在本页。
