旧项目里到处是 `process.env.XXX`，升上来之后构建能过、线上读到 `undefined`。这一节管的就是这件事：两步改动，四段代码告诉你该写成什么样。

## 为什么不能再用 process.env

正文第一段就是结论式的说法："If you wish to reference environment variables within your Nuxt 3 app, **you will need to use runtime config**."

接着给两条使用位置的规则：

- **在组件里引用这些变量时，要在 setup 方法（或 Nuxt 插件）里用 `useRuntimeConfig` 组合式函数。**
- **"In the `server/` portion of your app, you can use `useRuntimeConfig` without any import."** —— 服务端那一侧不需要写 import。

末尾一条 read-more 指向运行时配置那一节（细节与双层结构的完整解释都在那里）。

## 两步迁移

1. **把你应用里用到的环境变量加进 `nuxt.config` 的 `runtimeConfig` 属性。**
2. **把 `process.env` 换成 `useRuntimeConfig`，范围是整个 Vue 那一侧。**

注意第 1 步的措辞是"加进配置"——**先在配置里声明一遍，环境变量才有对应的键**；这一步就是"读到空值"最常见的缺口：`.env` 里有 `NUXT_API_SECRET`，但配置里没有 `apiSecret`，运行时就没有可被覆盖的目标。

## 四段并排代码

官方用一个 code-group 把四个位置放在一起给，这是这一节最实用的部分。

**配置（`nuxt.config.ts`）：两层结构在这里定形**

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  runtimeConfig: {
    // Private config that is only available on the server
    apiSecret: '123',
    // Config within public will be also exposed to the client
    public: {
      apiBase: '/api',
    },
  },
})
```

两句注释就是边界定义：顶层的 `apiSecret` **"只在服务端可用"**，`public` 下面的 `apiBase` **"会同时暴露给客户端"**。

**页面（`app/pages/index.vue`）：客户端只能读 public**

```vue [app/pages/index.vue]
<script setup lang="ts">
const config = useRuntimeConfig()

// instead of process.env you will now access config.public.apiBase
console.log(config.public.apiBase)
</script>
```

**服务端路由（`server/api/hello.ts`）：两个都读得到，且要传 `event`**

```ts [server/api/hello.ts]
export default defineEventhandler((event) => {
  const config = useRuntimeConfig(event)
  // In server, you can now access config.apiSecret, in addition to config.public
  console.log(config.apiSecret)
  console.log(config.public.apiBase)
})
```

**注意这段里 `useRuntimeConfig(event)` 显式把 `event` 传进去了**——这是服务端路由里的写法，与前面那句"服务端不用 import"是同一段代码同时演示的两件事。

还有一个笔误要指出来：**示例写的是 `defineEventhandler`，而框架导出的名字是 `defineEventHandler`（大写 H）。** 照抄这一段会直接报找不到导出，改过来即可。

**`.env`：变量名到键名的映射在这里**

```ini [.env]
# Runtime config values are automatically replaced by matching environment variables at runtime
NUXT_API_SECRET=api_secret_token
NUXT_PUBLIC_API_BASE=https://nuxtjs.org
```

注释那句是机制本身：**"Runtime config values are automatically replaced by matching environment variables at runtime."** 与配置对照可读出的映射是 `NUXT_API_SECRET` → `apiSecret`、`NUXT_PUBLIC_API_BASE` → `public.apiBase`。

**这一节没有写映射算法**（驼峰怎么转大写、连续大写怎么办、更深层嵌套怎么拼），整套 4.x 里这一句机制描述之外没有更细的规定——**这份文档只给了这两个方向的样例**。

## 四段合起来的读法

| 位置 | 能读什么 | 写法要点 |
| --- | --- | --- |
| `nuxt.config.ts` | 定义者 | 私密键写在顶层、公开键写进 `public` |
| `app/pages/*.vue` | **只有 `config.public.*`** | 在 `<script setup>` 里调用组合式函数 |
| `server/api/*.ts` | 两者都能读 | `useRuntimeConfig(event)`，且不必 import |
| `.env` | 覆盖来源 | 变量名要能对上配置里的键，否则覆盖不到 |

这张表其实就是"为什么构建期正常、线上读到空值"的诊断路径：**先确认配置里声明了这个键，再确认变量名对得上，最后确认读它的位置在服务端。**

## 自查

- 两步：① 在 `runtimeConfig` 里声明；② Vue 那一侧把 `process.env` 换成 `useRuntimeConfig`。
- 位置规则两条：组件里要在 setup（或插件）里用；`server/` 里**免 import**。
- 边界靠键名分：**顶层私密、`public` 与客户端共享**（这一点与配置参考里 `runtimeConfig` 那节完全一致）。
- 服务端路由示例把 `event` 传进 `useRuntimeConfig(event)`。
- **示例里的 `defineEventhandler` 是笔误，正确是 `defineEventHandler`。**
- 映射只有两个样例（`NUXT_API_SECRET`、`NUXT_PUBLIC_API_BASE`），**算法未写**；`.env` 只在 dev/build 阶段被读，生产要靠平台注入。
