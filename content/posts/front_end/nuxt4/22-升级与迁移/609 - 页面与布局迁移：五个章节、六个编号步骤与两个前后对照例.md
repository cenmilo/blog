升级之后最先崩的是页面层：布局不生效、子路由空白、动态路径 404、过渡动画没了。这一节有六个编号步骤，但**其中四条改动不在编号里**，很容易整块漏掉。

| `##` 章节 | 编号步骤 | 另有三级小节 |
| --- | --- | --- |
| `app.vue` | 无编号（一段建议） | Migration |

## app.vue：一个新的中心入口

"Nuxt 3 provides a central entry point to your app via `~/app.vue`."，一条 `::note` 是很多人不知道的行为：**"If you don't have an `app.vue` file in your source directory, Nuxt will use its own default version."**

它的用途原文给了两类：需要在应用启动时跑一次的自定义代码，以及每个页面都在的组件；并补了一句实用判断——**如果你只有一个布局，可以把它挪进 `app.vue`。**

这一节的 Migration **不是编号步骤**，只是一句建议：考虑建一个 `app.vue`，把需要在顶层跑一次的逻辑放进去。

## Layouts：三步，外加一条命名规则

这一节的定性是"只有一处小改动"："If you are using layouts in your app for multiple pages, there is only a slight change required." 但正文实际给了**两件**事。

**第一件是插槽化。** "In Nuxt 2, the `<Nuxt>` component is used within a layout to render the current page. In Nuxt 3, **layouts use slots instead**, so you will have to replace that component with a `<slot />`. **This also allows advanced use cases with named and scoped slots.**"

**第二件是命名规则，它不在步骤列表里**："Layouts will be **kebab-cased**. So `app/layouts/customLayout.vue` becomes `custom-layout` when referenced in your page." —— 旧项目里用驼峰命名的布局文件，引用名要改成连字符形式。

三步编号：

```diff [app/layouts/custom.vue]
  <template>
    <div id="app-layout">
      <main>
-       <Nuxt />
+       <slot />
      </main>
    </div>
  </template>
```

1. 把 `<Nuxt />` 换成 `<slot />`（上面这段）。
2. 用 `definePageMeta` 选布局，替掉组件选项里的 `layout: 'custom'`：

```diff [app/pages/index.vue]
+ <script setup>
+ definePageMeta({
+   layout: 'custom'
+ })
- <script>
- export default {
-   layout: 'custom'
- }
  </script>
```

3. **把 `~/layouts/_error.vue` 移到 `~/error.vue`**（这一步后面跟着指向错误处理文档的链接）。原文还给了配套的布局用法——**要在错误页上用布局，就直接在 `error.vue` 里用 `<NuxtLayout name="default">` 包住内容**。

```vue [error.vue]
<template>
  <div>
    <NuxtLayout name="default">
      <!-- -->
    </NuxtLayout>
  </div>
</template>
```

## Pages：动态路由改名与一个组件合并

定性句先讲触发条件："Nuxt 3 ships with an optional `vue-router` integration triggered by the existence of a `app/pages/` directory in your source directory." ——**有目录才有路由**。单页应用则建议**把那一节移进 `app.vue` 换更轻的构建**。

**Dynamic Routes 的两条改名规则**（编号但不在 Migration 步骤里）：

1. 过去用 `_id` 定义动态参数，现在用 `[id]`。
2. 过去用 `_.vue` 定义 catch-all，现在用 `[...slug].vue`。

对照示例把四条路径连参数名一起列了出来：

| Nuxt 2 文件 | Nuxt 3 文件 | 参数取法 |
| --- | --- | --- |
| `/pages/users/index.vue` | 同左（`/users`） | — |
| `/pages/users/_user.vue` | `/pages/users/[user].vue` | `params.user` |
| `/pages/users/_user/edit.vue` | `/pages/users/[user]/edit.vue` | `params.user` |
| `/pages/users/_.vue` | `/pages/users/[...slug].vue` | **`params.pathMatch` → `params.slug`** |

最后一行是**最容易漏的**：文件名换了之后，**catch-all 的参数名也从 `pathMatch` 变成了 `slug`**，模板和逻辑里读 `params.pathMatch` 的地方要一起改。

**Nested Routes 只剩一个组件**："In Nuxt 2, you will have defined any nested routes (with parent and child components) using `<Nuxt>` and `<NuxtChild>`. **In Nuxt 3, these have been replaced with a single `<NuxtPage>` component.**"

**Page Keys 与 keepalive 进 `definePageMeta`**：过去传给 `<Nuxt>` 的自定义 page key 或 keep-alive props，现在用 `definePageMeta` 设。示例把三件事并在一起给了：

```vue [Nuxt 3]
<template>
  <div>
    <NuxtPage />
  </div>
</template>

<script setup lang="ts">
// This compiler macro works in both <script> and <script setup>
definePageMeta({
  // you can also pass a string or a computed property
  key: route => route.slug,
  transition: {
    name: 'page',
  },
  keepalive: {
    exclude: ['modal'],
  },
})
</script>
```

注释里有两句要收：**`definePageMeta` 在 `<script>` 和 `<script setup>` 里都能用**、**`key` 也可以传字符串或计算属性**。

**过渡那一节的三条附带改动**，是这一节最容易被整段跳过的部分：

- 过去写在组件选项里的页面／布局过渡，现在要用 `definePageMeta` 设。
- **Vue 3 起 `-enter` 与 `-leave` 这两个 CSS 类已经改名**（原文给了 Vue 的过渡破坏性变更链接）。
- **`<Nuxt>` 上的 `style` prop 对用在 `<slot>` 上的过渡不再适用，要把样式挪到 `-active` 类里。**

**Pages 的 Migration 三步**：

1. 把带动态参数的页面文件改成新格式。
2. 把 `<Nuxt>` 与 `<NuxtChild>` 换成 `<NuxtPage>`。
3. 用 Composition API 时，可以把 `this.$route`／`this.$router` 迁成 `useRoute` 与 `useRouter`（原文用 "**you can**"，是可选）。

## NuxtLink 与编程式导航

`<NuxtLink>` 一节只有两句话：**语法与功能大体不变**，但**如果你用的是简写 `<NLink>`，要改成 `<NuxtLink>`**；并且 **`<NuxtLink>` 现在是所有链接的替代品，包括外链**（原文 "is now a drop-in replacement for *all* links, even external ones"）。

Programmatic Navigation 一节的核心是替换：旧版拿的是 Vue Router 实例（`this.$router`），新版用 **`navigateTo()`**，可以传路由与参数。示例里旧写法是 `this.$router.push({ path: '/search', query: {...} })`，新写法是**函数直接 `return navigateTo({...})`**。

配的那条 `::warning` 是硬要求：**"Make sure to always `await` on `navigateTo` or chain its result by returning from functions."** ——不 `await` 也不 `return`，跳转不会发生。

## 自查

- 六个编号步骤：布局 3（`<slot />`、`definePageMeta` 选布局、`_error.vue` 搬家）＋ 页面 3（改动态文件名、`<NuxtPage>`、可选的 `useRoute`/`useRouter`）。
- 四条不在编号里的改动：**布局名 kebab-case**、**catch-all 参数名 `pathMatch`→`slug`**、**过渡 CSS 类改名**、**`<Nuxt>` 的 `style` prop 失效要挪进 `-active`**。
- 有 `app/pages/` 目录才有路由；只有一个页面时官方建议移进 `app.vue`。
- `<NLink>` 要换成 `<NuxtLink>`，它现在也管外链。
- `navigateTo` 必须 `await` 或被 `return` 串起来。
