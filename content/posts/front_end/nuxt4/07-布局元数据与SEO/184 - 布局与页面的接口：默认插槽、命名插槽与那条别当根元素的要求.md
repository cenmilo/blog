给布局加一个"顶部可以被页面替换"的区域，我试过两种做法：一种是在布局里判断当前路由名字，另一种是用命名插槽。后者是官方示例的写法，也是这一篇的全部内容——顺便解释为什么那句"别当根元素"的要求会出现在这里。

## 页面内容走默认插槽

官方这句定义了一切的默认形状：

> In a layout file, the content of the page will be displayed in the `<slot />` component.

所以最小布局就是"结构 + 一个洞"：

```vue [app/layouts/default.vue]
<template>
  <div>
    <p>Some default layout content shared across all pages</p>
    <slot />
  </div>
</template>
```

结合 180 那条结构要求读，两件事互相解释：

> Unlike other components, your layouts must have a single root element to allow Nuxt to apply transitions between layout changes - **and this root element cannot be a `<slot />`**.

**根必须是布局自己的节点**（这里是 `div`），因为过渡要在外壳之间做进出；如果根就是 `<slot />`，那"外壳"没有自己的元素，切换时无从过渡。

## 命名插槽：布局开放区域，页面决定内容

官方给的完整一对，两边都要看。布局侧：

```vue [app/layouts/custom.vue]
<template>
  <div>
    <header>
      <slot name="header">
        Default header content
      </slot>
    </header>
    <main>
      <slot />
    </main>
  </div>
</template>
```

页面侧（前提是该页 `layout: false` 后自己套布局）：

```vue [app/pages/index.vue]
<script setup lang="ts">
definePageMeta({
  layout: false,
})
</script>

<template>
  <div>
    <NuxtLayout name="custom">
      <template #header>
        Some header template content.
      </template>

      The rest of the page
    </NuxtLayout>
  </div>
</template>
```

三个可读的点：

| 点 | 说明 |
| --- | --- |
| 插槽默认内容 | `<slot name="header">Default header content</slot>`——页面不给就用它，所以"区域有兜底"是布局的职责，不是每个页面的 |
| 默认槽的位置 | 页面里裸写的那段（"The rest of the page"）进 `<slot />` |
| 页面外层还有一个 `div` | 因为官方要求 `<NuxtLayout>` 别当根（下一节） |

`<NuxtLayout>` 那一页给的是同一个接口的更简版本，注释直接标了 `<!-- named slot -->`：

```vue [app/layouts/custom.vue]
<template>
  <div>
    <!-- named slot -->
    <slot name="header" />
    <slot />
  </div>
</template>
```

## 那句"别当根元素"是在为过渡让路

官方的解释句把插槽与过渡的关系说了出来：

> `<NuxtLayout />` renders incoming content via `<slot />`, which is then **wrapped around Vue's `<Transition />` component** to activate layout transition. **For this to work as expected, it is recommended that `<NuxtLayout />` is not the root element of the page component.**

再配上 layouts 页那条同内容的 important：

> If you use `<NuxtLayout>` within your pages, make sure it is not the root element (**or disable layout/page transitions**).

**两句合起来给了一个二选一**：要么外面垫一层非插槽节点，要么关掉过渡。官方推荐前者，括号里的"或"是退路。

这与 118 讲过渡时的形状是同一件事：过渡类名要挂在一个稳定元素上；`<NuxtLayout>` 当根时，它同时是"内容容器"和"页面根"，过渡就没有可操作的对象。

顺带对齐一个易混点：布局的插槽**真的决定 DOM 位置**。这与 186 会看到的 head 组件形成对比——那里官方明确说嵌套只是美观："**`<Head>` and `<Body>` can accept nested meta tags (for aesthetic reasons) but this does not affect where the nested meta tags are rendered in the final HTML.**"两种"包一层"的语义完全不同，别互相类推。

## 插槽传内容，props 传值

同一对文件之间还有另一条通道，官方分得很清：

| 通道 | 官方定义 | 适用 |
| --- | --- | --- |
| 插槽 | "the content of the page will be displayed in the `<slot />` component" | 传**一段模板/组件**进布局的某个区域 |
| 自定义 attrs | "`NuxtLayout` also accepts any additional props that you may need to pass to the layout. **These custom props are then made accessible as attributes.**" → `useAttrs().title` | 传标量、且页面愿意用 attribute 形态 |
| 页面元数据的 `props` | `definePageMeta({ layout: { name, props: {...} } })` → 布局侧 `defineProps`（v4.4，带类型） | 声明式配置，集中、可类型检查 |

**我的分法**：值来自路由/页面配置 → `definePageMeta` 的对象形态；值来自这段 UI 本身 → 插槽；需要类型提示就用 `defineProps`，别用 `useAttrs` 兜。

## 需要多个"页面出口"时，插槽不是答案

如果需求是"同一页里两块独立路由内容并排"（主内容 + 侧栏，各自可导航），那是命名视图的活（177）：`name@view.vue` + `<NuxtPage name="sidebar" />`。

| 我要 | 用 |
| --- | --- |
| 布局里有一块区域由页面填 | 命名插槽 |
| 一条路由同时填两个页面位置 | 命名视图（177） |
| 布局的某块内容随页面变化但只是数据 | props / attrs |
| 整页结构都由页面自己决定 | `layout: false` + 页面自己套（181） |
