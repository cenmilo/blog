我写这一段的时候最大的感受是：布局和 head 这两件事，各自的知识量都不大，难的是**别把它们的位置记混**。所以下面全部按"在哪儿写、写了会怎样"来排。

## 布局侧

**定义（四要点，逐条有出处）**

| 要点 | 文档原话 |
| --- | --- |
| 它是页面的外壳 | "Layouts are wrappers around pages that contain a common User Interface for several pages, such as header and footer displays." |
| 内容靠插槽给页面 | "Layouts are Vue files using `<slot />` components to display the **page** content." |
| 默认文件 | "The `app/layouts/default.vue` file will be used by default." |
| 自定义靠页面元数据 | "Custom layouts can be set as part of your page metadata." |
| 只有一个布局时 | "If you only have a single layout in your application, we recommend using `app/app.vue` with `<NuxtPage />` instead." |

**解析链**：`useLayout` 给出的顺序是 页面 `definePageMeta({ layout })` → 路由规则的 `appLayout` → `default`；它返回只读 computed，值可以是字符串或 `false`，且优先于 `route.meta.layout`（183）。

**四种"这一层不要布局"**（181）：`layout: false`、`appLayout: false`、`<NuxtLayout :name="false">`、以及**名字无效又没配 `fallback` 时静默什么都不渲染**——最后这条不是写法，是陷阱。

**分层怎么理解**（182）：4.x 文档里搜不到 "nested layouts"。真要分层，可用的是嵌套目录命名、命名插槽、页面级 `<NuxtPage>` 嵌套、命名视图这四条路，而单根元素的要求（理由句是 "to allow Nuxt to apply transitions **between layout changes**"）说明**同一时刻只有一层布局在跑**。

## 元数据侧

**三处入口怎么选**

| 入口 | 能反应式吗 | 文档依据 | 我用它的场合 |
| --- | --- | --- | --- |
| `app.head`（nuxt.config） | **不能** | "This method does not allow you to provide reactive data. We recommend using `useHead()` in `app.vue`." | 站点默认标题、`htmlAttrs.lang`、favicon 这类"不怎么会变"的（官方："It's good practice to set tags here that won't change such as your site title default, language and favicon."） |
| `useHead` / `useSeoMeta` | 能 | "The properties of `useHead` can be dynamic, accepting `ref`, `computed` and `reactive` properties." | 随页面数据变的标题、描述 |
| 九个组件 | 能（模板里绑值） | "`<Title>`, `<Base>`, `<NoScript>`, `<Style>`, `<Meta>`, `<Link>`, `<Body>`, `<Html>` and `<Head>`" | 个人偏好；包进 `<Head>`/`<Html>` 去重更直觉 |

**标题一族四个键**（187/188/194）

| 键 | 落点 | 备注 |
| --- | --- | --- |
| `app.head.title` | `<title>` 的兜底 | 注释就叫 "default fallback title" |
| `useHead({ title })` | `<title>` | "Sets the page title." |
| `titleTemplate` | `<title>` 的模板 | 字符串用 `%s`；函数形态不能放 `nuxt.config`，建议放 `app.vue` |
| `templateParams` | 模板的额外占位符 | 只在 SEO 页的 `MetaObject` 里出现，`useHead` 页的参数表没有它 |
| `definePageMeta({ title })` | **不是 `<title>`** | 自定义路由 meta，示例是布局读它拼 `og:title` |

**三个 composable 的分工**：`useHead`（全能，内容可用 `innerHTML`）→ `useHeadSafe`（有不可信来源时用，白名单会**静默剥掉** `innerHTML`、`http-equiv` 这类；`script` 组只允许 `type`/`textContent`/`nonce`/`blocking`）→ `useSeoMeta`（扁平、100+ 类型化字段，防的是 `name` 与 `property` 写错和拼写错）。反应式只在必要时给：官方明说 "In most instances, SEO meta tags don't need to be reactive as search engine robots primarily scan the initial page load."，静态的那些包进 `if (import.meta.server)`；`useServerSeoMeta` 已废弃，`future.compatibilityVersion: 5` 下自动导入会被移除（190/191）。

**时机**（193/198）：要标签出现在服务端 HTML 里，注册点得是同步 `setup`（任何 `await` 之前）、插件或中间件；开流式时更要注意，晚注册的会变成客户端补丁。

## 空白清单：这几条文档没写，别背，去测

| 我要知道什么 | 文档状态 | 一次能出结果的测法 |
| --- | --- | --- |
| head 标签的判重规则 | 只写了"包进 `<Head>`/`<Html>` 去重更直觉"与"要跨边界保留重复就给 `key`" | 两个组件注册同名 `description`，`nuxt preview` 后 `curl` 数次数，再在浏览器水合后数一次 |
| `ogImage` 渲染成什么属性、相对路径够不够 | 没写；四处示例三种绝对一种相对 | `curl` 首屏 HTML 搜 `og:image`，再用抓取工具各读一次 |
| `useHead` 是否真返回 `patch`/`dispose` | 同一页两句话相互矛盾 | `const e = useHead({...})` 后 `console.log(e)`，看类型与运行时是否都给对象 |
| `politeness` 三处（组件 prop / composable 选项 / 返回 Ref）谁赢 | 没写成规则 | 用 `off` 做判据，配真实屏幕阅读器或读 `aria-live` 元素属性 |
| 布局顺序与 `priority`、`unhead.legacy` 关掉的 Capo.js 排序具体怎么排 | 都只给了一句 | 同一页各构建一次（`legacy: true` / `false`），比对 `<head>` 内标签顺序 |
| `script` 白名单里没有 `src` 是不是有意为之 | 只有白名单本身 | `useHeadSafe({ script: [{ src }] })` 后 `curl` 看有没有输出 |

## 落地检查顺序

1. `nuxt prepare` 先跑一遍（类型没生成时，很多"配置没生效"是假象，179 讲过）。
2. `definePageMeta` 里的值想给模块在构建期读，确认它在 `scanPageMeta` 那六个键之内，不在就补 `extraPageMetaExtractionKeys`。
3. 布局名一律 kebab-case 核对一遍（`errorLayout.vue` → `error-layout`），无效名先自己给 `fallback`。
4. head 相关改动**不要只看 dev**：`nuxt build` + `nuxt preview` 之后用 `curl` 读服务端 HTML，再在浏览器里读一次 DOM，两份都记下来。
5. 最后按空白清单逐项自测，把结果写进项目的说明里——因为这半年内它不会被文档补上。

## 自查

1. 只有一个布局时官方推荐什么？（答：不用布局，`app.vue` 配 `<NuxtPage />`。）
2. `definePageMeta({ title })` 和 `useHead({ title })` 的差别？（答：前者是自定义路由 meta，文档没让它改 `<title>`；后者参数表原文 "Sets the page title."）
3. 空白清单里哪三条是你项目里必须自己测的？（答：按你的功能挑——我的答案是判重、`ogImage` 形状、流式下的注册时机。）
