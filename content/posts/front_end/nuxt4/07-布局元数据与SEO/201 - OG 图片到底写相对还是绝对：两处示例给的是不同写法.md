先给结论形状：这一篇我**不能**给你一个"照这样写就对"的答案，因为文档自己就没统一。能做的是把我手上四块证据摊开，再给一条判据让你在项目里定死它。

## 证据一：public 页给的就是根路径写法

`directory-structure/public` 整页很短，相关的三行照抄：

> Files contained within the `public/` directory are served at the root and are not modified by the build process. This is suitable for files that have to keep their names (e.g. `robots.txt`) *or* likely won't change (e.g. `favicon.ico`).

```bash [Directory structure]
-| public/
---| favicon.ico
---| og-image.png
---| robots.txt
```

```vue [app/app.vue]
<script setup lang="ts">
useSeoMeta({
  ogImage: '/og-image.png',
})
</script>
```

这一节的示例文件名叫 `og-image.png`，位置在 `public/`，值写成 `/og-image.png`——这是文档里**唯一**一处把 OG 图和 `public/` 放在一起写的地方，它给的形态就是"根路径 + 原名"。这跟第一句"serve at the root / not modified by the build process"是自洽的：不被构建过程改名，所以路径可以直接写死。

## 证据二：另外三处示例都是绝对 URL

| 出处 | 写法 |
| --- | --- |
| `getting-started/seo-meta` 的 `useSeoMeta` 示例 | `ogImage: 'https://example.com/image.png'` |
| `api/composables/use-seo-meta` Usage 示例 | `ogImage: 'https://example.com/image.png'` |
| `api/composables/use-seo-meta` 的 server-only 性能示例 | `ogImage: 'https://example.com/image.png'` |
| `directory-structure/public` | `ogImage: '/og-image.png'` |

四处里三处绝对、一处相对。文档没有任何一句解释这个差别，也没有一句约束它的形态。所以**我不写"绝对才对"或"相对也行"**，那两条都不是文档给的。

顺便把 192 的结论引过来，因为它比"相对还是绝对"更基础：`ogImage` 渲染成的到底是 `<meta property="og:image">` 还是别的，文档**没有给**。写明的只有 `description → name="description"`、`ogTitle → property="og:title"`、`ogDescription → property="og:description"`、`title → <title>` 这几条（依据是 `useHead` 的 Basic Meta Tags 示例与 `useSeoMeta` 的示例并读）。

## 证据三：NuxtImg 这一节帮不上忙

`api/components/nuxt-img` 全部内容就是这些：

> `<NuxtImg>` is a drop-in replacement for the native `<img>` tag.
> - Uses built-in provider to optimize local and remote images
> - Converts `src` to provider-optimized URLs
> - Automatically resizes images based on `width` and `height`
> - Generates responsive sizes when providing `sizes` option
> - Supports native lazy loading as well as other `<img>` attributes

以及启用方式和输出形状：

```bash [Terminal]
npx nuxt module add image
```

```html
<NuxtImg src="/nuxt-icon.png" />
```

> Will result in:

```html
<img src="/nuxt-icon.png" />
```

这一节**一次都没提 OG、meta、head**，也提不到 `ogImage`。我想记住的是那两句的张力：说明里写"Converts `src` to provider-optimized URLs"，而 Usage 又说 `src="/nuxt-icon.png"` 结果是 `<img src="/nuxt-icon.png" />`——原文如此，我没打算替它圆。想搞清图链接到底被改写成什么，得去它指向的外部文档（image.nuxt.com），不在 Nuxt 4.x 文档里。

另外一个更关键的判断：**`ogImage` 收的是字符串，`<NuxtImg>` 是组件，文档没有给出任何把组件输出接到 meta 里的通道**。所以我不会写"用 NuxtImg 生成 OG 图 URL"这种看起来很顺的话——它在文档里没有依据。真要用图片模块处理 OG 图，那是模块侧的能力，需要另找出处。

## 证据四：如果图在 CDN 上，文档只教了 favicon 那一例

186 引过的那条 note 在这里正好用得上，因为它讲的就是"静态写进 head 的路径不会被解析"：

> When you set `app.cdnURL`, assets in your `public/` directory (including `favicon.ico`) are served from that CDN. Nuxt resolves public assets against `cdnURL`, falling back to `app.baseURL`. However, a static `app.head` link such as `href: '/favicon.ico'` above is a literal path and is **not** resolved against `cdnURL`. To point the favicon at the resolved location, build the `href` from runtime config with `useHead()` in `app.vue`:

```vue [app/app.vue]
<script setup lang="ts">
const { cdnURL, baseURL } = useRuntimeConfig().app
useHead({
  link: [
    { rel: 'icon', type: 'image/x-icon', href: `${cdnURL || baseURL}favicon.ico` },
  ],
})
</script>
```

注意它的说法边界：原话针对的是 `app.head` 里静态写的 `link.href` 是**字面路径**；它没说 `ogImage` 的字符串会被怎样处理。我把这两件事分开，只当作"同类风险的线索"，不当结论。

## 我怎么在项目里定死它

文档给不了答案，就只能让页面自己说话。我的三步：

1. **看渲染结果**：`nuxt build` + `nuxt preview` 之后 `curl` 首页，搜 `og:image`（或你要的那条属性名）。这一步同时回答 192 遗留的问题——`ogImage` 到底渲染成什么属性、值原样还是被改写。
2. **看水合后有没有变**：浏览器里再读一次 `<head>`。190 讲过静态 meta 可以包在 `if (import.meta.server)` 里，如果包了，客户端 DOM 就没有它，两侧读数会不同，这属于预期而不是 bug。
3. **看真实抓取方的读数**：这一步不是文档教的，但只有它能证伪"相对路径够用"。用一个不跑 JS 的方式（`curl` 的读数就是）与一个社交抓取工具各读一次，看卡片出不出图。

我给自己留的一条硬规矩是：**如果第 1 步读出来的值和我写进去的不一样，那就是有解析在发生，别急着高兴，先确认这个解析在部署后的域名下还成立。**

## 自查

1. 文档里 `ogImage` 一共出现几处，分别是什么形态？（答：四处——三处绝对 URL（SEO 页一处、`useSeoMeta` 页两处），一处根路径 `/og-image.png`（`public` 页）。）
2. `ogImage` 最终渲染成哪个 meta 属性，文档写了吗？（答：没写，这是 192 就点过的空白，只能读渲染结果。）
3. `<NuxtImg>` 能直接喂给 `ogImage` 吗？（答：文档没有任何这种通道；`ogImage` 是字符串，`<NuxtImg>` 是组件。）
