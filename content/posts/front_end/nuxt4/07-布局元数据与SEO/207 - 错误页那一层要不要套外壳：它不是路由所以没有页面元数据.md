  摘要：出错页面上线后我发现一件很尴尬的事：正常页面有导航栏和页脚，一旦 404 就变成一块裸内容。原因藏在官方那段 note 里——"Although it is called an 'error page' it's not a route and shouldn't be placed in your `~/pages` directory. For the same reason, you shouldn't use `definePageMeta` within this page. That being said, you can still use layouts in the error file, by utilizing the `NuxtLayout` component and specifying the name of the layout."三句对应三个结论：**它不是路由**、**所以没有 `definePageMeta`**（181 里那套 `layout: false` 之类在错误页根本无从写起）、**要用外壳只能自己套 `<NuxtLayout>` 并显式给 `name`**。`NuxtLayout` 那一页给的就是错误页专用示例 `<NuxtLayout name="error-layout">`，还配了命名规范化那句："if your layout file is named `errorLayout.vue`, it will become `error-layout` when passed as a `name` property"，而 `fallback` 默认是 `null`、"If an invalid layout is passed to the `name` prop, no layout will be rendered."——**名字写错时错误页会连壳都没有**。另一半坑在静态托管：官方写 "By default `404.html` is an empty shell, so your `error.vue` (and its layout and data) only appear once the client app has booted."，解法是 `experimental.prerenderErrorPages`，构建期用一个合成的 404 错误渲染 `error.vue` 写进 `404.html`，还可以传 400 到 599 之间的状态码数组多生成几页。

先交代一句背景词：`error.vue` 是你放在项目根目录（`srcDir` 那一层，不是 `pages/`）的那个文件，专门用来显示运行时出错的页面；`404.html` 是静态托管用来兜住"访问了不存在的地址"的那个文件。它们配合起来才决定用户看到什么。

## 官方那段 note 里有三个结论

`error.vue` 那页的定位句很短："During the lifespan of your application, some errors may appear unexpectedly at runtime. In such case, we can use the `error.vue` file to override the default error files and display the error nicely."

接下来那段 note 是这一篇的全部依据：

> Although it is called an 'error page' it's not a route and shouldn't be placed in your `~/pages` directory. For the same reason, you shouldn't use `definePageMeta` within this page. That being said, you can still use layouts in the error file, by utilizing the `NuxtLayout` component and specifying the name of the layout.

| 原文 | 我的做法含义 |
| --- | --- |
| "it's not a route and shouldn't be placed in your `~/pages` directory" | 它不参与路由表，所以路由那一整套机制（中间件、`routeRules` 的页面侧、滚动行为）对它不自动成立 |
| "you shouldn't use `definePageMeta` within this page" | 181 讲的四种"不要布局"写法在错误页没地方用——`layout: false` 这类压根不该出现 |
| "you can still use layouts in the error file, by utilizing the `NuxtLayout` component and specifying the name of the layout" | 想要外壳必须**自己套 `<NuxtLayout>` 并显式写 `name`**，"specifying the name" 是原话里的硬性成分 |

页面给的错误页本体是这一小块：

```vue [error.vue]
<script setup lang="ts">
import type { NuxtError } from '#app'

const props = defineProps<{ error: NuxtError }>()
</script>

<template>
  <div>
    <h1>{{ error.status }}</h1>
    <NuxtLink to="/">Go back home</NuxtLink>
  </div>
</template>
```

配合那句 "The error page has a single prop - `error` which contains an error for you to handle."——**它只收一个 prop**。`NuxtError` 的八个字段（`status`、`fatal`、`unhandled`、`statusText`、`data`、`cause` 加两个 legacy 等价 `statusCode`/`statusMessage`）056 已经逐条讲过，这里只提与本篇有关的一条："If you have an error with custom fields they will be lost; you should assign them to `data` instead"，因为要显示给用户的说明文字如果落在自定义字段上，页面拿不到。

## 套外壳的官方示例，与它埋的那个坑

`NuxtLayout` 那一页开篇就把错误页列进适用范围："You can use `<NuxtLayout />` component to activate the `default` layout on `app.vue` or `error.vue`."，并且专门给了一个错误页示例：

```vue [error.vue]
<template>
  <NuxtLayout name="error-layout">
    <NuxtPage />
  </NuxtLayout>
</template>
```

紧挨着的 note 就是坑本体：

> Please note the layout name is normalized to kebab-case, so if your layout file is named `errorLayout.vue`, it will become `error-layout` when passed as a `name` property to `<NuxtLayout />`.

我的文件叫 `app/layouts/errorLayout.vue`，那么 `name` 要写 `error-layout`；反过来写 `name="errorLayout"` 会怎样？同一页 `fallback` 那条已经回答了一半：

> If an invalid layout is passed to the `name` prop, no layout will be rendered. Specify a `fallback` layout to be rendered in this scenario. It **must** match the name of the corresponding layout file in the `app/layouts/` directory.

`fallback` 的类型是 `string`、**默认 `null`**。所以名字拼错的表现是：错误页照常显示，但外面什么都没套（181 里我把这条叫"静默什么都不渲染"，这里补上它最难受的落点——出错的时刻本来就是最需要辨认"我还在这个站点里"的时候）。

另外这个示例里 `<NuxtPage />` 出现在错误页内部，这一点我不敢解释成"错误页会渲染当前路由"（它不是路由，185 讲的布局读 `route.meta` 那条链在错误页是否成立，文档一句都没写）。要弄清只能在 `error.vue` 里临时读一次 `useRoute()` 并打印，看它给的是哪个地址——我把这条记成需要你自己确认的一项，而不是结论。

## 静态托管下更麻烦的一半：那个空壳

这一条是我觉得最容易被忘的。`guide/concepts/rendering` 的原话：

> By default `404.html` is an empty shell, so your `error.vue` (and its layout and data) only appear once the client app has booted. You can prerender it instead:

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  experimental: {
    prerenderErrorPages: true,
  },
})
```

> Nuxt then renders `error.vue` at build time with a synthetic 404 error and writes the result to `404.html`, which hydrates in place at whatever URL your host served it from. Pass an array of status codes between 400 and 599 (`[404, 500]`) to emit additional pages, if your host can serve them.

三个信息点分开看：

1. **默认那份是空壳**，内容和外壳都要等客户端应用起来才出现——也就是说，不跑 JS 的一方看到的 404 页是空的。这跟 199 那句 "Search engines may index different content than what users actually see" 是同一类问题的另一个源头。
2. 打开之后是**构建期用"合成的 404 错误"渲染 `error.vue`**，所以你在错误页里读 `error.status` 拿到的就是那次合成出来的值。
3. 可以传**状态码数组**（400 到 599 之间，例子里写 `[404, 500]`）多生成几页，前提是"if your host can serve them"。

部署那一页把同一件事讲得更短，并提醒托管商差异：

> By default both fallbacks are empty shells. Set `experimental.prerenderErrorPages` to server-render your `error.vue` into `404.html` at build time.

> Some providers use `200.html`, some use `404.html`, and some let you configure both. Check your hosting provider's static fallback or rewrite settings after deployment.

这里"both"指 `200.html` 与 `404.html` 两个兜底文件；那一节还给了 `routeRules: { '/200.html': { prerender: true } }` 的写法。**具体哪家托管用哪个文件不在 Nuxt 文档里**（原话就是让你去查自己托管商的设置），所以我不会列厂商表。

## 落地清单

- [ ] `error.vue` 里没有 `definePageMeta`（有的话删掉）。
- [ ] 想要外壳：`<NuxtLayout>` 上显式写 `name`，值用 kebab-case 形态，和文件名逐一核对。
- [ ] 顺手加 `fallback`，把"名字写错就裸奔"这条路堵上。
- [ ] 部署到静态托管时，确认是否需要 `experimental.prerenderErrorPages`；需要哪些状态码就传数组。
- [ ] 验一次：`curl` 一个不存在的地址（走 `404.html` 那条），看返回的 HTML 里有没有你的外壳与文案。

## 自查

1. 为什么错误页里不能写 `layout: false` 这类配置？（答：`definePageMeta` 对它不适用，原话是 "it's not a route" 且 "you shouldn't use `definePageMeta` within this page"。）
2. `name` 拼错且没配 `fallback` 时看到什么？（答："no layout will be rendered"，只有错误页本体，没有任何外壳。）
3. 静态托管下 404 页为什么可能整页空白？（答：默认 `404.html` 是空壳，错误页内容、外壳与数据要等客户端应用启动才出现；解法是 `experimental.prerenderErrorPages`。）
