我一开始把布局理解成"另一种组件"。直到看到官方那句建议——**只有一个布局时别用布局**——才意识到它解决的不是"复用一段 UI"，而是"同一个外壳在不同页面之间要活着"。这一篇先把这件事的前提讲清。

## 定义：它是页面的外壳

官方在视图那一章给的定义句四件事一起说了：

> Layouts are **wrappers around pages** that contain a common User Interface for several pages, such as header and footer displays. Layouts are Vue files using `<slot />` components to display the **page** content. The `app/layouts/default.vue` file will be used by default. Custom layouts can be set as part of your page metadata.

框架自己在 layouts 目录页的自述更短：

> Nuxt provides a layouts framework to **extract common UI patterns into reusable layouts**.

三个要点合起来是布局的边界：

| 要点 | 含义 |
| --- | --- |
| **wrappers around pages** | 它包的是页面，不是包另一层布局的通用容器 |
| 用 `<slot />` 显示页面内容 | 页面渲染在插槽里（059 还有一条硬要求：根元素**不能就是** `<slot />`） |
| `default.vue` 是默认 | 什么都不指定时用它 |
| 自定义布局属于**页面元数据** | 也就是 `definePageMeta({ layout })` 那条路（135、136） |

官方给的那份三文件示例把关系画得很直白：

```vue [app/app.vue]
<template>
  <div>
    <NuxtLayout>
      <NuxtPage />
    </NuxtLayout>
  </div>
</template>
```

```vue [app/layouts/default.vue]
<template>
  <div>
    <AppHeader />
    <slot />
    <AppFooter />
  </div>
</template>
```

```vue [app/pages/index.vue]
<template>
  <div>
    <h1>Welcome to the homepage</h1>
    <AppAlert>
      This is an auto-imported component
    </AppAlert>
  </div>
</template>
```

**页面里那一行注释 "This is an auto-imported component" 是顺带确认了 150 的约定**：布局与页面共用同一套组件自动导入。

## 一句容易被忽略的性能事实

layouts 目录页第一条 tip（火箭图标）说的不是排版：

> For best performance, components placed in this directory will be **automatically loaded via asynchronous import when used**.

**这一句决定了布局的实际加载形状**：布局不是打进主包的静态依赖，用到哪个才异步取哪个。它与 159 那句"each global component is rendered in a separate chunk"是同族事实，只是这里是框架默认就这么做，不需要你换取。（059 那篇是按目录视角逐条讲的，这一篇是从"为什么需要布局"这一侧接手，落地动作看 181。）

## 启用只有一个动作，指定有三种入口

启用：

> Layouts are enabled by adding `<NuxtLayout>` to your `app.vue`:

```vue [app/app.vue]
<template>
  <NuxtLayout>
    <NuxtPage />
  </NuxtLayout>
</template>
```

**注意这里 `<NuxtLayout>` 直接成了根**——而 090/103 那条建议是外面再包一层 `div`（views 那一节给的示例也正是包了 `div` 的版本）。差别在过渡：`<NuxtLayout>` 那一节的建议是"**it is recommended that `<NuxtLayout />` is not the root element of the page component**"（为了让布局过渡正常生效）。这一格我在 181 连着 `name`/`fallback` 一起处理。

指定用哪个布局，官方给了三条并列入口：

| 入口 | 官方原话 | 细读 |
| --- | --- | --- |
| 页面元数据 | "Set a `layout` property in your page with definePageMeta." | 136、135 |
| 组件 prop | "Set the `name` prop of `<NuxtLayout>`." | 094、181 |
| 路由规则 | "Set the `appLayout` property in route rules." | 141（v4.3 那一格） |

两条配套 note：

> The layout name is normalized to kebab-case, so `someLayout` becomes `some-layout`.

> If no layout is specified, `app/layouts/default.vue` will be used.

**kebab 归一这一条能解释一类顽固报错**：`layout: 'errorLayout'` 找不到布局，因为框架要的名字是 `error-layout`（094 引过同一个例子）。

## 三种入口会不会打架？官方给的是一条链

三个入口同时存在时读哪个？`useLayout` 那一节把 `<NuxtLayout>` 自己的解析顺序写了清楚，因为它"uses **the same chain** as `<NuxtLayout>`"：

> `useLayout` returns a computed ref with the layout resolved for the current route, using the same chain as `<NuxtLayout>`: **the page's `layout` meta first, then the `appLayout` set via route rules, then `'default'`**.

这条链值得记下来，它同时回答了三件事：

1. **页面里写的 `layout` 优先于路由规则**——想集中管理时，别让某个页面的声明盖掉配置。
2. **两者都没给才落到 `default`**。
3. 这条链的结果**可以在运行时读到**（`useLayout()` 返回当前解析出的布局名，或被禁用时为 `false`），这比翻配置可靠。

官方还补了一句它相对 `route.meta.layout` 的优势："Unlike reading `route.meta.layout` directly, this accounts for a layout set through route rules and stays in sync as the route changes."

## 反直觉那句：只有一个布局就别用布局

同一句建议出现在两个页面，措辞略有差别：

> If you only have a single layout in your application, we recommend using `app.vue` instead.

> If you only have a single layout in your application, we recommend using [`app/app.vue`] with [`<NuxtPage />`] instead.

**它的逻辑是从"布局换什么"来的**：布局的价值在于**多个页面共享同一份外壳、并能在切换页面时不重建外壳**（094 讨论过 `<NuxtLayout>` 与布局变化的重建边界）。只有一个外壳时，这份价值拿不到，多出来的是一层 `<NuxtLayout>`、一次异步导入、以及一条 kebab 命名的转换规则。

我的取舍线因此很机械：**第二个外壳（登录页、后台、错误页任意一个）出现时才建 `layouts/`**。这也是 103 那篇"应用外壳"与这一篇的分界——外壳是 `app.vue` 那一层常驻结构，布局是**可切换的多套外壳**。

## 两条结构要求放在一起

layouts 目录页的 `::important` 一条塞了两件事：

> Unlike other components, your layouts must have **a single root element** to allow Nuxt to apply transitions between layout changes - and **this root element cannot be a `<slot />`**.

| 要求 | 原因（官方给的） |
| --- | --- |
| 单根 | 布局之间要能应用过渡 |
| 根不能就是 `<slot />` | 外壳要有自己的节点承载过渡与结构 |

这条与 118 那段过渡、以及"布局变化时页面过渡不会执行"是同一族约束——**它们都建立在"布局是带自己节点的一层壳"这个事实上**。
