summary:
  摘要：先说清楚一件事：**"布局套布局"这种写法，我在官方文档里找不到依据**——整份 4.x 文档没有出现过"nested layouts"这类表述，被记载的是另外四种分层。其一，**嵌套目录只是命名规则**："If you have a layout in nested directories, the layout's name will be based on its own path directory and filename, **with duplicate segments being removed**."，官方两张表的第一张是 `~/layouts/desktop/default.vue` → `desktop-default`、`~/layouts/desktop-base/base.vue` → `desktop-base`、`~/layouts/desktop/index.vue` → `desktop`，第二张是配套的改名建议（`DesktopDefault.vue`、`DesktopBase.vue`、`Desktop.vue`）并配一句"For clarity, we recommend that the layout's filename matches its name"。其二，**布局向内容开放的是插槽**：官方示例的写法是布局里 `<slot name="header">Default header content</slot>` 与 `<main><slot /></main>`，页面侧用 `<template #header>` 填——这是文档给的组合方向。其三，**层级真正发生在页面侧**：`<NuxtPage />` 在布局里、子页面又在自己的 `<NuxtPage />` 里（116 那条嵌套路由线）。其四，**同一时刻只有一层布局在参与切换**，因为那条单根要求的理由是"**your layouts must have a single root element to allow Nuxt to apply transitions between layout changes**"——它讲的是**布局之间**（between layout changes），不是布局之内。**官方明确允许的一种"套"是在页面里放 `<NuxtLayout>`**："If you are using pages, you can take full control by setting `layout: false` and then using the `<NuxtLayout>` component within the page."，同时配一条 important："If you use `<NuxtLayout>` within your pages, **make sure it is not the root element** (or disable layout/page transitions)."（181 展开过这条）。**结论**：想要多层外壳，文档支持的形状是"公共部分做成组件放进一个布局"或"某页 `layout: false` 后自己套一层"，而不是再声明一个布局来包住第二个布局。

我一度以为布局可以像组件那样互相套：一个 `desktop` 布局里再放一个 `sidebar` 布局。翻完布局相关的几页，我的结论变了——**文档里没有一个字支持这种写法**，它给的分层手段是另外四种。这一篇把这条边界说清，免得别人也照我的直觉走一遍。

## 先划边界：文档写了什么、没写什么

| 我猜的 | 文档实际有的 |
| --- | --- |
| 布局 A 里放 `<NuxtLayout name="B">`，形成两层外壳 | **没有这种记载**（没有"nested layouts"这类说法，也没有对应示例或限制条目） |
| "嵌套布局目录" = 布局套布局 | 有"nested directories"，但它是**命名规则**（下面第一张表），不是层级 |

所以这一篇剩下的问题是：**要多层外壳时，文档支持什么**。答案分布在四处。

## 一：嵌套目录只改名字，不改层级

> If you have a layout in nested directories, the layout's name will be based on its own path directory and filename, with duplicate segments being removed.

官方给的第一张表：

| File | Layout Name |
| --- | --- |
| `~/layouts/desktop/default.vue` | `desktop-default` |
| `~/layouts/desktop-base/base.vue` | `desktop-base` |
| `~/layouts/desktop/index.vue` | `desktop` |

第二张表是配套的改名建议：

| File | Layout Name |
| --- | --- |
| `~/layouts/desktop/DesktopDefault.vue` | `desktop-default` |
| `~/layouts/desktop-base/DesktopBase.vue` | `desktop-base` |
| `~/layouts/desktop/Desktop.vue` | `desktop` |

配一句"For clarity, we recommend that the layout's filename matches its name."

**读这三行表能确认一件事**：`desktop/index.vue` 与 `desktop-base/base.vue` 只是**两个并列的布局**，名字里带目录段而已。目录深度不等于层级——`desktop` 布局里不会自动出现第二层壳。

（这与 157 那条组件命名规则同构：路径拼名字、重复段移除。布局侧多一个特点：`index.vue`/`default.vue` 会被目录段吸收掉。）

## 二：布局向内容开放的是插槽

官方给的组合写法，是把"可替换的区域"用插槽暴露给页面：

```vue [app/pages/index.vue]
<template>
  <div>
    <NuxtLayout name="custom">
      <template #header>
        Some header template content.
      </template>
    </NuxtLayout>
  </div>
</template>
```

```vue [app/layouts/custom.vue]
<template>
  <div>
    <!-- named slot -->
    <slot name="header" />
    <slot />
  </div>
</template>
```

layouts 目录页那份"take full control"的示例还把插槽默认内容写出来了：

```vue [app/layouts/custom.vue]
<template>
  <div>
    <header>
      <slot name="header">
        Default header content
      </slot>
    </header>
    <main>
      <slot />
    </main>
  </div>
</template>
```

**这一层能力就替代了"再要一层布局"的大部分需求**：布局定义区域（`header`、默认区），页面决定每个区域里放什么。要"某页换个头部"，给那个命名插槽即可，不必声明第二层布局。

## 三：层级发生在页面侧，不在布局侧

真正被文档支持的多层嵌套是**页面套页面**：布局里放一个 `<NuxtPage />`，父页面模板里再放一个 `<NuxtPage />` 装子页面（116 那条线）。视图形状是这样：

```vue [app/app.vue]
<template>
  <div>
    <NuxtLayout>
      <NuxtPage />
    </NuxtLayout>
  </div>
</template>
```

```vue [app/layouts/default.vue]
<template>
  <div>
    <AppHeader />
    <slot />
    <AppFooter />
  </div>
</template>
```

**这里的分层是"外壳一层 + 页面树多层"**：布局只有一层参与，嵌套发生在 `<NuxtPage>` 之下。090 那篇讲视图五层时也是这个形状。

顺带一提 177 那条命名视图：`<NuxtPage name="sidebar" />` 能在**同一层页面**里开第二个出口，这也是文档给的"多块内容"手段，且它明确了一条后果——元数据只从默认文件读。

## 四：切换语义决定了"同一时刻只有一层"

布局的单根要求给了理由，那句话值得再读一遍：

> Unlike other components, your layouts must have a single root element **to allow Nuxt to apply transitions between layout changes** - and this root element cannot be a `<slot />`.

**"between layout changes"** 是关键：布局这套机制的模型是**换一层壳**（从 A 到 B，配过渡），不是叠两层壳。094 与 181 讨论的 `name` 切换、`setPageLayout`（139）、`appLayout`（180）全都落在这个"换"字上。

所以我按官方模型推的使用形状是：**一个页面在任一时刻只对应一层布局**。想验证很简单——给某页配布局 A，再动态换成 B，看过渡类名出现的是哪一层（118 那篇的类名表）。

## 真要多层外壳时，我照这两条走

| 需求 | 用 | 为什么 |
| --- | --- | --- |
| 大部分页面共享外壳、少数页要额外一圈 | 公共部分做成**组件**放进布局（`AppHeader`、`AppFooter` 这类），额外圈用命名插槽给 | 布局侧文档只给"一层 + 插槽"；组件是自动导入的正道（150） |
| 某页要完全自定义结构（含自己套布局） | `definePageMeta({ layout: false })` + 页面内 `<NuxtLayout>`，且**别当根**（181） | 这是官方唯一明写的"在页面里放布局"的形态 |
| 只是想让一批页面多带一个侧栏 | 命名视图开第二个出口（177），或布局里放一个 `<slot name="aside" />` | 两种都有官方形状，元数据/过渡语义清楚 |
| 直接写"布局里放 `<NuxtLayout>`" | 我先不用；非要用就**当成未文档化行为处理**：生产构建 + 过渡开关 + 布局切换三处都验一遍 | 文档没有这一条，也没有说它被支持 |

**最后一行是我留给自己的一句提醒**：不是"文档没写就一定坏"，而是"它不在承诺范围内，所以每次升级都要重新验"。这种地方我宁可用有官方形状的写法。
