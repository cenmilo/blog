同一个图片，写法有好几种，选错的代价各不相同：有的会 404，有的会静默把整个目录打进产物，有的本地好、SSR 就崩。官方给的选择其实只问一个问题——**文件名什么时候才知道**。

## 判据：静态字面量优先

> When an `src` is a static string literal in your template, the build tool rewrites it into a runtime helper that resolves the final URL.

所以能写死的就写死，两条路各有待遇：

```vue
<template>
  <!-- Static paths are rewritten: app.baseURL is applied at runtime, and the bundled file is hashed. -->
  <img src="/img/nuxt.png">
  <img src="~/assets/img/nuxt.png">
</template>
```

- `public/` 路径（`/img/nuxt.png`）：被包一层，渲染时应用 `app.baseURL`。
- `assets/` 路径（`~/assets/img/nuxt.png`）：**额外变成一个 import**，解析到 hash 后的产物文件。

官方还限定了解析范围："This resolution only happens for literal paths the build tool can see."——421/430 那些"运行时拼的路径不重写"的坑都源于此。

## 运行时才知道名字：分两种需求

### 需求 A：不需要处理、不需要 hash → 放 public，用 URL 引

官方给的正是 computed 拼 URL 的形态：

```vue [app/app.vue]
<script setup lang="ts">
const props = defineProps<{
  name: string
}>()

const imageUrl = computed(() => `/img/${props.name}.png`)
</script>

<template>
  <img
    :src="imageUrl"
    :alt="props.name"
  >
</template>
```

配一句定性："Files in `public/` keep their original filenames."

这条路的隐含成本 422 说过：拼出来的路径**不会**被补 `app.baseURL`，子路径部署要自己用 `useRuntimeConfig().app.baseURL`（例如 `joinURL`）拼。

### 需求 B：需要被处理 → 放 assets，三种显式写法

官方先标了适用范围：

> The approaches below are specific to Vite, Nuxt's default builder.

**候选已知就列出来。**"When the possible files are known, list their imports explicitly"——用 `?url` 后缀：

```vue
<script setup lang="ts">
const props = defineProps<{
  theme: 'light' | 'dark'
}>()

const logos = {
  light: () => import('./assets/img/logo-light.png?url'),
  dark: () => import('./assets/img/logo-dark.png?url'),
}

const logoUrl = (await logos[props.theme]()).default
</script>
```

要点两个：**`?url` 表示只要 URL 不要内容**，以及每项是**返回 Promise 的函数**（`logos[props.theme]` 是被选中的那一个才去 import，其它的不下载）。

**只有文件名是变量时，用变量动态导入。**官方在"许多文件共用一个目录和后缀"这种场合给的是第三条路，原话是 "When many files share a directory and extension, use a variable dynamic import instead of listing every file"：

```ts
async function getImageUrl (name: string) {
  const image = await import(`./assets/img/${name}.png?url`)
  return image.default
}
```

它跟上面两条的区别官方写明了：**只有文件名能动态**，目录与后缀必须留在模板串里——"Keeping the directory and extension in the import lets Vite find the possible files at build time"。目录一旦也变成变量，构建期就无法确定候选，重写也就无从谈起。而列举式那份（"Each import has a literal path, so Vite can find both files at build time while loading only the selected module at runtime"）靠的同样是每条 import 都有字面路径。

**候选是一组文件就 glob。**官方给的是 `import.meta.glob`，两种模式：

```ts
const images = import.meta.glob<string>('./assets/img/*.{png,jpg,svg}', {
  query: '?url',
  import: 'default',
})
```

加 `eager: true` 就立即加载所有匹配。官方对两种模式各给了一句后果：

> Every matching asset is still included in the build output. Lazy imports load each match on demand, while an eager glob loads all matches up front and can increase the initial JavaScript size or inline small assets.

也就是说：`glob` 不筛小，**匹配到的都会进产物**；`eager` 额外把体积压进初始 JS、还可能把小资源内联。想按需就保持懒（默认不加 `eager`），但下面那条约束就来了。

## 一条 SSR 硬约束

> Await a lazy import before using its URL in server-rendered markup. Vite's `new URL(..., import.meta.url)` pattern does not work with SSR.

两句要分开记：

1. 懒导入（`logos[...]()` 或 glob 的非 eager 项）的 URL **要 SSR 用就得先 await**，否则服务端渲出去时还没有值。
2. 社区常见的 `new URL('./img/x.png', import.meta.url)` 拿资源 URL 的写法，在 Nuxt 的 SSR 下**不工作**（426 也引过这条）——别拿它当替代方案。

## 别名：四个各管一片

资源与代码引用会碰到四个别名，边界不同：

| 别名 | 指什么 | 出处 |
| --- | --- | --- |
| `~/assets/...` | 项目内、交给构建工具处理的资源（`assets/` 目录没有自动扫描、名字可换） | 421 |
| `#shared/...` | `shared/` 里不被自动扫描的文件，官方说这别名让导入路径不随引用者位置变化 | 413 |
| `#imports` | 自动导入那张表，显式引框架自有函数与自动导入项 | 404 |
| `#build` | 构建期生成的虚拟文件（`.nuxt` 下的产物） | 052/395 |

typescript 那页对 `#imports`、`~/file`、`#build/file` 的说法是"生成的 tsconfig 里包含 path aliases like `#imports`, `~/file`, or `#build/file`"——这四个的**类型提示**都来自 `.nuxt` 生成物，所以 398 那条（刚 clone 先 `nuxt prepare`）在资源别名上同样成立。

## 自查

- 第一判据：**能不能写死字面量**。静态 `src` 会被重写（public 路径补 baseURL、`~/assets/` 变 import 指向 hash 产物），构建器看不见的字面量才不处理。
- 运行时才知道名字：不需处理/不需 hash → `public/` + computed 拼 URL（保留原名，但前缀要自己补）；需处理 → `assets/` + Vite 侧显式写法。
- Vite 侧三种：候选已知用 `?url` 的**函数形式** import 列表；只有文件名是变量用 `import(`…${name}.png?url`)`；候选是一组用 `import.meta.glob`（`query:'?url'`、`import:'default'`，`eager` 与否）。
- glob 的每个匹配都进产物；eager 会增大初始 JS 或内联小资源。
- SSR 里用懒导入的 URL 前必须 await；`new URL(..., import.meta.url)` 不支持 SSR。
- 别名分四片：`~/assets`、`#shared`、`#imports`、`#build`，类型都来自 `.nuxt` 生成物。
