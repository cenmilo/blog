`css` 数组里两个文件都定义了 `.container`，谁生效？这个问题在很多老教程里有一句干脆的答案，但在 Nuxt 4.x 文档里**找不到那句话**。这一篇既把 `css` 这个键讲完，也把这条边界说清。

## 官方对这个键说了什么

nuxt-config 的 `## css`，全部内容就三句加一个类型：

> You can define the CSS files/modules/libraries you want to set globally (included in every page).
> Nuxt will automatically guess the file type by its extension and use the appropriate pre-processor. You will still need to install the required loader if you need to use them.
> **Type**: `array`

三句各自的落点：

1. **作用域**：`included in every page`——这是"全局样式"的定义，和 415 路一（组件内引、只在引用处）正好相对。
2. **文件类型判定**：按**扩展名**猜用哪个预处理器。
3. **前置条件**：需要的话**自己装 loader**。

第 2 与第 3 句要连着读：写了 `.scss` 就代表 Nuxt 会用 Sass 去处理，但 `sass` 这个包不在依赖里，构建就会失败——报错会指向预处理器不可用，而不是"配置写错了"。装法见 418（`npm install -D sass`）。

## 官方给的三项示例

```ts
export default defineNuxtConfig({
  css: [
  // Load a Node.js module directly (here it's a Sass file).
    'bulma',
    // CSS file in the project
    '~/assets/css/main.css',
    // SCSS file in the project
    '~/assets/css/main.scss',
  ],
})
```

注意官方在注释里特意标了一句：`bulma` 这个包名**在这里是个 Sass 文件**。也就是说包名写进 `css` 时，走的仍是"按扩展名/入口类型猜预处理器"那条规则，不是特殊通道。styling 那页给的对应例子是 `animate.css`——组件内 `import 'animate.css'`、`@import url("animate.css")`、或者直接把 `'animate.css'` 写进 `css` 数组三种都行。

## 必须说清的边界：数组顺序文档没写规则

把 4.x 文档里 `css` 这个键相关的表述翻过：官方**没有**给数组项之间的层叠先后定过任何规则。没有"后面的覆盖前面的"，也没有"按引入顺序拼接"之类的句子。

所以凡是把 `css` 数组顺序当确定性行为来写的教程，都属于文档外推。这一篇把 `css` 数组的顺序当成一个**必须实测**的点处理，不给你一个看起来很专业的规则——因为它确实没被规定。

## 唯一叫"顺序"的配置是另一件事

搜"顺序"能找到 `postcss.order`，但它管的不是样式表：

> ### `order`
> A strategy for ordering PostCSS plugins.
> **Type**: `function`

**它排的是 PostCSS 插件的执行顺序**，跟"哪个样式文件先生效"是两个层面（419 讲插件链）。把 `postcss.order` 当成"控制 `css` 数组顺序的开关"是常见误读。

## 那实际该怎么确定

CSS 的层叠是**最终产物**决定的（谁在文件里出现得晚、选择器优先级、以及是否内联），而不是配置文件里数组的位置。所以要确定自己项目里谁盖谁，看产物而不是猜配置——两条路径：

- **构建产物**：`nuxt build` 之后看 `.output`（或预渲染的 `.output/public`）里生成的 CSS，以及 HTML 中内联样式的出现次序（415 说过本地样式表会被内联进渲出的 HTML）。
- **浏览器实测**：跑起来后在开发者工具 Styles 面板看那条规则最终被谁覆盖——面板给出的就是层叠的真相。

要"确定性"就用结构手段而不是顺序：给全局基础样式与主题样式用不同的选择器强度、或者干脆拆开作用域（组件内引 vs `css` 全局），别把正确性压在数组位置上。

## 自查

- `css` 是 `array`，语义是"全局、每个页面都包含"；项可以是 npm 包名或项目内路径，官方示例里 `bulma` 注明是个 Sass 文件。
- Nuxt 按扩展名猜预处理器，但**该装的 loader 要自己装**，缺依赖时报错指向预处理器。
- **4.x 文档没有为 `css` 数组项之间的层叠顺序写任何规则**——别照旧教程断言覆盖关系。
- 文档里唯一叫顺序的是 `postcss.order`，管的是 **PostCSS 插件**顺序，不是样式表顺序。
- 要确定谁盖谁：看构建产物里的 CSS 与内联次序，或浏览器 Styles 面板实测；要可控就用作用域与选择器强度，而不是数组位置。
