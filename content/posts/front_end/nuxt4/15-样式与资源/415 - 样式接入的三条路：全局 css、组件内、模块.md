一个 CSS 文件要生效，路径其实只有三条，但它们的**作用域**和**产物形态**不一样。选错路径的典型症状是：样式只在某页生效（你以为全局）、或者 SSR 时样式闪一下才出现。这一篇把三条路的边界与官方结论列清。

## 路一：组件内引入

官方给的位置很明确——本地样式表的"自然去处"是 `app/assets/` 目录，然后在页面、布局、组件里直接引：

```vue [app/pages/index.vue]
<script>
// Use a static import for server-side compatibility
import '~/assets/css/first.css'

// Caution: Dynamic imports are not server-side compatible
import('~/assets/css/first.css')
</script>

<style>
@import url("~/assets/css/second.css");
</style>
```

两种写法都在这里，但**注释里藏着一条硬区别**：静态 import 是 server-side compatible，动态 `import()` **不是**（官方原文就是 "Caution: Dynamic imports are not server-side compatible"）。在 SSR 项目里用动态导入引样式，服务端那一趟（368）就不会带上它。

JS import 与 CSS 的 `@import` 语句都支持。这条路的官方结论：

> The stylesheets will be inlined in the HTML rendered by Nuxt.

作用域是**引入它的那个组件所在处**——只在引了它的那些页面/布局生效，这是"以为全局其实不全局"的来源。

## 路二：`css` 数组，真正的全局

要"每个页面都带"，用 `nuxt.config` 的 `css`：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  css: ['~/assets/css/main.css'],
})
```

官方对它的作用域写得比路一明确："You can define the CSS files/modules/libraries you want to set globally (**included in every page**)."，配套的 tip 也说结果样式表会被内联、**注入到全局、出现在所有页面**。

nuxt-config 的 `## css` 还补了一句实现细节：

> Nuxt will automatically guess the file type by its extension and use the appropriate pre-processor. You will still need to install the required loader if you need to use them.

也就是**按扩展名猜用哪个预处理器**，但对应的 loader 仍要你自己装（418 那条 `npm install -D sass` 之类）。这一句很关键：只在 `css` 里写了 `.scss` 而没装 `sass`，报错会指向预处理器不可用，而不是配置写错。

`css` 数组项可以是本地路径，也可以是 npm 包名（官方示例三项就是这三种）：

```ts
export default defineNuxtConfig({
  css: [
  // Load a Node.js module directly (here it's a Sass file).
    'bulma',
    // CSS file in the project
    '~/assets/css/main.css',
    // SCSS file in the project
    '~/assets/css/main.scss',
  ],
})
```

styling 那页对 npm 包给的例子是 `animate.css`：装完之后既可以在组件里 `import 'animate.css'` 或 `@import url("animate.css")`，也可以**直接把包名当字符串**写进 `css`。

## 路三：外部样式表走 head

外链样式表不进打包流程，官方给三条挂法。

**① `app.head`（静态）**：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  app: {
    head: {
      link: [{ rel: 'stylesheet', href: 'https://cdnjs.cloudflare.com/ajax/libs/animate.css/4.1.1/animate.min.css' }],
    },
  },
})
```

**② `useHead`（动态）**：

```ts
useHead({
  link: [{ rel: 'stylesheet', href: 'https://cdnjs.cloudflare.com/ajax/libs/animate.css/4.1.1/animate.min.css' }],
})
```

官方注明 Nuxt 底层用 `unhead`，要更多控制去看它的文档。

**③ Nitro 插件改渲染结果**——官方定性为"more advanced control"，在 `render:html` 钩子里往 head 数组 push：

```ts [server/plugins/my-plugin.ts]
export default defineNitroPlugin((nitro) => {
  nitro.hooks.hook('render:html', (html) => {
    html.head.push('<link rel="stylesheet" href="https://cdnjs.cloudflare.com/ajax/libs/animate.css/4.1.1/animate.min.css">')
  })
})
```

`render:html` 就是 371 时间轴上"发出 HTML 前"那一位。注意这条是 `server/plugins`，跟 ① ② 的作用层次不同：它在服务端拼 HTML 时动手脚。

## 三条路的性能差别

前两条内联进 HTML、第三条外链，代价不一样。官方在外部样式表那节末尾点了这条：

> External stylesheets are render-blocking resources: they must be loaded and processed before the browser renders the page. Web pages that contain unnecessarily large styles take longer to render.

外链是**渲染阻塞资源**——浏览器要先把它下载并处理完才渲染页面，样式太大就直接拖慢首屏。这也是路一/路二"内联进 HTML"的价值所在。

## 自查

- 三条路：组件内引（局部）、`css` 数组（每页都带）、head 挂外链（不进打包）。
- 组件内引要用**静态 import**；动态 `import()` 官方明写不是 server-side compatible。
- `css` 数组按扩展名猜预处理器，但 **loader 仍要自己装**；项可以是本地路径也可以是 npm 包名。
- 路一/路二的结果官方都说是**内联**进 Nuxt 渲出的 HTML；路二额外"注入全局、所有页面都有"。
- 外部样式表是 render-blocking，先下载完才渲染。
- Nitro 插件走 `render:html` 钩子 push 进 head，属于服务端层。
