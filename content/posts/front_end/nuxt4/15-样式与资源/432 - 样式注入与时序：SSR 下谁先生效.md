"样式晚了一步"有两种表现：内容先以无样式闪现（FOUC），或者首屏样式与最终样式不同然后跳一下。它们的成因不在同一处——前者是样式文件到得晚，后者往往是那块 DOM 压根没在服务端渲出来。这一篇把时序拆成三问。

## 第一问：它进那份 HTML 了吗

服务端那一趟（368 第 6-7 步）会把样式和 HTML 一起拼出来。官方对本地样式表写的结论是同一句，两条路都算：

- 组件里 import 或 `@import`：`The stylesheets will be inlined in the HTML rendered by Nuxt.`
- `css` 数组：`The stylesheets will be inlined in the HTML rendered by Nuxt, injected globally and present in all pages.`
- 预处理器：`In both cases, the compiled stylesheets will be inlined in the HTML rendered by Nuxt.`

但"内联什么"由 427 那个默认值决定：`features.inlineStyles` 默认 `(id) => id.includes('.vue')`，也就是**只内联 Vue 组件样式，全局 CSS 不在其中**。升级指南把这条变化讲得很直白——"Nuxt will now only inline styles for Vue components, not global CSS"，此前的行为才是"全部 CSS 内联并移除指向独立 CSS 文件的 `<link>`"。

于是判断首屏样式来源要先问一句：**head 里看到的是 `<style>` 还是 `<link>`**。是 `<link>` 就是独立文件、多一次请求；这是默认形态，不是配置出错。

## 第二问：那块 DOM 是服务端渲的吗

样式进了 HTML，还得有对应节点才谈得上生效。三处"服务端没渲"的情况：

**① `<ClientOnly>`。** 官方定性是"purposely rendering a component only on client side"，且默认插槽内容**被 tree-shake 出服务端构建**——附带后果官方自己写了：里面组件用到的 CSS 在渲首屏 HTML 时可能不会被内联。所以这块的样式与内容一起晚到，是设计而不是 bug；服务端那段由 `#fallback` 骨架占位（376/415）。

**② 岛屿（服务端组件）。** 静态岛屿没问题，"their HTML is embedded at render time"；但**完全交互**的岛屿部件靠水合前一段内联脚本把 teleport 搬到位，脚本被禁时搬不了（377/381 那条 `::warning`）。

**③ 整个 `noScripts` 路由。** 注意它的影响面：**只去脚本、CSS 不受影响**——"CSS is unaffected: stylesheet links and inlined styles are still rendered, so the page looks identical."（353）。所以"去脚本后页面变素了"这种判断是错的，视觉不变，只是永不水合。

## 第三问：开流式时样式在哪一段

`experimental.ssrStreaming` 会改变 HTML 的分段（324 详讲机制），官方对样式落点有一句专门的口径：

> **Route styles are streamed, JS hints are entry-only.** The shell is flushed before the route renders, so its `<head>` carries entry-chunk styles and hints only. Once render registers the page and layout modules, their CSS is streamed straight after the shell (inlined as `<style>` when `inlineStyles` is enabled, otherwise as stylesheet links), so page, layout, and top-level async-component styles arrive before the body paints (nested async components are a FOUC caveat, covered below).

拆成三点：

1. **壳里的 `<head>` 只带入口 chunk 的样式与提示**——壳先于路由渲染发出。
2. 页面、布局模块一被注册，它们的 CSS **紧跟壳之后**流出；形态取决于 `inlineStyles`（开→`<style>`，关→样式链接）。
3. 结论是**页面/布局/顶层异步组件的样式在 body 绘制前到位**，而**嵌套异步组件是 FOUC 的一个注意点**。

也就是说：`inlineStyles` 与流式两件事在这里叠在一起——它决定流出的 CSS 形态，流式决定它相对 HTML 的先后。

## 主题值导致的"跳一下"

还有一类不是加载晚，而是**两端算得不一样**：服务端渲出 A 样式、水合后变 B。374 的第一与第五类成因都长这样（`localStorage` 读主题、时间/环境判断进模板），后果就是 373 说的 "content flashing or unexpected layout shifts"，而且水合不匹配会**逼 Vue 重渲整棵组件树**。

正解不是调样式顺序，而是让服务端不渲那份不确定内容：`<ClientOnly>` 包起来给骨架，或者把偏好类切换交给专门处理这件事的模块（`@nuxtjs/color-mode` 与 `nuxt-time` 就是官方点名的"操作 DOM 以避免水合不匹配"的例子，428）。

## 自查顺序（症状 → 问哪一问）

| 症状 | 先问 |
| --- | --- |
| 无样式闪现（FOUC） | 是全局 CSS 独立文件吗（427）；开了流式时是否嵌套异步组件（第三问） |
| 某块始终无样式/结构错位 | 那块是不是 `<ClientOnly>` 或岛屿里的交互部件（第二问） |
| 首屏样式随后跳一下 | 是否两端渲得不一致（374）而不是加载慢 |
| 去脚本后觉得"变素" | 想错了：`noScripts` 不动 CSS（353） |

## 自查

- 时序三问：样式有没有进那份 HTML、那块 DOM 是不是服务端渲的、开流式时样式排在壳的哪一侧。
- 官方对本地样式/预处理器的结论都是内联进渲出的 HTML；但默认只内联 `.vue` 组件样式，全局 CSS 走独立可缓存文件。
- `<ClientOnly>` 内容首屏 HTML 里没有（默认插槽 tree-shake 出服务端构建，里面的 CSS 可能不内联）；交互岛屿依赖水合前的内联脚本搬位。
- `noScripts` 只去脚本，CSS 照常，页面外观不变。
- 流式下壳的 head 只有入口样式，页面/布局 CSS 紧跟壳后流出（形态看 `inlineStyles`），嵌套异步组件是 FOUC 注意点。
- "跳一下"多为水合不匹配（会重渲整树），解法是让服务端不渲那份不确定内容，不是调加载顺序。
