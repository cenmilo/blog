`nuxt build` 跑完，`dist` 里没有你要部署的东西——`.output` 才有。接下来第一步是决定：**这个应用在生产环境里靠什么跑**。

## 四条路，官方在第一句就给完了

> A Nuxt application can be deployed on a Node.js server, pre-rendered for static hosting, or deployed to serverless or edge (CDN) environments.

这一句和后面的小节标题对得上：

| 小节 | 官方给的是什么 | 你要做的决定 |
| --- | --- | --- |
| Node.js Server | 一个能直接跑起来的入口文件与它的三个环境变量 | 有没有一台 Node 主机 |
| Static Hosting | 预渲染成静态文件、或 `ssr: false` 的纯客户端单页 | 要不要服务端 |
| Hosting Providers | 一句"可以少配置部署到几家云上"，加一个站内链接 | 用平台还是自己运维 |
| Presets | 显式指定预设：`nitro.preset` 或 `NITRO_PRESET` | 目标平台是否已知 |

还有一个"厂商清单"的提示，位置值得注意：

> If you are looking for a list of cloud providers that support Nuxt, see the Hosting providers section.

那个链接指向的是站点的 `/deploy` 页，**不在 `docs/4.x` 里面**。文档里也没有逐厂商的部署章节——厂商差异全部交给那一页和 Nitro 的部署文档。所以别在 docs 路径下找 `deployment/vercel` 这类地址，它不存在。

## Node.js Server：这一节是唯一能当场执行的

开头三条定性，官方列的是：

- **Default output format** if none is specified or auto-detected（没指定、也没自动识别出来时，这就是默认输出格式）
- Loads only the required chunks to render the request for optimal cold start timing（只加载渲染这次请求所需的 chunk，冷启动更好）
- Useful for deploying Nuxt apps to any Node.js hosting（适用于任何 Node 托管）

第二条是唯一一处关于产物形状的收益描述：**按需加载 chunk**，所以它把冷启动时间当作卖点。

入口那句是 "When running `nuxt build` with the Node server preset, the result will be an entry point that launches a ready-to-run Node server."，命令一行：

```bash [Terminal]
NODE_ENV=production node .output/server/index.mjs
```

官方补一句：这会启动你的生产 Nuxt 服务器，**默认监听 3000 端口**。

## 那条 `::important`：不设 NODE_ENV 会淹日志

原文点名了一个具体依赖：

> Set `NODE_ENV=production` when running the server. Some dependencies (notably Vue Router) only strip development-only warnings when this is set, so leaving it unset can flood your logs with messages like `[Vue Router warn]: No match found for location with path …` on unmatched routes.

三件事在这条里：这是个**必须显式设**的东西，不是构建时自动带的；后果不是行为错乱而是**日志被灌满**；给出的例子是未匹配路由上的 `[Vue Router warn]: No match found for location with path …`，而且它说这类开发期警告**只有设了这个值才会被剥掉**。

顺带一个呼应：`nuxt build` 与 `nuxt preview` 两条命令都会把 `process.env.NODE_ENV` 设成 `production`，但那是**命令**做的，不是你的产物做的。直接 `node .output/server/index.mjs` 时没有命令替你设，这就是官方为什么把这条写成 `::important`。

## 三个运行环境变量

官方原句是 "It respects the following runtime environment variables"，列了三项：

| 变量 | 默认 | 官方说明 |
| --- | --- | --- |
| `NITRO_PORT` 或 `PORT` | `3000` | 监听端口 |
| `NITRO_HOST` 或 `HOST` | `'0.0.0.0'` | 监听主机 |
| `NITRO_SSL_CERT` 与 `NITRO_SSL_KEY` | 无 | **两个都给**时才以 HTTPS 模式启动 |

SSL 那条的后半句是官方主动给的劝阻：绝大多数情况下**不该用它，只用于测试**，Nitro 服务器应该跑在 nginx 或 Cloudflare 这类反向代理后面，由代理终结 SSL。

默认主机是 `0.0.0.0`（所有网卡），意味着只要端口暴露出去，公网接口就能直连这台服务——放容器里时这一点尤其要看清，需要限制就显式设 `NITRO_HOST`。

同页后面还有两个变量的用法，位置在别的示例里：`NUXT_APP_BASE_URL`（子路径部署，配 `app.baseURL`）与 `NUXT_APP_CDN_URL`（用自定义 CDN 服务 `.output/public` 里的静态资源）。都出现在 `node .output/server/index.mjs` 这条命令前面，与上面三个是同一类东西：运行时注入，不改代码。

## PM2 与 cluster 只提一句，写法在后面

这一节还给了 PM2 的 `ecosystem.config.cjs`（`script` 指向 `./.output/server/index.mjs`、`exec_mode: 'cluster'`、`instances: 'max'`、`env` 里带 `NODE_ENV: 'production'`）与 Cluster Mode（`NITRO_PRESET=node_cluster`，负载默认按 round robin 分给 worker）。这两段内容多，我在讲进程管理的那篇里逐行拆开讲。

## 自查

- 官方给的形状是三条加四节：Node.js 服务器、静态托管（含预渲染与 `ssr: false`）、serverless/边缘；厂商清单在站点 `/deploy`，docs 路径下没有逐厂商章节。
- 生产入口是 `NODE_ENV=production node .output/server/index.mjs`，默认 3000 端口；直接这样起时没人替你设 `NODE_ENV`。
- `NODE_ENV` 不设的官方后果是日志被 Vue Router 的开发期警告灌满，不是功能坏掉。
- 三个运行变量各有默认值：端口 `3000`、主机 `0.0.0.0`（默认对外可读，容器里要注意）、SSL 两个必须同时给且官方只建议用于测试。
- Node server preset 的三条定性里有一条是产物形状：只加载渲染本次请求所需的 chunk。
