CI 里跑 `nuxt build` 几乎没输出，本地同样的命令却刷屏。你在 `nuxt.config` 里把 `logLevel` 设成 `info`，CI 里还是空的。

这不是配置没生效。日志这一层在文档里分散在五页，各自管一段，把它们并起来才看得懂那个现象。

## 第 1 层：构建期级别

命令行侧的写法在每条命令上都有，措辞完全一致：

| 选项 | 说明 |
| --- | --- |
| `--logLevel=<silent\|info\|verbose>` | Specify build-time log level |

注意 **"build-time"** 这个限定词——它管的是构建期的日志，不是浏览器里看到的运行时输出。`nuxt dev`、`build`、`generate`、`analyze`、`prepare`、`typecheck`、`add`、`module`、`build-module`、`upgrade`、`init`、`preview`、`add-template` 这些命令的选项表里都列着同一行。

配置项那一条的原文更值得逐句读：

> Log level when building logs.
>
> Defaults to 'silent' when running in CI or when a TTY is not available. This option is then used as 'silent' in Vite and 'none' in webpack

- **Type**: `string`
- **Default:** `"info"`

三件事解释了开头那个现象：**默认值是 `info`，但在 CI 或没有 TTY 时默认按 `silent` 走**——所以 CI 里安静是框架行为，不是你写错了。第二句还说明这个值会**翻译成两套构建器的各自词汇**：Vite 侧用 `silent`，webpack 侧用 `none`。

## 第 2 层：钩子级 debug

配置项 `debug` 是当前能看到钩子层输出的开关：

> Set to `true` to enable debug mode.
>
> At the moment, it prints out hook names and timings on the server, and logs hook arguments as well in the browser.
> You can also set this to an object to enable specific debug options.

- **Type**: `boolean`
- **Default:** `false`

三个要点：默认关；**服务端打印的是钩子名与耗时**，而**浏览器侧连钩子参数一起打**；官方用"At the moment"（就目前而言）限定了这个行为，并说也可以传对象只开其中某些项。

这一层适合回答的问题很具体：**某个钩子有没有被调用、按什么顺序、各花了多久**（对照 019 与 371 那两篇的钩子顺序）。

## 第 3 层：模块侧的 logger

写模块时不要自己 `console.log`，官方给的是 Kit 的 Logging 那一节。

> Nuxt provides a logger instance that you can use to log messages with extra features. `useLogger` allows you to get a logger instance.

签名和底层实现一句带过：

```ts
function useLogger (tag?: string, options?: NuxtLoggerOptions): NuxtLogger
```

> Returns a logger instance. It uses consola under the hood.

两个参数的官方说明值得照抄，因为它们决定了日志长什么样：

- **`tag`**：A tag to suffix all log messages with, displayed on the right near the timestamp.（**加在所有消息后缀上的标签，显示在时间戳右侧**）
- **`options`**：Logger options, such as `level`, `reporters`, `defaults` and `formatOptions`.

官方给的两个用法示例，第二个是"按模块自己的选项控制级别"的常见写法：

```ts
import { defineNuxtModule, useLogger } from '@nuxt/kit'

export default defineNuxtModule({
  setup (options, nuxt) {
    const logger = useLogger('my-module')

    logger.info('Hello from my module!')
  },
})
```

```ts
const logger = useLogger('my-module', { level: options.quiet ? 0 : 3 })
```

`level` 用数字（示例里是 `0` 与 `3`）而不是第 1 层那三个字符串——**两套词汇不通用**，这一点官方没写明对应表，只给了这个示例（文档未记载映射）。

## 第 4 层：终端交互原语

同一页还有 `useTerminal`，它的定性解释了"同一份模块代码在两种环境下表现不同"：

> Returns a set of primitives for interacting with the user's terminal. When Nuxt is running inside an interactive host such as the `nuxt dev` terminal UI, prompts, tasks and notifications are handed to it, so they are answerable and rendered in one place. Otherwise they fall back to logging.

**有交互式宿主（比如 `nuxt dev` 的终端 UI）时，提问、任务、通知都交给它**，因此可被回答、集中渲染；**否则退化成打日志**。

返回的 `NuxtTerminal` 五项，官方逐项说明：

| 成员 | 官方说明要点 |
| --- | --- |
| `interactive` | 是否存在交互式宿主；为 `false` 时下面这些原语改为往当前进程流里打日志 |
| `withTerminal` | 在 `work` 期间借用终端，暂停宿主 UI 并释放 `stdin`；并发调用会被串行化，借用中嵌套的调用立即执行 |
| `prompt` | 向用户提问，提问打开期间借用终端；选项与 `logger.prompt` 相同 |
| `startTask` | 起一个长任务，显示在宿主的 status 面板上；用 `task.stop(message?, outcome?)` 结束、`task.update(label)` 改标签 |
| `notify` | 显示一条消息并留在屏上，直到用户确认或调用返回的 `notice.dismiss()`；`notice.dismissed` 在消息消失后落定 |

这一层与错误的关系是：**`level`/`interactive` 决定同一条信息是变成能回答的提示，还是变成一行日志**——CI 里那种"模块问了一句没人答"的卡住，判据就在 `interactive` 为 `false` 的退化路径上。

## 第 5 层：dev 终端里看日志

`nuxt dev` 的交互面板把日志折在固定面板上方，官方给的快捷键里三个和日志直接相关：

| 键 | 动作 |
| --- | --- |
| `l` | Browse the log history |
| `e` | Open the logs at the last error |
| `c` | Clear logs, requests and the console |

`e` 是这一篇最实用的一键：**直接跳到最后一条错误**。当输出被折起来、日志很多时，它省掉了往上翻。

面板的退化条件有四种（输出不是终端、CI、**attach 了调试器**、终端太小），退化后的 plain 模式仍有一小组键：`r` 重启、`o` 打开、`u` 显示 URL、`qr` 二维码、`copy` 复制地址、`c` 清屏、`h` 帮助、`q` 退出。要强制开面板用 `NUXT_TUI=1`（管道/重定向时无效），`NUXT_TUI=plain` 关掉；终端背景色探测不出来时用 `NUXT_TERM_THEME=light|dark`。

还有一条与排查耗时相关的：**请求追踪视图（按 `n` 选中请求再按 `enter`）在时间线与 Vite 编译耗时之后，会列出那条请求产生的日志**。

## 两个相邻面

**测试里**。`@nuxt/test-utils` 的 e2e `setup` 有两个和日志直接相关的选项：`captureServerLogs` 默认 `true`，会**把服务端子进程的 stdout/stderr 收起来、通过 `getServerLogs()` 取**，设成 `false` 才恢复旧的继承 stdio 行为（官方注明这在本地调试测试时有用）；`logLevel` 默认 `1`，可用环境变量 `NUXT_TEST_LOG_LEVEL` 覆盖。

**性能报告里**。`--profile=verbose` 那句官方写的是"also prints a full report to the console"——这是唯一会把大量文本打进控制台的 profiling 形态，默认只写文件。

## 自查

- `--logLevel` 是构建期级别，几乎每条命令都有；配置项 `logLevel` 默认 `info`，但 **CI 或无 TTY 时默认按 silent**，并分别映射为 Vite 的 `silent` 与 webpack 的 `none`。
- `debug` 默认 `false`，打开后服务端打钩子名与耗时、浏览器打钩子参数，官方用"At the moment"限定当前行为、也可传对象细选。
- 模块侧用 `useLogger(tag?, options?)`（底层 consola，tag 显示在时间戳右侧，可配 level/reporters/defaults/formatOptions），级别是数字。
- 需要提问或任务用 `useTerminal()`，`interactive` 为 `false` 时全部退化成日志——CI 卡住的排查起点在这。
- dev 面板里 `e` 跳最后一条错误、`l` 翻历史、`c` 清空；attach 调试器会让面板退化成纯日志流。
- 测试侧看 `captureServerLogs`/`getServerLogs()` 与 `NUXT_TEST_LOG_LEVEL`。
