错误码页的编号看着有规律，实际到处是空号：`e3` 族只有 3001、3008、3009，`e7` 族只有 7001 和 7007 到 7010，`e2` 族没有 2006。想按号补齐会白跑。

这一篇把剩下的六条一次性收进一张表，用的时候按症状查，不用记号。

## 六条速查

| 码 | 官方标题句 | 现场（描述原文要点） | 修法（Resolution） |
| --- | --- | --- | --- |
| e6001 | Missing Unhead instance | `useHead()` 这类 head 组合式函数在没有活动 Unhead 实例时调用；官方举例是"脱离的异步回调里，Nuxt 实例已不可用" | 在组件 `setup()`、Nuxt 插件或路由中间件里同步调用；`await` 之后要用就先取上下文再用 `runWithContext()` 包 |
| e7001 | Payload URL includes a hostname | 请求载荷 URL 时给了含主机名的完整地址；**载荷永远与应用同源**，带主机名就是指向应用之外，因此被拒绝 | 传相对路径而不是完整 URL：`loadPayload('/some-page')` |
| e7007 | useState init must be a function | `useState()` 收到非函数的初始值 | `const counter = useState('counter', () => 0)` |
| e7008 | callOnce fn must be a function | `callOnce()` 收到非函数的 `fn` 参数 | `await callOnce('setup', () => { /* runs once */ })` |
| e7009 | useState key must be a string | `useState()` 收到非字符串的 key | 同 e7007 那一行 |
| e7010 | callOnce key must be a string | `callOnce()` 收到非字符串的 key | 同 e7008 那一行 |

两个细节值得留意：**e6001 那一节连 read-more 都没有**（其余五节各有一条指向对应能力条目）；**每一对（useState、callOnce）的两条错误码共用同一行修法代码**——官方把 key 和值两半各写了一节，但正确写法只有一种。

## e6001：和 E1001 是同一个根

E1001（468 讲过）说的是"需要 Nuxt 实例的组合式函数在上下文外运行"，e6001 说的是同一种错在 head 那一侧的表现：

> A head composable such as `useHead()` was called without an active Unhead instance. This happens when it runs outside a valid Nuxt context, for example in a detached async callback after the Nuxt instance is no longer available.

**detached async callback**（脱离的异步回调）这个用词就是原因。官方给的修法代码把"先取值、再包一层"的顺序写死了：

```ts
const nuxtApp = useNuxtApp()
await someAsyncWork()
nuxtApp.runWithContext(() => useHead({ title: 'Late title' }))
```

三行分别是：**在还在上下文里时拿到 `nuxtApp`**、做异步工作、**用 `runWithContext()` 包住需要上下段的调用**。这一条和 468 的 E1001 修法一致，只是报错来自 Unhead 而不是 Nuxt 实例本身——所以两个码可以互相印证：**看到 e6001 就顺着同一条链查异步边界**。

顺带一条相关的呈现规则（450 记过）：开了流式渲染时，`await` 之后注册的 head 标签会退化成客户端打的补丁。**e6001 修好了"能不能调用"，不解决"来不来得及进 `<head>`"**，两件事要分开看。

## e7001：载荷不跨源

官方描述句里有一个明确的架构事实：

> Payloads are always served from the same origin as the app, so a URL with a hostname points outside the app and is rejected.

**载荷同源提供**，所以带主机名的请求会被拒绝。修法只有一句加一行：

> Pass a relative path instead of a full URL:

```ts
loadPayload('/some-page')
```

这一条在实践里最常来自两处：把 `app.baseURL` 或完整站点地址拼进了 `loadPayload` 的参数（064/422 记过运行时拼出来的路径不会被改写），或者从别处复制了一段带域名的示例。它接得上 448 的载荷文件机制——`_payload.json` 就是那条同源路径下被取的东西。官方这一节的 read-more 指向 `useNuxtApp` 的 payload 小节，是它的能力出处。

## e7007 与 e7009：useState 的两半

e7007 的描述句里带了一个**理由**，这条理由是 252 那篇用过的同一句：

> `useState()` received a non-function initial value. The initializer must be a function so that it only runs once, on the server, and its result can be serialized into the payload for hydration.

三件事连着：**只在服务端跑一次**、**结果能序列化进载荷**、**因此水合才有初值**。所以传字面量而不传函数，Nuxt 没法保证"每个请求各算一次"。

e7009 的 key 说明句则点出 key 的两重身份：

> The key identifies the shared state across the app and in the hydration payload, so it must be a non-empty string.

**跨应用共享**与**在hydration 载荷里标识这份状态**——第二个身份解释了为什么 key 必须是字符串：**它要出现在载荷里**。这一条也提醒 261 那篇记过的空白：`useState` 的值存在哪、会不会被路由跳转清掉，文档仍没写。

## e7008 与 e7010：callOnce 的两半

e7008 的描述句把 `callOnce` 的语义写在一句话里：

> `callOnce()` received a non-function `fn` argument. The value to run once must be a function so Nuxt can execute it a single time and skip it on subsequent calls.

**执行一次、后续调用跳过**——这是 `callOnce` 的全部承诺（255 那篇还补过一条：它靠往载荷里写数据来避免水合时重跑，且不返回任何东西）。

e7010 更短：

> `callOnce()` was called with a key that is not a string. The key is used to track whether the function has already run, so it must be a non-empty string.

**key 是用来记账"这个函数跑过没有"的**，所以非空字符串是硬要求。

两节给的修法都是同一行：

```ts
await callOnce('setup', () => {
  // runs once
})
```

## 自查

- e6001 与 E1001 同根：异步边界丢了上下文；修法是 `useNuxtApp()` 先取、`runWithContext()` 后包。
- e7001 的前提是"载荷同源提供"，参数只能给相对路径。
- `useState` 的初始值必须是函数（只在服务端跑一次、结果进载荷）；key 必须是字符串（跨应用与载荷里都靠它标识）。
- `callOnce` 的值必须是函数（执行一次、后续跳过）；key 必须是字符串（记账是否跑过）。
- 这一批错误码页编号大量跳号，别按号去猜不存在的页。
