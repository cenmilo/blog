把 `useFetch` 的地址换成从环境变量拼出来的值，页面报 `NUXT_E3001`；把 `useAsyncData` 的 key 写成变量传进去，报 `NUXT_E3008`。这两条错误码页都只有两段话，但各给了一条硬规则。

## 三条一览

| 码 | 官方标题句 | 触发 | 修法 |
| --- | --- | --- | --- |
| e3001 | useFetch request URL starts with `//` | 传给 `useFetch()` 的 URL 以 `//` 开头 | 用带明确协议的绝对地址，或用相对路径 |
| e3008 | useAsyncData key must be a non-empty string | `useAsyncData()` 没有合法 key | 第一个参数给非空字符串 |
| e3009 | useAsyncData handler must be a function | `useAsyncData()` 调用时缺了 handler 函数 | 第二个参数给一个函数 |

## e3001：双斜杠是协议相对地址

官方描述句把原因写得很清楚：

> The URL passed to `useFetch()` starts with `//`. A protocol-relative URL like this resolves to an external host, which is almost never intended and is rejected to avoid leaking requests to a different origin.

三个点：**`//` 开头是协议相对地址**（浏览器会补上当前页面的协议，于是它指向**另一个主机**）、**这几乎不是本意**、**拒绝它是为了避免请求泄漏到不同的源**。

最后那半句把它归类清楚了：**这是一条防数据外流的检查，不是格式洁癖**。同一个地址在 `<a href="//cdn.example.com/...">` 里是合法的，但在 `useFetch` 里意味着你会带着站内上下文去请求一个外部源。

官方给的修法示例两行：

```ts
useFetch('/api/data')
useFetch('https://api.example.com/data')
```

也就是：**要么相对路径（同源），要么写全协议**。

这一条最容易从配置里冒出来。如果基地址来自 `runtimeConfig`（245 那篇那条链），检查一下环境变量里填的是不是 `//api.example.com` 这种省略了协议的写法——`.env` 少写 `https:` 就会撞上它。

## e3008：key 非空字符串，是为了去重

官方描述句里连着给了理由：

> `useAsyncData()` was called without a valid key. The first argument must be a non-empty string so Nuxt can cache and deduplicate the request across components.

**必须是第一个参数、非空、字符串**，三个条件都在句子里；而"so"后面是这件事的意义：**Nuxt 要靠它在组件之间缓存并对请求去重**。这就接上 243/252 记过的那条：同一个 key 的调用共享同一份数据与状态。

修法示例：

```ts
const { data } = useAsyncData('users', () => $fetch('/api/users'))
```

按这条规则看，常见踩法有两类：把 key 写成空字符串占位（`useAsyncData('', ...)`），或者传了数字/对象而不是字符串。

## e3009：handler 是干活的那个函数

官方描述句解释了它的角色，而不是只说类型：

> `useAsyncData()` was called without a handler function. The handler is the function that performs the fetch and returns the data, so it cannot be omitted or of another type.

**handler 是执行取数并返回数据的那个函数**，所以既不能省、也不能是别的类型。这一条经常和 e3008 一起出现，因为漏写 handler 的写法常常是 `useAsyncData('users')`——key 有了，但没有取数动作。

值得注意的是：**e3008 与 e3009 两节给的修法代码是完全同一行**：

```ts
const { data } = useAsyncData('users', () => $fetch('/api/users'))
```

两节都指向 `useAsyncData` 参考条目的 read-more。这一行同时补齐了 key 与 handler，所以官方复用了它。

## 这两条与两种调用形状的关系

`useAsyncData` 有两套参数形状（243 那篇记过）：位置式的 `useAsyncData(key, handler, options)`，以及对象式 `useAsyncData(options)`。e3008 那句明确说的是**第一个参数**——它针对的是位置式写法。

用对象式写法时 key 从哪来、缺 key 会不会同样报 e3008，**这两节没有写**（文档未说明）。要确认，就在同一个项目里分别用两种形状各去掉一次 key，看报的是不是同一条。

## 自查

- `//` 开头会被当成协议相对地址解析到外部主机；`useFetch` 直接拒绝它，属于防泄漏检查。基地址来自环境变量时优先查这一点。
- key 必须是第一个参数位置上的非空字符串，作用是让 Nuxt 能跨组件缓存与去重；空串或非字符串类型都不合法。
- handler 是真正执行取数并返回数据的函数，省略或类型不对都会报 e3009。
- e3008 与 e3009 的官方修法是同一行：`useAsyncData('users', () => $fetch('/api/users'))`。
- 对象式调用形状下的 key 行为，这两节未记载，需要自己对比测试。
