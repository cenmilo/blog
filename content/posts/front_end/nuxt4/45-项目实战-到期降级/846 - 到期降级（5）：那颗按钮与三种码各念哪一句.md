打开会员区，屏幕上有两句各说各的话（渠道说生效中，本站说这一期已经过了），有一列数字，还有一个"重新取一次"。没有一样东西能按下去。上一站立起来的那道 409 也一样，它只存在于接口回体里，页面上没有一个位置会念它。

这一站补的就是这一小块，屏幕上多出来的是这样一段：

```html
<p data-testid="checkout-outcome" aria-live="polite">{{ 下单句 }}</p>
<p v-if="下单地址" data-testid="checkout-url">{{ 下单地址 }}</p>
<button ref="开始钮" type="button" data-testid="checkout-start" :disabled="下单中" @click="去下单()">
  {{ 下单中 ? '正在打开付款页…' : '开通这个会员' }}
</button>
<button v-if="给重试" ref="重试钮" type="button" data-testid="checkout-retry" :disabled="下单中" @click="去下单()">
  再试一次
</button>
```

## 按下去之后，页面凭什么决定念哪一句

**分支只看 `data.code`**。不看状态码数字，也不拿句子当条件：409 与 503 到了浏览器里都只是"一个非 2xx"，而它们要的处理正好相反（一个不许再点，一个正是要你再点）。句子也不在这份文件里长，页面只念接口带回的那一句 `message`，唯一的兜底是词表里的 `unheard`，用在连 `message` 都没有的那一刻。

判据 `test/unit/checkout-button.test.ts` 七档，第一趟读数：

```
[按钮·分支] {"读码":1,"按数字分支":0,"按句子分支":0,"集合里是码":2}
[按钮·句子] {"页面自拼的失败句":0,"页面引词表次数":1,"词表有兜底句":"这一步没有回话，请稍后再试。"}
```

后面那两位数的不是"提了几回名字"，是把 import 那一行先剥掉之后数**用了几次**。上一轮这条判据第一次就跑红了，`页面引词表次数` 读到 2，理由是那句兜底话既在 import 里出现又在代码里出现——**静态判据数错东西时，先改判据，别急着改代码**。

## 409 不给重试，503 才给

给不给重试由一张只有两项的表决定：

```
[按钮·重试] {"表":"'CHECKOUT_NOT_CONFIGURED', 'CHECKOUT_CHANNEL_FAILED'","含409":false,"重试位有vIf":true}
```

欠着与渠道没答好，是"再试一次可能就成了"；**409 再点一次还是 409**，给它重试按钮等于向用户承诺一件永远不会发生的事。这就是 760 那条口径在这一路的落点，码决定行为，句子只负责让人读懂。

## 两把尺各挡一半连点

`disabled` 挡鼠标与键盘，函数里那一句 `if (下单中) return` 挡同一次渲染里的连点。少任何一把都测得出来：Playwright 点得比 DOM 更新快，样式上还没禁用它就已经把第二下打进去了。端到端 `846④` 用 `force: true` 硬打第二下，数的是发出去几趟请求：

```
[按钮·连点] {"请求数":1,"请求":["http://localhost:3739/api/billing/checkout"],"禁用":false,"句":"付款这一步暂时打不开，请稍后再试。"}
```

`禁用: false` 不是漏了，是这一趟已经飞完、`下单中` 归位了；请求数才是这一档要看的那个东西，这一路每多一趟就多向渠道要一张新单子。

## 两个只有真点击才现形的毛病

这两个都是这一站当场改掉的，都不是设想出来的。

**第一个是等法。** 重试那一档原本用固定 600 毫秒等第二趟的结果，红了一次：

```
[按钮·503] {"第一次":{"句":"付款这一步暂时打不开，请稍后再试。","有重试位":1,"行数":0},
            "第二次":{"句":"","行数":0}}
```

那句空白不是页面念错了，是它还在飞。等一个固定毫秒数去量一个瞬时状态，量到的是"此刻它还没回来"，而不是"它不会回来"。改成等结果区重新有字（有上限 15 秒），第二趟读到的仍是那一句 503，`行数` 一动不动，重试没有偷偷往库里写东西。

**第二个是焦点。** 改成正确的等法之后，同一档又红了一次，这次读到的是 `BODY`：焦点不在任何按钮上。原因很实在，`disabled` 一挂到用户刚点中的那颗按钮上，浏览器就把焦点还给 `<body>`；而更早一版还在飞行开头清了码，那一清会把整颗按钮从 DOM 里抽走。键盘用户按了"再试一次"之后，位置没了。

修法两步，都不在样式层：

```ts
  下单中.value = true
  // 不清 `下单码`：清了就把用户刚点中的那颗按钮整个 v-if 掉。
  下单句.value = ''
  ...
  } finally {
    下单中.value = false
    await nextTick()
    if (import.meta.client && document.activeElement === document.body) {
      (给重试.value ? 重试钮.value : 开始钮.value)?.focus()
    }
  }
```

三个细节各挡一种坏法：等一 tick 是因为 `disabled` 还挂着时 `focus()` 打不动；判 `=== document.body` 是因为他已经走到别处，页面不该把他拽回来；放回哪一颗跟着 `给重试` 走，因为 409 之后那颗重试根本不存在。找那两颗按钮用模板 `ref`，不用 `data-testid`——后者是判据用的，不是产品用的。

改完之后两档的读数分别是 `checkout-retry` 与 `checkout-start`：

```
[按钮·409] {"进场那句":"你现在的会员还在有效期内，不用重复下单。","有重试位":0,"开始位还在":1,
            "订阅栏":"生效中","拦后行数":1,"焦点在":"checkout-start"}
[按钮·503] {"第一次":{"句":"付款这一步暂时打不开，请稍后再试。","有重试位":1,"行数":0},
            "第二次":{"句":"付款这一步暂时打不开，请稍后再试。","行数":0,"焦点在":"checkout-retry"}}
```

## 匿名访客那一档读的不是状态码

```
[按钮·匿名] {"状态":200,"是会员区":false,"有按钮":false,"标题":"账户 · Substrate"}
```

200，但不是会员区。门挡下来发回来的是一份 200 的别页，只看状态码会以为进来了（840 立的这条，这一站又用了一次）。这一档问的是"这一段会不会出现在没登录的人的 HTML 里"，答案是不会，按钮压根没渲出来，也就没有"点了必然吃 401"那种形状。

## 拿到地址那一步，两站都在本机

```
[按钮·跳转] {"现在在":"http://127.0.0.1:3414/c/cs_846","期望":"http://127.0.0.1:3414/c/cs_846"}
```

`window.location.assign` 是真的会走，所以这一档把接口和跳转目标都接在本机替身上，读到的是浏览器现在在哪，而不是"页面里有一句跳转"。判据读的是 `checkout-url` 那个位，跳转本身只在 `import.meta.client` 里发生——服务端渲这一页时没有 `window`，上一站就撞过一次这种 500。

## 改坏七处，各红几档

| 改坏的地方 | 改成什么 | 红了谁 |
| --- | --- | --- |
| 409 进可重试那张表 | 表里加一项 | `①` 与 `④` 红（字面量数到 3、`含409` 变 true） |
| 重试位不再禁用 | 删掉 `:disabled` | `③` 红（`禁用绑到飞行中` 从 2 变 1） |
| 飞行开头清了码 | 加回那一句 | `⑥` 红；端到端 `846②` 的焦点读数也会变 |
| 跳转的客户端守卫删掉 | `if (回.url)` | `⑤` 红（服务端渲这页时就是那个 500 的形状） |
| 兜底句子写在页面里 | 换成中文字面量 | `②` 红两处（页面自己编了一句、词表不再被引） |
| 不等一 tick 就 focus | 删掉 `await nextTick()` | `⑦` 红（`等过DOM`、`只在掉到body时抢` 双双为 false） |
| 无条件 focus | 去掉 `=== document.body` | `⑦` 同一趟红（用户已经走开也会被拽回来） |

前两批是五个改坏一起下，红的正好是该红的那六档，`⑦` 全绿——它守的东西没被动过；第三批只动 `finally` 那一段，`⑦` 单独红。还有一处不是变异，是它自己撞出来的：焦点那一档在修复前读到 `BODY`，判据当场就是红的，这是这套判据本轮唯一一次"先于修复就正确"。

## 加第二个读者，撞红一条老判据

那颗按钮要设 `x-csrf-token`，于是页面里读 `csrf` 那一位的文件从一份变成两份。`test/unit/identity-surface.test.ts` 有一条正对照（同一把尺子在别处要读得到东西，防止整档扫空），它钉的是文件名单：

```
[cookie 的用处] {"读sid的文件":[],"读csrf的文件":["app/pages/console/index.vue","app/pages/me.vue"]}
```

这条红是登记，不是抹灯：它原来钉的那份名单只有一份，是因为当时确实只有一份。名单里再出现第三个文件时，先问的是"是不是又多了一个地方在读会话相关的东西"，而不是把数字放宽。

## 你自己跑一遍

```bash
cd Substrate
npm run test:unit -- checkout-button      # 七档，离线可跑
NUXT_E2E_DB=1 E2E_PORT=3739 npx playwright test test/e2e/checkout-button.spec.ts
```

第二条是不配渠道密钥那一趟，本轮打印值 **5 passed**。`846②` 那一条要的就是"没配密钥"，配了密钥它会 skip（503 才是这一路的形状）。

整条线那五份端到端文件并跑时要小心两件事，本轮都撞上了：

- **带库那一趟必须在命令里给出签名密钥**。少了它，那七档"同一趟里既走写口子又走读口子"的判据连同另外十几档会一起静默 skip：本轮第一次全量带库读到 **316 passed／72 skipped**，补上这个变量之后是 **342 passed／46 skipped／0 failed**。两趟的用例总数一样，差的 26 条一条都没红，只是没跑。
- **单独并跑这五份文件，每趟都有一档卡在 30 秒超时，且换的不是同一档**（三趟分别是 `846⑤`、`845②`、`844③`；前两个都在打印完自己的读数之后才卡住）。同一条判据在全量那一趟里 6.8 秒过。所以这条线往后的收口依据取全量那一趟，小范围并跑只当冒烟。

| 撞上的现象 | 原因与读法 |
| --- | --- |
| 五条全 skipped | 没给 `NUXT_E2E_DB=1`，库串是空串，第一条 skip 条件就把它挡下 |
| ② 永远 skip | 本站配了渠道密钥；这一档要的是没配那一站 |
| 焦点读到 BODY | 修复前的真实形状。检查 `finally` 里那一 tick 与 `=== document.body` 判据还在不在 |
| 第二次读到空串 | 有人在用固定毫秒数等飞行中的页面，改成等结果区重新有字 |
| `页面引词表次数` 读到 2 | import 行没剥掉，判据数的是"提了几回名字"而不是"用了几次" |
| 全量带库的 skip 比上一轮多一截 | 命令里少了签名密钥那个变量，整批判据静默 skip；用例总数不变，红数也不变 |

## 收了哪一格，还欠哪一格

"到期降级"这句话到这一站有了用户看得见的那半，**到期这件事既改了一个动作的结果，也有一句话会在屏幕上被念出来**。845 拦下的那一位现在知道为什么按不动，844 那句"这一期已经过了"现在旁边有一颗真的能按的按钮。

还欠的是收口那一步：这一句验收在本机到底能兑现到哪一格、哪几格仍只能等一次带库的完整跑，以及时区、多份订阅、真投递、发票页那四笔旧账各还差什么。下一站（847）不再新增实现，逐句把它们判完。
