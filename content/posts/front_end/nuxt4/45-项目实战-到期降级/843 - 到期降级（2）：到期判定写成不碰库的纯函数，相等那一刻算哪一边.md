842 那一站的读数是：库里那一行的 `current_period_end` 已经过去 3,600,533 毫秒，接口仍回 `active`，页面仍念"生效中"。要开始管这件事，最顺手的第一步是在页面加一个判断：

```vue
<!-- 看着没错，但它是第二份规则 -->
<p v-if="订阅.subscription.currentPeriodEnd < Date.now()">已到期</p>
```

写下这一行的时候，全站就有了两处到期判定：一处是状态机里那个 `<=`，一处是这里新加的 `<`。**这两处可以在"正好相等"那一瞬间给出相反的答案**，而它们判的是同一条订阅。这一站不碰页面，先把规则收成一份。

## 一个只吃两个数的函数，三个答案

新文件 `shared/utils/period-expiry.ts`，函数签名是这样：

```ts
export type 周期判定 = '已过' | '未到' | '无从判断'

export function 判周期末 (周期末: number | null | undefined, 现在毫秒: number): 周期判定 {
  if (typeof 周期末 !== 'number' || !Number.isFinite(周期末)) return '无从判断'
  if (typeof 现在毫秒 !== 'number' || !Number.isFinite(现在毫秒)) return '无从判断'
  return 已过判据(周期末, 现在毫秒) ? '已过' : '未到'
}
```

**为什么是三个答案**：布尔值只能表达"过期／没过期"，而现实里还有第三种格子——这一格里**根本没有一个时刻**。842 已经在库里读到了这种行（`没有周期末: 1`），`payload.ts` 那句 `秒换毫秒` 对不带这一位的事件给的也是 `null`。把 `null` 兜成 `false`（还没过期），等于替一个不存在的事实编一个好消息；这与 840 那条"库里一行都没有"与"有一行说它是 `none`"必须分开的理由是同一族。

判据表 `test/unit/period-expiry-rule.test.ts` 的 `①` 打了十行，期望值逐行手敲（**不调用被测实现算期望**）：

```
[到期·边界] {"现在":1000,"读数":["没有这一格（null）→无从判断","干脆没传→无从判断","不是数（NaN）→无从判断",
  "无限远（+Infinity）→无从判断","无限靠前（-Infinity）→无从判断","正好相等那一瞬→已过",
  "还差一毫秒才到→未到","一毫秒前就过了→已过","一小时前就过了→已过","一小时后才到→未到"]}
```

## 那个"不是数"不是假设，是从库里走出来的

写三态容易被人问一句"你为什么要防 `NaN`"。这一站把它量出来了。往 `timestamptz` 那一列写 `'infinity'`——Postgres 允许，列上没有任何约束挡它——端到端那一档 `843⑥` 读回来的是：

```jsonc
[到期·infinity] {
  "库侧": { "构造函数名": "Number", "类型": "number", "值": "Infinity", "是有限数": false },
  "接口": { "状态": 200,
            "体": "{\"subscription\":{\"status\":\"active\",\"currentPeriodEnd\":null,\"updatedAt\":1792479359037}}" },
  "页":   { "状态": 200, "句子": "生效中", "到期": "没有到期记录" }
}
```

这条链条一环一环是这样：驱动把 `infinity` 读成一个 number（不是 `Date`），timestamp 列的映射拿它去 `new Date(...)` 得到一个无效日期，`read.ts` 那句 `.getTime()` 于是吐 `NaN`，而 `JSON.stringify(NaN)` 写出来就是 `null`。中间那一环由单测档 `②` 单独取证：

```
[到期·坏时刻] {"各坏时刻":["NaN→无从判断","Infinity→无从判断","-Infinity→无从判断"],
  "裸比较":[false,true,false],
  "中间环":{"newDate的结果":"Invalid Date","getTime":null,"是非有限数":true}}
```

打出来那一行有个自嘲的细节：`"getTime": null`——**这个 JSON 里正躺着它要说明的那个东西**。`NaN` 在 `JSON.stringify` 下面活不下来，只能变成 `null`。

于是这一格落到页面上是"没有到期记录"。**"永远不到期"与"这一格是空的"，走完读口子变成了同一句话。** 这一站不修它（修它要动显示层与词表，那是 844 之后的事），但把它钉在判据里：`②` 断言 `裸比较` 那三个布尔值是 `[false, true, false]`——布尔写法遇到 `NaN` 会答"还没过期"，遇到 `Infinity` 会答"已经过了"，两个方向都错。

## 相等那一瞬：符号不是风格问题

`周期末 === 现在` 这一瞬间算哪一边？本站早有答案，只是没人注意：状态机第③步写的是 `周期末 <= 事件.occurredAt`，**相等判"已过"**，而且它已经带着这个符号跑过 834 的乱序与重放判据。所以新函数照抄这个符号，不是"也可以这样写"，是"必须与已经生效的那一处一致"。

判据 `④` 与 `⑤` 把这四个时刻各问一遍：

```
[到期·状态机行为] {"掉了":"expired","整点":"expired","续上":"no-rule","空时刻":"no-rule","整点状态":"inactive"}
[到期·转发] {"事件在过去":false,"事件在整点":true,"事件在未来":true,"事件带来新时刻":false}
```

`整点` 那一行就是"事件到达的那一刻正好等于周期末"——它判 `expired`，状态落 `inactive`。`空时刻` 那一行是周期末为 `NaN` 的现状配上一条晚一点的事件：判不出来，于是不硬降级，走后面的规则（`no-rule`），把这一行原样留着。渠道那边"周期末这一秒到底还算不算这一期"没有承诺，这条挂进未闭合，不替它决定。

## 状态机改成调用它，行为一条都没变

`server/services/billing/state.ts` 里那一行由

```ts
if (周期末 !== null && 周期末 <= 事件.occurredAt) {
```

变成

```ts
if (事件时刻已过期(当前, 事件)) {
```

转发函数只有一行，**里面不许再出现比较符号**——这是判据 `③` 钉的形状：

```
[到期·形状] {"规则里的比较":1,"状态机自拼的周期末比较":0,"状态机调用转发":1,"转发体里的符号":0,"转发体里的调用":1}
```

四个数字各管一件事：规则层只有一处符号；状态机自己不再拼；它调用了一次；转发那一行不带新规则也没有把规则复制一份。`831` 与 `834` 那两份老判据在这一站**一条都没红**——规则搬家而行为不变，才是这一站真正交付的东西。

改形状的同时，上一站两条判据的期望值也跟着改了，这是登记不是抹红灯：

| 老判据 | 原来钉的 | 现在钉的 |
| --- | --- | --- |
| 842 `③` | `if (周期末 !== null && 周期末 <= 事件.occurredAt) {` 那一整行 | `if (事件时刻已过期(当前, 事件)) {`；"比的是事件那一刻不是现在"这句交给 `⑤` |
| 842 `⑤` | 提到这一列的源码是 7 份 | 8 份（多出来的就是新规则层那一份） |

## 三次改坏，看谁红

| 改坏的地方 | 改成什么 | 红了几条 |
| --- | --- | --- |
| 规则层的符号 | `<=` 改成 `<` | 3 条：`①`（相等那行）、`④`（整点不再掉）、`⑤`（在整点那条）——而 831／834 那两份老档一条都不红 |
| 状态机 | 把比较符号自己拼回去（还写成了 `<`） | 3 条：`③`（自拼 1 次、调用 0 次）、`④`、842 `③`（那一行找不到） |
| 兜底那一支 | `null` 不再给 `无从判断`，改给 `未到` | **只有 1 条红**：`①` |

第三行最值得一看：把"没有时刻"兜成"还没过期"这种错，目前只有一个地方能发现。因为还没有第二个消费者——下一站（844）让读的那一层真的用起这个函数之后，同一类错误就会有更多地方能撞出来。这也是这条线一直的做法：先让规则只有一份，再让越来越多的人来问它。

## 你自己跑一遍

```bash
cd Substrate
npm run test:unit -- period-expiry-rule        # 五档，全离线
NUXT_E2E_DB=1 E2E_PORT=3714 npm run test:e2e -- test/e2e/period-expiry-rule.spec.ts
```

第二条会先构建再起产物服务，跑完是 `1 passed`；不带 `NUXT_E2E_DB` 那一趟它是 skipped（与 842 那两档同一族：要库）。全量不带库这一趟 **257 passed／117 skipped**，归族 **要库 50／要外部服务变量 42／要内容目录读得到 14／要另一趟构建的开关 11**——比上一站的 49 多出的一条就是这一站新增的那档端到端。

| 撞上的现象 | 原因与读法 |
| --- | --- |
| `Test Files 1 failed`，红的是边界表 | 符号被改了。先看那一行是不是 `<`——相等那一瞬的归属全押在这一个字符上 |
| 形状档报"状态机自己又拼了一个符号" | 有人在 `state.ts` 里直接写了比较。把那一行换回调用，别在两边都留 |
| 端到端那档读到 `页.到期` 是 `(读不到)` | 插进去的那一行没有周期末，页面按设计不出现这一行（`v-if`）；`infinity` 那档才有它 |
| 端到端报 `体里读不到那一句` | `read.ts` 那句 `.getTime()` 换掉了，`NaN` 不再产生 ⇒ 这条链条的解释要跟着改，判据与正文一起 |
| 带库全量那一趟红一两档、报 `connect ECONNREFUSED` | 远端连接额度的状态，不是代码。原样重跑，取失败最少那一趟，并把是第几趟写清 |

## 这一站收了什么，还欠什么

收掉的：到期判定现在**只有一份**，相等那一瞬有了明确归属，规则层不碰库、不读钟、不碰网络，能在手心算。

还欠的三件，都记进了这一线的账：

- 这份规则**还没有第二个消费者**。读的那一层仍然不判到期（842 的读数在那儿摆着），下一站把它接进 `read.ts` 与那一栏。
- `infinity` 与"这一格是空的"在页面上长成同一句话（"没有到期记录"）。要分开，得先决定 `read.ts` 那份 `number | null` 到底该带不带第三种信息。
- `null` 那一格兜错只有一条判据能发现——这是"规则还没被人用"的自然结果，不是判据写得差。

下一站（844）动的是形状：读的那一层多给出"还能不能用"这一位，词表补上那句"渠道说生效中、日子已经过了"。842 埋好的三条哨兵（接口体键集合三位、两个函数 `length===1`、读的一路时钟计数 0）在那一站会红——那是登记。

## 本文依据

- `docs/4.x/guide/directory-structure/shared`——`shared/` 是唯一能被应用侧与服务端两侧同时导入的位置，这一层的规则放在这儿正是因为**两个调用方在两侧**（状态机在服务端，显示在应用侧）。
- `docs/4.x/api/composables/use-async-data`——服务端算出来的那一位怎么进负载、页面接手时不再算一遍；两处各算一遍正是 840 那站水合不匹配的由来。
- 同一节里那句 `::important`（不要把服务端专用代码引到应用侧）：新函数没有引入任何服务端符号，才让"规则只有一份"这件事在两侧都成立。
