上一站（841）收官时留了一句：会员区那一栏会显示订阅状态和一个日子，但**没有人把"日子过了"变成用户能感受到的差别**。这一站就把这句话量成读数——不改任何实现，只问四个问题：这一列被谁读了、读的时候比了什么、比的是哪个时刻、页面上能不能说出"已经到期"。

## 先看到那一栏此刻在说什么

判据 `test/e2e/period-expiry-baseline.spec.ts` 的 `842⑦` 干的事很直白：给自己建一个用户、一条会话，往 `subscriptions` 里放一行——状态写 `active`，周期末写 `now() - interval '1 hour'`。然后用真的应用出口读一遍。跑出来的读数（原文照抄）：

```jsonc
[到期·已过一行] {
  "库里": { "status": "active", "已过": true },
  "接口": { "状态": 200, "键": ["currentPeriodEnd", "status", "updatedAt"],
            "体": { "subscription": { "status": "active",
                                      "currentPeriodEnd": 1792473693950,
                                      "updatedAt": 1792470093950 } } },
  "页": { "是会员区": true, "状态词": "active", "句子": "生效中",
          "到期": "2026-10-20（按 UTC 记）" },
  "现在毫秒": 1792477294483
}
```

`currentPeriodEnd` 与"现在毫秒"相减是 **3,600,533 毫秒**——已经过去一小时零三分秒了。库里那一格自己承认这件事（`"已过": true` 是同一条 SQL 里 `current_period_end < now()` 读出来的），接口照样回 `active`，页面照样念"生效中"。

还有一层更隐蔽的：**那一栏显示的日期就是今天**。上站讲过显示格式取的是 UTC 那一段日子（840），一小时前的那个时刻与"现在"落在同一个 UTC 日期里，所以一个用户盯着屏幕看，看到的是"生效中／2026-10-20"，一个字都读不出"过期"。

## 这一列被读的地方只有一处，比时间的地方也只有一处

`842⑤` 把 `app/`、`server/`、`shared/` 三棵源码树扫一遍（注释整行剥掉再找，否则注释里提一句"周期末"就成了假命中），七份文件提到这一列：

```jsonc
[到期·全站] {
  "提到周期末的文件": ["app/pages/console/index.vue", "server/services/billing/ingest.ts",
                       "server/services/billing/payload.ts", "server/services/billing/read.ts",
                       "server/services/billing/state.ts", "shared/copy/subscription.ts",
                       "shared/types/billing.ts"],
  "走过newDate": ["server/services/billing/ingest.ts"],
  "与现在同行": []
}
```

`与现在同行` 是空的：**没有任何一行源码把周期末和 `Date.now()` 或 `now()` 写在同一句里**。`走过newDate` 只有一份，而且是在写的那一侧——`ingest.ts` 拿事件里的毫秒换成一个 `Date` 往库里放。显示用的那份（`shared/copy/subscription.ts`）里那句 `new Date(毫秒)` 所在的那一行没有"周期末"三个字，所以它落不进这个统计，这也正是它不是比较的原因。

再细分到"读的那一路"，`842①` 数的是三份源码里时钟与这一列各出现几次：

```jsonc
[到期·读的一路] { "读的那层": { "时钟": 0, "周期末": 6 },
                  "接口": { "时钟": 0, "周期末": 0 },
                  "页面": { "时钟": 0, "周期末": 1 } }
```

读的那一层（`server/services/billing/read.ts`）把这一列选出来、换成毫秒递出去，出现 6 次；接口一次都不碰它；页面提 1 次，就是那一行显示。**三次时钟读取都是 0**。

## 把那条 SELECT 摊开看

`read.ts` 里的查询是 drizzle 拼的，源码看不出最终语句长什么样。做法与前面量发券那条 SQL 一样（假 client 只把语句抄下来，一次库连接都不建立），`842②` 读到的原文：

```sql
select "status", "current_period_end", "updated_at"
  from "subscriptions"
 where "subscriptions"."user_id" = $1
 order by "subscriptions"."updated_at" desc, "subscriptions"."id"
 limit $2
```

```jsonc
[到期·SQL] { "参数": ["00000000-0000-4000-8000-000000000001", 1], "比过时刻": false }
```

`where` 那一段逐字就是 `"subscriptions"."user_id" = $1`，两个参数一个是用户编号、一个是 `limit` 的行数。**没有第三个参数是时刻**，`where` 里也没有 `now()`。这条语句无论什么时候跑、跑多少次，回来的都是同一行——库不会替你把"已经过了"这一位筛掉。

那唯一一处比较在哪儿？在状态机里，`server/services/billing/state.ts` 第 47 行，判据把这整行逐字钉住：

```ts
if (周期末 !== null && 周期末 <= 事件.occurredAt) {
```

比较的另一头是 **`事件.occurredAt`**——事件到达的那一刻，不是"现在"。`842③` 用两个手敲输入把它演了一遍：现状是 `active`、周期末早就过了，来一条**没带新周期末**的更新事件 ⇒ `reason: 'expired'`、状态落 `inactive`；同一条事件如果**带了未来的周期末** ⇒ `reason: 'no-rule'`、状态不动。也就是说这条规则只在**有事件进来**的时候才有机会跑。本站没有任何定时任务去喂它（第十八、十九两线都没建），所以"到期即停"这一句今天成立的唯一前提是：渠道恰好送来一条新事件。

## 库里此刻有几个已经过了

`842⑥` 是一条只读聚合，一条查询读回来的就是那一刻的状态，所以"三类相加等于总行数"这种自证不受别的档并发写入影响：

| 问法 | 读数 |
| --- | --- |
| 这张表一共几行 | 1 |
| 没有周期末那一格 | 1（`sub_834_d1792461474798`） |
| 还没到那一刻 | 0 |
| 已经过了那一刻 | 0 |
| 状态是 `active` 且已经过了 | 0 |

这一行是第十八线某次跑失败的档留下的痕迹：它没有周期末，而 `read.ts` 对"没有周期末"给的是 `null`，页面那一栏就干脆不显示日期。全部跑完之后再看一次，这一位还是 1——本线两档自建自删（订阅行按 `sub_r842_%` 点名删，用户和会话删自己的），没往里加东西。

此刻是 0 不代表这件事不存在。`842⑦` 就是自己造了一个"已经过了"的行出来，才把差别拍到。**这一列现在的处境是：被读、被显示，但不被判。**

## 词表里说不出"已经过了"

840 那份词表只有五个状态名，每个状态一句。`842④` 读到的是：

```jsonc
[到期·词表] { "给人看arity": 1, "周期末arity": 1,
              "五句": ["还没有过订阅", "生效中", "逾期未付", "到期后停止", "已停止"] }
```

`arity` 是函数的入参个数。`订阅状态给人看(值)` 只吃一个值——状态词。**这两个函数的入参里都没有"现在几点"这一格**，所以"状态是 active、日子已经过了"这句话在词表里没有落点：它只能念出"生效中"。要让它说出别的话，得先让它收第二个入参，而那正是下一站的活。

## 把三处各改一下，看谁红

绿灯不等于判据有效。这一站改了三次代码，每次改完就跑，跑完还原：

| 改哪一处 | 改成什么 | 红了几条 |
| --- | --- | --- |
| 词表 `active` 那句 | 改成"生效中（这一期可能已经过了）" | 3 条：840①、840②、842④ |
| `read.ts` 返回之前 | 加一行 `const 现在 = Date.now()` | 1 条：842①（`时钟` 从 0 变 1）；**842⑤ 没看见这一行** |
| `read.ts` 的返回形状 | 多给一位 `可用: true` | 1 条：842⑦ 的键集合，读到 `["currentPeriodEnd","status","updatedAt","可用"]` |

第二行那条最值得记：**`842⑤` 找不到"下一行才去比"的写法**。它判的是"同一行里既提到周期末又读了钟"，而真实代码常常是上一行取钟、下一行拿来比。所以那条判据只当"有没有人写在一行里"的粗筛，真正封住读的一路的是 `842①`（整份文件的时钟计数）——两条的分工不一样，缺一条就有一段漏网。

第三行是下一站的预告：读口径一旦多派生一位，端到端那条键集合断言当场就红。这条判据现在写死了三位，改它的时候要在正文里点名，是登记不是抹红灯。

## 你自己跑一遍

判据都在仓库里，两条命令分别覆盖离线与带库：

```bash
cd Substrate
npm run test:unit -- period-expiry-baseline        # 五档，一次库连接都不建立
NUXT_E2E_DB=1 E2E_PORT=3701 npx playwright test test/e2e/period-expiry-baseline.spec.ts
```

第二条会自己起一次构建再打产物（`npm run build && node .output/server/index.mjs`），跑完是 `2 passed`。不带 `NUXT_E2E_DB` 那一趟跑同一份文件，两档全 skip——本线新加的两档都挂在"要库"这一族里，全量不带库那一趟的数字是 **257 passed／116 skipped**（要库 49、要外部服务变量 42、要内容目录读得到 14、要另一趟构建的开关 11）。

| 撞上的现象 | 原因与读法 |
| --- | --- |
| 两档都显示 skipped | 没给 `NUXT_E2E_DB=1`，`NUXT_DATABASE_URL` 是空串；这一档的第一条 skip 条件就是它 |
| `listen EADDRINUSE :::3701` | 这台机器会把那段端口先分配给出站连接，监听表里查不到条目。换个号就好，别去动任何进程 |
| 页面那一栏读到 `(读不到)` | 会话或门没对上。这一档同时读 `是会员区` 那一位（`console-marker`），它为 `false` 就说明发回来的是别的页 |
| `842②` 报 `(读不到那一段)` | 语句形状变了：`where` 到 `order by` 之间找不到，说明读口径加了新谓词，判据与正文都要跟着改 |
| 全量带库那趟红几十条 | 服务端日志里是 `connect ECONNREFUSED`，红的档散在本线没改过的文件里；同一趟重跑即可，报数以失败最少那一趟为准 |

## 这一站的读数收在这里

四个问题四个答案：这一列被三个地方读（读的那层、页面、状态机），比时间的只有状态机一处且比的是**事件那一刻**；那条 SELECT 的参数里没有时刻；词表只吃状态词，说不出"已经过了"；库里此刻有 0 行"active 且已过"，但造一行出来只要三行 SQL，而那一行在页面上依旧写着"生效中"。

下一站（843）把"到期"写成一个不碰库的纯函数：`null`、非有限数、以及 `周期末 === 现在` 那一个边界点算哪一边。这三个形状都不是假想——`null` 是 839 量到的"删除事件先到"那一行，非有限数是不带周期末的事件留下的空档，相等那一瞬是渠道把周期末写到整点的常见形状。

- `docs/4.x/directory-structure/server`——被自动扫描注册成接口与服务端处理器的目录只有 `api/`、`routes/`、`middleware/` 三个。`server/services/` 不在这个清单里：它是本站自己的分法，理由写在 `read.ts` 的文件头，改了不会被框架发现，只能靠判据守着。
