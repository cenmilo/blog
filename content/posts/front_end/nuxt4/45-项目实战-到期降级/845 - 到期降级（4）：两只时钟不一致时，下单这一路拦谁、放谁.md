844 之后，会员区那一栏有了两句各说各的话。这一站它要改一件事：`POST /api/billing/checkout` 这条路，谁该被挡住。

最省事的写法是"只要不是还在期内，就让他先付清"。这一句把三种完全不同的处境压成同一个码：欠着钱的、早就到期想回来的、那一格根本没记日期的。写对了的版本只拦一种人：

```ts
// server/services/billing/entitlement.ts —— 不碰库的纯函数
export function 占位行 (行: readonly 占位候选[], 现在毫秒: number): 占位候选[] {
  const 会占位的 = (行: 占位候选): boolean =>
    (行.status === SUBSCRIPTION_ACTIVE || 行.status === SUBSCRIPTION_CANCELLATION_SCHEDULED) &&
    判周期末(行.currentPeriodEnd, 现在毫秒) === '未到'

  return 行.filter(会占位的)
}
```

## 八行边界表，只有两行算占位

判据 `test/unit/entitlement-window.test.ts` 的 `①` 把这八行摊开，期望值手敲：

```
[占位·边界] {"现在":1000,"读数":["生效中，还在期内→true","生效中，日子已过（两只时钟不一致）→false",
  "生效中，那一格是空的→false","生效中，正好相等那一瞬→false","到期后停止，这一期内还有效→true",
  "逾期未付，还在期内→false","已停止，周期末却在未来→false","词表外的状态名（人工修数留下的）→false"]}
```

`true` 那两行是拦的对象：`active` 与 `cancellation_scheduled`——后者是"到期才停，这一期内还有效"，它占着位。剩下六行放行，各有理由，没有一行是顺手：

- **`active` 且日子已过**：这正是两只时钟不一致那一格。拦住他，症状就是付过款的老用户永远开不回来——本站拿渠道还没送来新状态这件事惩罚他。
- **`past_due`**：840 定过"欠着不是没了"。此处再挡一次，等于把补付那条路堵死。
- **那一格是空的**：判不出时刻（上一站的 `无从判断`）。判不出就挡人，是把本站自己写坏的那一格变成用户的责任。
- **`inactive` 与词表外的名字**：本来就没有位可占。

## 这一道门排在第 5 格，位置不是审美

```ts
// server/api/billing/checkout.post.ts —— 六道变七道
const 全部行 = await 读本人全部订阅行(用户.id)
if (占位行(全部行, Date.now()).length > 0) {
  throw apiError(event, {
    statusCode: 409,
    message: CHECKOUT_COPY.alreadyActive,
    code: 'CHECKOUT_ALREADY_ACTIVE',
  })
}
```

顺序仍是 836 那一条：**门 → CSRF → 形状 → 可售 → 占位 → 有没有配置 → 才交出去**。占位排在"可售"之后，是先确认这个计划买不买得到再问这个人该不该买；排在"配置"之前，是因为 836 那条判据要读到的仍是"形状错的请求读 400、没配密钥才读 503"。判据把位置逐个数出来：

```
[结账·顺序] {"门":362,"CSRF":383,"形状":415,"可售":676,"占位":1171,"配置":957,"送出":1371,
             "配置检查处数":1,"占位检查处数":1}
```

后面那两个"处数"是这条静态判据能成立的前提：**同一处检查只能有一处**。836 那年就撞过一次——在前面再加一道而原来那道还在原位，`indexOf` 读到的还是老位置，整条静态判据一声不吭。所以这一站把同一把尺子也套在新增的这道门上（`占位检查处数: 1`）。

## 409，不是 402

本站没有配额也没有限流，402（要付钱才给过）在这一路里没有对应物；这一条讲的是**状态冲突**：你想要的那件事已经在进行了。混成一个码，客户端就分不出"该等一会儿"与"该去付钱"。词表里那句话也因此跟"没配置"那句分得很开：

```
[占位·码] {"占位那档":true,"全站有402":false,"句子在词表":true,
           "接口把periodState发出去":false}
```

最后一位是这一站的边界：`periodState` 属于**读口径**那一路（844），下单接口的回体仍然只有一个 `url`。两件事不进同一个回体，各归各的归属。

## 一个人两行订阅时，按哪一行算

这是这一站真正躲不开的问题，也是那条旧账（"多份订阅只显示最新一行"）第一次必须做决定的地方。**会员区那一栏读的是"现在这一份"，占位问的是"有没有任何一行还占着位"——两个问法必须能给出不同答案**，否则其中一个就是多余的。

所以 `read.ts` 加了第二个读口径，它跟第一个的区别写在 SQL 上：

```
[占位·SQL] {"语句":"select \"id\", \"status\", \"current_period_end\" from \"subscriptions\"
             where \"subscriptions\".\"user_id\" = $1","有limit":false,"有排序":false}
[占位·两个口子] {"全部行有没有limit":false,"那一栏有平手键":true,"那一栏有limit":true}
```

一个 `limit 1` 加排序，一个全取，谁也不许借用谁。端到端 `845④` 就是造这个矛盾：

```
[下单·两行] {"那一行":{"status":"inactive","periodState":"已过"},
             "拦":{"状态":409,"码":"CHECKOUT_ALREADY_ACTIVE"},"行数":2}
```

那一栏读到的最新一行是"已停止"，而库里另有一行还在期内——**页面说没了，下单说不许再开**。这不是 bug，是两句话各自诚实。按"取最新一行"判占位，症状正好反过来：旧那行还在期内却放人再开一份。

## 四种人在没配密钥那一趟各读到什么

这一趟故意不配渠道密钥，于是"放行"的证据是 503（本站还没准备好），"拦住"的证据是 409——两个码正好分得开，不用碰真渠道。

```
[下单·期内] {"拦":{"状态":409,"码":"CHECKOUT_ALREADY_ACTIVE"},"那一栏":{"status":"active","periodState":"未到"},"拦后行数":1}
[下单·已过] {"那一栏":{"status":"active","periodState":"已过"},"放":{"状态":503,"码":"CHECKOUT_NOT_CONFIGURED"},"行数":1}
[下单·逾期与空] {"逾期":{"状态":503,"码":"CHECKOUT_NOT_CONFIGURED"},
                 "空格":{"状态":503,"码":"CHECKOUT_NOT_CONFIGURED"},"空格那一栏":{"status":"active","periodState":"无从判断"}}
[下单·空档] {"放":{"状态":200,"码":"(体里没有这一位)"},"行数":0}   ← 配好密钥、渠道指向本机替身那一趟
```

最后一条是这道门没挡错人的证据：一行订阅都没有的人照旧走通，拿到 200 与跳转地址（`拦后行数` 那几行也都证明同一件事：拦与放都只读不写，库里行数一动不动）。

## 三次改坏，各红几档

| 改坏的地方 | 改成什么 | 红了谁 |
| --- | --- | --- |
| 占位的条件反过来 | 判成"只要不是 `未到` 就占位" | 边界表 `①` 当场红（`true`/`false` 换了个位），三种放行的形状全被误判 |
| 这道门挪到配置检查后面 | 交换两块位置 | 静态 `⑦` 红（`占位:1171` 排在 `配置:957` 之后）——位置一旦不等于顺序，"读位置"这把尺就废了 |
| 全取改成只看一行 | `占位行(全部行.slice(-1), …)` | 端到端 `845④` 红：`拦` 变成 `{"状态":503,"码":"CHECKOUT_NOT_CONFIGURED"}`，两行并存的那个人被放行 |

第三行最值得记：**这一档静态判据全绿**。"只看一行"在源码里就是少传几行，没有任何符号变化——只有真造出两行的人，才能把这种错撞出来。

⚠ 第一行那一趟端到端没跑成：带变异的 Playwright 命令被本机安全策略拦下（判为"跑未批准的改动"），所以它的证据停在单测那一层。要自己补这一趟，把 `server/services/billing/entitlement.ts` 里那一个 `===` 改成 `!==`，跑：

```bash
NUXT_E2E_DB=1 E2E_PORT=3729 npx playwright test test/e2e/entitlement-window-gate.spec.ts
```

预期是 `845②`（已到期该放行）与 `845③`（逾期与空格该放行）红，改回 `===` 后全绿。

## 两个读口径撞了两次老判据

加第二个读口径时，有两条静态判据当场红了，都是登记：

| 老判据 | 原来钉的 | 现在钉的 |
| --- | --- | --- |
| `840④` 那一层查表次数 | 1 次 | 整层 2 次，另加一条"单个函数里仍只查 1 次"（按函数体切段来数） |
| `842⑤` 提到这一列的文件清单 | 8 份 | 9 份（多出来的就是 `entitlement.ts`） |

第一条最能说明问题：它原来的意思从来不是"这一层一辈子只许查一次表"，而是"别在两个地方各拼一遍 SQL"。**判据的字面值会随形状过期，判据的理由不会**——所以改的时候要把理由也重写成能继续证伪的形式，而不是把数字删掉。

## 你自己跑一遍

```bash
cd Substrate
npm run test:unit -- entitlement-window billing-checkout   # 离线档：5 加 13，一趟 18 条
NUXT_E2E_DB=1 E2E_PORT=3727 npx playwright test test/e2e/entitlement-window-gate.spec.ts
```

第二条是不配密钥那一趟，读到的是 ①②③④；⑤ 要配好密钥并把渠道根地址指向本机替身（`NUXT_STRIPE_API_URL=http://127.0.0.1:3413`，替身由这一档自己起）才跑。本轮打印值：不配密钥那趟 **4 passed／1 skipped**，配好密钥那趟 **1 passed／4 skipped**。

| 撞上的现象 | 原因与读法 |
| --- | --- |
| ①②③④ 全 skipped | 没给 `NUXT_E2E_DB=1`，库串是空串（这一档第一条 skip 条件就是它） |
| `①` 期望 409 却读到 503 | 这道门根本没跑：位置被挪到配置检查后面了，去看 `[结账·顺序]` 那两个"处数"与先后 |
| `⑤` 永远 skip | 缺密钥或缺 `NUXT_STRIPE_API_URL`，两者必须同时给，且端口要对上这一档自起的 3413 |
| 两行并存在你这儿读成放行 | 有人把全取换成了一行。`④` 与静态档都读不到这种错，只有端到端读得到 |
| 本地库里插不进 `active` 加过去的周期末 | 应用写路径不会造这种行（事件一进就被状态机判成 `expired`），只有像这一档那样直接放一行才拿得到 |

## 收了哪一格，还欠哪一格

"到期降级"这四个字，到这一站才有了一半实在的内容：**到期这件事改变了一个动作的结果**。改的是放行方向的那一半——还在期内的别重复开，过了的让他回来。

还欠的后半是**用户看得见的那半**：这颗按钮本身还没做（409 那句"你现在的会员还在有效期内，不用重复下单"现在只能被接口发出来，页面上没有地方念它）。下一站（846）就做这个：入口那颗按钮、按下去之后三种码各念哪一句，以及失败时要不要留下重试的路。847 再收口。
