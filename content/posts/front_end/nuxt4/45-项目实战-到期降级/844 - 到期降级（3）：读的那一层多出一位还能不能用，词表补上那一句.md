上一站结束时，`判周期末` 那一份规则躺在 `shared/utils/period-expiry.ts` 里，除了状态机没人调用它。这一站把它接进读的那一层——改动一共四处：`read.ts` 多派生一位、接口多发一位、`shared/copy/subscription.ts` 多开一份词表、页面多一栏字。

## 读的那一路第一次读钟，只读一次

```ts
// server/services/billing/read.ts
const 现在 = Date.now()
const 周期末毫秒 = 这一行.currentPeriodEnd ? 这一行.currentPeriodEnd.getTime() : null

return {
  status: 这一行.status,
  currentPeriodEnd: 周期末毫秒,
  updatedAt: 这一行.updatedAt.getTime(),
  periodState: 判周期末(周期末毫秒, 现在),
}
```

`时钟: 1` 而不是 `2` 是有理由的：如果选行与判定各读一次钟，一趟请求里跨过一次周期末边界，那一栏就会出现"这一行是新的，但判定用的是前一秒的时刻"。判据 `842①` 钉的就是这一位：

```
[到期·读的一路] {"读的那层":{"时钟":1,"周期末":6,"过期比较":0,"走规则层":1},
                 "接口":{"时钟":0,"周期末":0,"过期比较":0,"走规则层":0},
                 "页面":{"时钟":0,"周期末":1,"过期比较":0,"走规则层":0}}
```

`过期比较` 全是 0、`走规则层` 是 1：读的那一层**没有自己写比较符号**，它只把两个数交给那一份规则。接口那一头 `周期末: 0`——它仍然只把对象原样递出去，不碰内容。

## 接口多出来的那一位，与它没做的事

端到端 `844①` 造了一行 `status='active'`、周期末在一小时前的订阅，读回来：

```jsonc
[判定栏·已过] {
  "库里": { "status": "active", "已过": true },
  "接口": { "status": "active", "currentPeriodEnd": 1792477052989,
            "updatedAt": 1792480652989, "periodState": "已过" },
  "页":   { "是会员区": true, "状态词": "active", "渠道那句": "生效中",
            "本站那句": "这一期已经过了", "到期日": "2026-10-20（按 UTC 记）" }
}
```

注意接口里**两件没发生的事**：`status` 没被改掉（渠道说 `active` 就发 `active`），也没有多发明一个"会员已过期"的状态名。新增的只有一位 `periodState`，值就是 843 那份规则给的三个词之一。**接口仍然不发句子**——760 与 840 立的那条口径没动：机器位给程序，句子由念词表的地方说。

## 词表开了第二份，而不是往五格里加第六行

`shared/copy/subscription.ts` 里现在躺着两份表：

```ts
export const 周期判定文案: Record<周期判定, string> = {
  已过: '这一期已经过了',
  未到: '这一期还在期内',
  无从判断: '这一期没记到结束日子',
}

export function 周期判定给人看 (值: unknown): string {
  return (周期判定文案 as Record<string, string>)[String(值 ?? '')] ?? '这一栏读不出来，请稍后再看'
}
```

判据 `⑥` 量出来这两份表没有一行撞名（`两份词表同名: false`），三句话也互不相同：

```
[订阅栏·判定词表] {"三格":["已过=这一期已经过了","未到=这一期还在期内","无从判断=这一期没记到结束日子"],
  "各输入":{"陌生词":"这一栏读不出来，请稍后再看","空":"这一栏读不出来，请稍后再看",
            "没给":"这一栏读不出来，请稍后再看","数字":"这一栏读不出来，请稍后再看"},
  "入参位数":1,"两份词表同名":false,"句子有重复":false}
```

为什么不写成第六个状态名？因为那个值**在库里根本不存在**——`status` 列里躺的是渠道给的词，`periodState` 是本站算出来的。塞进一张表之后，症状有三层：扫源码找不到"库里的这个状态是谁写的"；`Record<SubscriptionStatus,string>` 那条类型护栏（少一格 typecheck 当场报错）被绕开；最要紧的是页面只剩下一个位置念一句话，**两件事被迫折成一句**。

页面因此多了第四栏：

```vue
<p v-if="consoleSubscription?.subscription" data-testid="subscription-period-state">
  {{ 周期判定给人看(consoleSubscription.subscription.periodState) }}
</p>
```

两栏并排，一句归渠道、一句归本站。不一致的时候（就是这一档造的形状）屏幕上同时出现"生效中"和"这一期已经过了"——**看着像 bug，其实这正是"到期"第一次变得可见**。

## 三种格子各自的形状

`844②③④` 把另外两种形状也量了：

| 库里那一行 | `status` | `periodState` | 渠道那句 | 本站那句 |
| --- | --- | --- | --- | --- |
| `active`，周期末已过 | `active` | `已过` | 生效中 | 这一期已经过了 |
| `active`，周期末还有三天 | `active` | `未到` | 生效中 | 这一期还在期内 |
| `inactive`，周期末是 `null` | `inactive` | `无从判断` | 已停止 | 这一期没记到结束日子 |
| 一行都没有 | — | 体里没有这一位 | 还没有开通这个会员 | **这一栏不出现** |

最后一行是判据里最要紧的一条断言：`expect(接口体).toEqual({ subscription: null })` 且 `有判定栏: false`。**没有一行时不许出现"这一期……"那句**——那等于替一个不存在的事实下结论，和 840 那条"空档不许兜成 `none`"是同一条线。第三行则验证"没记到结束日子"与"还没有开通"仍是两句话：前者有一行、后者一行都没有。

## 三条哨兵随形状登记，还有一条没红

842 埋过三条"一改就红"的哨兵，这一站就是要用它们当登记簿：

| 哨兵 | 原来钉的 | 这一站改成 | 状态 |
| --- | --- | --- | --- |
| 端到端 `842⑦` 键集合 | 接口体三位 | 四位（多 `periodState`） | 红过，已登记 |
| 单测 `840⑤` 标识名单 | 那一栏三位 | 四位（多 `subscription-period-state`） | 红过，已登记 |
| 单测 `842④` 函数入参位数 | `length===1` | 不改 | **没红** |

第三条值得说：交接时预计它会红，因为"词表要开始吃到期与否"。真做的时候选的是开第二份词表，两个老函数的入参位数一个都没变，所以它还绿着。**这条预测落空本身要写下来**——如果哪天有人图省事把 `订阅状态给人看(状态, 判定)` 改成两个入参，这条哨兵会立刻红，而那时候该问的是"为什么要合并"。

## 三次改坏，各红几档

| 改坏的地方 | 改成什么 | 红了谁 |
| --- | --- | --- |
| `read.ts` 的判定入参 | `判周期末(周期末毫秒, Date.now())`（时钟读两次） | 2 条：`842①`（`时钟: 2`）与 `842⑤`（周期末与 `Date.now()` 写进了同一行） |
| `read.ts` 的派生位 | 硬编码成 `'未到'` | 2 条端到端：`844①`（已过被判成未到）与 `844③`（没有时刻也被判成未到） |
| 页面第四栏 | 让它念 `订阅状态给人看(status)`（两句合一） | 3 条端到端：`844①②③` |

第一行有个意外收获。842 那一站记下一条教训："`⑤` 看不见'上一行取钟、下一行才比'的写法"。这一站把 `Date.now()` 写进判定那一行时，`⑤` **报了**——它不是没用，它管的就是"两件事被写在同一行"这一种形状，而那种形状恰恰是"又长出一份判定"的常见起点。两条判据各管一段，缺一条就有一段漏网，这条分工到这里被量完整了。

第二行红了的是端到端而不是单测——因为"乐观默认"这种错，只有让真数据穿过整条读口子才会露出来：库里明明是空的，接口却发一个"还在期内"。

## 你自己跑一遍

```bash
cd Substrate
npm run test:unit -- console-subscription       # 六档，含新开的判定词表
NUXT_E2E_DB=1 E2E_PORT=3719 npm run test:e2e -- test/e2e/period-expiry-column.spec.ts
```

第二条四档全跑，这一档不需要签名密钥（探针直接放行，不走渠道事件那条写口子）。全量不带库那一趟现在是 **257 passed／121 skipped**，归族 **要库 54／要外部服务变量 42／要内容目录读得到 14／要另一趟构建的开关 11**。

| 撞上的现象 | 原因与读法 |
| --- | --- |
| `本站那句` 读到 `(读不到)` | 那一行 `v-if` 挂在"读到一行"上：库里没行时这一栏本来就不该出现（`844④` 判的就是这个） |
| `844③` 报"没有时刻却被判成一个具体结论" | `read.ts` 没走 `判周期末`，或者 843 那份三态被改成两态了 |
| 键集合那条（`842⑦`）红成五位 | 有人又往接口体加了一位。**先问这一位归谁**：归渠道的应该走 `status`，归本站的才是 `periodState` |
| 两栏念出同一句话 | `⑥` 里那句 `两份词表同名: false` 与端到端的 `not.toBe` 一起挡的事；多半是词表被合并了 |
| 带库全量某档红、日志是 `ECONNREFUSED` | 远端连接额度。原样重跑，取失败最少那一趟，把趟次写清 |

## 这一站收了哪一格，还欠哪一格

到这一步，"到期"终于有了可观察面：库里写着生效中、日子已经过了——这种情况接口发得出来、页面也说得出口。上一线与跨线挂着的那条"`与渠道不一致` 没有可观察面"，从这里开始可以落地——不一致的两个输入（`status` 与 `periodState`）已经在同一个回体里了。

还欠的：这一位目前只是**被看见**，还没有任何东西因它改变行为。下一站（845）问的就是这个——两只时钟各说各的时，本站那一路的动作该不该跟着变；再下一站（846）才动那颗按钮后面的门。

本文还有一条没修的旧账：`infinity` 那一格（843 量到的）走到这里仍然是"没有到期记录"＋"这一期没记到结束日子"，两句都算诚实，但它们说的其实是同一件坏事——要不要给脏数据单独一句，等 847 收口时一起判。

## 本文依据

- `docs/4.x/guide/directory-structure/shared`——`shared/` 是应用侧与服务端两侧共用的唯一位置；词表放这里，页面才能与服务端排查日志对上同一句话。
- `docs/4.x/api/composables/use-async-data`——服务端派生的那一位怎么进负载、浏览器接手时不再算一遍；这正是 840 那条"按 UTC 出字"要避免水合不匹配的同一类问题。
