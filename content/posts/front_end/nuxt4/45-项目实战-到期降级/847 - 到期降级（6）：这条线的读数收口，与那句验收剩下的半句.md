这条线走到第六站，屏幕上不会多任何东西：会员区那一栏、那颗"开通这个会员"的按钮、失败时那一句，都是上一站立起来的。这一站要回答的是另一个问题："到期降级"这件事，做完了吗？

要回答它，先得找到"它"到底是哪句话。"到期降级"这四个字在需求文档里出现了四处，写法不一样，要做的东西也不一样。

## 四处写法，逐句判

| 出现在哪 | 那句话怎么写的 | 判下来 |
| --- | --- | --- |
| 验收硬指标那一句 | "到期降级任务可手工触发并有日志" | **未闭合**。没有任务，也就没有"手工触发"这回事 |
| 管理后台那一节 | "每日到期降级任务" | **未闭合**。没有定时触发的任何东西 |
| 详细设计那一段 | `server/tasks/subscriptions.downgrade.ts`（cron 每日 03:10）把过期未续的人 role 降回 `free`、写 `audit_logs`、发一封到期提醒邮件，可用 `nuxt task` 手工触发 | **一句话都没落地**，缺件逐条见下 |
| 范围表那一格 | "Checkout、webhook 幂等与状态机、发票页、到期降级" | **接了"到期"这一位，没接"降级"这个动作**（发票页仍未做） |

第三行是本篇真正要说的一处。它列了五件具体的事，这一站把它们逐个问到源码上：

```
`server/tasks` 目录            不存在（`ls` 报 No such file or directory）
`defineTask` 出现次数          0（app／server／shared／nuxt.config.ts 全问一遍）
nuxt.config.ts 里的 tasks 节    没有这一节
`cron` 出现次数                0
`server` 里有没有 UPDATE users 0 处（`role` 只在两个查询里被读出来，从来没人写它）
`server/services/billing` 里引用发信模块 0 处（发信那一个口子只服务登录链接）
```

`db/tables/users.ts` 里那一列是真有的：`userRole = pgEnum('user_role', ['free','member','admin'])`，`role` 默认 `free`。列在、默认值在、写它的那一条语句不在。所以"降回 `free`"不是一个还没调好的功能，是一个还没开始的功能。

⚠ 这一段是本篇最想让你记住的东西：**需求文档里那句"到期降级"，字面上是"把人的身份降一级"，而这条线做的全是"把到期这件事判出来、读出来、让它在下单那一路起作用"**。两件都有价值，但不能因为标题撞了就算同一件事已交付。

补一件给下一站省事的事：官方那一节写得很明白，Nitro 只在任务开关打开之后才扫 `tasks` 目录——

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  nitro: {
    experimental: {
      tasks: true,
    },
  },
})
```

本站这一节都没有（上面第二行确证读到的 0 就包括它）。所以真要建那个目录时，`nuxt task list` 读到空的第一件事是回头看这个开关，而不是怀疑目录名写错了。

## 这条线实际接的是哪半句

六站各留一句，每句后面都能指到判据：

| 站 | 这一句是结论，不是标题 | 自己复现要用哪条命令 |
| --- | --- | --- |
| 842 | 那一列日期谁都没拿它跟"现在"比：读的那一路时钟 0 次，全站唯一的比较比的是**事件那一刻** | `npm run test:unit -- period-expiry-baseline` |
| 843 | 判定收成一份纯函数，必须三态：那一格写成 `'infinity'` 会一路变成"没有到期记录" | `npm run test:unit -- period-expiry-rule` |
| 844 | 读的那一层派生出一位，词表开第二份：渠道那句与本站那句**并排不一致就是设计目标** | `NUXT_E2E_DB=1 E2E_PORT=3750 npx playwright test test/e2e/period-expiry-column.spec.ts` |
| 845 | 到期第一次改动作：还在期内的人再下单回 **409**（不是 402），已过／逾期／那一格空的三种人放行 | `NUXT_E2E_DB=1 E2E_PORT=3750 npx playwright test test/e2e/entitlement-window-gate.spec.ts` |
| 846 | 分支只看 `data.code`；409 不给重试；`disabled` 一挂上焦点会掉回页面根，要人把他放回去 | `NUXT_E2E_DB=1 E2E_PORT=3750 npx playwright test test/e2e/checkout-button.spec.ts` |
| 847 | 上面那四处写法逐句判完，第三处一个字都没做 | 本篇全部命令 |

表里 842 与 843 那两条离线就能跑（它们各自另有一条端到端档要连库），844—846 那三条都要库。这条线**净新增判据 40 条**（现数得来：单测 23 条、端到端 17 条），另外改了四份老判据的形状（`console-subscription`、`billing-checkout`、`identity-surface`、`period-expiry-baseline` 自己的哨兵）。

## 判据今天跑成什么样

同一批判据在三种环境开关下是三张脸，收口必须分开报，不能合成一个"全绿"：

```
离线档（`npm run check` 八项 ok）              单测 363 条／56 文件；组件层 67 条／16 文件
不带库全量（3746 第 1 趟）                     254 passed／1 failed／2 未跑／131 skipped
不带库全量（3748 第 2 趟）                     257 passed／131 skipped／0 failed
带库全量（3747，命令里给了签名密钥）             342 passed／46 skipped／0 failed
```

- 3746 那一趟的红不在本线里：`landing.spec.ts:179` 那条声明式预取判据（`Received: 0`），844 那站它就红过一次；重跑（3748）257 条全过。同一趟还有 2 条"没跑"，那是 Playwright 在同一份工作里撞到失败之后停下的。
- 带库那一趟里本线 17 条端到端全过，用时 3.8—8.8 秒，唯一没跑的是 845⑤（要配好密钥并把渠道根地址指向本机替身）。
- **把这五份文件单独并跑不算验收**：846 那站连跑三趟（默认并发与 `--workers=1` 都试过），每趟都有一档卡满 30 秒，而且每趟换一档（`846⑤`→`845②`→`844③`），卡的都在打印完自己的读数之后。同一批判据在全量那一趟里 5 秒上下就过了。⇒ 小范围并跑只当冒烟，收口看全量。

## 一条会让"全绿"变成假话的环境事实

带库那一趟必须在命令里显式给出签名密钥那一个变量。这条是 846 撞出来的，它比看上去严重：

```
第 1 趟（没给签名密钥）  316 passed／72 skipped／0 failed
第 2 趟（给了）          342 passed／46 skipped／0 failed
```

两次用例总数一模一样、一条都没红，差的 26 档是静默消失的（`console-subscription-column` 那七档连同 webhook 两批，它们的 skip 条件是"库串与签名密钥都要有"，而第一条命中的条件把它们归进了"要外部服务变量"那一族）。所以任何"带库跑过了"这句话，都要跟一句"哪个变量给了"。归族数在这里能当报警器用：46 变 72，就是缺件。

## 库里此刻的样子，和它证明不了的事

这一档（842 立的）是全表聚合，本轮带库那一趟读到：

```
[到期·库内] {"行":2,"没有周期末":1,"还没到":1,"已经过了":0,"写着生效中却已过":0,"其余状态":0,
             "没有周期末的行":["sub_834_d1792461474798"]}
```

三个相加等于总行数，这一条自证不受并发影响。但它证明不了"本线没留残留"：`还没到:1` 那一行是谁的，这份读数答不了——并发跑着的时候，别的探针的行也会被数进来（这张表已经被全表计数骗过三次了）。明细列只筛了"没有周期末"那一种，于是第十八线留下的那一行 `sub_834_…` 看得见，本线六个前缀有没有留下东西，**没有任何一档按前缀数过**。这条进未闭合池。

## 未闭合池，摊开重数

从五份工程记录里把条目抄出来去重，再按今天的源码状态判一次（**计数自己数，不传话**）：

| 状态 | 条 | 数 |
| --- | --- | --- |
| 本线合上 | 到期无人判（判定那份）、规则没有第二个消费者、没有动作面、没有那颗按钮、空档那格不许混用（844④ 已证） | 5 |
| 仍未闭合 | "降级"这个动作本身（任务／cron／`UPDATE users`／审计／提醒邮件／`nuxt task`）、`null` 的行永远跳过状态机那一步、渠道对周期末那一秒无承诺、`infinity` 与空档在屏幕上同形、多份订阅怎么摊给用户看、真投递三问与占位价格、焦点归还缺读屏级验证、残留没按前缀数过、时区那半句、没有配额与限流、`processed_at` 空标记位无补处理、并发"新建"仍撞主键、`846②` 只在没配密钥那站成立 | 13 |
| 环境纪律（不是功能，但会让读数说谎） | 带库全量要给签名密钥并逐档具名、允许重跑取失败最少那趟、小范围并跑只当冒烟、CI 不跑带库、带库全量依赖远端连接额度 | 5 |

还欠的那半句因此有了名字：**"到期降级"里，"到期"这条线做完了，"降级"没有。** 下一段要做的不是补一句文案，而是那一整个还没存在的东西：任务、它的触发方式、它写完之后的可观察面。

## 你自己跑一遍

```bash
cd Substrate
npm run check                                     # 八项；离线可跑
E2E_PORT=3750 npx playwright test                  # 不带库全量
NUXT_E2E_DB=1 NUXT_STRIPE_WEBHOOK_SECRET=whsec_本地专用 E2E_PORT=3751 npx playwright test
```

| 撞上的现象 | 原因与读法 |
| --- | --- |
| 带库全量的 skip 比上一轮多一截，红数一条没变 | 命令里少了签名密钥那一个变量；先比归族数再比红数 |
| 单独并跑这条线那五份文件，每趟都有一档卡 30 秒 | 这是并跑形态本身，不是那条判据坏了；去全量那一趟读它 |
| 想看"到期降级任务"的代码却找不到目录 | 它确实不存在。上面那六条确证里第一条就是 `server/tasks` 报 No such file；但要建的时候先看那个开关 |
| 全表聚合读到"还没到 1 行"，以为漏了残留 | 数的是整张表，包含别的探针；残留要按编号前缀问，而今天还没有那一档 |

## 本文依据

- `docs/4.x/api/commands/task`——`nuxt task list` 与 `nuxt task run <名字> --payload`；那一句提示是原话：**只有开了任务开关，Nitro 才扫你的 `tasks` 目录**（开关写在 `nuxt.config.ts` 的 `nitro.experimental.tasks`）。本站开关与目录都没有，所以"手工触发"这一条没有承载物。
- `docs/4.x/directory-structure/server`——这一节列的是 `server/` 下哪些目录会被自动扫描、`utils` 与 `services` 属本地约定。它没有把任务目录列为本站已有的一项——本站也确实没有。缺一个目录不会报任何东西，这是这一族问题最难发现的原因。
- `docs/4.x/guide/concepts/error-handling`——这条线全程共用的那一份错误形状（`data.code` 给程序分支）由前面几站立好；本篇只是把它的消费者逐个点名，没有新增一个码。
