## 先在屏幕上找到那一块

浏览器打开 `http://localhost:3100/docs/getting-started`，按 Ctrl+U 看源代码。搜索"你需要知道的三件事"——**它就在 HTML 里**，是服务端拼好发过来的，不是你机器上算出来的。

这一页在仓库里是 `app/pages/docs/[slug].vue`，那一段正文落在第 106 行附近的一个空标签上：

```vue
<div
  class="doc-body"
  data-testid="doc-body"
  v-html="doc.html"
/>
```

`doc.html` 是服务端把 markdown 渲好之后交下来的 HTML 字符串。**这一段内容不会变**：没有按钮、没有输入框、点它没有任何反应。它就是官方讲服务端组件那一节点名的那一类——那句原话是「For content-heavy components (markdown rendering, syntax highlighting, CMS output) that never change on the client, this is wasted work」。

"白在哪"要说得更准：**水合**（浏览器接手服务端给的那段 HTML、把事件挂上去）跑完之后，这段 DOM 一个字都不会变。为它下载、解析、执行的那份代码，唯一的工作就是重现一份已经在页面上的 HTML。

## 三行数字，差的是一千二百倍

`test/e2e/island-baseline.spec.ts` 是这一站新加的判据，**应用代码一行没动**。四条读数（生产构建 ＋ 真浏览器，工具原样打印）：

```text
[切片基线·正文] {"status":200,"正文字节":255,"响应字节":4138,"负载字节":1032,"DOM出现次数":1,"负载里也带着这一份":false,"正文开头":"<p>这一篇讲第一次进来看见什么。</p>\n<h2>你需要知道的三件事</h2>"}
[切片基线·下载] {"脚本条数":13,"原始字节合计":308412,"正文字节":255,"倍数":1209,"最大的三条":[{"地址":"/_nuxt/BvhoSpNT.js","字节":78654},{"地址":"/_nuxt/C-43eD1u.js","字节":77486},{"地址":"/_nuxt/B90kFGnj.js","字节":69304}]}
[切片基线·水合] {"服务端字节":255,"水合后字节":255,"一字不差":true}
[切片基线·渲染器] {"服务端文件数":519,"服务端命中文件":["_/index2.mjs"],"客户端chunk数":18,"客户端命中数":0}
```

读法：**那段正文 255 字节**，整页响应 4,138 字节；浏览器为了这一页实际下载了 **13 个脚本、308,412 字节原始体积**（chunk＝打包后拆出来的小文件）。308,412 与 255，一千二百倍。而水合跑完，那段 255 字节**一字不差**。

那个"倍数"不是拿来比较的性能分，是这一站的**结构性判据**：`expect(合计).toBeGreaterThan(正文字节 * 10)`。留了两位数量级的余量——它不会因为一次构建抖一下就红，但只要哪天"为一段静态文字发一整个应用"这件事变得不明显了，它先响。

## 有一个容易以为成立的前提，量出来不成立

写第一版判据时，假设是"这段正文在一次响应里被发了两遍：DOM 里一遍，内联负载（服务端顺手塞进 HTML 的那份数据，浏览器接手时从它拿初始值）里再一遍"。断言写成 `出现次数 >= 2`。

跑出来是 `DOM出现次数:1`、`负载里也带着这一份:false`。两处原因叠在一起：

- 负载里那份不是原样的字符串。JSON 序列化会把换行写成 `\n`、把引号转义，直接拿 DOM 里那段去数是数不到的。改成先 `JSON.stringify` 再匹配，仍然没有。
- 因为这一页的取数负载根本不在 HTML 里。`experimental.payloadExtraction` 本站没设，默认 `true`＝把负载提取成独立的 `_payload.json` 文件。而 `payload.spec.ts` 那条判据已经量过：`/docs` 既没预渲染也没进缓存，产物里没有那份文件——所以浏览器接手时只能再去打一次接口。

**所以白给的不是重复字节，是下载、解析、执行和一次没有产出的水合。**这句话决定了这条线要切的到底是什么。

## 把脚本关掉，这一页还剩什么

同一份判据里另开一个不带脚本的浏览器上下文：

```text
[切片基线·关脚本] {"标题":"第一次登录要准备什么","正文文本字符数":72,"正文头两行":"这一篇讲第一次进来看见什么。 / ","回列表链接在":true}
```

标题、那 72 个字的正文、"回到列表"那条链接，全都在。这一页本来就是服务端渲的，**关掉脚本不损失内容**——这正是后面几步敢把它切成服务端组件的底气：切坏内容的风险很低，省下来的才是那 308 KB 的一部分。

阈值写在这里要留一句：正文文本判的是 `> 40` 字。本站内容文件只有 305 字节（`content/docs/getting-started.md`），第一版顺手写了 `> 200`，直接红——**基线阈值必须由本轮打印值决定，不能凭"一篇文档应该有多长"的印象**。

## 渲染器今天在哪一侧

有人会说：那这段 HTML 是 markdown 渲出来的，渲染器不就是重依赖、它不也在浏览器包里？量一次就知道在不在：拿渲染器里一段独有的字符串，去两边各搜一遍。

```text
[切片基线·渲染器] {"服务端文件数":519,"服务端命中文件":["_/index2.mjs"],"客户端chunk数":18,"客户端命中数":0}
```

服务端产物 519 个文件里命中 1 个，客户端 18 个 chunk 里命中 0 个。**渲染器已经留在服务端了**——这条线要拿走的是另一件东西：那 13 个脚本里，为这一页服务的组件代码。

这一条判据里那句"服务端也要命中"不是顺手写的。第一版只扫了 `.output/server/index.mjs` 一个文件，读到"服务端也没有"，差点写成"渲染器根本不在产物里"。实际业务代码在 `.output/server/chunks/` 那棵子树下面，入口文件不含它。**搜出 0 命中的时候，先证明你的扫描能找到东西。**

## 这份基线注定会红

`island-baseline.spec.ts` 是基线判据，跟会员区那条 `console-baseline.spec.ts` 一样：它的价值就是**在改动之后变红**。这条线后面几步会把正文那块换成服务端组件，届时：

- 下载字节数会掉，`倍数` 那条大概率先红——红了就更新阈值，**同时把引入之前那五组读数留在 `.series/R72-795.md`**，不改历史；
- `一字不差` 那条应该继续为真：切片改的是"谁负责把 HTML 放上来"，不是内容；
- `DOM出现次数:1` 也会继续为真；如果哪天它变成 2，说明负载形状又变了，那是另一件事。

## 排错表

| 想查的东西 | 现成的读数字段 | 它为什么在那儿 |
| --- | --- | --- |
| 那段正文是不是服务端给的 | `正文开头`、`DOM出现次数` | 客户端拼的 HTML 不会出现在响应里 |
| 为这一页下了多少代码 | `脚本条数`、`原始字节合计` | 只数 resourceType 为 script 的响应 |
| 水合到底改没改这段 | `服务端字节` 对 `水合后字节` | 一模一样就说明这份代码没产出 |
| 负载里有没有再抄一份 | `负载里也带着这一份` | 比较前要先把字符串按 JSON 转义 |
| 关掉脚本还剩什么 | 关脚本那一档 | 内容全在＝切片风险低 |
| 重依赖在哪一侧 | `渲染器` 那一档两边命中数 | 0 命中要先有能命中的对照 |

## 自己动手跑一遍

```bash
npm run build
E2E_PORT=3270 npm run test:e2e -- test/e2e/island-baseline.spec.ts
```

预期 `5 passed`，四组读数与上面一致（chunk 名和字节数会随构建变，`倍数` 那一档掉不到 10 以下）。想看关脚本那一档，用浏览器菜单里"禁用 JavaScript"再刷新一次同一页，Ctrl+U 里那段正文仍然在——这就是这一站的全部底气所在。
