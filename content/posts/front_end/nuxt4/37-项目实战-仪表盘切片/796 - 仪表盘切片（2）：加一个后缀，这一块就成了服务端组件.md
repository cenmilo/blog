## 屏幕上多出来的那一截

浏览器打开 `http://localhost:3100/docs/getting-started`，按 Ctrl+U，搜 `doc-body`。上一站那个空标签现在长这样：

```text
<div class="doc-body" data-testid="doc-body" data-island-uid="8107ea83-166e-47c1-b32f-1912607d44e8">
```

`data-island-uid` 是这一站的唯一屏幕证据：这一位现在是**岛屿**（island，服务端单独渲好、把 HTML 嵌进页面的组件）。改动只碰两个文件——新增 `app/components/DocBody.server.vue`，页面模板里那句 `v-html` 换成一行：

```vue
<DocBody :slug="slug" />
```

## 后缀就是开关，配置一行没加

官方讲服务端组件那一节的写法是一句「Add the `.server` suffix to a component to make it a standalone server component」，用法和普通组件没区别。

`nuxt.config.ts` 里要配 `experimental.componentIslands` 吗？**不用**。本站那一份配置只在环境变量 `NUXT_PAYLOAD_MODE` 存在时才写 `experimental`，里面只有 `payloadExtraction` 这一项，`componentIslands` 从没出现过。依据是同一节的「The default value is `'auto'`, which enables the feature automatically as soon as your app contains a server component or island, so in most cases you do not need any configuration」。

要显式配置的只有一件：想让岛屿里某个组件在浏览器上接手（`nuxt-client`），得开 `selectiveClient: true` 或 `'deep'`。这一站不碰它。

## props 传整段正文，判据当场红

第一版按最直觉的方式写：正文已经在页面手里，传进去不就完了。

```vue
<DocBody :slug="slug" :html="doc.html" />
```

端到端跑出来的地址：

```text
[岛屿·点进来] {"方法":"GET","地址长度":877,"查询串长度":785,"查询串里带着整段正文":true,"地址前缀":"http://localhost:3282/__nuxt_island/DocBody_vQySYFGkcSdVtMlyTUaXOxpNzz1iI7CfwTuo8HkOgI.json","页面的取数请求":["/api/docs/getting-started"]}
```

判据里那句 `expect(带着正文).toBe(false)` 红在 `Received: true`。依据是 props 那一段的三句原话：「Props are serialized and sent as GET query parameters」、「props are limited by URL length, so avoid passing large amounts of data」、「props may be visible in server access logs, CDN caches and `Referer` headers」。785 个字符的查询串里躺着一整篇正文——它会进服务端访问日志、进 CDN 的缓存键、可能还进 `Referer`。

换成只传 `slug`，同一个位置读回来：地址长度 135、查询串长度 44、`查询串里带着整段正文: false`。**"props 走查询串"这条不是一句提示，是一个能红的断言**——把它写成判据之后，任何人以后想传大对象进去都会立刻被拦下来。

## 岛屿里不能直接引那个渲染函数

props 只给 `slug`，正文就得在岛屿内部自己取。最省事的是引现成的服务 `server/services/content`——构建直接断在这里：

```text
Could not resolve "../../../../../shared/schemas/content.ts" from ".nuxt/dist/server/_nuxt/DocBody.server-*.js"
```

断点的位置就是原因：服务端组件会被单独打成一个 server chunk，构建输出里能看到它自己那一位（`.output/server/chunks/build/DocBody.server-BGSevoTq.mjs (2.1 kB)`）。这条 import 链上任何指向 `shared/` 的解析都在这一步断掉——`server/services/content` 自己就引了 `#shared/schemas/content`，所以引服务和直接引 `#shared/...` 撞的是同一堵墙。相对路径引 `server/services/**` 那一趟也过不去，同样因为下游那位拖着 `shared/`。

换成走接口，解析就回到正常的 nitro 构建里：

```ts
const props = defineProps<{ slug: string }>()
const page = await $fetch<DocPage>(`/api/docs/${props.slug}`).catch(() => null)
```

`catch(() => null)` 而不是往外抛：抛出去整个岛屿算失败，而 `.server.vue` 是自动包装出来的岛屿，拿不到 `<NuxtIsland>` 那个 `#fallback` slot——官方限制清单里那句「Server components rendered via the auto-generated wrapper do not expose load and error events; use `<NuxtIsland>` directly if you need its `error` event」说的就是这件事。形状不对、文件不在、是草稿，接口一律回 404，这里渲一个空 `div`。

## 内容一字没变，代码多了 13,416 字节

三份判据本轮一起跑（`12 passed (28.9s)`）：

| 读数 | 引入之前 | 这一步之后 |
| --- | --- | --- |
| 那段正文的字节 | 255 | 255 |
| 水合后是否一字不差 | true | true |
| 首屏响应里的岛屿请求 | 0 | 0 |
| 关掉脚本后正文还剩 | 72 字 | 72 字 |
| 整页响应字节 | 4,138 | 4,610 |

| 下载原始字节合计 | 308,412 | 321,828 |
| 客户端 chunk 数 | 18 | 20 |

**这一刀换回来的不是省，是净增 13,416 字节。** 前四行没动，说明切的是"谁把这段 HTML 放上来"，不是内容；后四行全线上涨。

为什么省不下来？官方那句说的是「none of its JavaScript is sent to the client. Its dependencies (a markdown parser, a highlighting library) stay on the server too」——省下来的是**这一块自己带的依赖**。而这一段正文没有自己的依赖：markdown 在服务端早就渲完了（上一站量过渲染器在客户端 0 命中），页面里那段只是把一个字符串贴进 `v-html`。切完之后新增的是岛屿这套包装：客户端要多了能挂岛屿的那位，`__nuxt_island` 那一次往返也得有代码来发。官方限制清单里对应的是那句「Using islands can significantly increase the number of chunks generated at build time」。

所以这句话要换个说法带走：**"服务端组件省 JavaScript"只在一种形状下成立——那块自己拖着渲染器、高亮库、CMS 输出的取数与加工。** 只贴一个字符串的时候切它，是往里加代码。上一站那条结构性判据（下载合计 大于 正文字节乘以 10）没红；红的是"切片之后字节该掉"这个期待，它现在被写进了排错表。

## 单根元素那条规矩，构建不拦

同一节的 warning 原话：「Server components (and islands) must have a single root element. (HTML comments are considered elements as well.)」

临时在模板里加了第二个根：

```vue
<div class="doc-body" data-testid="doc-body" v-html="page ? page.html : ''" />
<p>临时变异：第二个根元素（官方那条"单根元素"的 warning 说的就是这一位）</p>
```

`npm run build` 仍然 exit 0，整段输出里没有一句跟 root 有关的提示——**这条约束不在构建阶段兜底**。红的是页面上那条判据：

```text
[岛屿·首屏] {"正文头两行":"这一篇讲第一次进来看见什么。 / ","正文字符数":72,"响应里正文在":true,"岛屿请求数":0,"那一位的下一位":"P:临时变异：第二个根元素（"}
```

原本那一位读 `P:回到列表`：正文块后面应当直接跟页面自己的"回到列表"那一段。多出来的根会插到中间去，所以判据钉的是兄弟节点，而不是"构建有没有报错"。注释也算元素这句同样成立——最外层多一行 HTML 注释，根就变成两个。

## 从列表页点进来，多一次往返

`[岛屿·点进来]` 里 `页面的取数请求` 只有一条 `/api/docs/getting-started`，加上岛屿那一次 `__nuxt_island`，站内点进来是两趟。依据：「On the initial server-rendered page load, islands are rendered inline and there is no extra request. On client-side navigation, however, each island on the destination page must be fetched from the server」，以及「islands block on a network round trip during navigation, unless you pass the `lazy` prop (with a `#fallback` slot) to render them non-blockingly」。

首屏那一趟确实没有额外请求（`岛屿请求数: 0`），这一站的两个档位刚好把这两句话分开钉住了。`lazy` 与那份回退文本留给下一站。

## 排错表

| 撞上的现象 | 先查这里 | 依据 |
| --- | --- | --- |
| 岛屿地址长到几百字符 | 页面传进来的 props 大小 | props 当 GET 查询串发出去 |
| 正文在页面上是空的 | 岛屿里那次取数成没成 | 抛错会让整个岛屿失败，而自动包装拿不到 `#fallback` |
| 构建报 `Could not resolve ... shared/...` | 岛屿的 import 链 | 服务端组件单独成 chunk，那条链在这一步断 |
| 正文后面多出别的东西 | `那一位的下一位` | 单根元素不在构建阶段拦 |
| 切片之后 JS 反而涨了 | 那块自己带不带依赖 | 省的是它自己的依赖，没有就只剩包装 |
| 站内点进来慢了一拍 | `__nuxt_island` 那一次请求 | 客户端导航每个岛屿多一次往返 |

## 自己动手跑一遍

```bash
npm run build
E2E_PORT=3284 npm run test:e2e -- test/e2e/island-doc-body.spec.ts
```

预期 `3 passed`，三组读数与上面一致（那个 `data-island-uid` 每次都不同、岛屿文件名里的哈希也随内容变，属正常）。想复现那条红的判据：把模板改回 `<DocBody :slug="slug" :html="doc.html" />`，同时在组件里声明 `html` 这个 prop 并把它贴到 `v-html` 上，再跑一次——`地址长度` 会从 135 跳到 800 以上，`查询串里带着整段正文` 变成 `true`，判据停在那句 `toBe(false)`。
