## 这个格式是给谁用的

页面给的定义：LLMs.txt 是一种**专门为大型语言模型设计的结构化文档格式**；Nuxt 提供的这些文件包含关于这个框架的完整信息，让 AI 工具更容易理解并协助 Nuxt 开发。第二个文件说明写得更具体：它们为 AI 消费做了优化，内容是**概念、API、使用模式与最佳实践的结构化信息**。

它解决的问题很实际：让模型回答 Nuxt 问题时**引用的是官方文档**，而不是训练数据里的旧版本记忆。

## 两个路由，量级差二十倍

| 路由 | 里面是什么 | 页面标注的体量 |
| --- | --- | --- |
| `/llms.txt` | **所有文档页面的结构化概览与它们的链接** | 约 5K tokens |
| `/llms-full.txt` | 完整文档，包括上手指南、API 参考、博客文章与部署指南 | 约 1M+ tokens |

`/llms.txt` 的性质是索引而不是正文：它给你的是**有哪些页面、以及每个页面的链接**。所以它适合"先让助手知道去哪找"，正文还得按链接去取。

那条信息框给的选择标准是两句连着的：

> **大多数用户应该从 `/llms.txt` 开始**——它包含所有必需的信息，并且能与标准的 LLM 上下文窗口配合工作。
>
> 只有当你需要完整的实现细节、**并且你的 AI 工具支持大上下文（200K+ tokens）**时，才使用 `/llms-full.txt`。

这里的算术很清楚：**1M+ tokens 的内容塞不进 200K 的窗口**。所以"支持大上下文"这个前提不是可选项，而是一票否决——多数模型直接把 `llms-full.txt` 截断，而截断的部分正是 API 参考这种后面几页的内容，你看不出来它少了什么。

## 一条容易违反的操作注意

页面上唯一的警告框讲的是使用方式而不是内容：

> **`@` 符号必须手工输入**——在使用 Cursor 或 Windsurf 这类工具时，`@` 必须在聊天界面里用手敲出来。**复制粘贴会破坏工具把它识别为上下文引用的能力。**

也就是说 `@docs` 这种引用**不能整段粘贴**，包括那个 `@` 在内要现场敲出来才会触发工具自己的引用选择器。

## Cursor 与 Windsurf 各自怎么接

两边给的是同一个动作，写法略有差别。

**Cursor**：两种方式——**在提问时直接提及这些 LLMs.txt 的 URL**，或者**用 `@docs` 把这些具体 URL 加进项目上下文**。进一步阅读指向 Cursor 自己的文档里 Web and Docs Search 那一节。

**Windsurf**：说法是它能直接访问 Nuxt 的 LLMs.txt 文件来理解框架用法与最佳实践，用法同样是两条——**用 `@docs` 引用具体的 LLMs.txt URL**，以及**在工作区里创建持久化的规则来引用这些 URL**。第二条比 Cursor 那节多给了一个做法：写进 rules 里，就不必每次手动引用。指向的是 Windsurf 文档的 Cascade Web Search 一节。

**其他工具**：页面那句是通用的——**任何支持 LLMs.txt 的 AI 工具都能用这两个路由**。给 ChatGPT、Claude 或其他模型的示例句式是两条，把 URL 直接写进提示里：

- 提示中使用 `https://nuxt.com/llms.txt` 里的 Nuxt 文档
- 让它遵循 `https://nuxt.com/llms-full.txt` 里的完整 Nuxt 指南

## 第三个入口：`sitemap.md`

这一节没提，但文档站还有一条对模型更友好的路径：`https://nuxt.com/sitemap.md`——**文档里每一页底部那条 "Sitemap" 段落指向的就是它**，形式是纯文本的页面清单。与 `llms.txt` 的差别在于它是站点地图而不是带结构的概览，**页面里对两者的取舍没有任何说明**，要判断哪个更合你的助手就两个都取一次比一下。

## 与 MCP 那条路的分工

上一篇讲的 MCP 与这一篇的 llms.txt 解决的是同一件事的两种形态：

| | MCP | LLMs.txt |
| --- | --- | --- |
| 需要什么 | 支持 MCP 的客户端与一次配置 | 一个能把 URL 放进提示的入口 |
| 交互形式 | 工具调用（列表、按路径取页、按主题找） | 把文本喂进上下文 |
| 粒度 | 单页、单模块、单个部署提供商 | 概览级（索引）或全站（全文） |
| 成本 | 需要配置，但按需取内容 | 零配置，但**上下文要么很小（5K）要么超窗（1M+）** |

日常问答更适合 MCP，因为它能只取需要的那一节；不方便配 MCP、或工具不支持时，`/llms.txt` 是一条零配置的兜底——**把它当目录用，让助手按链接再取具体页面**，而不是指望一次塞进全文。

## 用之前确认三件事

1. 你的助手单次能装多少 token；低于 200K 就不要碰 `llms-full.txt`。
2. 引用要生效的话，`@` 是不是手敲的（复制粘贴无效）。
3. 你要的是"让它知道有哪些页面"（`/llms.txt`）还是"把正文一次给它"（按索引取单页更省）。
