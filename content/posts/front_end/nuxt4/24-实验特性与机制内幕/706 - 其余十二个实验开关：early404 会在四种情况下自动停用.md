## 六个只有一两句话的开关

这几个整节内容很少，先把已知信息原样给出，不补推测：

- **`asyncContext`**：启用原生异步上下文，让 Nuxt 与 Nitro 里的嵌套组合式函数都能访问到它；它打开了"在异步组合式函数里用组合式函数"的可能，并**降低出现 `Nuxt instance is unavailable` 错误的概率**。完整解释指向 PR #20918。默认值未声明。
- **`writeEarlyHints`**：在使用 node server 时启用写出 early hints。默认值未声明。
- **`localLayerAliases`**：让图层内部的 `~`、`~~`、`@`、`@@` 别名**按该图层自己的 source 与 root 目录解析**。默认开。这条与图层那篇里"层内别名按用户项目解析"的旧限制是同一件事的两面。
- **`clientNodeCompat`**：用 `unenv` 自动为客户端构建 polyfill Node.js 导入。附带一条 note：**要让 `Buffer` 这类全局对象在浏览器里工作，得自己注入**，示例是 `import { Buffer } from 'node:buffer'` 然后 `globalThis.Buffer ||= Buffer`（那两个竖线字符是"或赋值"运算符，不是表格分隔）。
- **`cookieStore`**：启用 CookieStore 支持，监听 cookie 更新（**浏览器支持才有）并刷新 `useCookie` 的 ref 值**。默认开。
- **`stripNeverHydratedData`**：对**用 `hydrate-never` 懒水合的组件里**发出的 `useAsyncData`/`useFetch` 调用默认施加 `serialize: false`，把这些数据留在 `__NUXT_DATA__` 之外；理由是这些组件在客户端根本不水合，它们的数据对水合没用。**显式的 `serialize` 选项永远优先**；如果同一个 key 与会水合的组件共享，**要跨调用保持一致，Nuxt 在开发模式下会对不一致的情况告警**。默认值未声明。

## `early404`：省的是整个应用的加载

它的行为：对那些**路径不可能匹配任何页面路由**的请求直接回早期 404，**不加载 Vue 应用、插件或服务端中间件**。机制是页面路由（含别名）在构建期被编译成一个静态路由匹配器，进入的请求在服务端渲染开始前就对着它检查一遍，匹配不上的跳过加载直奔错误页。

两类请求的响应形状不同：**没有 `Accept: text/html` 头的请求（API 客户端、多数扫描器）拿到的是 JSON 错误，完全不加载应用**——但 `future.compatibilityVersion` 为 `5` 时不是这样；HTML 请求仍然服务端渲染错误页。另外**如果有一条覆盖该路径的 `cache` 路由规则，它会把 `maxAge` 作为 `Cache-Control` 标在 GET/HEAD 的 miss 上**，让 CDN 能吃掉对未知路径的重复请求。

那条警告是这一节最该读的部分：

> 这是 opt-in 的，因为它会破坏依赖运行时路由的应用。

两类会被破坏的写法：在插件里用 `router.addRoute()` 动态添加的页面（而且**开启该选项后，`useRouter` 返回的 router 类型上会移除 `addRoute`**，好让这件事早点暴露）；把未知路径重定向到已有页面的路由中间件。

还有**四种自动停用的情形**：开发模式下、`hashMode` 开启时、存在匹配所有路径的根级 catch-all 页面（例如 `pages/[...slug].vue`）、以及自定义的 `app/router.options` 文件可能修改 `routes` 时（**默认导出是不含 `routes` 键的普通对象的那个仍然兼容**）。

## `navigateToEarlyReturn`：把重定向变成提前 return

它把 `<script setup>` 顶层的 `await navigateTo()` 在导航成功时**编译成 setup 的提前 return**。原文给了不开的后果：`await navigateTo()` 之后的代码仍会继续跑，结果可能是后面的代码（包括再次调用 `navigateTo`）**覆盖掉这个重定向，或者试图用缺数据的内容渲染页面**。开启后成功的导航会终止 setup 其余部分的执行，组件渲染一个占位注释，同时导航继续推进。

官方示例正好演示了"这行什么时候才跑"：

```vue [pages/example.vue]
<script setup lang="ts">
const { data } = await useFetch('/api/data')

if (!data.value) {
  await navigateTo('/fallback')
}

// with the flag enabled, this only runs if the navigation did not happen
const processed = data.value!.map(item => item.name)
</script>
```

四个边界都写在文中：

- **只转换"结果未被使用"的顶层 `await navigateTo()` 语句**；带 `open` 选项的、或选项无法静态分析的都不转换，因为它们不应该阻止当前页面渲染。
- 提前返回**只在导航成功时发生**，也就是 `navigateTo` 解析为 `undefined` 时。被导航守卫拦下、或导航到当前路由这类失败/中止，后面的 setup 代码照常跑。
- 成功导航时 `navigateTo` 之后的一切都不执行，**包括 `defineExpose` 和 `<script setup>` 后面注册的生命周期钩子**。
- 默认值是"`compatibilityVersion: 5` 时启用"，也可以显式关掉。完整解释指向 issue #23698。

## `entryImportMap`：chunk 稳定性靠一个 import map

默认行为：Nuxt 用 import map 来解析打包产物的入口 chunk，从而提升 chunk 稳定性。它在 `<head>` 顶部注入这样一行：

```html
<script type="importmap">{"imports":{"#entry":"/_nuxt/DC5HVSK5.js"}}</script>
```

Vite 产出的脚本 chunk 里对入口的引用都写成 `#entry`，于是**入口变化不会让那些本来没变的 chunk 失效**。

一条 note 给出两个自动禁用的条件：`vite.build.target` 里配置了不支持 import map 的浏览器；或者 `vite.build.rolldownOptions.output.entryFileNames` 设成了一个不含 `[hash]` 的值。

想关掉它有两种写法，文档同时给了建议：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  experimental: {
    entryImportMap: false,
  },
  // or, better, simply tell vite your desired target
  // which nuxt will respect
  vite: {
    build: {
      target: 'safari13',
    },
  },
})
```

注释那句是文档原样：**更好的做法是直接告诉 Vite 你要的目标浏览器**，Nuxt 会尊重它。

## 三个"调试与观测"用途的开关

- **`browserDevtoolsTiming`**：为 Nuxt 钩子在浏览器 devtools 里加性能标记，可在 Chromium 系浏览器的 Performance 面板里追踪。**开发模式下默认启用**；实现细节指向 PR #29922。
- **`debugModuleMutation`**：记录模块上下文里对 `nuxt.options` 的改动，用于调试模块在 Nuxt 初始化阶段做的配置变更。**当 `debug` 模式开启时默认启用**，也可以显式打开（`debugModuleMutation: true`）；细节指向 PR #30555。这一条对模块作者是直接可用的——怀疑某个选项被别的模块改了，就开它。
- **`defaults`**：给核心组件与组合式函数指定默认选项。官方示例的形状是三层嵌套：`nuxtLink`（`componentName`、`prefetch`、`prefetchOn.visibility`）、`useAsyncData`（`deep`）、`useState`（`resetOnClear`）。**`useState.resetOnClear` 控制的是 `clearNuxtState` 把状态重置回 `useState` 的 `init` 提供的初始值，还是设成 `undefined`**，它在 `compatibilityVersion: 5` 下默认 `true`。这一节还挂着那句迁移预告：这些选项将来很可能被挪到 `app.config` 或 `app/` 目录。

## 十二个开关的默认值分布

| 默认状态 | 开关 |
| --- | --- |
| 明确默认开 | `localLayerAliases`、`cookieStore`，以及 `entryImportMap`（原文句式是 "By default, Nuxt improves chunk stability..."） |
| 由别的设置决定 | `debugModuleMutation`（`debug`）、`browserDevtoolsTiming`（开发模式）、`navigateToEarlyReturn` 与 `useState.resetOnClear`（compatibilityVersion 5） |
| 整节没声明 | `asyncContext`、`writeEarlyHints`、`early404`（但警告里说了它是 opt-in）、`clientNodeCompat`、`stripNeverHydratedData`、`defaults` |
