## 命令的形状

```bash [Terminal]
npx nuxt docs [QUERY] [--cwd=<directory>] [--open]
```

参数一个：

| 参数 | 说明 |
| --- | --- |
| `QUERY` | 要在文档里搜索的词 |

选项三行：

| 选项 | 默认 | 说明 |
| --- | --- | --- |
| `--cwd=<directory>` | `.` | 指定 Nuxt 项目的根目录 |
| `--open` | `true` | 在浏览器里打开最合适的那一篇 |
| `--no-open` | | 打印命中的页面而不打开浏览器 |

`QUERY` 是方括号，可以省——**不给查询词时它打开文档首页**。这一条与命令描述放在一起读才有意义：它的默认动作是"跳去文档"，给了词才变成"搜完跳过去"。

## 版本对齐是这条命令的核心价值

页面对这件事的表述是两句：

> 搜索跑在**你的项目所依赖的 Nuxt 版本的文档**上，而不是当前发布出去的版本，因此答案与你在用的版本一致。当项目里装了 `@nuxt/docs` 时使用它，否则下载它。

这两句合起来解决了三个老问题：

- 你手上是 4.x，搜索引擎给你的是 3.x 的写法（或者反过来）。
- 你在迁移期同时维护两个版本，需要各自的文档。
- 你查的东西在最新站点上已经改了（本系列里已经遇到：某些页被删、某些函数被标弃用）。

`@nuxt/docs` 是那个数据来源的名称——**项目里装了就用本地的，没装就下载**。所以离线程度取决于你是否装了它：这一节**没有说明下载下来的东西会被缓存多久、也没有说明完全断网时的行为**，要确认只能实测一次。

## 排序规则与交互选择

命中的组织方式写得很具体：

> 结果按页面标题排序，然后按小节标题，然后按描述；**这些命中会先在打开之前打印出来**，然后打开最合适的那一篇。当有多个页面命中而终端是可交互的，**会问你打开哪一个**。

三档优先级意味着：这个词**是某个页面的标题**时它排得最前；只在某个小节标题里出现次之；只在页面描述里出现最后。而"先打印再打开"这个行为说明 `--no-open` 不是退而求其次的选项，它是同一套结果的纯文本视图——**在 CI、远程终端或你不想要浏览器跳出来的场合用它**。

官方给的示例只有一条：

```bash [Terminal]
npx nuxt docs "server routes"
```

注意查询词带引号，因为它是两个词。

## 与另外两条"取文档"的路比较

上一讲（AI 读文档）和 MCP 那一讲凑起来，官方一共给了三条路，它们的差别不在内容而在**谁在查、查多大范围**：

| | `nuxt docs` | LLMs.txt | MCP |
| --- | --- | --- | --- |
| 使用者 | 你，在终端里 | 支持该格式的任何模型 | 支持 MCP 的客户端 |
| 需要的配置 | 无（`npx` 即可） | 无，把 URL 放进上下文 | 每个客户端一次配置 |
| 取回的粒度 | 一篇页面（在浏览器里） | 索引约 5K tokens 或全文 1M+ | 按工具逐页、逐模块、逐提供商 |
| 版本 | **跟着你项目依赖的版本** | 站点当前版本（`/llms.txt` 默认 v4.x 的说法出现在 MCP 的资源里） | 资源默认 v4.x，工具支持 3.x/4.x/5.x/all 过滤 |
| 输出 | 打开浏览器或打印命中 | 文本进上下文 | 结构化 JSON |

有一处值得单独注意：**只有 `nuxt docs` 这条路径明确承诺"用你项目那一个版本的文档"**。MCP 那三个资源里 `documentation-pages` 说的是"默认 v4.x"，工具支持版本过滤；llms.txt 那一节压根没提版本。所以**在版本敏感的排查里，`nuxt docs` 是三者中最不容易给错答案的一个**。

## 三种把它用进日常的方式

- **排查时**：`npx nuxt docs --no-open "<关键词>"`，先看命中列表，避免浏览器打断思路；命中多个时它也会打印出来。
- **写脚本或文档时**：`--cwd` 指到别的项目根，就能查那个项目对应版本的文档——这一条对同时维护多个版本仓库的人有用。
- **想离线**：把 `@nuxt/docs` 装进项目。页面只说了"装了就用它，否则下载"，没给包的管理入口，所以这一步的实际做法是**把它作为依赖装进那个项目**。

## 四项已知与未知

知道的部分：命令的形状与三个选项、默认打开浏览器、三档排序、多命中时交互选择、版本随项目依赖、数据来源是 `@nuxt/docs`。

**这一节没写**的三件：命中为零时的输出形状；`@nuxt/docs` 被下载后的缓存位置与失效时间；以及它是否会像 `nuxt dev` 那样受 `NUXT_IGNORE_UPDATE_CHECK` 之类环境变量的影响（那张环境变量表只挂在 `dev` 那一节）。
