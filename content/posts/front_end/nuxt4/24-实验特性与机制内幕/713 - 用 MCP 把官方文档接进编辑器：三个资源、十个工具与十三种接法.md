## MCP 是什么，Nuxt 这个服务提供什么

页面给的定义：MCP（Model Context Protocol）是一种标准化协议，让 AI 助手能访问外部数据源与工具；Nuxt 提供的 MCP 服务器让 Claude Code、Cursor、Windsurf 这类助手**直接访问文档、博客文章与部署指南**。它的作用被概括为一句：**提供对 Nuxt 文档的结构化访问**，让 AI 工具更容易理解并协助 Nuxt 开发。

## 三个资源：给"浏览"用的

| 资源 | 用途 |
| --- | --- |
| `resource://nuxt-com/documentation-pages` | 浏览所有可用的文档页面（**默认是 v4.x**） |
| `resource://nuxt-com/blog-posts` | 浏览所有 Nuxt 博客文章，包含发布与教程 |
| `resource://nuxt-com/deploy-providers` | 浏览所有部署提供商与托管平台 |

用法那句也写了：在 Claude Code 这类工具里可以用 `@` 访问这些资源。

## 十个工具：给"取内容"用的

按页面给的五个类别，工具名与说明逐个落地（**名字都是 kebab-case，配置 `X-MCP-Tools` 时要用这个精确形式**）：

**Documentation 三个**

- `list-documentation-pages`：列出所有可用文档页面及其分类与基本信息，**支持版本过滤，可取 3.x、4.x、5.x 或 all**
- `get-documentation-page`：按路径取某个文档页面的内容与详情
- `get-getting-started-guide`：取指定 Nuxt 版本的上手指南

**Blog 两个**：`list-blog-posts`（列出所有博客文章及其元信息，含日期、分类、标签）、`get-blog-post`（按路径取文章内容与详情）。

**Deployment 两个**：`list-deploy-providers`（列出 Nuxt 应用的所有部署提供商与托管平台）、`get-deploy-provider`（按路径取某个部署提供商的详情与说明）。

**Modules 两个**：`list-modules`（列出所有可用模块，**可按下载量、star 数或日期做可选过滤与排序**）、`get-module`（取某个模块的完整信息，包括 README、兼容性、维护者与统计数据）。

**Changelog 一个**：`get-changelog`（取 Nuxt 核心与官方模块的最新发布）。

这里有一条与部署有关的实情值得单记：**`docs/4.x/deployment/*` 那一整段路径在文档站里并不存在**，厂商差异走的正是这里的 `get-deploy-provider` 或部署站。也就是说想知道"部署到某平台怎么做"，MCP 这条路比猜 URL 更靠得住。

## 三个引导式提示：给"工作流"用的

| 提示 | 用途 |
| --- | --- |
| `find-documentation-for-topic` | 为一个具体主题或特性找到最合适的 Nuxt 文档 |
| `deployment-guide` | 取某个特定托管平台的部署说明 |
| `migration-help` | 获取在 Nuxt 版本之间迁移的帮助 |

访问方式那一句与资源不同：资源用 `@`，**这些提示在 Claude Code 这类工具里用 `/`**。

## `X-MCP-Tools`：三态语义，空值最危险

要限制可用工具，就设这个可选的 HTTP 请求头，值是逗号分隔的工具名列表，作用是**减少发给助手的工具上下文**。示例给的是：

```json
{
  "X-MCP-Tools": "list-documentation-pages,get-documentation-page"
}
```

三种情况的处置，原文一句话讲清：**没有这个头就暴露全部工具；空头（设了但没值）暴露零个工具；写了不存在的工具名会返回一个配置错误。**

"空字符串等于全关"是最容易被误当成"用默认"的一种——如果你用脚本生成配置，键名写了、值忘了填，助手就会一个工具都拿不到，而且不报错，只是回答里没有文档来源。

## 十三种接法，键名各不相同

页面先给了共性：**这个 MCP 服务器使用 HTTP 传输**，然后逐个客户端给步骤。把它们并排看，最有用的信息是**每一项用什么键放那个 URL**：

| 客户端 | 放 URL 的键 | 形式 |
| --- | --- | --- |
| ChatGPT | 无（图形界面填表） | Settings → Connectors → Advanced settings → Developer mode，名称 `Nuxt`、URL `https://nuxt.com/mcp`、认证 `None` |
| Claude Code | 命令行参数 | `claude mcp add --transport http nuxt https://nuxt.com/mcp` |
| Claude Desktop | `command` 加 `args` | 走 `npx mcp-remote https://nuxt.com/mcp`，改 `claude_desktop_config.json` 后重启应用 |
| Cursor | `type` + `url` | `.cursor/mcp.json`，`"type": "http"`；也给了一个 `cursor://` 深链按钮 |
| Gemini CLI | `httpUrl` | `~/.gemini/settings.json`（**这个键名与其他都不同**），之后重启终端会话或重载 CLI |
| Le Chat Mistral | 图形界面 | Intelligence → Connectors → Add Connector → Custom MCP Connector，填名称与 Server URL |
| VS Code | `servers` + `type`/`url` | `.vscode/mcp.json`（**注意外层键是 `servers`**） |
| GitHub Copilot Agent | `mcpServers` + `tools` | 仓库 Settings → Code & automation → Copilot → Coding agent 的 MCP configuration；**要把 VS Code 那份的 `servers` 键换成 `mcpServers`，并且必须加一个 `tools` 键**，例如 `"tools": ["*"]` |
| GitHub Copilot CLI | `mcpServers` + `tools` | `/mcp add` 表单（Server Name `nuxt`、Type `HTTP`、HTTP Headers 留空、Tools `*`），或写 `~/.copilot/mcp-config.json`；用 `/mcp show` 确认 |
| Google Antigravity | `serverUrl` | `mcp_config.json`，之后回 Manage MCP Servers 标签点 Refresh |
| Windsurf | `serverUrl` | `.codeium/windsurf/mcp_config.json`，路径从 Settings → Windsurf Settings → Cascade → Manage MCPs → View raw config 进 |
| Zed | `context_servers` 下的 `url` | `.config/zed/settings.json`（**外层键是 `context_servers`，不是 `mcpServers`**） |
| Opencode | `mcp` 下的 `type: "remote"` | 项目根 `opencode.json`，带 `"$schema": "https://opencode.ai/config.json"` 与 `"enabled": true` |

三种前提也在页面上标了 note：**ChatGPT 那边"使用 MCP 的自定义连接器"目前对 Pro 与 Plus 账号的网页版可用**；**Claude Code 需要先装好**（指向 Anthropic 的快速开始）；**VS Code 需要先装 GitHub Copilot 与 GitHub Copilot Chat 两个扩展**；**给 GitHub Copilot coding agent 配置 MCP 需要仓库管理员权限**。

## 配好之后能问什么

页面给的八个例子可以当作能力边界的一次抽查：

- "列出所有可用的 Nuxt 文档页面"
- "取 introduction 那篇文档"
- "v3 与 v4 的区别是什么？"
- "我怎么部署到 Vercel？"
- "显示最新的博客文章"
- "帮我从 Nuxt 3 迁到 Nuxt 4"
- "搜索关于 composables 的文档"
- "找 Cloudflare 的部署指南"

最后一句是它对机制的总结：助手会用这个 MCP 服务**取结构化 JSON 数据**，然后提供有引导的协助。

## 验证 GitHub Copilot Agent 那条配置

这一条给的是一个五步流程，值得照做一遍而不是"看起来配好了"就算完：

1. 在仓库里创建一个 issue 并指派给 Copilot
2. 等 Copilot 创建出一个 pull request
3. 在这个 PR 里，点 "Copilot started work" 这个时间线事件上的 **View session**
4. 点右上角的省略号（**...**），然后在侧栏里点 **Copilot**
5. 展开 **Start MCP Servers** 这一步，看已配置的 Nuxt 工具是否列出

页面对这一节的收尾是给 GitHub 文档的延伸阅读（Extend coding agent with MCP）。
