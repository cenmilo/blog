`nuxt.config.ts` 里最容易被忽略的一行是 `modules: [...]` 里那个字符串。它不是插件名，也不是运行时才加载的东西——它在你敲下 `nuxt dev` 的那一刻就执行完了。想明白这件事需要读两页文档，因为官方把它拆成了"这是什么"和"从哪开始写"。

## 先解释三个词

**构建期（build time）**：代码在打包阶段执行，执行完就结束，不会留在浏览器或服务器里跑。与之相对的是运行期。

**钩子（hook）**：框架在启动流程的几个固定点留出的回调位置，模块往这些点里塞函数。

**分层（layer）**：可以被别的 Nuxt 项目继承的目录，模块也能从分层里带进来。

## 概念页给了什么

概念页讲模块的那一页有 4 个小节。

**为什么要有一套模块系统**，理由是两头都难受：做多租户的生产级应用时框架核心功能不够用，而配置项加插件虽然能扩展，但**把这套定制维护在多个项目里"枯燥、重复、耗时"**；反过来，如果把这些需求全都塞进核心，Nuxt 会变得非常复杂、难用。模块系统是这个两难的出口。

**模块是什么**，原话是：Nuxt 模块是**异步函数**，在开发模式用 `nuxt dev` 启动、或生产用 `nuxt build` 构建时**按顺序（sequentially）运行**。它们能覆盖模板、配置 webpack loader、加 CSS 库，以及做许多别的事。**分发方式是 npm 包**，所以能跨项目复用、能分享给社区。

**怎么挂上去**，就是 `modules` 数组的四种写法（下一篇逐条拆）。这一节末尾有一条 `::warning`，原文：

> Nuxt modules are now build-time-only, and the `buildModules` property used in Nuxt 2 is deprecated in favor of `modules`.

这句警告做了两件事：**宣布模块是构建期专用**，然后**说明 Nuxt 2 的 `buildModules` 为什么被 `modules` 取代**。也就是说 2 里"构建期模块"和"运行期模块"的区分，在新版本里不存在了——因为只剩下构建期。

**要禁用某个模块**，这是概念页独有的一节，标题带 **v4.3** 的标记。做法是把那个模块的配置键设成 `false`：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  // 禁用 @nuxt/image 模块
  image: false,
})
```

文档点明的用途是**关掉从分层继承来的模块**——那种模块不在你的 `modules` 数组里，所以没法靠"不写它"来去掉。这一节末尾指向分层页里"禁用分层中的模块"那一小节。

最后一节"自己写模块"只有一句话："每个人都有机会开发模块"，加一个跳转，目标就是作者指南页。

## 作者指南页给了什么

这一页的正文很短，两个段落，然后全是卡片。

第一段说扩展能力来自两套系统：**配置**和**钩子**，它们让定制 Nuxt 的每一个方面成为可能，也能加任何需要的集成，括号里列的是 Vue 插件、CMS、服务端路由、组件、日志。

第二段把定义**又写了一遍**，措辞和概念页有一处差别：这里写的是"模块是**函数**，在 `nuxt dev` 或 `nuxt build` 时按顺序运行"，**没有"异步"两个字**。后半句是新增的价值：用模块可以把自定义方案**封装好、测试好、作为 npm 包分享**，而不用往项目里堆样板代码，也不用要求 Nuxt 本身改动。

然后是八张卡片，一张一个去处。按页面上的顺序：

## 两页的分工与三处不一致

| 事项 | 概念页 | 作者指南页 |
| --- | --- | --- |
| 模块定义的措辞 | 异步函数 | 函数 |
| `buildModules` 已废弃 | 有，`::warning` | 无 |
| 禁用模块（v4.3） | 有一节 | 无 |
| webpack loader 能配置 | 列在能力里 | 未列 |
| CMS、日志这类集成 | 未列 | 列在配置与钩子的作用里 |
| 后续阅读入口 | 1 个跳转 | 8 张卡片 |

两处措辞不同、两处内容单侧存在，都不算矛盾，但会误导只读一页的人：**只读概念页会以为模块能配 webpack loader 是唯一能力面**；**只读指南页会不知道 `buildModules` 已经废弃**，而这正是从 Nuxt 2 迁过来的人最容易撞上的。

## 这两页都没说的

三件事值得先记下，后面几篇按去处找：

- 多个模块之间的**执行顺序保证**。两页都只说"按顺序运行"，没写顺序由什么决定、`modules` 数组的先后是否等于执行先后。
- 模块**能不能做运行期的事**。警告只说模块本身是构建期专用，没说模块注入的代码在运行期能做什么。
- **inline 函数那种写法有什么限制**。概念页的示例里第四种就是一个匿名异步函数，两页都没解释它的选项参数与 `nuxt` 参数怎么用。
