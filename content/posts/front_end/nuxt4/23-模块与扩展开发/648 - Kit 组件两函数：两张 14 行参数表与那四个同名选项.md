组件页里的东西 Nuxt 会自动扫，但**模块 runtime 里的组件不在扫描范围内**——那需要显式登记。这一节只有两个函数，坑集中在"全局"那一个字上。

## 页面怎么介绍这两件事

定性句：**组件是你 Nuxt 应用的构件，是可复用的 Vue 实例；在 Nuxt 里，components 目录下的组件默认会被自动导入**。**如果你需要从另一个目录导入组件，或者希望按需选择性地导入，`@nuxt/kit` 提供了 `addComponentsDir` 与 `addComponent` 两个方法**，它们让你自定义组件配置。

所以分工很清楚：

| 你要做的 | 用哪个 |
| --- | --- |
| 把 runtime 里一整个组件目录交给 Nuxt 扫 | `addComponentsDir` |
| 只暴露一个（或几个）具名组件 | `addComponent` |

## `addComponentsDir`：登记目录，默认不是全局

定性句里带了一句提醒：

> Register a directory to be scanned for components and imported only when used. Keep in mind, that this does not register components globally, until you specify `global: true` option.

**"只在被使用时才导入"是它的设计目标**，而**不写 `global: true` 就不注册成全局组件**——这是模块作者最容易误判的一点：以为扫进目录就等于到处能用。

```ts
export default defineNuxtModule({
  meta: {
    name: '@nuxt/ui',
    configKey: 'ui',
  },
  setup () {
    addComponentsDir({
      path: resolve('./runtime/components'),
      prefix: 'U',
      pathPrefix: false,
    })
  },
})
```

官方示例给的就是"**前缀 `U` ＋ 不按路径再加前缀**"这个组合，而这两个键恰好是最佳实践里"给导出加前缀"的落地方式。

`dir` 参数的 14 个字段：

| 属性 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `path` | `string` | `true` | 目录路径（绝对或相对）；**可以用 Nuxt 别名（`~` 或 `@`）指向项目内目录，也可以直接用一个 npm 包路径** |
| `pattern` | `string \| string[]` | `false` | 对指定路径运行的接受模式 |
| `ignore` | `string[]` | `false` | 对指定路径运行的忽略模式 |
| `prefix` | `string` | `false` | **用这个字符串前缀所有匹配到的组件** |
| `pathPrefix` | `boolean` | `false` | 用组件所在路径作为名字前缀 |
| `prefetch` | `boolean` | `false` | 见下方"两个只提 webpack 的字段" |
| `preload` | `boolean` | `false` | 同上 |
| `isAsync` | `boolean` | `false` | **标记该组件应异步加载（独立 chunk），不论有没有用 Lazy 前缀** |
| `extendComponent` | `(component) => Promise<Component \| void> \| (Component \| void)` | `false` | 对目录里找到的每个组件都会调用；接收组件对象，应返回组件对象或解析到组件对象的 promise |
| `global` | `boolean` | `false` | 启用时把组件注册为全局可用 |
| `island` | `boolean` | `false` | 启用时把组件注册为 island |
| `watch` | `boolean` | `false` | 监听指定路径的变化，**包括新增与删除文件** |
| `extensions` | `string[]` | `false` | Nuxt builder 支持的扩展名 |
| `transpile` | `'auto' \| boolean` | `false` | 用 `build.transpile` 转译指定路径；**设成 `'auto'` 时，路径里含 `node_modules/` 就为 `true`** |

第二个参数：

| 属性 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `prepend` | `boolean` | `false` | 为 `true` 时，**这个目录用 `unshift()` 而不是 `push()` 放进数组** |

**`unshift` 这个词就是答案本身：目录的先后位置会参与解析，`prepend` 是把自己排到最前面**。

三个字段的作用域容易混：**`prefix` 是"统一加一个字符串"，`pathPrefix` 是"用路径当前缀"，`pattern`/`ignore` 是"哪些文件算组件"**。示例里 `pathPrefix: false` 的存在说明**默认会按路径加前缀**，所以 `runtime/components/form/Input.vue` 这种会带上 `FormInput` 一类的名字。

## `addComponent`：单个组件，14 个字段

定性一句：**注册一个组件使其被自动导入**。

```ts
import { addComponent, createResolver, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  meta: {
    name: '@nuxt/image',
    configKey: 'image',
  },
  setup () {
    const resolver = createResolver(import.meta.url)

    addComponent({
      name: 'NuxtImg',
      filePath: resolver.resolve('./runtime/components/NuxtImg.vue'),
    })

    addComponent({
      name: 'NuxtPicture',
      filePath: resolver.resolve('./runtime/components/NuxtPicture.vue'),
    })
  },
})
```

**只有 `name` 与 `filePath` 两个必填**，其余 12 个都有默认或推导：

| 属性 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `name` | `string` | `true` | 组件名 |
| `filePath` | `string` | `true` | 组件路径 |
| `declarationPath` | `string` | `false` | **声明文件路径，用于生成组件的类型模板；不提供时用 `filePath`** |
| `pascalName` | `string` | `false` | **不给则从组件名生成** |
| `kebabName` | `string` | `false` | 同上，kebab 形态 |
| `export` | `string` | `false` | 指定具名或默认导出；**不提供时设为 `'default'`** |
| `shortPath` | `string` | `false` | 短路径；不给则从组件路径生成 |
| `chunkName` | `string` | `false` | 组件的 chunk 名；不给则从组件名生成 |
| `prefetch` | `boolean` | `false` | 见下 |
| `preload` | `boolean` | `false` | 见下 |
| `global` | `boolean` | `false` | 启用时注册为全局可用 |
| `island` | `boolean` | `false` | 启用时注册为 island |
| `mode` | `'client' \| 'server' \| 'all'` | `false` | **该组件应渲染在客户端、服务端还是两者；默认在两端都渲染** |
| `priority` | `number` | `false` | **同名组件中优先级最高的那个被使用** |

`export` 那条另有专门示例——**从 npm 包里导入一个具名导出的组件**：

```ts
import { addComponent, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  setup () {
    // import { MyComponent as MyAutoImportedComponent } from 'my-npm-package'
    addComponent({
      name: 'MyAutoImportedComponent',
      export: 'MyComponent',
      filePath: 'my-npm-package',
    })
  },
})
```

注释把这行的语义直接写成了等价的手写导入：**`name` 是用户使用的那个名字，`export` 是包里真实的导出名**。漏掉 `export` 时会按 `'default'` 处理，**表现就是"包里有这个组件但运行时拿到 undefined"**。

`declarationPath` 与 `filePath` 分开的意义在第一行注释里：**它只影响生成的类型模板指向哪儿**，运行时仍用 `filePath`。

## 两张表重叠的四个字段

`prefetch`、`preload`、`global`、`island` 四个字段在两节里**描述逐字相同**，所以按任一处读都一样。其余各自独有：

| 只出现在目录那侧 | 只出现在单组件那侧 |
| --- | --- |
| `path`、`pattern`、`ignore`、`prefix`、`pathPrefix`、`isAsync`、`extendComponent`、`watch`、`extensions`、`transpile` | `name`、`filePath`、`declarationPath`、`pascalName`、`kebabName`、`export`、`shortPath`、`chunkName`、`mode`、`priority` |

`priority` 只在单组件表里出现，**目录那一侧靠 `prepend` 与位置来解决先后**。

## 两个只提 webpack 的字段

`prefetch` 与 `preload` 的描述在两处都是同一句：**这两个属性（prefetch/preload）在生产中用于配置带 Lazy 前缀的组件如何被 webpack 通过它的 magic comments 处理**，并给了 webpack 文档的链接。

**默认用 Vite 的 4.x 里，这两段说明仍然只写 webpack**，页面没有给 Vite 侧的对应行为，所以**不要把这两个字段当成"跨 builder 的预取开关"**。

## 自查三条

1. 用了 `addComponentsDir` 却发现组件必须每次 import？——**这是默认行为**，要全局得显式 `global: true`，而全局组件会为每个组件生成独立 chunk，代价在最佳实践那章写过。
2. 组件名字比预期多了一段？——**`pathPrefix` 默认按路径加前缀**，示例里那句 `pathPrefix: false` 就是关掉它。
3. 从 npm 包注册的组件运行时拿不到？——**检查 `export` 有没有写**，具名导出在不写时会被当成默认导出。

文档未给的部分保持标注：`priority` 的默认值、`prefix` 与 `pathPrefix` 同时开启时的叠加顺序、以及 `island` 与 `mode` 的组合限制。
