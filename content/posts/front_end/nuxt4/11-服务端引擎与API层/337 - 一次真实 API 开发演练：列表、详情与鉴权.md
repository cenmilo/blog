前面几篇都是单个零件。这一篇拿一个最小可用的后端——一个待办的"列表 + 详情 + 鉴权"——把零件串一遍。每一步都落回官方写法，不发明文档没有的东西。

## 接口一：列表（GET，返回 JSON）

放 `server/api/todos.get.ts`，文件名 `.get` 后缀把它绑到 GET 方法（303）：

```ts [server/api/todos.get.ts]
export default defineEventHandler(async (event) => {
  // 真实项目里在这查数据库；这里示意返回一个数组
  return [{ id: 1, title: 'Buy milk', done: false }]
})
```

要点（全来自文档）：路径自动是 `/api/todos`（api 目录带 `/api` 前缀，302）；`return` 一个可 JSON 序列化的值，h3 自动转 JSON 响应（304）；`defineEventHandler` 不写 import 用的是 h3 那份（311）。

前端这么调（列表页）：

```vue [app/pages/todos.vue]
<script setup lang="ts">
const { data } = await useFetch('/api/todos', { key: 'todos' })
</script>
```

显式 `key: 'todos'` 是为下一步详情复用缓存做准备（228）。相对 `/api` 路径两端都指自家应用，SSR 阶段服务端直调 handler、并经 useRequestFetch 自动转发头（332/318）。

## 接口二：详情（动态段 + 校验）

放 `server/api/todos/[id].get.ts`，动态段用 `getRouterParam` 取（306）：

```ts [server/api/todos/[id].get.ts]
export default defineEventHandler((event) => {
  const id = getRouterParam(event, 'id')
  return { id, title: 'Buy milk', done: false }
})
```

如果要严格校验 `id` 是整数，用带校验的取值（305/334 那条"输入先过 schema"）或 `getValidatedRouterParams` 配 Zod。非法就让它落到 400，而不是拿着脏值往下走。

详情页取数时复用列表缓存、避免重复请求（官方 useNuxtData 示例的写法，228）：

```vue [app/pages/todos/[id].vue]
<script setup lang="ts">
const { data: todos } = useNuxtData('todos')
const route = useRoute()
const { data } = useLazyFetch(`/api/todos/${route.params.id}`, {
  key: `todo-${route.params.id}`,
  default () {
    return todos.value?.find(t => String(t.id) === route.params.id)
  },
})
</script>
```

`useNuxtData('todos')` 拿列表缓存当占位、`useLazyFetch` 后台补详情。

## 接口三：鉴权（服务端挡）

碰用户数据的接口必须在服务端挡，这是 334 的基线条目五。用 `requireUserSession`（292/326），没会话抛 401：

```ts [server/api/stats.get.ts]
export default defineEventHandler(async (event) => {
  const { user } = await requireUserSession(event)
  return {}
})
```

页面侧另配一个客户端路由中间件守体验（`authenticated` + `definePageMeta`，292），但**那只是体验层**，真护数据的是上面这句。

## 接口四：写操作（POST + 校验 + 密钥在服务端）

新增一条待办的接口 `server/api/todos.post.ts`：读体前校验、且如果它要代理调用第三方、密钥从 runtimeConfig 私有键读（327）：

```ts [server/api/todos.post.ts]
import { z } from 'zod'

export default defineEventHandler(async (event) => {
  const body = await readValidatedBody(event, z.object({ title: z.string() }))
  // 若需第三方：const config = useRuntimeConfig(event); config.apiSecret 只服务端可读
  return { created: body.title }
})
```

前端触发写之后按粒度刷新（240）：`refresh()`（这个 useFetch 实例）/`refreshNuxtData('todos')`（按 key）/ 不传参全站重取。

## 串起来这条链上谁做什么

| 环节 | 用到的东西 | 篇目 |
| --- | --- | --- |
| 路由成 `/api/...` | 文件放 server/api、`.get`/`.post` 后缀 | 302/303 |
| 返回/校验输入 | return JSON、readValidatedBody、getRouterParam | 304/305/306 |
| 鉴权 | requireUserSession（服务端） | 292/326 |
| 密钥 | runtimeConfig 私有键 + useRuntimeConfig(event) | 327 |
| 前端取数 | useFetch 相对路径 + 显式 key + useNuxtData 复用 | 215/228/332 |
| 写后刷新 | refresh / refreshNuxtData | 240 |

## 自查

- 接口按方法拆文件（`.get`/`.post`），动态段用 `getRouterParam`，进业务的输入一律 `readValidatedBody` 校验。
- 碰敏感数据的接口在**服务端** `requireUserSession` 挡，客户端中间件只守体验。
- 第三方密钥只在 `useRuntimeConfig(event)` 的私有键里，不进前端。
- 前端用 useFetch 相对路径 + 显式 key，详情用 useNuxtData 复用列表缓存；写操作后按粒度 refresh。
