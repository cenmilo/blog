314–318 讲了一堆 `useRequest*` / `useResponse*`。它们名字像、能力互补，但有个共性被各自的页用不同措辞点过。这一篇把它们并到一张表上，专门记"在浏览器里它们分别是什么表现"。

## 共性：摸的是服务端那一趟请求

SSR 阶段服务端正在处理这次请求，才有"入站请求头""待发出的响应"这些东西。到浏览器，请求已经收完了、也没有"待我写的响应"，所以这些组合式在客户端多半拿不到值或不生效。官方在每个页上都单独写了这句——我把它们凑齐：

| 组合式 | 干什么 | 在浏览器里 |
| --- | --- | --- |
| `useRequestEvent()` | 拿这次请求的底层 event | 返回 `undefined` |
| `useRequestHeader('name')` | 读单个入站头 | 返回 `undefined` |
| `useRequestHeaders([...])` | 读多个入站头 | 返回空对象 `{}` |
| `useRequestURL()` | 拿这次请求的 URL 对象 | **两端都有值**（例外） |
| `setResponseStatus(event, code)` | 设响应状态码 | 无效果 |
| `useResponseHeader('name')` | 设响应头 | 依赖服务端那一趟 |
| `useRequestFetch()` | 服务端取数转发头 | 等同普通 `$fetch` |

前三行是"读入站"，中间是"写响应"，最后是"转发"。

## 一句一句的官方原话

- **useRequestEvent**："In the browser, `useRequestEvent` will return `undefined`."（314）
- **useRequestHeader**："In the browser, `useRequestHeader` will return `undefined`."（315）
- **useRequestHeaders**："In the browser, `useRequestHeaders` will return an empty object."（315）——注意它和单数版不同，是 `{}` 不是 `undefined`。
- **useRequestURL**：定位就是 "returns an URL object working on both server-side and client-side."（316）——它是这组里少见的"两端都正常"的，因为它有浏览器的 location 可以对齐。
- **setResponseStatus**："In the browser, `setResponseStatus` will have no effect."（307）
- **useRequestFetch**："In the browser during client-side navigation, `useRequestFetch` will behave just like regular `$fetch`."（318）

## 为什么读头的是 undefined/空对象、写响应的是"无效果"

分两种：

- **读入站**（event/header/headers）：浏览器这次导航没有"服务端正在处理、带着原始请求头的那个 event"。单数取一个值→没有就是 `undefined`；复数取一个集合→没有就是空对象 `{}`。判空时要按各自的"没值形态"来。
- **写响应**（setResponseStatus/useResponseHeader）：响应头/状态码是服务端发响应时才有的东西，浏览器改不了"已经收到的响应的头"，所以这些在客户端"无效果"（不报错，就是没用）。

## 判据：这些要么判侧、要么只放服务端路径

它们都只能在 Nuxt 上下文里调（295 四类位置），且实际生效只在服务端那一趟。所以用法上：

- 只在服务端会走到的路径里用（`import.meta.server` 分支、`.server` 插件、服务端 handler/中间件里的等价逻辑）。
- 或取到后判空再用：`const event = useRequestEvent(); if (event) { ... }`（307/314 官方示例都是这个形状）。
- 别在"客户端才会跑到"的地方指望它们有值——比如纯客户端导航的中间件后半程。

SSR 取数要转发登录态头，也别手动扒这些——直接用 `useFetch`（底层走 `useRequestFetch`，318）或 `useRequestHeaders([...])` 精挑几个（315）。

## 自查

- 记牢"浏览器里各是什么"：event/单数头 → undefined；复数头 → `{}`；useRequestURL → 两端有值；写响应的 → 无效果。
- 读入站、写响应这两类基本是服务端专用，用之前判侧或判空。
- 别把 useRequestURL 当"也是服务端专用"——它是这组里的例外，两端都对。
- SSR 要带登录态取数，优先 useFetch/useRequestFetch，而不是自己拼这些读头的组合式。
