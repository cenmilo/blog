需求很常见：页面要显示 GitHub 仓库信息，得带一个 token 调 GitHub API。但 token 要是写进前端，等于公开。官方给的路径是"服务端代理"：密钥只待在服务端，前端调你自己的接口。

## 密钥放哪：runtimeConfig 的私有键

265 已经立过这条——`runtimeConfig` 顶层的键是私有的、只服务端可读。nuxt-config 对它的定位：

> It mainly should hold *private* configuration which is not exposed on the frontend. This could include a reference to your API secret tokens.
> Anything under `public` and `app` will be exposed to the frontend as well.

所以 token 放顶层、不放 `public`。两端读写差别也印证（265）：客户端只有 `public`/`app` 可读，服务端整个可读但只读。

## 官方那条完整链路

server 那页 "Runtime Config" 给了一个把密钥、接口、环境变量三处串起来的完整例子。三块：

**一、handler 里读密钥、带去请求第三方**（`server/api/foo.ts`）：

```ts [server/api/foo.ts]
export default defineEventHandler(async (event) => {
  const config = useRuntimeConfig(event)

  const repo = await $fetch('https://api.github.com/repos/nuxt/nuxt', {
    headers: {
      Authorization: `token ${config.githubToken}`,
    },
  })

  return repo
})
```

**二、nuxt.config 声明私有键**：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  runtimeConfig: {
    githubToken: '',
  },
})
```

**三、.env 提供实际值**：

```ini [.env]
NUXT_GITHUB_TOKEN='<my-super-token>'
```

三块连起来读：**handler 用 `useRuntimeConfig(event)` 读到 `config.githubToken` → 拼进 `Authorization` 头打 GitHub → 把结果 `return` 给前端。** 前端只调 `/api/foo`，永远看不到 token。这就是"密钥不进客户端包"的实现方式。

## 为什么这里用 useRuntimeConfig(event) 传 event

官方 note：

> Giving the `event` as argument to `useRuntimeConfig` is optional, but it is recommended to pass it to get the runtime config overwritten by environment variables at runtime for server routes.

传 `event` 才能拿到"运行时被环境变量覆盖"过的那份 config（265 的 `NUXT_` 前缀在运行时覆盖机制）。不传 event，服务端路由里可能拿到的是构建期的默认值而非运行时的环境变量值。

## 几个要点串起来

- **为什么不在前端 `$fetch` 第三方**：token 得写在前端、进客户端包，用户能翻到（264 那条"app.config/客户端包都是明文"同源）。放服务端 handler 里调，token 只在服务端可读。
- **为什么键要在 nuxt.config 声明过**：265 那条前提——"Custom runtime config variables must be defined in your `nuxt.config`. This ensures that arbitrary environment variables are not exposed to your application code."——没声明的 `NUXT_*` 不会自动进 runtimeConfig。
- **前端怎么拿这个代理接口**：`useFetch('/api/foo')` 直接调自家服务端，返回的是 GitHub 数据（已带类型，300/304）。
- **别把值外泄**：265 的 caution——别把 runtimeConfig 私有键渲染出来、或 `useState`（会进 payload、发给浏览器）。代理接口 `return` 的是第三方结果，不是 token 本身。

## 自查

- 第三方密钥放 `runtimeConfig` 顶层私有键，不放 `public`、不放 app.config、不渲染、不进 useState。
- 在 server/api handler 里 `useRuntimeConfig(event)` 读密钥 → 拼进请求头 → 打第三方 → return 结果；前端只调你自家 /api。
- 服务端路由里 `useRuntimeConfig` 建议传 `event`，才拿到运行时被 `NUXT_` 环境变量覆盖过的值。
- 对应的 `NUXT_GITHUB_TOKEN` 生产环境要自己设（.env 只在 dev/build/generate 读，265）。
