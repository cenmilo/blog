到这里 300-339 已经讲了插件、中间件、取数、设响应头。这一篇把它们摆回**一条时间线**上——官方 nuxt-lifecycle 那页，把服务端"每个初始请求"拆成七步。看懂顺序，很多"这段代码啥时候跑"的问题就自动有答案。

官方口径：

> On the server, the following steps are executed for every initial request to your application.

## 第 1 步：Server plugins（Nitro 插件，跑一次）

> When Nitro starts, it initializes and executes the plugins under the `/server/plugins` directory.

这是 `defineNitroPlugin` 那些（287、301）。官方给了一个关键限定：

> Nitro plugins are executed only once when the server starts. In a serverless environment, the server boots on each incoming request, and so do the Nitro plugins. However, they are not awaited.

三点：只在服务启动时跑一次；serverless 下"每个请求冷启"、插件也跟着每次启动；但插件**不被 await**（不要指望插件里 await 的东西阻塞后续步骤）。

## 第 2 步：Server middleware（服务端中间件，每请求）

> After initializing the Nitro server, middleware under `server/middleware/` is executed for every request.

就是 291、301 那批。官方在这步放了个 warning，比 291 说得更重：

> Returning a value from middleware will terminate the request and send the returned value as the response. This behavior should generally be avoided to ensure proper request handling!

也就是服务端中间件**返回值会直接终止请求、把返回值当响应发出去**——这正是 291 那条"不该返回任何东西"背后的后果：你一旦 return，请求就到这儿结束了。

## 第 3 步：App plugins（应用插件）

> The Vue and Nuxt instances are created first. Afterward, Nuxt executes its app plugins.

这步先创建 Vue 与 Nuxt 实例，再跑 `app/plugins/` 的插件（含不带后缀的和 `.server` 后缀的，见 270/288）。官方给时机：

> After this step, Nuxt calls the `app:created` hook.

跑完这步触发 `app:created`（275 那张表、285 错误分流里都见过它）。

## 第 4 步：Route validation（先于中间件）

> After initializing plugins and before executing middleware, Nuxt calls the `validate` method if it is defined in the `definePageMeta` function.

页面 `definePageMeta` 里的 `validate`（111、135）。两条要点官方列了：参数合法返回 `true`；不合法返回 `false` 或带 `status`/`statusText` 的对象终止请求。

一句最关键的顺序——**validate 早于中间件**（"before executing middleware"）。这条 149、135 都强调过，是"为什么 validate 里拿不到某些中间件才设的东西"的原因。

## 第 5 步：App middleware（路由中间件）

> Nuxt executes all global middleware on the initial page load (both on server and client) and then again before any client-side navigation. Named and anonymous middleware are executed only on the routes specified in the middleware property.

290/293/292 的中间件全在这步。官方还给了这步和服务端重定向的连接：

> Any redirection on the server will result in a `Location:` header being sent to the browser; the browser then makes a fresh request to this new location. All application state will be reset when this happens, unless persisted in a cookie.

服务端重定向 = 发 `Location` 头、浏览器重新请求 → **所有应用状态被重置，除非存在 cookie 里**。这句把 268 那张"跨请求存活"表钉死：重定向后 useState 没了、cookie 还在。

## 第 6 步：Page and components（取数，但 Vue 钩子不跑）

> Nuxt renders the page and its components and fetches any required data with `useFetch` and `useAsyncData` during this step.

210-249 的取数在这步。官方给了一条贯穿 SSR 的事实：

> Since there are no dynamic updates and no DOM operations occur on the server, Vue lifecycle hooks such as `onBeforeMount`, `onMounted`, and subsequent hooks are NOT executed during SSR.

**SSR 阶段 `onMounted` 这类钩子根本不执行**。连带一条 important（232 讲过的 setInterval 坑）：

> You should avoid code that produces side effects that need cleanup in root scope of `<script setup>` ... because the unmount hooks will never be called during SSR, the timers will stay around forever. To avoid this, move your side-effect code into `onMounted`.

服务端没有卸载钩子、定时器清不掉 → 副作用挪进 `onMounted`（它在服务端不跑、只在浏览器跑）。这也解释了 278 为什么第三方库初始化放 `onMounted`。

## 第 7 步：HTML Output

> After all required data is fetched and the components are rendered, Nuxt combines the rendered components with settings from `unhead` to generate a complete HTML document.

生成 HTML 时合并 `unhead` 的标签设置（180-209 那几篇 SEO 那一路）。两个钩子时机官方点明：

> After rendering the Vue application to HTML, Nuxt calls the `app:rendered` hook.
> Before finalizing and sending the HTML, Nitro will call the `render:html` hook. This hook allows you to manipulate the generated HTML, such as injecting additional scripts or modifying meta tags.

**先 `app:rendered`（Vue 渲染完）、后 `render:html`（Nitro 发出去前）**。`render:html` 正是 287、298 那个能改 HTML（往 head 推标签）的钩子。

## 七步速览

| 步 | 跑什么 | 关键事实 |
| --- | --- | --- |
| 1 Nitro 插件 | `server/plugins` | 启动跑一次、不 await |
| 2 服务端中间件 | `server/middleware` | 每请求；return 会终止请求 |
| 3 应用插件 | `app/plugins` | 建实例后跑 → `app:created` |
| 4 路由校验 | `validate` | 早于中间件 |
| 5 路由中间件 | `app/middleware` | 全局初始页两端各一趟；服务端重定向清状态（cookie 除外） |
| 6 页面与组件 | `useFetch`/`useAsyncData` | SSR 不跑 onMounted |
| 7 HTML 输出 | 合并 unhead | `app:rendered` → `render:html` |

客户端那半截（应用插件、validate、中间件、`app.mount('#__nuxt')` 水合、`app:beforeMount`/`app:mounted`、完整 Vue 生命周期）官方也列了，客户端才跑完整 Vue 生命周期——这条正好和第 6 步"服务端不跑"对照。

## 自查

- "这段代码在服务端什么时候跑"回到这张七步表对号入座。
- 记住三条硬事实：服务端中间件 return 会终止请求；validate 早于中间件；SSR 不跑 onMounted（副作用挪进 onMounted）。
- 服务端重定向会重置应用状态，只有 cookie 存的东西留得住。
- 两个渲染钩子的先后：`app:rendered`（Vue 渲染完）先、`render:html`（Nitro 发出前）后。
