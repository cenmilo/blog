`nuxt build` 之后项目里多出来的那个 `.output/`，就是你要拿去部署的东西。这一篇讲它的性质、使用规矩，以及"给哪种平台构建"这件事（preset）。

## .output 是什么、三条规矩

官方 output 那一节定位：

> Nuxt creates the .output/ directory when building your application for production.

三条它明确写的使用规矩：

1. **要 .gitignore**（important）：

> This directory should be added to your `.gitignore` file to avoid pushing the build output to your repository.

2. **用它部署**："Use this directory to deploy your Nuxt application to production."
3. **别手改里面的东西**（warning）：

> You should not touch any files inside since the whole directory will be re-created when running `nuxt build`.

里面每次 `nuxt build` 会**整个重建**，所以改了也白改。它和 053 讲的一致：跟着构建重建、独立于 node_modules。

## 为什么它能独立部署

300 那条从引擎侧解释过，这里补上含义。server-engine 那一节：

> Nitro produces a standalone server dist that is independent of `node_modules`.
> Nuxt generates this dist when running `nuxt build` into a `.output` directory.
> The output contains runtime code to run your Nuxt server in any environment (including experimental browser service workers!) and serve your static files ...

关键就是"independent of node_modules" + "runtime code to run your Nuxt server in any environment"——产物自带运行时，不依赖装机上的 node_modules，这才是它能被扔到各种环境的底层原因（对比 Nuxt 2 的服务端不独立、要拉 Nuxt core 跑 `nuxt start`）。

## preset：给哪种运行环境构建

部署到不同平台，构建方式不同。负责选这个的是 **preset**。官方 getting-started/server 那一节给的口径：

> Nitro offers the ability to deploy your Nuxt app anywhere, from a bare metal server to the edge network, with a start time of just a few milliseconds.

> There are more than 15 presets to build your Nuxt app for different cloud providers and servers, including:
> - Cloudflare Workers
> - Netlify Functions
> - Vercel Cloud

（还有 Deno、Bun 等运行时。）

学生口径解释 preset：它是"为哪种目标环境打包"的选择——`node_server`、`cloudflare`、`vercel`、`netlify` 各对应一种平台期望的产物形态与启动方式。它由 Nitro 提供，`nuxt build --preset` 或环境变量 `NITRO_PRESET`/`SERVER_PRESET` 控制（037 讲 build 命令时提过这个优先级）。默认不指定时 Nitro 会尽量自动检测平台。

## 一条必须说清的边界：没有逐厂商部署文档

这一篇最容易踩的坑，是把旧的"每个云厂商一章"结构写回来。当前 4.x 事实是：

- **`docs/4.x/deployment/*` 这套按厂商分的文档不存在**（实测 404、无重定向）。
- 部署在文档里只有 **`getting-started/deployment` 一页**。
- 厂商/preset 的具体差异，走站点的 `/deploy`（各平台 tab）或对应 MCP 工具，而不是靠一篇篇厂商章。

所以本系列到这里，preset 只在"概念 + 有哪些 + 默认怎么自动检测"这一层讲，不会写"Netlify 怎么配第 3 步第 4 步"这种文档里没有的东西。真要落地某个平台，去 deployment 那一节 + 站点 /deploy 看该平台条目。

## 自查

- `.output/` 是构建产物：加进 .gitignore、拿去部署、别手改（每次 `nuxt build` 重建）。
- 它能独立部署是因为自带运行时、不依赖 node_modules（Nitro 的 standalone dist）。
- preset = 为哪种目标环境打包，Nitro 有 15+ 个；用 `--preset` 或 `NITRO_PRESET`/`SERVER_PRESET` 控制，默认尽量自动检测。
- 别找 `deployment/<厂商>` 那种目录——4.x 没有，部署只有 getting-started/deployment 一页，厂商差异走站点 /deploy。
