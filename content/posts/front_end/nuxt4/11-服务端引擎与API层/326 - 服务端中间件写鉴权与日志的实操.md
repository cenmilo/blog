服务端中间件放在 `server/middleware/`，每个请求进来都先过它一遍（291）。这一篇把两个最常见的用途写成能照抄的样子，并把那条"别 return"落到实处。

## 规矩再钉一遍

官方 server 那一节的两条：

> Middleware handlers will run on every request before any other server route to add or check headers, log requests, or extend the event's request object.

> Middleware handlers should not return anything (nor close or respond to the request) and only inspect or extend the request context or throw an error.

生命周期那一节（319）说得更狠：**return 值会终止请求、把返回值当响应发出去**。所以服务端中间件能做的只有三件——**检视请求、扩展 `event.context`、抛错**。别在这 return。

## 实操一：日志中间件

最朴素的"检视请求、不返回"：

```ts [server/middleware/log.ts]
export default defineEventHandler((event) => {
  console.log('New request: ' + getRequestURL(event))
})
```

每个请求都记一行 URL，不碰响应、不 return。`getRequestURL` 是服务端可用的 helper（h3/nuxt/server 面，311）。这类"全局埋点、日志、请求计时"就是服务端中间件的典型活——它跑在每个请求前，比在每个 handler 里各写一遍省事。

## 实操二（A）：往 event.context 挂身份给下游

官方给鉴权中间件的例子是"扩展 context、不返回"：

```ts [server/middleware/auth.ts]
export default defineEventHandler((event) => {
  event.context.auth = { user: 123 }
})
```

这就是 306 讲的"中间件给下游传数据"的正规通道：把解析结果挂 `event.context.xxx`，后续 handler 用 `event.context.auth` 读。它是**每请求一份**的 context（300 讲的 Nitro 每请求隔离），不会串用户。这个例子本身只"挂身份"、不拦——拦不拦交给下游或下一段。

## 实操二（B）：直接拦——没会话抛 401

真要在中间件这一层挡下未授权请求，官方 Sessions 配方给的武器是 `requireUserSession`（nuxt-auth-utils）：

> The auth-utils module provides the `requireUserSession` utility function to make sure that users are logged in and have an active session.

> This will throw a 401 error if the request doesn't come from a valid user session.

```ts [server/api/user/stats.get.ts]
export default defineEventHandler(async (event) => {
  const { user } = await requireUserSession(event)
  return {}
})
```

抛错是服务端中间件/handler 的第三种合法动作（308 的 createError 语义：throw）。放在中间件里，就相当于"没会话的请求一律先被 401 挡掉"。

一句必须记住的分层（259、292 反复讲的那句）：

> Client-side middleware is helpful for the user, but without server-side protection your data can still be accessed.

客户端路由中间件守的是体验，**数据保护必须在服务端**——服务端中间件或 handler 里的 `requireUserSession` 才是真护住数据那层。

## 两个用途的差别

| 你要做的事 | 落点 | 关键 |
| --- | --- | --- |
| 每请求记日志/计时 | server/middleware 里读 `getRequestURL(event)` | 检视、不返回 |
| 解析身份、传给下游 handler | server/middleware 里挂 `event.context.xxx` | 扩展 context、不返回 |
| 直接拦未授权 | server/middleware 或 handler 里 `requireUserSession` 抛 401 | 抛错、不返回 |

三行的共同底线：都在 `server/middleware/`、都跑在每个请求前、都**不 return**。

## 别在中间件里碰前端代码

服务端中间件也是服务端代码，遵守 app↔server 不互 import 那道墙（288、312）：别在 `server/middleware` 里 import Vue 组件/组合式。要用服务端的取数/会话工具，从 `nuxt/server` 或模块（如 nuxt-auth-utils）拿（313）。

## 自查

- 服务端中间件只能：读/查请求、扩展 `event.context`、或抛错——**绝不 return**（否则终止请求、把返回值当响应）。
- 记日志：`getRequestURL(event)` + console；挂身份：`event.context.xxx`；拦未授权：`requireUserSession(event)` 抛 401。
- 数据保护靠服务端这层，客户端中间件只护体验。
- `server/middleware` 里别 import 前端 app 代码。
