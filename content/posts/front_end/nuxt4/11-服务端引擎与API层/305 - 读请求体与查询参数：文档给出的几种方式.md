一个接口最常做的两件事就是"读进来的数据"和"把数据回出去"。上一篇讲了"回"，这一篇讲"读"。读入站数据分两处：请求体和查询串，官方各给了工具。

## 读请求体：readBody

客户端 POST 提交的 body，用 `readBody`：

```ts [server/api/submit.post.ts]
export default defineEventHandler(async (event) => {
  const body = await readBody(event)
  return { body }
})
```

前端这样打：

```vue [app/app.vue]
<script setup lang="ts">
async function submit () {
  const { body } = await $fetch('/api/submit', {
    method: 'post',
    body: { test: 123 },
  })
}
</script>
```

一条硬约束，官方 note 又出现一次（303 讲过，这里连上读体）：

> When using `readBody` within a GET request, `readBody` will throw a `405 Method Not Allowed` HTTP error.

所以：**读 body 的 handler，文件名后缀必须是 `.post`（或别的允许带体的方法），不能是 GET。** 这是"读请求体"这件事和方法后缀绑定的原因。

## 读查询参数：getQuery

URL 问号后面那段（`?foo=bar&baz=qux`），用 `getQuery`：

```ts [server/api/query.get.ts]
export default defineEventHandler((event) => {
  const query = getQuery(event)
  return { a: query.foo, b: query.baz }
})
```

查询参数不需要"方法"限定——GET 请求就带 query，读它也不涉及 body。官方给的示例文件名就是 `query.get.ts`。

## 加校验：getValidatedQuery 与 readValidatedBody

`getQuery`/`readBody` 读出来是原始值（类型是宽松的）。要在运行时和类型两层都安全，官方推荐换成带校验的版本——server 那一节两处都给了 tip：

> Alternatively, use `getValidatedQuery` / `readValidatedBody` with a schema validator such as Zod or Valibot for runtime and type safety.

server-imports 那一节 "Validation" 一节把规则和用法说全：

> `readValidatedBody` and `getValidatedQuery` take any Standard Schema (Zod, Valibot, ArkType and others), or a function that returns the validated value, `true` to accept the input or `false` to reject it.

示例：

```ts [server/api/users.post.ts]
import { defineEventHandler, readValidatedBody } from 'nuxt/server'
import { z } from 'zod'

export default defineEventHandler(async (event) => {
  const user = await readValidatedBody(event, z.object({ name: z.string() }))
  return { created: user.name }
})
```

校验失败的行为官方也定了：

> Invalid input is rejected with a `400` whose `data.issues` lists what failed. Pass `onError` to reject it with a different error.

拆成人话：

- 校验不过 → 自动返回 **400**，具体哪些字段没过列在 `data.issues` 里。
- 想换别的错误（不是默认 400）→ 传 `onError`。
- schema 可以是 Zod / Valibot / ArkType 等符合 Standard Schema 的库；也能直接传一个"函数"：返回校验后的值、返回 `true` 表示接受、`false` 表示拒绝。

## 两处读取的对应表

| 要读什么 | 不校验 | 要校验 |
| --- | --- | --- |
| 请求体（POST 提交） | `readBody(event)` | `readValidatedBody(event, schema)` |
| 查询串（?key=val） | `getQuery(event)` | `getValidatedQuery(event, schema)` |

两个"校验版"都在 `nuxt/server` 里导出（示例 import 的就是 `nuxt/server`），也都在服务端代码面里用（288：别从组件/插件 import 这些）。

## 自查

- 读 body → `readBody`，但 handler 后缀必须是允许带体的方法（`.post` 等），GET 里读体会 405。
- 读查询串 → `getQuery`，不受方法限制。
- 想要运行时的输入安全 + 类型收窄 → 换 `readValidatedBody` / `getValidatedQuery` 接一个 schema，失败自动 400、`data.issues` 列问题，`onError` 可改错误。
- 这些是服务端工具，只在 `server/` 侧用。
