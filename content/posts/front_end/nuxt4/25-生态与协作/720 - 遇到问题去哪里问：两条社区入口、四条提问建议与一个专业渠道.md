## 两个入口，用途不一样

页面开头给了两张卡片：

- **Discord**（`https://go.nuxt.com/discord`）：**实时帮助**、与核心团队和社区交流、跟进 Nuxt 的最新消息。
- **Nuxters**（`https://nuxters.nuxt.com`）：与其他 Nuxt 爱好者建立联系。

差别在第一句用词上：需要"有人现在就看一眼"的是 Discord；Nuxters 那一句只说 connect，没有承诺实时性。

## 第一种情况：我读过文档但还是不知道怎么做到

官方给的答案很明确：**最好的做法是开一个 GitHub Discussion**。位置在 `nuxt/nuxt` 仓库的 Discussions。

紧跟着有一句是给提问者的心理建设：**别为"觉得自己问了个蠢问题"而不好意思，我们都经历过**。然后是一段决定了回答质量的说明——**你会遇到的每个人都是在自愿帮忙，不是拿钱办事，所以最善意的做法是让他们容易帮到你**。这里给了四条具体建议，每条都带例子：

- **说清你的目标，而不只是你遇到的问题。**原文的例子是："我需要确保表单输入是可访问的，所以我在想办法让 id 在服务端与客户端之间保持一致。"——这句话比"我的 id 不一样"可回答得多。
- **确认你已经读过文档、也用过搜索引擎**，并且把这件事告诉别人。例子是那句原话："我搜过 'nuxt script setup'，但找不到任何代码示例。"
- **说明你试过什么。**告诉对方你尝试过哪些方案以及为什么，原文的解释是：**这样往往能让别人的建议更贴合你的处境**。
- **分享你的代码。**只看到报错信息或截图，别人多半帮不上；**把代码以可复制粘贴的格式发出来，情况就完全不同——最好是做成一个最小复现，例如 CodeSandbox。**

## 一条容易被忽略的礼仪：直接问

页面最后一段专门讲这个：

> 最后，就把问题问出来！不需要**请求允许提问**，也不需要**等别人回复你的"你好"**。如果你这样做了，可能反而得不到回应，**因为大家会等你把整个问题说完才开始介入**。

两个被点名的习惯各给了参考页面（dontasktoask.com 与 nohello.com）。实际含义是：**别在 Discord 里发"在吗"然后等回复**，直接把目标、试过什么、代码一起发出来。

## 第二种情况：这可能是个 bug

页面给的判断路径是这样的：东西没有按文档说的那样工作，你不确定是不是 bug，**而且你已经在 open issues 与 discussions 里搜过、什么都没找到**。这时官方推荐的下一步是去读"如何报告 bug"那一页，并且补了一句：**Nuxt 仍在积极开发中，每一个 issue 都在让它变得更好**。

同一段里有个括号很容易被跳过，但它是个明确规则：**如果存在的是一个已关闭的 issue，请新建一个**，而不是去已关闭的那条下面回复。

## 第三种情况：我需要专业支持

页面给的第三条路是**付费渠道**：当社区无法在你需要的时间范围内提供帮助时，**NuxtLabs 通过 Nuxt Experts 提供专业支持**（入口 `https://nuxt.com/enterprise/agencies`）。

这一节对它的定位说了三点：**Nuxt Expert 的目标是为 Vue 生态提供支持，同时为参与开源的人创造接单机会，从而帮助生态保持可持续**；这些专家是**被挑选出来的 Vue、Nuxt 与 Vite 贡献者**，提供专业支持与咨询服务。

也就是说这条路不是"售后"，而是把开源贡献者变成可付费的服务方——它同时是社区可持续性的一部分。

## 按情况选渠道

| 你的处境 | 走哪条 | 理由 |
| --- | --- | --- |
| 看得懂文档但不会组合用法 | GitHub Discussion | 页面明说这是 best thing；这是提问不是缺陷 |
| 需要有人现在帮你排一眼 | Discord | 卡片第一句就是 real-time help |
| 确定行为与文档不符 | 先搜 issues 与 discussions，再按报告 bug 那一页做最小复现 | 直接开 issue 而不复现，多半会被要求补复现 |
| 已关的 issue 里有人遇到同样问题 | **新建一个 issue** | 括号那句规则 |
| 有交付期限、社区时间不够 | Nuxt Experts | 页面给的正是这种情况 |

## 发出问题前的六项自查

1. 我有没有把目标写出来，而不只是报错文本。
2. 我有没有说明搜过什么、读过哪一节（能写出章节名最好）。
3. 我试过哪些方案，为什么放弃。
4. 代码是否可复制粘贴，或者已经做成最小复现。
5. 我是不是直接问了，而不是先发"你好"。
6. 如果这是缺陷：相关的 open issue 与 discussion 搜过了吗，搜到的那条是否已经关闭。
