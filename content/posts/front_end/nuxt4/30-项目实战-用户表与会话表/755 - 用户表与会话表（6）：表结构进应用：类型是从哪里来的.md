## 先看删掉一行会怎样

`server/utils/db.ts` 里和数据库有关的一共三行：第 4 行引 `drizzle`、第 6 行引整个 schema、第 31 行把它交给 `drizzle(pool, { schema })`。

```ts [server/utils/db.ts 的关键三行]
import { drizzle } from 'drizzle-orm/node-postgres'
import * as schema from '../../db/schema'
// …
return drizzle(pool, { schema })
```

把第 6 行删掉，`npx nuxt typecheck` 报的是这一句：

```text
server/utils/db.ts(30,26): error TS18004: No value exists in scope for the shorthand property 'schema'. Either declare one or provide an initializer.
```

这条只说明"少了一个变量"。真正的问题在后面：`{ schema }` 这个参数到底给代码带来了什么？不问不行，因为这一句在六个文件里被写了七次，而全仓 `useDb()` 有 18 处调用（分布在 9 个文件）。

## 四段探针：两红两绿

造一个只看类型的临时文件（跑完就删），四个函数分别试四种写法：

```ts [db/probe-schema-arg.ts（本轮探针，已删）]
// 临时探针（跑完即删）：不连库，只看类型。问两个问题——
// ① `drizzle(pool, { schema })` 里那个 schema 到底买到了什么；
// ② 列名写错时，类型检查是不是真认得这张表的列。
import { drizzle } from 'drizzle-orm/node-postgres'
import type { Pool } from 'pg'
import * as schema from './schema'
import { users } from './schema'

export function withSchemaArg (pool: Pool) {
  const db = drizzle(pool, { schema })
  return db.query.users      // 期望：不报错
}

export function withoutSchemaArg (pool: Pool) {
  const db = drizzle(pool)
  return db.query.users      // 期望：报错——这一位就是这个参数的全部作用
}

export function wrongColumnName (pool: Pool) {
  const db = drizzle(pool, { schema })
  return db.select().from(users).then((rows) => rows[0].emial)   // 期望：报错并提示 email
}

export function rightColumnName (pool: Pool) {
  const db = drizzle(pool, { schema })
  return db.select().from(users).then((rows) => rows[0].role)    // 期望：不报错，且类型是那三个枚举值
}
```

`npx nuxt typecheck` 的完整输出四行、`rc=2`：

```text
db/probe-schema-arg.ts(16,19): error TS2339: Property 'users' does not exist on type 'DrizzleTypeError<"Seems like the schema generic is missing - did you forget to add it to your DB type?">'.
db/probe-schema-arg.ts(21,49): error TS2532: Object is possibly 'undefined'.
db/probe-schema-arg.ts(21,57): error TS2551: Property 'emial' does not exist on type '{ id: string; email: string; name: string | null; role: "free" | "member" | "admin"; githubId: string | null; createdAt: Date; bannedAt: Date | null; }'. Did you mean 'email'?
db/probe-schema-arg.ts(26,49): error TS2532: Object is possibly 'undefined'.
```

- 第 11 行不报错、第 16 行报错：**`db.query.<表>` 这一整条关系查询 API，就是那个 `schema` 参数换来的东西**。不传它，包里直接给你一个 `DrizzleTypeError` 文案，提醒你忘了加。
- 第 21 行那句 `emial` 被 `TS2551` 报了错，并且**顺手把这一行的完整形状打了出来**（见下一节）。
- 第 26 行的 `.role` 没有报"属性不存在"——它通过类型检查了，说明列名守卫是真的在看着这张表。

一句要老实说的边界：本仓库 `.query.` 出现 0 次，取数全部是手写的 `select`／`update`／`delete`。也就是说这个参数今天买到的是一条**还没走的路**；但删掉它，`useDb()` 的返回类型立刻退化，所以它属于"接口先备好、后面几站才用"的那类约定。

## 那一串形状就是表定义的镜像

第 21 行报错里列出的七个字段，跟第 4 步里 `db/tables/users.ts` 那七列逐字对得上：

```text
{ id: string; email: string; name: string | null; role: "free" | "member" | "admin";
  githubId: string | null; createdAt: Date; bannedAt: Date | null }
```

三件事一次看清：

- **可空规则是从列定义来的**。`name`、`githubId`、`bannedAt` 带 `| null`，因为那三列在表上没写 `NOT NULL`；`email` 不带，因为它 `NOT NULL` 且没有默认值。
- **枚举值域也是**。`role` 是三个字面量的联合，来源就是 `pgEnum('user_role', [...])` 那三个值（第 3 步量过：改清单，全仓赋值处当场红）。
- **`uuid`／`inet` 这种"库里挑形状"的列，在类型里只是 `string`**（第 2 步量过的 `userId`、`createdIp` 两条负对照）。所以类型能挡拼错字段，挡不住非法值。

## 为什么 `rows[0]` 被当成可能没有

两处 `TS2532: Object is possibly 'undefined'` 不是包的毛病，是配置：本轮读到的四份生成配置——`app`、`server`、`shared`、`node`——里 `noUncheckedIndexedAccess` 全是 `true`，而仓库自己的 `nuxt.config.ts` 从没写过这一位（只补了三条 `include`）。

后果直接落在服务层的写法上。`server/services/auth/token.ts` 第 59 到 66 行、`verify.ts` 第 58 到 68 行都是同一个模式：

```ts
const [row] = await useDb().insert(loginTokens) /* … */ .returning({ id: loginTokens.id })

if (!row) {
  throw new Error('issueLoginToken(): returning() 没有拿回行，插入未成功')
}
```

解构拿到的是"可能 undefined"，所以判空分支不是防御性冗余，而是编译要求。把这一位当常识写进代码，比之后满屏 `!` 强。

## 形状有两份来源，各管一段

这是这条线最后要钉住的分层，两边不能混：

| 哪一类形状 | 住在哪 | 谁能不写 import 直接用 | 改了谁会红 |
| --- | --- | --- | --- |
| 数据库里的行 | `db/schema.ts` 出口（表定义在 `db/tables/`） | 只有引了它的服务端文件；`db/` 不被 Nuxt 扫描 | 改列名、改可空、改枚举，查询那一段当场红（本轮 `emial` 就是这条的镜像） |
| 接口与页面之间 | `shared/types/`（本轮数到四个文件：`metrics.ts`、`doc.ts`、`current-user.ts`、`plan.ts`） | 两端都免 import（`shared/types/` 在自动导入名单里，`shared/` 其它位置不在） | 页面与接口的字段名不同步时红 |

为什么不让页面直接吃表类型？`shared/types/metrics.ts` 的文件头给了实际理由：`#server` 别名只能在服务端用，客户端 import 它会直接报错，所以接口返回的形状必须有一份住在两端都看得见的位置。绕开的代价很实在：本轮 grep 到"绕过 `db/schema` 出口、直接从 `db/tables/` 引表"的地方是 **0 处**，六个文件七处全部走出口——一旦有人绕过，改一次表就要在多处找漏网。

## 出问题对照

| 症状 | 原因 | 怎么办 |
| --- | --- | --- |
| `db.query` 下面没有你要的那张表，还带一句 `DrizzleTypeError` | 建客户端时没传 `schema` | `drizzle(pool, { schema })`，schema 从 `db/schema.ts` 整体引 |
| 字段名报错，列表里那串和你表定义一样 | 正常，它就是守卫 | 照报错里的名字改；别改成 `as any` |
| 每一处 `rows[0]` 都报 possibly undefined | 生成的四份配置里 `noUncheckedIndexedAccess: true` | 判空或者用解构后 `if (!row) throw`，服务层已经这么写 |
| 传一个不像 uuid 的字符串，类型检查不报 | `uuid` 列在类型里就是 `string` | 值域要挡就自己写校验，别指望类型 |
| 改了列名，服务端红了、页面绿着 | 页面吃的是 `shared/types/` 那份形状，不是表 | 两份都要改；这正是它们分开的代价，别合并 |

## 你自己跑一遍

1. 把 `server/utils/db.ts` 第 6 行注释掉，跑 `npx nuxt typecheck`，看它先报 `TS18004`（这是本轮的读数）；再跑第二遍：把第 31 行改成 `drizzle(pool)`，报的就是那句 `DrizzleTypeError`。两次记得改回来。
2. 造一个临时文件试 `db.select().from(users).then(r => r[0].emial)`，把报错里那串形状和 `db/tables/users.ts` 的七列对一遍。
3. `npx nuxt prepare` 之后读 `.nuxt/tsconfig.app.json`、`tsconfig.server.json`、`tsconfig.shared.json`、`tsconfig.node.json`，确认 `noUncheckedIndexedAccess` 都是 `true`。
4. 需要库的一条留给可丢弃实例：真取一次 `db.select().from(users).limit(1)`，把返回对象的键与那七个字段对一遍。本轮没有连库，这条没有读数。

## 这条线走完

| 步 | 钉住的东西 |
| --- | --- |
| 750 | 默认值是列上的库属性：去掉 `.default('free')` 生成一句 `DROP DEFAULT`（53 字节），换值生成一句 `SET DEFAULT`（61 字节），旧文件一字节不动 |
| 751 | 外键的删除规则不进类型：把 `cascade` 换成 `no action`，typecheck 的报错行逐字相同；而 SQL 侧要两条语句，先 `DROP` 再 `ADD` |
| 752 | 券表故意没有外键：表统计那行是 `6 columns 0 indexes 0 fks`，一次性靠一条带条件的 `UPDATE … RETURNING`；真的加上外键能生成、类型和生成器都不拦矛盾组合 |
| 753 | `set null` 那列在类型里是"字符串或 null"，`cascade` 那列永远是字符串；把 `set null` 写在 `NOT NULL` 列上，两道闸门一声不响 |
| 754 | 十段依赖表：单拿一份会停在哪一句、跑第二遍会停在哪一句；顺序自检一红一绿——乱序报 6 条，换内容报 0 条 |
| 755 | 表结构进应用靠 `db/schema.ts` 这一个出口；`{ schema }` 买的是 `db.query.<表>`，列形状与可空规则都从表定义来，`rows[0]` 的判空是配置要求 |
