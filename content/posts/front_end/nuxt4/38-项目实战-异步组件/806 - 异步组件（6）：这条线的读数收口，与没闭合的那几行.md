## 先看你自己的屏幕上多了什么

这条线是从"少发一点 JavaScript"这个念头开始的。六步走完，回到最初那台服务上，屏幕上留下的是这些数字（下面所有读数都来自同一趟构建与同一趟判据）：

文档区那条链接现在有 12 条实验位入口，`?islandLab=` 后面挂着 11 种档。`/docs/getting-started` 的 HTML 头部 `<link rel="prefetch">` 从这条线开始前的 3 条涨到 6 条——涨出来的三条正是 802、803、805 各自那块实验面板。首页那一趟是 37 条请求、323,785 字节，最大三条里第二条仍然是那块校验库的 78,654 字节。

**这条线为了让自己可读，自己变成了它要优化的对象**。这不是笑话，是收口必须写的第一行：判据要跑就得有载体，载体本身进了产物。

## 六步各留一句

| 编号 | 一句结论 | 凭哪条读数 |
| --- | --- | --- |
| 801 | `Lazy` 只把组件拆成单独文件，第一趟照样下载 | 组件单独成文件，却在第一趟第 27 条被取 |
| 802 | `v-if` 决定渲不渲，不决定取不取 | 三种写法位次 27／29／29，一条都没挪走 |
| 803 | 可见策略要滚进来才接手，空闲策略不等视口 | 视口外点不动、滚进来 66 毫秒后计数翻 1；空闲档没滚也接手 |
| 804 | 时间、布尔、"永不"三种人为时机各有形状 | `after` 等满 1200 毫秒；`never` 被一次 prop 改动当场推翻 |
| 805 | 三条限制都是真的，而且白挂时事件根本不发 | 三种白挂计数都是 0，但点一下就加 |
| 806 | 没有任何一种写法能推迟下载 | 本节那四行：`面板在prefetch里: true`、`起因: ["parser"]` |

## 三种写法各自的分工，最后合成一张表

| 你写的 | 生效在 | 管的事 | 不管的事 |
| --- | --- | --- | --- |
| `Lazy` 前缀 | 打包阶段拆文件 | 代码在哪个文件里 | 什么时候取 |
| `v-if` | 渲染阶段 | 渲不渲、脚本跑不跑 | 什么时候取 |
| `hydrate-on-visible` / `-on-idle` | 水合阶段 | 什么时候能交互 | 什么时候取、内容在不在 |
| `hydrate-after` / `-when` / `-never` | 水合阶段 | 交互时机由谁决定 | 同上 |
| `<link rel="prefetch">` | **服务端 HTML 头部** | **什么时候取** | —— |

前两行是官方承诺过的（`controlling the chunk sizes`），第三行是那节文档自己补的冷水（`they still load eagerly unless conditionally rendered`），最后一行是这条线读出来的、那句冷水在本站不成立的部分：**在这套版本上，只要那位组件静态写在模板里，它就进了这一页的 prefetch 名单，`v-if` 与 `hydrate-*` 都改不了这件事**。

## M4 那三句验收：两句有数，一句缺一次带库的运行

**"禁 JS 时那块内容还在"**——这条线一路都在复核它，五处读数彼此一致：`[异步组件·关脚本] {"有这一行":true,"HTML字节":6543}`、`[延迟水合·关脚本] {"可见档有那一段":true,"空闲档有那一段":true}`、`[定时机·关脚本] {"after":{"有那一段":true},"when":{"有那一段":true},"never":{"有那一段":true}}`、`[限制·出路] {"服务端HTML里有那一段":true,"HTML字节":7416}`，加上基线那条 `[baseline no-js] {"/docs":{"status":200,"h1":1,"testids":19,"text":220,"inlineScript":4}}`。延迟水合、条件渲染、服务端组件这三件事都**不减内容**。

**"错误边界内抛错不许白屏"**——还没开始。基线判据现在读回来是：

```text
[baseline error boundary] {"vueFiles":21,"boundaryHits":0,"mainHits":4,"hasErrorPage":true}
```

`app/` 下 21 个 `.vue` 里，`NuxtErrorBoundary` 出现 **0 次**；同一批文件里 `<main` 有 4 处（这一位是扫描的对照组，证明它真的读了文件而不是读了个空目录）。所以这句话要留给下一条线做，不能拿这条线已经绿的 28 条判据来顶替。

**"页面上的数字要和库里手查的一致"**——本线一次都没跑过带库的判据，这一句仍是空缺。要补上它，需要允许我建一次开发库并跑这两条命令（跑完即止，不留常驻服务）：

```bash
npm run db:migrate
E2E_PORT=3369 npm run test:e2e -- test/e2e/metrics-endpoint.spec.ts test/e2e/async-data-count.spec.ts
```

## 一条构建告警，替这条线说了句实话

`npm run build` 现在会打这一行：

```text
WARN  [INEFFECTIVE_DYNAMIC_IMPORT] app/components/LabLimitPanel.vue is dynamically imported by
app/lazy/lab-object-panel.ts ... but also statically imported by app/pages/docs/[slug].vue,
dynamic import will not move module into another chunk.
```

起因是 805 那两位：同一个 `.vue` 既被页面静态用了一次（"无前缀"那一位），又被出路那一位动态导入了一次。结果就是**它根本没有单独成 chunk**——延迟接手仍然生效（805 的行为读数没变），但"分包"这件事取决于这份文件还有没有别人在静态引用它。这条告警值得留着：它是"行为对了但账没对上"这类情况少数会被编译器主动说出来的例子。

## 这条线没做出来的那件事

目标是"少发点 JavaScript"。六步走完，能确定的是：**`Lazy`、`v-if`、`hydrate-*` 三种写法没有一个能推迟下载**。要让某块代码真的晚点来，只有两条路，都不在这几节文档的范围里——要么让那位组件不出现在这一页的模板里（换成别的入口，比如点了才挂载的另一条路由），要么去动打包层的入口与依赖图。

还有一条留着的空缺：prefetch 在浏览器请求队列里的优先级、会不会挤掉要紧的资源，本线只读到它确实传了多少字节，没读它的排队位置。

## 排错表

| 想复核的东西 | 命令或读数 | 它为什么可信 |
| --- | --- | --- |
| 三种写法各自管什么 | 五份判据同一趟跑 | 位次、DOM、点击行为三位一起读 |
| 下载是谁发起的 | HTML 里 `rel="prefetch"` 的名单 ＋ 网络记账的发起方 | 名单能数、发起方是浏览器自己的账 |
| 跳过的 57 条各缺什么 | `node _research/skip-families.mjs <日志>` | 分类用的是每条用例自己写的那句条件 |
| 内容有没有被延迟掉 | 不执行脚本读一次 HTML | 五处读数彼此一致 |
| 错误边界做没做 | `boundaryHits` | 同一行里带一个非零对照组 |
