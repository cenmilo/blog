Nuxt 文档里有一页叫 Code Style，但它不讲缩进、不讲命名规范，只讲一件事：lint 怎么接。副标题就是结论——"Nuxt supports ESLint out of the box"。

## 官方只推荐一条路：`@nuxt/eslint` 模块

原话：

> The recommended approach for Nuxt is to enable ESLint support using the `@nuxt/eslint` module, that will setup project-aware ESLint configuration for you.

关键词是 **project-aware**。这条对 Nuxt 特别重要：项目的自动导入、别名这些是框架生成的（395/404），普通 ESLint 配置不认识它们，就会把 `ref`、`useFetch` 报成未定义。模块负责把配置和你的项目对齐。

## 装法与生成时机

官方给的 Quick Setup 只有一行：

```bash
npx nuxt module add eslint
```

然后注意这句，生成时机不是装完、而是启动：

> Start your Nuxt app, a `eslint.config.mjs` file will be generated under your project root. You can customize it as needed.

所以流程是**装模块 → 跑起来 → 项目根出现 `eslint.config.mjs` → 之后按需改它**。没启动过就没有那份配置文件，这是很多人装完找不到文件的的原因。改的位置是 `eslint.config.mjs`，不是去改 `.nuxt` 里的生成物（395 那条禁令同理）。

## 一个格式前提：flat config

官方用 callout 点明了这个模块的适用格式：

> The module is designed for the new ESLint flat config format which is the default format since ESLint v9. If you are using the legacy `.eslintrc` config, you will need to configure manually with `@nuxt/eslint-config`. We highly recommend you to migrate over the flat config to be future-proof.

拆成三条决定：

1. 模块是为 **flat config** 设计的。
2. flat config 从 **ESLint v9** 起是默认格式。
3. 还在用 legacy `.eslintrc` 的人：不能靠这个模块自动配好，要改用 `@nuxt/eslint-config` **手动配置**；并且官方"强烈建议迁到 flat config 以面向未来"。

也就是说 `.eslintrc` 不是不能配 Nuxt 规则，而是要走另一条包（`@nuxt/eslint-config`）手动接——这是新项目直接选 flat config 的理由。

## 这一节没讲什么（同样重要）

按文档为准的写法要把边界说清，这一节**没有**提供：

- 任何**规则清单**（没说开了哪些规则、哪些是 error 哪些是 warn）。
- **Prettier / Stylelint** 的配置方式，一个字没提。
- `eslint.config.mjs` 该不该提交进版本控制。
- lint 与 `nuxt typecheck` 的先后关系（类型检查走 399 那条路，跟 lint 是两件事）。

要细节，官方把出口指向 Nuxt ESLint 自己的文档，而不是在这一节展开。

## 和"外部配置文件"那条规矩对齐

347 那张表里有一条：Nuxt 不再读取 `nitro.config.ts`/`vite.config.ts`/`postcss.config.js`/`webpack.config.ts`，但 **eslint/prettier/stylelint/tailwind/vitest/tsconfig 仍各自留文件**。`eslint.config.mjs` 正属于后者——它就该是一个独立文件，别想着搬进 `nuxt.config.ts`。这条边界很多人搬错。

## 自查

- 官方只推荐一条路：`@nuxt/eslint` 模块，作用是给你一套 project-aware 的 ESLint 配置。
- 装法 `npx nuxt module add eslint`；配置文件 `eslint.config.mjs` 是**启动应用时**生成在项目根的，之后按需改它。
- 模块面向 flat config（ESLint v9 起为默认）；还在用 `.eslintrc` 要改用 `@nuxt/eslint-config` 手动配，官方强烈建议迁 flat config。
- 这一节不给规则清单、不提 Prettier/Stylelint、也不谈提交策略；细节看 Nuxt ESLint 文档。
- `eslint.config.mjs` 属于"各自留文件"那一类，不要搬进 `nuxt.config.ts`。
