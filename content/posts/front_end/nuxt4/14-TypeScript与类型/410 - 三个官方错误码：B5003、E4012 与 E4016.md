在 TypeScript 那一章里必须先澄清一件事：Nuxt 的官方错误码不是"类型错误清单"。`runtimeConfig.apiSecre` 少写一个字母，`tsc`/`vue-tsc` 会直接报 TS 错，那串文字里不会有 `NUXT_` 前缀。官方带编号的错误页讲的是**运行时、构建、配置**三类问题。这一篇挑三个最常见的逐个拆。

## B5003：`runtimeConfig.app` 是保留命名空间

官方描述：

> You have custom keys under `runtimeConfig.app`, a namespace Nuxt reserves for internal values (such as `baseURL` and `cdnURL`). Custom keys here can collide with Nuxt's own config.

这条在 395-414 里出现是因为它和 406 的类型增强直接联动——`runtimeConfig.app` 里的 `baseURL`、`buildAssetsDir`、`cdnURL` 是 Nuxt 自己用的（361 那张表），官方另一处的措辞是"Runtime config keys prefixed with `app` are reserved for Nuxt (currently `runtimeConfig.app` and `runtimeConfig.appSecret`). Do not use them for your own values."

官方 Resolution 给了去处，二选一按是否要暴露给客户端决定：

```ts
export default defineNuxtConfig({
  runtimeConfig: {
    // instead of runtimeConfig.app.myKey
    public: {
      myKey: 'value',
    },
  },
})
```

- 要给客户端看到 → 挪进 `runtimeConfig.public`
- 只服务端用 → 挪到顶层自定义命名空间（`runtimeConfig.myKey` 这种）

## E4012：岛屿响应解析失败

官方描述：

> Nuxt could not parse the response returned when rendering a server component (island). This usually means the server component endpoint returned something other than the expected island payload, such as an error page or malformed HTML.

先解释词：**服务端组件（岛屿）**是只在服务端渲染、把 HTML 塞进页面的组件（008/405 那条线）。它有自己的请求端点，返回的是特定格式的负载而不是普通 HTML 片段。

官方列的成因方向是"端点返回了预期负载以外的东西"，举的两个例子是**错误页**和**畸形 HTML**。

官方 Resolution 三步：

> Check the server component for errors that would prevent it from rendering, and confirm the island endpoint returns a valid response. Inspect the network response for the island request to see what the server actually returned.

也就是：① 查那个服务端组件本身有没有让它渲不出来的错误；② 确认岛屿端点返回的是有效响应；③ 打开网络面板看那次岛屿请求实际返回了什么。第 ③ 步是关键——报错只说"解析不了"，真正的原因在响应体里。

和 377 那条 `::warning` 连起来记：岛屿的 teleport 靠水合前一段内联脚本搬位置，所以在 `noScripts` 路由上交互型岛屿部件本来就不工作——那属于配置预期行为，而 E4012 是响应内容坏了，两回事。

## E4016：父页面没渲染 `<NuxtPage />`

官方描述：

> The current route matches a nested page, but the parent page component does not render `<NuxtPage />`. Vue Router can only display a child page inside its parent's `<NuxtPage />` outlet, so the child page is never shown.

官方给的就是这个目录结构，前提是 `parent.vue` 里没有 `<NuxtPage />`：

```bash [Directory Structure]
-| pages/
---| parent/
------| child.vue
---| parent.vue
```

`pages/parent.vue` 与 `pages/parent/child.vue` 同时存在，就构成嵌套路由；子页必须有地方渲染进去，那个位置就是父页里的 `<NuxtPage />`。

官方 Resolution 分两种意图：

> Add `<NuxtPage />` to the parent page component so the child route can render inside it. If you did not intend to create a nested route, restructure your `pages/` directory so the page no longer has child routes.

- 确实要嵌套 → 父页里加 `<NuxtPage />`
- 没打算嵌套 → 改目录结构，让这一节不再有子路由

## 三个码怎么归类

| 码 | 类别 | 一句话成因 | 官方给的下一步 |
| --- | --- | --- | --- |
| B5003 | 配置 | 自定义键塞进了保留的 `runtimeConfig.app` | 挪到 `public` 或顶层自定义命名空间 |
| E4012 | 运行时（服务端组件） | 岛屿端点返回了非预期负载（错误页/畸形 HTML） | 查组件错误 + 看网络面板实际响应 |
| E4016 | 结构（路由） | 父页面没渲染 `<NuxtPage />` | 加上它，或改掉目录别搞出嵌套 |

## 自查

- 官方错误码不按"TS/构建"分类；类型错误来自 `tsc`/`vue-tsc`，没有 `NUXT_` 编号。
- B5003：`runtimeConfig.app` 是 Nuxt 保留命名空间，自定义键挪 `public` 或顶层。
- E4012：岛屿响应解析失败，成因是端点返回了预期负载以外的东西，去看那次请求的实际响应。
- E4016：嵌套页不显示，因为父页没渲染 `<NuxtPage />`；不想嵌套就改目录。
