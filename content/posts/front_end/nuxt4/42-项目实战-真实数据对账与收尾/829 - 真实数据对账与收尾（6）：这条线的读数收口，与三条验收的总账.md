## 这一站不加判据，只把数一次跑齐

会员区这一组功能一共立了三句验收：**页面数字与库里条数一致**、**禁用 JavaScript 时岛屿那块仍出内容**、**门后页要有一道真正的门**。前四站各自读到了一句，最后一站（822）读的是公开实验位。本篇做的事只有一件：把这一组判据在当前代码上重新跑一遍，把每句验收落到"哪条命令、哪一档判据、读出什么"。应用代码零改动。

`--workers=1` 不是可选项：带库那几本都往同一张表写探针行，并行跑会互相看见对方的行，读数就不是那一位用户的了。带库那趟只点名要跑的规格文件，绝不带库跑全量——全量里有一条钉的是"没配库 ⇒ 503"。

本轮整趟读到的其它数字：默认三本 1 passed／15 skipped (31.2s)；带库三本 16 passed (1.6m)；门与趟数那两本 5 passed (43.6s)；全量端到端 253 passed／72 skipped (58.1s)，跳过分类是要库 40、要内容目录读得到 14、要另一趟构建的开关 10、要外部服务变量 8；聚合八项全过（单测 281 条、组件级 67 条、typecheck 7298ms、build 27570ms）。

## 五站各留一句（都用本轮打印值）

824 那一站说的是：能连库读到行数这件事本身要先跑通。同一句话两种问法——`db-probe` 那把工具认 `NUXT_DATABASE_URL` 也认 `DATABASE_URL`，而应用运行时只认前一个（运行时配置只捡带 `NUXT_` 前缀的变量）。本轮库里 `meter_events` 是 1 行／1 位用户。

825 把库、接口、页面三段一次对平：

```json
[对账·三段] {"库里的分组":[{"kind":"login","n":1}],"库里的总数":1,"接口状态":200,"接口总":1,
  "接口分组":[{"kind":"login","count":1}],"页面状态":"success","页面总数":"1","页面响应状态":200}
```

空表也是合法形状：`{"状态":200,"总":0,"分组长度":0,"页面那一位":"0"}`——第一次进来什么都没有，接口不该 404 也不该 500，页面不该显示 `-`。

826 说的是分项要逐位对，而两栏相等证明不了同一份：

```json
[对账·逐位] {"接口体":{"total":3,"kinds":[{"kind":"probe_a","count":2},{"kind":"probe_b","count":1}]},
  "渲出来的":[{"名":"probe_a","数":"2"},{"名":"probe_b","数":"1"}],"列表项数":2}
```

把出口里那个 `key` 摘掉，负载里 `payload.data` 的键清单从 `["console:metrics"]` 变成两个自动键，而逐位比、两栏、水合后三档全部照旧绿。这一位是整条线最容易被糊过去的地方。

827 写一笔进去，看谁先变、谁不变：

```json
[写入·谁没变] {"进场顶栏":"1","库里":2,"没动的顶栏":"1","接口现在":2}
[写入·两法] {"点完顶栏":"2","点完面板":"2","刷完顶栏":"3","刷完面板":"3"}
[写入·隔离] {"甲":{"库":1,"接口":1,"页面":"1"},"乙":{"库":3,"接口":3,"页面":"3"},"全表":5}
```

三句合起来：页面那一栏是进场那一刻服务端算好的读数，接口每次都现算，两处共用一个键才会一起变。

828 读的是门后页不发脚本照样出真数：

```json
[门后·不发脚本] {"脚本面":{"入口模块脚本":0,"全部脚本标签":0,"modulepreload":0,"prefetch":0,
  "负载段在":false,"importmap在":false,"整页字节":3591},"接口总":2,"页面那一位":"2","状态栏":"success"}
```

同一枚会话下两页逐位比，`{"开规则":{"页面":"3","props":"页面递进来的总数=3","静态位":"1"},"没开":{逐项相同}}`——岛屿那块显示的数来自 props，props 来自服务端算好的那份库里的数。

## 三条验收逐句对着读

| 验收那句 | 现在能不能算合上 | 命令与读数 | 还差什么 |
| --- | --- | --- | --- |
| 页面数字与库里条数一致 | **本机可算合上**，条件见下 | 带库那趟 16 passed；三段链 `1=1=1`、逐位 2/1 对 2/1、三位置一起 `2→3`、两位隔离 1 与 3 | 证据只在带库那一趟；默认趟 15 档是 skip |
| 禁 JS 时岛屿区块仍出内容 | **合上**（公开位＋门后位各半句） | 822 那一站的三档位；本轮 `[门后·不发脚本]` 四类全 0 而正文与数字仍在、`[门后·逐位]` 两页逐项相同 | 无 |
| 门后页要有一道真正的门 | **合上**，且新页上也重读了一遍 | `console-gate` 带库 4 passed（`302`、`location=/me`、正文 89 字节无标记句、`x-request-id` 在）；`[门后·无会话]` 两位逐位相同 | 无 |

第一句那句"合上"要带两个条件，别只抄结论。其一，它只在 `NUXT_E2E_DB=1` 那一趟成立：默认趟里这一族 15 档是 skip，而 **skip 是没测，不是测过了**。其二，"对平"是同一时刻三处相减，不是并发下的保证——库里在两趟读之间被写入时，`分组后相加` 与 `count(*)` 就会不等（本轮读到的是 `{"分组后相加":1,"直接count":1}`，那是本机没有并发写的形状，不是它给了保证）。

## 还缺什么，明写

- **应用侧那条写入路径始终没被真触发过。** 记一笔画的是登录那一步调的 `recordMeterEvent`，而真登录要一封真邮件；这一族判据一直在"要外部服务变量"那一池（本轮 8 条）。这一线的读数是用 SQL 写探针行问出来的，问的是缓存归属，不是"应用的写入通了"。
- **流水线里没有带库那一趟。** 上面所有正向读数都来自本机；构建流水线上不跑 `NUXT_E2E_DB=1`，所以这条验收在项目层面还挂着"未验证"。
- `static.data` 那一支没读到。默认缓存函数在水合之后读的是 `nuxtApp.static.data[key]`，而会员区这几条路由都不预渲染，所以那一路本机压根不会走到；要读它得拿一条预渲染页或缓存路由。
- `refreshNuxtData` 与组件自带 `refresh` 的分工、`dedupe` 在连点两次时的行为，都只有文档那两句话，没落成读数。
- 自动生成的键长什么样只读到形状（`$fptszqe08h2y3` 这种 `$f` 加一串），官方那句 call site location 具体怎么编码，没量。
- 默认那趟每次都有 4 行 `ECONNREFUSED` 日志（自 824 那几趟就在），还没定位是谁在连什么；以及那条预取判据偶发红（`landing.spec.ts:179`，本轮没撞）。
- 岛屿的 props 会进查询串是文档明写的（`nuxt-island` 那一节的提醒：会出现在访问日志、CDN 缓存与 `Referer` 里），本站只递过数字，没量过"递了敏感值会怎样"这条防线。

## 怎么自己跑一遍

1. 用自己的库：把连接串放进项目根的 `.env`，变量名用 `NUXT_DATABASE_URL`（另一个名字只给命令行工具用，应用运行时不认）。文章里不写任何真实主机、账号或口令。
2. 迁移跑一遍，让 `meter_events`、`sessions`、`users` 三张表存在。
3. 带库那趟只点名规格文件，并加 `--workers=1`；跑完看的是 16 passed，不是"整趟绿"。
4. 探针行都由用例自己建、自己删（计量行与会话都挂在 `onDelete: 'cascade'` 上，删用户就一起带走）。跑完库里不该多行；本轮收尾时读回的是背景那 1 行／1 位用户。
5. 想看禁 JS 那一格，不必关浏览器引擎：`routeRules` 里 `/console/nojs-lab` 那一位是服务端不发脚本，与"引擎关掉只禁执行"是两件事（819 那一站并排量过）。

## 这一线留下的账

这一线新增判据 22 条（单测 6＋端到端 16），改动应用代码三处：会员区一位"重新取一次"按钮、一对门后实验页、两条 `routeRules`。还登记了一次事实性变化：新增门后路由要同步四条既有清单（门后名单与计数、`noScripts` 键清单、出口调用清单两处）。上一线（禁 JS 与 `noScripts`）累计的未闭合与各站新账，全部并进上面那节"还缺什么"。

下一组功能换到订阅付费：把 webhook 的三类事件，连同重放、乱序、签名错这五种输入，摆成一张"响应与库里结果"的表。两条边界先说死：这一段用测试模式的密钥与本地录制的事件样本，**不需要你提供真账号**；换成国内渠道要动哪几层接口只讲边界，**明写未接入**。
