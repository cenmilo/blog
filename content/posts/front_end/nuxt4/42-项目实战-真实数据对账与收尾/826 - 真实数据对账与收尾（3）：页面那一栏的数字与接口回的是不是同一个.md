## 屏幕上写着两个数，凭什么说它们是同一个

打开会员区，你会看到数字出现在两处：上面一大块里有状态、总数，下面还跟着一个列表，一种动作一行；再往下是第二块，标题就写着「第二块，同一个出口」，里面也是状态加总数。这一次同一条链上的三份读数是这样的：

```json
{"metrics":{"total":3,"kinds":[{"kind":"probe_a","count":2},{"kind":"probe_b","count":1}]}}
```

库里三行、两种动作，各两行和一行。要确认"页面显示的就是库里那几个"，其实要回答三个不同的问题：分项列表能不能**一项一项**对上；两块的总数是不是同一个；两处调用读的是不是**同一份**数据。前两个看屏幕就能判断，第三个看不出来——三份数据如果数值刚好相同，屏幕上完全是一片正常。

## 这一页上到底有几个调用点

页面自己取一次，面板再取一次，两处调的是同一个出口：

```ts
// app/pages/console/index.vue:26
const { data: consoleMetrics, status: metricsStatus } = await useConsoleMetrics('/api/console/metrics')

// app/components/ConsoleMetricsPanel.vue:6
const { data: panelMetrics, status: panelStatus } = await useConsoleMetrics('/api/console/metrics')
```

出口只有一行，键是烤死在里面的：

```ts
// app/composables/use-console-metrics.ts:10
export const useConsoleMetrics = createUseFetch(() => ({
  key: 'console:metrics',
}))
```

所以"两处是不是同一份"这一问，落地就是这一问：**`console:metrics` 这个键，在浏览器收到的那份负载里占了几位**。

## 分项列表：按文字逐位比

判据加在上一站那个文件后面（`test/e2e/dashboard-reconciliation.spec.ts`），跑法不变：

```bash
NUXT_E2E_DB=1 npm run test:e2e -- test/e2e/dashboard-reconciliation.spec.ts
```

第一项要先把数据造出能区分的样子。库里现存的动作行只有一位用户、一种动作（上一站读到的是 `login` 一行），一项一份时"逐位比"会退化成"比一个数"——顺序错了、把总数串到分项上，都看不出来。所以这一档自己建一个用户，写两种类共三行，用完自己删（计量表的行是账号自己的东西，外键是 `cascade`，删用户就把行一起带走）。

然后同一枚会话下读两次：接口体拿 JSON，页面拿 HTML，把列表里那些 `<li>` 的文字抠出来，剥掉标签、压掉空白，按 `': '` 拆成名字和数字。本轮的打印：

```json
[对账·逐位] {"接口状态":200,"页面状态":200,
  "接口体":{"total":3,"kinds":[{"kind":"probe_a","count":2},{"kind":"probe_b","count":1}]},
  "渲出来的":[{"名":"probe_a","数":"2"},{"名":"probe_b","数":"1"}],
  "列表项数":2,"分项数字":["2","1"]}
```

顺序先钉一次：接口那一段的 `kind` 按字典序排，两边按同一规则排好，才谈得上"第几项对第几项"。比的是页面上写出来的字符，不是数字类型——屏幕上是 `2` 这个字符，接口回的是 `2` 这个数，直接 `toEqual` 会永远红。

## 两块面板：服务端渲的那一份里就相等

第二问只读服务端发出去的那一份 HTML，不碰浏览器接手之后的事：

```json
[对账·两栏] {"接口总":3,"顶栏":"3","面板":"3",
  "顶栏状态":"success","面板状态":"success","面板块在不在":true}
```

两栏的状态栏也都是 `success`。这里要防的是上一站已经被纠正过一次的那个混淆：页面状态栏的取值是 `success`／`pending`／`error`／`idle` 四个，接口那边回的是 `200`，**两套词**，谁也不能替谁。数字这一位读不到时页面显示的是 `-`，所以看到 `-` 应该去看状态栏，而不是以为"库里就是 0"。

## 第三问：把负载摊开数键

负载是服务端拼 HTML 时一起塞进响应体的一段 JSON（浏览器接手时读它，这一份就免掉一次请求）。它不是一棵嵌套的树，而是**一维数组加下标引用**：对象里的值存的是"第几位"。所以要把 `payload.data` 那一位摊开才看得见里面有几个键。本轮：

```json
[对账·键] {"接口体顶层键":["metrics"],"负载data键":["console:metrics"],
  "那一位的键":["metrics"],"键名出现次数":2,
  "错误槽键":["console:metrics"],"错误槽那一位":"(空位：-1 就是 UNDEFINED)"}
```

`data` 里只有一个名字，就是那个烤死的键。这就是"两处读同一份"的证据。

顺带一条被自己绊到的地方：**"名字出现几次"当不了判据**。这一页的负载里 `console:metrics` 出现 2 次，第二处在这里：

```text
...["ShallowReactive",22],{"console:metrics":-1},true...
```

摊开之后才明白，第二次出现的位置是负载根上的错误槽（根的形状是 `data`、`state`、`once`、`_errors`、`serverRendered`、`path` 那几位），里面给这个键留了一个位，值是 `-1`——那正是序列化里"空"的编码。所以正确的问法是"**`data` 的键清单里有几个名字**"，而不是"这个字符串出现几次"。官方讲 `useNuxtApp` 那一节只列了 `payload` 的 `serverRendered`、`data`、`state` 三位，`_errors` 这一位文档未提，属于产物里读到的形状。

## 把键摘掉：只有一档红，其余三档照样绿

上面的绿灯值不值钱，看摘掉键之后是什么。把出口改成不写键，重新构建、重跑同一批判据：

```json
{"负载data键":["$fptszqe08h2y3","$fykrht3o51g3o"],"键名出现次数":0,
 "那一位的键":[],"那一截":"(读不到)"}
```

自动键长这样，一个调用点一个，于是 `data` 里出现两位。而本轮的失败只有一档——**数键的那一档**；逐位比、两栏、水合之后那三档全部继续绿。这不是巧合，两处各自取数、取的是同一个接口，服务端拿到的数值仍然一模一样。

这就是"两栏数字相等证明不了只取了一份"。官方那两句话正好对上：

> The auto-generated key is unique to each call site, so calling `useFetch` with the same URL and options in different components will not share state and each call performs its own request.

> Multiple instances of the same component do share state, since they use the same call site. To share the same `data`, `error` and `status` refs across different components, provide the same explicit `key` to each call.

参数表里 `key` 那一行还给了自动键是怎么来的：generated from the URL, options and call site location in the source code——源码里的调用点位置参与生成，所以同一段代码在两个组件里就是两个键。

改回原样后八档全绿。另一条对照更直观：把面板那一行的表达式从 `panelMetrics.metrics.total` 换成 `panelMetrics.metrics.kinds.length`，两栏那一档立刻红：

```text
Error: 面板那栏 ≠ 接口体的 total：两栏里有一栏读的不是这一趟
Expected: "3"
Received: "2"
```

## 水合之后会不会自己改数

浏览器接手这段 HTML、把事件挂上去叫**水合**。接手之后组件会重新跑一遍取数语句，此时读的是负载里那一份还是再发一次请求？官方给的默认缓存函数就写明了这一支：

```ts
const getDefaultCachedData = (key, nuxtApp, ctx) => nuxtApp.isHydrating
  ? nuxtApp.payload.data[key]
  : nuxtApp.static.data[key]
```

水合中读 `payload.data[key]`。判据做法是整页打开那一页，**先等到水合标记出现**再读数（不等的话读到的还是服务端那份，这一档就没在问它要问的事）：

```json
[对账·水合后] {"接口总":3,"顶栏":"3","面板":"3","状态":"success",
  "列表":["probe_a: 2","probe_b: 1"]}
```

与水合前逐字相同，分项列表也原样。这一档不问"发了几趟"——那件事在讲取数次数那一站已经在真数据上数过了（整页加载 0 趟、客户端导航 1 趟、走开再回来 1 趟），重复量只会多一条会互相打红的判据。

## 手上剩的位

接口体顶层只有 `metrics` 一个键，负载里那一位的键清单也只有 `metrics`，所以模板里必须写成 `consoleMetrics.metrics.total`——多出来的那一层包装就是页面手上"剩的位"。这一页没有用 `pick`，参数表里那一行 Only pick specified keys from the result 的效果在讲负载收敛那一站已经量过；这里只把它的对立面钉住：**不挑就整份带**，接口多回一位，页面就多一位对不上的可能。

## 读数对不上时先看哪一处

| 症状 | 先看哪里 | 为什么 |
| --- | --- | --- |
| 两栏数字不等 | 面板里那一位的表达式 | 同一个键两份读数，中间必有一处读的不是这一趟 |
| 列表行数与接口项数不等 | 模板 `v-for` 的来源与排序 | 分组顺序是字典序，两边不同规则就错位 |
| `payload.data` 里两个键 | 出口里的 `key` 是否被顶掉或摘掉 | 自动键按调用点生成，两处就是两份 |
| 数字栏显示 `-` | 状态栏是不是 `error` | `-` 是没取到，不是 0 |
| 四条全部 skip | 有没有带 `NUXT_E2E_DB=1`，连接串变量名 | 这一档没库无可对；skip 是没测，不是测过 |
| 带库跑打红了"没配库回 503"的档 | 是不是跑了全量 | 带库只点名这一条规格 |

## 这一档把"一致"从两句变成三句

三段链现在是四件事：库里的行数、接口回的聚合数、**分项逐位**、**两栏同一份**，再加一条"同一份"的证据只能从负载里数出来。下一站要让数字真的变一次——写一行进去，再看三个位置各自变成多少、谁没变。

本轮跑法记录：默认那趟八条全 skip；带库那趟 8 passed；摘键变异只红数键那一档；改表达式变异红两栏那一档；全量端到端 252 passed／65 skipped（skip 分类：要库 33、要内容目录读得到 14、要另一趟构建的开关 10、要外部服务变量 8）。库里那三行是这一档自建的探针行，跑完即删。
