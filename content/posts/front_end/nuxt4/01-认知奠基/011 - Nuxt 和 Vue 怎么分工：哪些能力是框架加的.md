上一讲算完了"不用 Nuxt 要做什么"。这一讲换个方向问：**Nuxt 到底改了 Vue 的哪些规矩，哪些完全没改？** 把这条线分清，你就能判断一个报错是"我 Vue 写错了"还是"我不懂 Nuxt 的约定"。

## 官方的分工声明

这一页的标题下就是这么一句：

> Nuxt 使用 Vue.js，并增加了诸如**组件自动导入**、**基于文件的路由**，以及**为 SSR 友好使用而准备的组合式函数**等功能。

三件事正好是三种性质：一个是开发体验（少写 import），一个是架构约定（文件即路由），一个是运行模型（SSR 友好的取数）。**第三件最容易被低估**，因为它意味着"有一个纯 Vue 里不存在的约束"。

## 完全没被改动的部分：组件怎么写

Nuxt 没有发明新的组件语法。官方对 SFC 的定义就是 Vue 自己的定义：

> Vue 的单文件组件（SFC 或 `*.vue` 文件）封装了一个 Vue 组件的标记（`<template>`）、逻辑（`<script>`）与样式（`<style>`）。Nuxt 为 SFC 提供**零配置**体验，并带有热模块替换（HMR），带来顺畅的开发体验。

注意这句里的分工：**前半句是 Vue 的，后半句是 Nuxt 的。** 组件内部的一切（props、emit、插槽、`<script setup>`、生命周期钩子）都照 Vue 的规矩走。

所以本系列不会替你教 Vue 语法——官方自己也说了：

> 虽然使用 Nuxt 并不要求对 Vue 有深入的知识，但我们建议你阅读 vuejs.org 上的文档并过一遍一些示例。

我的建议（000 讲也提过）：**先用 Nuxt 跑通一个应用，再回头补 Vue 的组合式 API**。因为 Nuxt 的约定会替你建立一套正确的心智模型，反过来学容易先陷进一堆框架无关的细节。

## 改动一：组件不用导入，而且没用的不进包

官方在 Vue 开发那页的原文：

> 在 Nuxt 项目的 `app/components/` 目录里创建的每个 Vue 组件，都将可以在你的项目里使用**而无需导入**。**如果一个组件在任何地方都没有被使用，你的生产代码就不会包含它。**

这句有两个层次，第二个常被漏掉：

1. **书写成本降低**：不用为每个组件写 `import`。
2. **产物不因此变大**：tree-shaking 仍然生效，没用到的组件不进包。

于是有一个非常实用的推论：**"我没写 import"和"这个组件被打包进去了"是两件事。** 想知道某个组件真的被用到，去看产物或者用 `nuxt analyze`（构建那一段会讲），而不是去看模板里有没有 import 语句。

## 改动二：页面文件就是路由

官方说法：

> 大多数应用需要多个页面以及一种在它们之间导航的方式。这被称为**路由**。Nuxt 使用 `app/pages/` 目录与命名约定，**用官方的 Vue Router 库**直接创建映射到你文件的路线。

最后那几个字很关键：**用的是官方 Vue Router**。Nuxt 不是自造一套路由，它是**替你生成 Vue Router 需要的配置**。这个事实解释了后面很多事：为什么 `useRouter()` 的行为与 vue-router 提供的那个一致、为什么路由中间件不传 `next()` 而是用返回值、为什么命名路由和 params 的概念和 Vue Router 文档通用。

代价你也已经知道了：**"这个页面对应哪个 URL"由文件位置决定。** 路由类问题要先看目录，这一点在路由那一段会反复出现。

## 改动三：为 SSR 准备的组合式函数

第三件是真正的分工分水岭。纯 Vue 应用里你调 API 就是 `fetch()`，没有"在哪一侧执行"的问题；Nuxt 里官方给的是：

> **取数工具**：Nuxt 提供组合式函数来处理 **SSR 兼容**的数据取数，以及不同的策略。

以及一句会决定你怎么写代码的说明：

> Nuxt 自动导入用于执行数据获取、访问应用上下文与运行时配置、管理状态，或者定义组件与插件的函数与组合式函数。
>
> Vue 暴露了诸如 `ref` 或 `computed` 这样的响应式 API，以及生命周期钩子和辅助函数，都由 Nuxt 自动导入。

两类都"自动导入"，但**约束不一样**。Vue 那批（`ref`、`computed`、钩子）你在组件里随便用；Nuxt 这批里有很多依赖**上下文**，官方的原话是：

> 当你使用 Vue 和 Nuxt 提供的内置 Composition API 组合式函数时，要注意它们中的许多都依赖于在正确的*上下文*里被调用。
>
> 这意味着（除了极少数例外）你**不能**在 Nuxt 插件、Nuxt 路由中间件或 Vue setup 函数之外使用它们。而且必须**同步**使用——也就是说，你不能在调用组合式函数之前 `await`……

这就是那个"纯 Vue 里不存在的新约束"。**很多新手的第一次框架级报错就来自这里**（`Nuxt instance is unavailable`），而它看起来像是 Nuxt 的 bug，其实是分工：Vue 的规矩没变，Nuxt 加了一条。

上下文这条线后面会专门用一整篇讲（组合式函数与自动导入那一段），现在只要认住：**同样是自动导入，Vue 的没有上下文要求，Nuxt 的大多有。**

## 一张分工表收束

| 事项 | 谁规定 | 你的动作 |
| --- | --- | --- |
| 组件内部语法（props/emit/插槽/生命周期） | Vue | 照 Vue 文档写 |
| 组件是否要 import | **Nuxt** | 不用写，但要知道没用到的不进包 |
| 页面与 URL 的关系 | **Nuxt**（底层用官方 Vue Router） | 先看文件位置，再谈路由配置 |
| 取数 | **Nuxt**（SSR 友好） | 别裸用 `fetch` 决定页面数据；注意水合复用 |
| 响应式 API 与钩子 | Vue，由 Nuxt 自动导入 | 注意自动导入的 `ref`/`computed` 在模板里不解包那条限制 |
| 组合式函数的调用位置 | **Nuxt** | 插件 / 路由中间件 / setup，且同步调用 |
| 应用启动时做什么 | Nuxt（`app/plugins/`）+ Vue 插件 | 分清"运行期插件"与"构建期模块" |

最后一行顺手接上 009 讲的区分：`app/plugins/` 的官方说明就是"**在 Nuxt 应用创建时使用 Vue 插件及更多内容**"——它既管 Vue 那套 `app.use()`，也管 Nuxt 自己的启动逻辑。
