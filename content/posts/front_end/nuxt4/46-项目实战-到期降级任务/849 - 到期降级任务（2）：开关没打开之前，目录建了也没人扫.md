屏幕上这一站什么也没多。多出来的是仓库里的两样东西：一个新目录 `server/tasks/`，和配置文件里的一行开关。上一站数出来的那几个 0，这一站要还掉两个。

## 那行 import 抄不得

Nitro 官方那一节的示例长这样：

```ts
import { defineTask } from 'nitro/task'

export default defineTask({
  meta: { description: 'Run database migrations' },
  async run () { return { result: 'Database migrations complete!' } },
})
```

本站照着抄，`nuxt build` **成功**，产物照出，屏幕上什么都没有——因为 `'nitro/task'` 这个子路径在本项目装的版本里不存在。Nuxt 4.5 带的是 nitropack v2，`defineTask` 在 `server/` 侧属于自动导入，那一位的来源写在生成物里：

```
.nuxt/types/nitro-imports.d.ts
  const defineTask: typeof import('../../node_modules/nitropack/dist/runtime/internal/task').defineTask
```

只有跑 typecheck 才看得见那一句：`server/tasks/refresh-roles.ts(11,28): error TS2307: Cannot find module 'nitro/task'`。**同一个错误，构建说没事、类型说有**——这一站的写法因此是不写 import，而它的验收线从"build 过了"挪到"`npm run check` 八项过了"。

正确形状落在磁盘上是这一份（`export default` 一个任务，名字与描述写在 `meta` 里，业务先不做）：

```
[注册·形状] {"目录":["refresh-roles.ts"],"有名字":true,"默认导出":true,
            "meta名字":"subscription:refresh-roles","有描述":true}
[注册·import] {"那份文件里的显式import":false,"配置文件里":false}
[注册·开关] {"开关处数":1,"在读nitro节里":true}
[注册·还没有业务] {"取此刻":false,"碰库":false,"写角色":false}
```

## 它现在回报"什么都没做"，这是有意的

`run()` 的返回体只有一位 `result`（那是这一层的形状：跑完了要能带东西回来），本站这份带的是两个字段——`处理行数: 0` 与一句"选取规则还没写（850），落点写入也还没开（851）"。为什么不干脆让它去数几行、显得像个能跑的任务？因为 853 那一站要验的是**同一份任务连跑两次不重复动手**，比对的就是这两次的返回。今天要是随手编一个数字，那条比对就是空的，红也红不出道理。

同理，这一站没有顺手把"每日 03:10"那张排期表也填上。定时触发与手工触发是两件事：spec 那句话里两个都在，但一次只验一件，坏了才说得清是哪一件坏的。排期留在 853 一起判。

## 开关那句原话，和它挡住的那种排查

`api/commands/task` 那一节的提示块是这么写的：**Nitro 只在任务开关打开之后才扫你的 `tasks` 目录**，并且直接给了写法——

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  nitro: {
    experimental: {
      tasks: true,
    },
  },
})
```

本站开关只写一处，判据把"只写一处"也钉住：

```
[任务层·配置] {"nitro那几行":["nitro: {","nitro: { prerender: { crawlLinks: true, routes: ['/'] } },"],
              "开关写着":true,"在nitro节里":true}
[任务层·目录] {"顶层目录":["api","middleware","routes","services","tasks","utils"],"defineTask处数":1,"task函数处数":0}
```

`nitro` 那两行里，第一行是这次新加的顶层节，第二行是 `$production` 里原有的预渲染设置。**要留意的是本站还有一个 Nuxt 自己的 `experimental` 节**（放 `payloadExtraction` 那一位的），所以"配置里有 `experimental`"不等于任务开关开了——那条判据问的是 `nitro: {` 底下紧跟着 `experimental: { tasks: true`。

## "它到底被扫到了没有"，今天还没有一个能证到的读法

这是本篇最该写清楚的一段。试了三个面：

| 读法 | 结果 | 够不够格 |
| --- | --- | --- |
| `nuxt prepare` 之后在生成物里找那个名字 | 关着找不到，开着也找不到 | 不够。它压根不生成任务表，两侧同为"找不到"，问不出任何事 |
| `nuxt build` 之后在 `.output` 里找那个名字 | 找不到，也没有名字带 `task` 的分块 | 不够。产物是打包压缩过的，**查不到不等于没注册**（这条本站记过一次） |
| 对着跑起来的服务器问 `nuxt task list` | 这一站没跑：上一站试起开发服务时被本机策略判为"要用户确认的常驻服务"，同一口径下这一站没有再试 | 只有这一条够格 |

所以结论要写成两句：**形状与开关这一站就位了；"被扫到"这一格仍是空的**，判据里也没有任何一条假装它成立。想自己补这一格的，两条命令按顺序跑：

```bash
cd Substrate && npx nuxt dev --port 3756        # 另开一个终端
npx nuxt task list --url http://localhost:3756  # 应能读到 subscription:refresh-roles
```

读到名字，才算把这一格填上；读不到，回来查 `nitro.experimental.tasks` 那一位，而不是先怀疑目录名。

## 变异一次，照出三条判据自己的毛病

新写的四档要能被子变异撞红，于是把三处改坏同时下手（那行 import 加回来、`meta.name` 删掉、任务里加一句 `Date.now()`、开关翻成 `false`），红的是该红的那几档——顺带照出三个不是代码问题的东西：

| 撞出来的 | 症状 | 归谁 |
| --- | --- | --- |
| 上一站 `⑤` 里那条"其中在 `tasks` 目录的取此刻者"从不红 | 它是从一份**已经按 billing 收窄**的名单里再筛的，永远筛不出 `server/tasks/` | 判据的死断言。改成扫整个服务端，同一批变异立刻把它撞红 |
| "这一站还不写角色"那条被自己的说明文字绊红 | 任务文件的 `description` 里写着"把 users.role 刷新成……" | 判据。摘掉字符串再问；同时**别把摘完串的正文喂给找 `'admin'` 那类字面量的断言**，那会把真读者也摘没了，变成假绿 |
| lint 红在 `node:fs` 被 import 两次 | 新档里先写了 `readFileSync` 又补了一行 `readdirSync` | 代码。合并成一行，顺手去掉没用到的那位 |

三处都还原后再跑一遍全量单测：**372 条／58 文件**全过。

## 你自己跑一遍

```bash
cd Substrate
npm run test:unit -- task-registration task-layer-baseline   # 4 加 5 条，离线
npm run check                                                # 八项，含 typecheck
```

| 撞上的现象 | 原因与读法 |
| --- | --- |
| 任务文件加了，`nuxt build` 也过了，`nuxt task list` 还是空 | 先看开关；开关在就查那行 import 是不是抄了 v3 的子路径——那种错构建不报 |
| typecheck 报 `TS2307: Cannot find module 'nitro/task'` | 就是上一条。`server/` 侧 `defineTask` 是自动导入，删掉那行即可 |
| 判据里"取此刻的名单"少了一个名字，但你没动过逻辑 | 八成是只认了一种写法。名单式子要并起 `Date.now()` 与空参 `new Date()` |
| 一条断言怎么改坏都不红 | 怀疑它筛的那份名单已经被上一步收窄过滤过——本轮那条就是这么被照出来的 |
| `nuxt task list` 报连不上 | 它对着跑起来的服务器说话，要么起 dev，要么用 `--url` 指一个在跑的实例 |

## 收了哪一格，还欠哪一格

这一站还掉的是"目录不存在"和"开关没开"那两个 0；**还欠"它被扫到了"这一格**，因为够格的读法需要一次授权起服务。这个欠法要带着走后面几站：850 写选取规则时，判据仍然只能钉形状与纯函数那一层，除非那一格先补上。

下一站（850）问的是"**谁该被降**"：选取要只调上一线那一份判定规则（全站唯一出现比较符号的地方），而"那一格判不出时刻"的人**不降**——把脏数据的后果留给本站自己，不摊给用户。

## 本文依据

- `docs/4.x/api/commands/task`——`nuxt task list`／`nuxt task run <名字> --payload` 的用法，以及那句"任务开关没打开时 Nitro 不扫 `tasks` 目录"和它的 `nitro.experimental.tasks` 写法。
