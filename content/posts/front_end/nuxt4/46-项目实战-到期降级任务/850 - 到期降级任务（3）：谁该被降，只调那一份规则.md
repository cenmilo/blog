## 最省事的写法会降错三种人

前面那条线上已经有一份判断叫"还占着会员位吗"（`entitlement.ts` 的 `占位行`），下单那一路用它挡人。看一眼就会想：降级不就是它的反面——

```ts
// 看着最省事的写法，本站没有采用
const 该降 = (行, 现在) => 占位行(行, 现在).length === 0
```

三种输入下它当场把人降错：

| 那一行长什么样 | `占位行` 答 | 取反就变成 | 应该 |
| --- | --- | --- | --- |
| `active`，周期末是空的（或写的是 `infinity`，读出来不是个时刻） | 不收 | 该降 | 不动手：读不出是本站自己写坏那一格，不是他到期了 |
| `past_due`，这一期还没过 | 不收（845 明写"欠着不是没了"，收了就堵死补付那条路） | 该降 | 不动手：欠着钱正在宽限期里 |
| 状态栏里是一个站外的词（那一列在库里就是普通文本，人工修数的痕迹） | 不收，名单里没有它 | 该降 | 不动手：连那一行说什么都没读懂 |

三个"不该降"理由各不相同，所以答案不能压成一个布尔。四个值里只有"该降"要动手，另外三种都写着"这一趟别动他"，但依据要分开存着：下一站写日志、再下一站发提醒邮件，都靠这一位认出该给谁发。

```ts
export type 降级判定 = '该降' | '还在期内' | '等补付' | '判不出'

export function 判降级 (行: readonly 占位候选[], 现在毫秒: number): 降级结论 {
  if (行.length === 0) return { 判定: '该降', 依据: '没有一行', 命中的行: null }

  // 先拒绝：读不懂的行排在前面，坏格子要露出来，不该被另一行的好消息盖掉。
  const 不认识 = 行.find(这一行 => !合法状态.includes(这一行.status))
  if (不认识) return { 判定: '判不出', 依据: '状态名不认识', 命中的行: 不认识.id ?? null }

  const 读不出 = 行.find(这一行 =>
    要周期末说话的状态.includes(这一行.status) && 判周期末(这一行.currentPeriodEnd, 现在毫秒) === '无从判断')
  if (读不出) return { 判定: '判不出', 依据: '周期末读不出', 命中的行: 读不出.id ?? null }

  // 再放行。"什么算占位"只在 845 那一份里定义，这里不重抄。
  const 还占着 = 占位行(行, 现在毫秒)
  if (还占着.length > 0) return { 判定: '还在期内', 依据: '还占着位', 命中的行: 还占着[0]?.id ?? null }

  const 欠着 = 行.find(这一行 => 这一行.status === SUBSCRIPTION_PAST_DUE && 判周期末(这一行.currentPeriodEnd, 现在毫秒) === '未到')
  if (欠着) return { 判定: '等补付', 依据: '欠着等补付', 命中的行: 欠着.id ?? null }

  return { 判定: '该降', 依据: '没有一行还占位', 命中的行: null }
}
```

两个细节要停下来看。**入参是一整套行，不是"最新那一行"**：一个人可以同时有两行订阅，旧那行还在期内就不能降。**结论里带一个 `命中的行`**：它把这一票指回具体那一行——日志只写"判不出"，运维还得自己去库里翻。

时刻这一头，整份文件里没有一次 `Date.now()`，也没有一个比较符号：时刻由调用方传进来，比较只走那份已经跑过乱序与重放的规则，全站唯一出现比较符号的地方仍然是它。

## 边界表：二十一行样本各落到哪一格

期望值是手敲的，不从被测函数里取——从实现里取期望，实现改成什么样都验不出来。读数原样贴几行，`现在` 固定成一个数，方便看"相等那一瞬"：

```
[降级·边界表] {"现在":1000,"样本数":21,"读数":[
  "生效中、周期末正好等于现在→该降/没有一行还占位/-",
  "生效中、周期末晚一毫秒→还在期内/还占着位/a",
  "逾期未付、这一期也过了（宽限期不是无限期）→该降/没有一行还占位/-",
  "生效中、那一格是空的→判不出/周期末读不出/a",
  "生效中、写的是 infinity（那条链读出来就是它）→判不出/周期末读不出/a",
  "还没有过订阅（none 的周期末天生可以是空的）→该降/没有一行还占位/-",
  "词表外的状态名（人工修数留下的）→判不出/状态名不认识/a",
  "两行：旧那行已过、新那行还在期内（全部行都要看）→还在期内/还占着位/new",
  "两行：一行还在期内、一行读不出（坏格子要露出来）→判不出/周期末读不出/bad",
  "钟本身坏了（NaN）＋生效中→判不出/周期末读不出/a"]}
```

第一条是上一线那个口径在这里的继承：周期末**正好等于**现在算"已过"，于是这个人被降。第四、第五行看着一样糟（都读不出时刻），落点完全不同，差别在下面一节。

"取反"那三种人也各钉了一条，每条都先证明自己的前提还在：

```
[降级·不是取反] ["欠着钱、这一期还在内：占位行数=0，降级判定=等补付",
"生效中、周期末是空的：占位行数=0，降级判定=判不出",
"词表外的状态名：占位行数=0，降级判定=判不出"]
```

左边那句"占位行数=0"是在说**它们确实都不占位**。哪天 `占位行` 改成收它们了，这条会先在这里红，提醒"两个问法的分工要重判"。少了这条前提断言，整段对照就是空的：拿一个恒真的假设去证差异。

## 空周期末不是一种坏消息，也不是一种好消息

同一个"读不出时刻"，在两种状态里含义不一样。`active` 要说"我还占着位"，靠的就是周期末这一格；格子空了，它凭什么占着？不知道，所以不动手。而 `none`（还没有过订阅）与 `inactive`（已经停止）**本来就说不占**，它们的周期末天生可以是空的——拿"读不出"去拦它们，等于让一个空的显示位挡住一条已经写明答案的结论。

所以这一族被单独钉成一行样本：`还没有过订阅（none 的周期末天生可以是空的）→该降/没有一行还占位`。写反的代价是双向的：把 `none` 也当成"读不出"，这个人的会员标签永远降不下来，投影这条路闭不上；把 `active` 加空格也当成"不占位"，就是把本站写坏的那一格算到用户头上。

方向也要说清：降错的代价是把还在期内的人关在门外，漏降的代价是他多享受一期。两边不对称，所以判不出这一族宁可不动手，把名字露出来让人去看那一行。

## 形状档被自己的箭头函数绊红了一次

"这一层不许自己比较时刻"这条判据，第一版写成"摘掉注释和字符串之后，本文件不许出现尖括号"。跑出来直接红：

```
AssertionError: 本层出现了尖括号 ⇒ 有人在这儿自己拼时刻比较: expected 1 to be +0
```

代码一行都没错。红的是 `if (还占着.length > 0)`——那是在数条数，跟时刻无关。而真正该挡的两样它一样没挡住：把 `判周期末(...) === '未到'` 换成 `那一行的周期末 > 现在` 这种等价改写会溜过去；箭头函数 `=>` 里那个 `>` 反倒被当成证据。

判据要问的是它想问的那件事：**有没有拿时刻做比较**，不是**有没有那个符号**。改完之后的读数：

```
[降级·形状] {"时刻比较":0,"等号方向符号":0,"还剩的尖括号":1,"取此刻":0,"碰库":false,
"走规则层":2,"走占位口径":1,"任务里已经调它":0}
```

`还剩的尖括号` 现在只打印、不判红——它是给人看的上下文。`走规则层: 2` 钉的是那两个问时刻的地方（这一行读不读得出周期末、欠着那行这一期过没过期）：多了要问第三个问法是什么，少了说明有一族输入没人判。

## 变异五组：哪几条红了，哪几条没红

| 改坏的那一处 | 红了什么 | 判读 |
| --- | --- | --- |
| 把两段"先拒绝"整块摘掉，也就是取反写法 | 四档全红：边界表报 `生效中、那一格是空的: expected ['该降', …null] to deeply equal ['判不出', …'a']`；对照档报 `expected '该降' to be '判不出'`；四值档少了一格 | 这就是这一站的动机，撞得最狠 |
| 把 `判周期末(...) === '未到'` 换成本地比较 | **只有形状档红**，二十一行边界表一条没红 | 两种写法此刻等价，红的是"第二份比较符号长出来了"这个形状。行为判据管不到它 |
| 把 `还占着.length > 0` 换成 `>= 1` | 形状档报"出现 `<=`／`>=`" | 上一行那种等价改写正是会溜过去的形状，现在兜住了 |
| 把"等补付"塌进"还在期内" | 对照档与四值档红 | 依据不能合并：851 的日志与 852 的信要分得开 |
| 在任务的 `run()` 里先加一句 `判降级([], 0)` | 形状档报"任务里已经调 `判降级`" | 给下一站准备的报警器：规则写好却没人调用，静态上没有任何东西会红 |

还有一件只能记在这里：上面第二组那次改坏，是测试文件里一处属性名写错之后被 `npm run check` 的类型检查拦下来的——

```
test/unit/downgrade-selection.test.ts(69,45): error TS2339: Property '命中' does not exist on type '降级结论'.
```

断言用的是正确的属性名，所以四档判据一直绿；坏掉的是**打印出来的那行证据**，每一行的"命中的行"都印成了 `-`。单测不做类型检查，属性名写错不会红，只会让读数失去意义，而这一站的读数就是交付物。

## 这一站测不到的三件事

- **端到端一条判据都没有**。上一线量过：`users.role` 有读者没有写者，全站没有一处按 `member` 判权限。"降了"这件事今天在界面上看不出来，硬加一条页面判据只能钉一个我自己编的形状。证据停在纯函数与形状两层。
- **"取几行"发生在 SQL 里，这里证不了**。边界表喂进去的数组已经有两行了，函数怎么处理数组与库给了几行是两件事——把取数那侧写成只取最新一行，这些档一条都不会红。那是 845 撞过的同一个坑，只能靠 851 的取数判据管。
- **"任务被扫到了没有"这一格还是空的**。够格的读法只有一种：对着跑起来的服务器问一次 `nuxt task list`。

```bash
cd Substrate

```

| 撞上的现象 | 原因与读法 |
| --- | --- |
| 四档全绿，`npm run check` 却停在类型检查 | 测试文件里属性名或类型写错了。单测不做类型检查，它照样绿并把读数印成 `-` |
| 形状档报"出现 `<=`／`>=`"，而你只改了一处数条数 | 这一档把这两个符号当成拼到期比较用的。真要用它们表达别的，把判据改成按上下文筛，别放宽 |
| 某行边界样本红了，你没动过选取逻辑 | 红消息里三条一起比（判定、依据、命中行）。多半是 `占位行` 那份口径变了——它同时管下单挡人，两个问法要一起重判 |
| `命中的行` 印成 `-` 但判定是对的 | 那一行没带 `id`。它是可选的，判据要它只为指回具体那一行 |

## 收了哪一格，还欠哪一格

这一站收的是"把过期未续的人降回 `free`"那句里的**"过期未续"四个字**：它现在有一份能背下来、能逐条撞红的定义，四个答案各有出处。还欠的三样也一并写明——`role` 的可观察面、取数侧的"全取"、任务被扫到那一格。

下一站（851）动全站第一条 `UPDATE users`：名单从库里捞出来、降下去、留下审计，还要回答"改一半失败时读到什么"。届时这一站的报警器会红一次（"任务里已经调 `判降级`"），那是登记，不是回归。
