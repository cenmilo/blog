"组件要不要全局注册"这个问题我为难过三次：先是嫌写 import 麻烦想全放开，然后看到"每个一个 chunk"想全收回手动导入，最后发现**手动导入的代价是另一批能力会失效**。这一篇把三条全局入口和两个显式出口放在一起，给出我的选择路径。

## 先摆官方的态度词

整目录全局那句，官方用了明确的评价：

> Alternatively, **though not recommended**, you can register all your components globally, which will **create async chunks for all your components** and make them available throughout your application.

```diff
  export default defineNuxtConfig({
    components: {
+     global: true,
+     dirs: ['~/components']
    },
  })
```

选择性那句则给出两条入口和一句用量警告：

> You can also **selectively** register some components globally by placing them in a `~/components/global` directory, or by using a `.global.vue` suffix in the filename. As noted above, **each global component is rendered in a separate chunk, so be careful not to overuse this feature.**

**两个评价词并排读，官方立场是清楚的**：`global: true` 配整目录 = not recommended；`global/` 目录与 `.global.vue` = 允许但要省着用。

## 三条全局入口，粒度从粗到细

| 粒度 | 写法 | 官方依据 |
| --- | --- | --- |
| 整目录（不推荐） | `components: { global: true, dirs: ['~/components'] }` | 上一节那句 "though not recommended" |
| 单个目录项 | `{ path: '...', global: true }` | "The `global` option can also be set per component directory."；`components` 默认值第一项就是 `{ "path": "~/components/global", "global": true }` |
| 单个文件 | 放进 `~/components/global/` 或改名 `.global.vue` | 选择性那句给的两个入口 |

模块侧对应两处，各自的提醒都值得记：

- `addComponentsDir` 的定位句："Register a directory to be scanned for components and imported only when used. **Keep in mind, that this does not register components globally, until you specify `global: true` option.**"
- `addComponent` 的参数表里有 `global`："If enabled, registers component to be globally available."

**这两句合起来回答了一个常见误解**：模块注册进来的组件默认也是"用到才导入"的，不会因为你装了模块就全局铺开。而 152 那条关闭路径也印证了方向——`components.dirs: []` 关得掉你自己的目录，"though note that this **will not affect components added by modules**"。

## 全局注册买到了什么

不是"少写 import"这么简单。官方在两处给了实际用途：

| 买到的东西 | 依据 |
| --- | --- |
| "make them **available throughout your application**" | 整段注册句 |
| **`preloadComponents` / `prefetchComponents` 能点名它们** | 168：两个函数都写着"individual components **that have been registered globally**" |
| 动态组件的另一种解法（配合 `resolveComponent`） | 161 |

**第二条是我实际改主意的原因**：想按名字预热某个组件的 chunk，前提是它全局注册；否则那两个函数点不到名。于是这道题变成：**为了用预热能力，值不值得为一个组件付一条独立 chunk 加一份全局暴露？**

## 两个显式出口，以及它们各自削掉什么

出口一：`#components`

> You can also explicitly import components from `#components` if you want or need to **bypass Nuxt's auto-importing functionality**.

```vue [app/pages/index.vue]
<script setup lang="ts">
import { LazyMountainsList, NuxtLink } from '#components'
</script>
```

出口二：`resolveComponent`（只在动态组件那条路上有用）

```vue [app/pages/index.vue]
<script setup lang="ts">
import { SomeComponent } from '#components'

const MyButton = resolveComponent('MyButton')
</script>

<template>
  <component :is="clickable ? MyButton : 'div'" />
  <component :is="SomeComponent" />
</template>
```

**但显式导入的代价是能力削减**，官方有两处明写：

| 失去的能力 | 官方原话 |
| --- | --- |
| 延迟水合 | "Currently Nuxt's built-in lazy hydration only works in single-file components (SFCs), and requires you to define the prop in the template (rather than spreading an object of props via `v-bind`). **It also does not work with direct imports from `#components`.**" |
| `.client` 后缀 | "This feature only works with Nuxt auto-imports and `#components` imports. **Explicitly importing these components from their real paths does not convert them into client-only components.**" |
| 全局预热函数 | `#components` 导入的是"这一个引用"，`preloadComponents` 认的是全局注册名（168） |

**第二条要分清楚**：从 `#components` 导入是**仍然有效**的（它在这条列表里），失效的是"从真实路径导入"。所以显式导入的正确出口是 `#components`，不是 `~/components/Xxx.client.vue`——这一点很容易写错，因为真实路径看起来更直观。

## 一张取舍表

| 你的诉求 | 该走哪条 |
| --- | --- |
| 只是嫌写 import 麻烦 | 什么都不用做——目录自动注册已经免写（150） |
| 一个组件真的到处出现（外壳、图标容器） | `.global.vue` 或放进 `components/global/` |
| 一整批同类的组件都要全局 | 单独给那个目录加一条 `{ path, global: true }`，别动整目录 |
| 想按名字预热某个组件 | 先确认它全局注册（168），否则点不到名 |
| `<component :is="变量">` 需要组件对象 | 从 `#components` 导（161），别用 `resolveComponent(变量)` |
| 这个组件要用 `Lazy` + `hydrate-*` | 走自动导入/SFC，**不要用 `#components` 直接导入**（限制句） |
| 想要依赖关系在文件头可见 | `#components`，并接受上面那一行削减 |
| 装了模块担心组件被全局铺开 | 不用管——`addComponentsDir` 默认不全局 |

## 已经全局化了，怎么退回来

我的顺序是按粒度倒着收，一次动一档、每档验一次：

1. 把 `components: { global: true, dirs: [...] }` 这种整目录配置**删掉**，改为具体目录项或 `.global.vue`（官方 not recommended 那一档）。
2. 逐个把不再需要全局出现的组件从 `components/global/` 移出、或去掉 `.global` 后缀。
3. 需要"用到才知道有没有问题"的地方，改成从 `#components` 显式导入。
4. **每改一档跑一次 `nuxt build` + `nuxt analyze`**（175 那件工具），看 chunk 数量与体积的变化——这正好对上官方那句警告："**each global component is rendered in a separate chunk**"。
5. 最后确认动态组件那几处仍在（`<component :is>` 用的对象是否还能拿到），因为退回过程最容易撞坏的就是它。

第 4 步我认为是唯一可靠的一步：**"全局组件的 chunk 数量"是一个可以直接数出来的东西**，官方那句警告说的就是这个数量关系。
