把组件放进 `components/` 就能用，这件事我只需要一次相信。但当目录变成多个、或者组件不遵循默认布局时，问题就变成两个很具体的：**它到底扫了哪些目录，按什么顺序扫**。这一篇只钉这一条。

## 默认范围：只有一个目录

> By default, **only the `~/components` directory is scanned**. If you want to add other directories, or change how the components are scanned within a subfolder of this directory, you can add additional directories to the configuration:

这一句里两个动机被合并讲了，值得分开看：

| 动机 | 做法 |
| --- | --- |
| **加**别的目录（模块目录、领域目录） | 往数组里加一项 `{ path: '...' }` |
| **改**默认目录里某个子目录的扫法 | 给那个子目录单独加一项（带 `prefix`、`pathPrefix`、`pattern` 等） |

第二种是很多人不知道的：`~/components` 仍然被扫，但你可以为它的某个子目录**另加一条更具体的规则**。而这条"更具体的规则"能不能生效，取决于顺序——下一节。

## 顺序不是风格，是能不能覆盖的前提

官方示例的四行注释连起来就是这一节：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  components: [
    // ~/calendar-module/components/event/Update.vue => <EventUpdate />
    { path: '~/calendar-module/components' },

    // ~/user-module/components/account/UserDeleteDialog.vue => <UserDeleteDialog />
    { path: '~/user-module/components', pathPrefix: false },

    // ~/components/special-components/Btn.vue => <SpecialBtn />
    { path: '~/components/special-components', prefix: 'Special' },

    // It's important that this comes last if you have overrides you wish to apply
    // to sub-directories of `~/components`.
    //
    // ~/components/Btn.vue => <Btn />
    // ~/components/base/Btn.vue => <BaseBtn />
    '~/components',
  ],
})
```

**第三条是"覆盖"的实例**：`~/components/special-components` 这条规则要在整目录规则之前出现，`Special` 前缀才有意义——如果 `'~/components'` 排在前面，那个子目录已经被按默认方式注册过了。

官方随后补的那条 note 给的是**通用方向**：

> Any nested directories need to be added first as they are scanned in order.

两条合起来读，规则是：**更深的目录先加，更宽的目录后加**。这与直觉里"写得越具体越优先"并不总是一致——**这里靠的是数组顺序，不是具体程度**。

我在多个子目录上加覆盖时用的检查方法很笨但可靠：加一条 `console.log` 级别的验证不现实，但可以在 dev 下直接试标签名（`<SpecialBtn />` 能不能解析），或者临时把数组顺序调整一次看是否解析失败。顺序问题一次就能测出来。

## 两种配置形态，默认值只有一处写着

数组形态上面已经见过。对象形态官方用 diff 块给：

```diff
  export default defineNuxtConfig({
    components: {
+     global: true,
+     dirs: ['~/components']
    },
  })
```

`nuxt-config` 那一页给的是对象形态，并把默认值写全：

> Configure Nuxt component auto-registration.
> Any components in the directories configured here can be used throughout your pages, layouts (and other components) without needing to explicitly import them.

- **Type**: `object`
- **Default**

```json
{
  "dirs": [
    {
      "path": "~/components/global",
      "global": true
    },
    "~/components"
  ]
}
```

三件事一次说清：

- 默认是**两项**，第一项带 `global: true`——`~/components/global` 这个目录天生就是全局注册用的。
- **写成数组等于换掉整个 `dirs`**：`components: [...]` 是配置"扫哪些目录"的完整列表，`components: { dirs: [] }` 则是清空（152 讲过它的后果）。
- `global` 这一层键的对象形态写法（`components: { global: true, dirs: ['~/components'] }`）与逐项 `global` 是两回事，官方专门给了一句：

> The `global` option can also be set per component directory.

## 文件层控制一：`pattern` 与 `ignore`

官方给这两项的适用场景写得很具体——**目录结构不遵循默认布局时**：

> Each directory entry also accepts `pattern` and `ignore` glob options, which control which files are scanned within `path`. This is useful when your components live in nested folders that don't follow the default layout, **such as a domain-driven structure**:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  components: [
    // ~/domains/blog/components/PostCard.vue => <PostCard />
    {
      path: '~/domains',
      pattern: '*/components/**',
      pathPrefix: false,
    },
  ],
})
```

这一例三个字段配合得很紧，缺一就不成立：

| 字段 | 在这例中的作用 |
| --- | --- |
| `path: '~/domains'` | 扫描起点是领域根目录，而不是 `components/` |
| `pattern: '*/components/**'` | 只收"每个领域下的 `components/` 目录"里的文件 |
| `pathPrefix: false` | 名字只用文件名本身，于是是 `<PostCard />` 而不是 `<BlogComponentsPostCard />` 之类 |

`kit` 侧的 `addComponentsDir` 参数表里对这两项的定义是一致的：`pattern` — "Accept Pattern that will be run against specified path."；`ignore` — "Ignore patterns that will be run against specified path."（都非必需，`path` 是唯一必需项，其定义还提到可以用别名或 npm 包路径："You can use Nuxt aliases (~ or @) to refer to directories inside project or **directly use an npm package path similar to require**."）

## 文件层控制二：扩展名，以及一条互斥

默认什么文件算组件，官方把决定权指向了另一个配置项：

> By default, any file with an extension specified in the **extensions key of `nuxt.config.ts`** is treated as a component. If you need to restrict the file extensions that should be registered as components, you can use the extended form of the components directory declaration and its `extensions` key:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  components: [
    {
      path: '~/components',
      extensions: ['.vue'], // [!code ++]
    },
  ],
})
```

也就是说：**默认跟着 `extensions` 走（`.vue`、`.tsx`、`.jsx`…），但组件目录可以比全局更窄**。081 那篇已经确认过一件事：官方在 `extensions`、组件扫描、以及其他几处列出的扩展名清单**并不相同**，别把一处列表当成全站清单。

然后是那条必须单独背的互斥：

> If `pattern` is specified, the `extensions` option **has no effect**, so make sure your pattern matches the file extensions you want to scan.

**这条互斥最容易被忽略**：一旦写了 `pattern`，`extensions: ['.vue']` 就变成了装饰，glob 是唯一的过滤器。按官方那句话读，我推断 `**` 这种宽写法收进来的东西不再受扩展名约束（**这是我的推论，文档没写具体匹配结果**）——真要收窄，直接在 glob 里写扩展名（如 `*/components/*.vue`）或用 `ignore` 排除，并以实际解析出来的标签为准。
