This doesn't work inside of Docker.**"）、`nuxt analyze` 与 DevTools 的 Render Tree/Inspect。**最容易被跳过的动作是重启与重跑生成**：改动落在构建期钩子上时（`imports:dirs`、`components:dirs` 这类"Called at setup"），热更新不会替你重跑名单生成。

这一段写完，我手上攒了一串失败样本：编辑器满屏红、名字用不了、能用一半、运行时炸上下文、解析成别的组件、以及最阴的"什么都没发生"。这一篇把它们整理成清单——**每一行都是一个动作，不是解释**。

## 先分诊：六类症状

| 症状 | 归类 | 一句话定性 |
| --- | --- | --- |
| 编辑器报红，页面跑得通 | A | 类型层落后 |
| 名字根本不存在 | B | 不在扫描范围 |
| 有的能用有的不能用 | C | 开关关错对象 |
| `Nuxt instance is unavailable` | D | 位置/时机 |
| 渲染出来是另一个组件 | E | 撞名 |
| 配置写了、无报错、无效果 | F | 编译期特性没被识别 |

**F 类最难，因为没有反馈**。我把它放最后单独处理，前五类按顺序走就够。

## A 编辑器红线、运行正常

唯一该先做的动作：**重跑一次生成**，官方这句话就是依据：

> These types are stored in the `.nuxt` directory and are **generated when you run the dev server or build your application**. You can also generate these files manually by running **`nuxt prepare`**.

三种情况都要跑：新加了一个自动导入目录、新装了一个模块、改了类型增强的文件位置。

跑完还红，再往下查**增强放对目录没有**——官方那句是硬条件：

> TypeScript will not recognize augmentations placed outside these directories **unless they are explicitly included in the appropriate context**.

`app/` / `server/` / `shared/` 三个上下文各放各的（155）。

## B 名字根本用不了

对着三条范围句逐个核对文件路径：

| 侧 | 范围句 |
| --- | --- |
| app | "Nuxt can auto-import your `app/components/`, `app/composables/` and `app/utils/`." |
| server | "In the `server` directory, Nuxt auto-imports exported functions and variables from `server/utils/`." |
| shared | "Only files in the `shared/utils/` and `shared/types/` directories will be auto-imported." |

两条例外最容易漏：

1. **嵌套子目录不算**："Files nested within subdirectories of these directories **will not be auto-imported** unless you add these directories to `imports.dirs` **and** `nitro.imports.dirs`."
2. **`node_modules` 里不算**："Auto-imports are not enabled for files within `node_modules` (the location where a published module will eventually live) **for performance reasons**." → 模块 runtime 里必须显式 `from '#imports'`（154）。

组件还多一条：文件扩展名。默认算组件的扩展名来自 `nuxt.config` 的 `extensions` 那一项，而**一旦给目录项指定 `pattern`，`extensions` 就完全失效**（"If `pattern` is specified, the `extensions` option has no effect"，156）。

## C 能用一半

三个开关各管一片，配错对象就会出现"一半生效"：

| 我看到的现象 | 大概率配了 |
| --- | --- |
| `ref` 也要写 import 了 | `imports.autoImport: false`（`#imports` 仍可用） |
| 框架 API 能用、我自己的 composable 不行 | `imports.scan: false`（副作用：破坏 layers 覆盖） |
| 我的组件不解析、模块的组件照常解析 | `components.dirs: []`（"will not affect components added by modules"） |
| 整目录组件全变全局了 | 上一节那条 diff（`components: { global: true, dirs: [...] }`，官方 not recommended） |

## D 运行时报上下文错误

官方给的读法只有一句，方向明确：

> If you get an error message like `Nuxt instance is unavailable` then it probably means you are calling a Nuxt composable **in the wrong place in the Vue or Nuxt lifecycle**.

动作清单按这两问走：

1. **位置**：调用点是否在"Nuxt 插件、路由中间件、Vue setup"这三处之一？模块顶层就调用是经典错法（151 那个 breaking 例子）。
2. **时机**：`await` 之后有没有再调 composable？只有四个例外可以跨 `await`：`<script setup>`、`defineNuxtComponent` 的 setup、`defineNuxtPlugin`、`defineNuxtRouteMiddleware`。

两个补充判据：非 SFC 组件要 `defineNuxtComponent` 而不是 `defineComponent`；开了 `vue.vapor` 时，Vapor 组件里 `await` 后可能丢上下文（164 那条限制）。

## E 渲染出来是另一个组件

先确认撞名，再确认裁决：

- 撞名的三个来源在 159：两个目录同名文件 + `pathPrefix: false`、模块带来的同名、`addComponent` 手工取的名字撞上本地文件。
- 裁决句只有一句："if multiple components have the same name, **the one with the highest priority will be used**."
- 顺序机制："Any nested directories need to be added first as **they are scanned in order**." 与覆盖规则那条"comes last"。

**动作**：给关键组件显式写 `priority`，把胜负变成可读的数字。"顺序 vs priority 谁更强"官方没有表，需要实测（159 给了测法：两个候选各渲染一个可见差异）。

## F 静默不生效：一次只动一处

这一类的共同点是**都由编译器在识别特定写法时注入**，所以失败没有反馈。我的检查顺序是固定的：

| 检查 | 官方依据 |
| --- | --- |
| 是不是 SFC？ | "lazy hydration only works in single-file components (SFCs)"；"Most features for server-only and island components, such as slots and `nuxt-client` components, are only available for single file components." |
| 有没有绕过自动导入？ | `.client`："This feature only works with Nuxt auto-imports and `#components` imports."；延迟水合："It also does not work with direct imports from `#components`." |
| prop 是不是写在标签上的？ | "requires you to define the prop in the template (rather than spreading an object of props via `v-bind`)" |
| 宏的参数是不是字面量？ | "avoid using external variables"；`resolveComponent`："must be a literal string… statically analyzed at the compilation step" |
| 是不是只在水合后才出现？ | `.client` 与 `<ClientOnly>` 的内容"rendered only after being mounted"（要 `await nextTick()` 或 `watch(ref, …, { once: true })`） |
| 有没有被 `noScripts` 收掉？ | `noScripts` 路由下"the page simply never hydrates, which means nothing on it is interactive"（141、171） |

**每改一项就重跑一次生产构建**：开发期看不到生产形态，官方对这一点的提醒是那句重复过两遍的"be sure to test these using `nuxt preview`"（175）。

## 三件能看见真相的工具

| 工具 | 官方说明 | 在排错里的用法 |
| --- | --- | --- |
| sourcemap 配置 | "**Sourcemaps are enabled for your server build by default, and for the client build in dev mode**, but you can enable them more specifically in your configuration." + `sourcemap: { server: true, client: true }` | 客户端生产报错要定位时，先确认这一项 |
| Node Inspector | `nuxt dev --inspect`；"This will start Nuxt in `dev` mode with debugger active."；限制："Note that the Node.js and Chrome processes need to be run on the same platform. **This doesn't work inside of Docker.**" | 服务端名单/钩子行为断点 |
| `nuxt analyze` + DevTools | analyze"allows you to analyze the production bundle… leverages `vite-bundle-visualizer`"；DevTools 的 Render Tree"Shows connections between Vue components, scripts, and styles"、Inspect"Lists all files used in the Vue app with their size and evaluation time" | 判断组件到底解析成了哪个文件、多带了什么 |

IDE 侧官方还给了两份可直接粘的配置（VS Code 的 `client: chrome` + `server: nuxt` + compound，JetBrains 的 `nuxt.run.xml`），其中一行注释很实用：`"webRoot": "${workspaceFolder}/app"` 旁写着 "**this should point to your Nuxt `srcDir`, which is `app` by default**"——**断点打不上时先检查这里**。

## 一个总该先做的动作：让名单重新生成

排错清单里我放在最前面的其实是这一条。六个构建期钩子里有四个写着 "Called at setup"（`imports:sources`、`imports:extend`、`imports:dirs`，以及 `components:dirs` 那句"Called within `app:resolve`"），**它们是 setup 期跑的**；开发期的文件监听是另一件事（`builder:watch` 的官方定义："Called at build time in development when the watcher spots a change to a file or directory in the project."）。

所以：**改目录、改 `imports`/`components` 配置、装模块之后，跑一次 `nuxt prepare`（或重启 dev）**，再看症状属于 A-F 哪一类。顺序反了的话，很可能在 A 类问题上耗掉半小时。
