一句总结这条线在说什么：**负载是发给浏览器的第二份拷贝**。它该带上页面要用的东西，不该带上没人读的东西，也不该带上进不去的东西；三件事分别由 `pick`／`transform`、值本身的可序列化性、以及一对 reducer/reviver 来管。

## 版本账：那两个选项本机读不到

讲 `useAsyncData` 那一节的参数表里，`serialize` 与 `middleware` 两行右边挂着 v4.6 的小标记；本线用的 `pick` 与 `transform` 两行是空的，它们比 4.x 早得多，容易被当成新版本的东西而不敢用。这一列里带标记的是 `getCachedData`（v3.8）、`deep`（v3.8）、`dedupe`（v3.9）、`enabled`（v4.5）、`serialize` 与 `middleware`（v4.6）。先记一句读法：徽章两节都有（讲 `useFetch` 那一节也带着从 v3.2 到 v4.6 的标记），所以**升没升版本要一项一项查**，不能只看一处。本机这份 Nuxt 是：

```bash
node -e "console.log(require('./node_modules/nuxt/package.json').version)"
#   4.5.2
grep -c serialize node_modules/nuxt/dist/app/composables/asyncData.js    #   0
grep -c middleware node_modules/nuxt/dist/app/composables/asyncData.js   #   0
```

也就是说，**跟着文档抄那两行会抄出一个不存在的选项**。`serialize` 是给整个键的一枚开关，原话是「Whether to store resolved data in the Nuxt payload (`__NUXT_DATA__`). When `false`, server-fetched data is kept out of the payload and the client will refetch after hydration if a component renders it.」——它做的事正是这条线前几步在做的事（把那一份拷贝从响应里去掉），代价也写得很直白：客户端渲到那一块时会再取一次。这个"再取一次"本线是手工量出来的（815 那三档计数），而在 v4.6 上它是这一枚开关自带的行为。`middleware` 则是给一次取数套上包裹函数（`AsyncDataMiddleware[]`，收到 `next` 与 `{ signal }`），也升不到就用不了。

本线用到的这些是有的，逐个在 `asyncData.js` 里数得到（括号内是出现次数）：`server`（6）、`lazy`（3）、`immediate`（6）、`pick`（4）、`transform`（3）、`watch`（5）、`deep`（3）、`dedupe`（5）、`getCachedData`（7）、`default`（5）、`timeout`（5）、`signal`（7）。

一句话口径：徽章只标在参数表那一行的末尾，正文里它和别的选项写在一起，读快了会以为是同一层的东西——**抄之前先看那一格**。

## 未闭合的账，逐行

本线（813-818）攒下的：

1. 只注册一半（有 reducer 没 reviver）时，`devalue` 那句 `Unknown type 周期`（`parse.js:226`）为什么没冒到 `page.on('pageerror')`——页面卡住是唯一症状，症状背后的捕获链没读。
2. 同一次键的两处调用给了不同 `pick`/`transform` 会不会算两份缓存：`asyncData.js:421` 把 `pick` 算进这次取数的键哈希，只看到源码，没测。
3. 开发模式那条 `NUXT_E3004`（同键多处调用选项不一致）与 `NUXT_E3006`（结果为 `undefined`）都只在 `import.meta.dev` 跑，本机这两条判据都没在运行时读到过。
4. 加 `pick`／`transform` 之后，负载里 `_errors` 与 `once` 那两位怎么变（`-1` 那个 `undefined` 占位、那个空 `Set`）——没读。
5. `/docs` 每次客户端导航进来都重取一次：读到的是"这一键排不进 `static.data`"（`asyncData.js:413-415` ＋ `payload.client.js:26-34`），但它是载荷取回来没这一键、还是压根没去取，没分开。
6. `Promise`／thenable 这一类没试（源码另有一句 `Cannot stringify a Promise or thenable — use stringifyAsync instead`，`stringify.js:144`）。
7. `Map`／`Set` 的键是对象时，负载里写成什么形状：没试（本线用的都是字符串键）。
8. 只筛顶层键这件事，`pick` 在嵌套上给的是 `{'a.b': undefined}`——写进判据的是文档未记载、源码可指，但没测更细的边界（键名里带引号、带点）。

跨线的两笔：真会话下 `$scurrentUser` 那一位长什么样（要库）；某趟全量跑报过一条 `1 failed／2 did not run`，失败用例名没取到，之后四趟全量（含本轮 234 passed）都没复现。

## 四句可以带走的话

- 收敛负载的起点不是"能删哪些字段"，而是**读一次响应体**：`/me` 的负载占整页 11.6%，这一页看着最轻，发出去最重。
- 判断"这一位能不能削"的标准只有一条：**负载里那一份有没有人读**。正文那一段就是例子——它在负载里躺着，但页面读的是服务端组件自己取的那一份。
- `pick` 与 `transform` 不是一层的东西：前者只筛顶层键（数组上直接给你 `{}`），后者能改形状，且顺序是先 `transform` 后 `pick`。
- 判据要能在"什么都没报错"的时候仍然变红。这一站最阴的一条是状态码 200、HTML 齐全、控制台干净，只有"某个只在水合后才出现的读数"没出现——所以判据要**调那个类独有的方法**、要数那一行的个数，别断"页面还在"。

下一站 819 开新的第一条：把脚本整体关掉（`noScripts` 路由规则）之后，这一站量过的那些负载与岛屿还剩什么在页面上——官方那一句"island slots and `nuxt-client` components rely on a small inline script … On routes rendered with `noScripts`, that script is omitted, so fully interactive `nuxt-client` components will not hydrate there"是要现量的取舍。
