## 先在浏览器里找到那一段

打开本站任意一个页面，按 `Ctrl+U`（macOS 是 `⌥⌘U`）看源码，搜 `__NUXT_DATA__`。你会在 `</body>` 之前看到一条脚本标签：

```html
<script type="application/json" id="__NUXT_DATA__" data-ssr="true">[{"state":1,"once":4,……}]</script>
```

这一段叫**负载**（payload）。官方那一节讲 `useNuxtApp` 时给的定义是一句：「`payload` exposes data and state variables from server side to client side.」——服务端把数据和状态变量交给客户端。它下面列了三个键：`serverRendered`（这一份响应是不是服务端渲的）、`data`（用 `useFetch` 或 `useAsyncData` 取回来的结果记在这里）、`state`（`useState` 设的状态记在 `payload.state.[name-of-your-state]`）。

浏览器拿到这段 JSON 之后做的事叫**水合**：服务端已经把 HTML 渲好了，浏览器不重画，而是把这段 HTML 认领过来、挂上事件和响应式状态。认领的依据就是负载——讲 `useAsyncData` 那一节原话是「handles adding responses to the Nuxt payload so they can be passed from server to client **without re-fetching the data on client side** when the page hydrates」：取回来的结果进负载，页面水合时**不用再发一趟请求**。

这一站不改任何代码。原因是接下来五步要动的东西——少发几个字段、别把函数塞进去、让一个类过得去——改的全是这一段。改之前得先有它的账：现在到底发了多少字节、里面是哪几个键。

## 三条路由的账

本项目跑在生产构建上（`node .output/server/index.mjs`），起服务用一个终端，读另一个终端里发命令。

```bash
cd Substrate
npm run build
PORT=3000 node .output/server/index.mjs
```

另开一个终端，把三页的响应体存成文件再量。判据走 HTTP 层读响应体，而不是去读浏览器里水合完的 `useNuxtApp().payload`：同一份东西，但响应体不受"客户端有没有又取一遍"干扰。

```bash
for p in "" "docs" "me"; do
  curl -s "http://localhost:3000/$p" -o "page.html"
  node -e 'const fs=require("fs");const h=fs.readFileSync("page.html","utf8");const m=/<script[^>]*id="__NUXT_DATA__"[^>]*>([\s\S]*?)<\/script>/.exec(h);const p=m?.[1]??"";console.log(JSON.stringify({整页字节:h.length,负载字节:p.length,占比:Math.round(p.length/h.length*1000)/10,有data位:/"data":/.test(p)}))'
done
```

三页跑下来是这样一张账（本机版本号 4.5.2，你跑出来的字节数会和内容长度绑定，不必相同）：

| 路由 | 整页字节 | 负载字节 | 负载占比 | 负载里有 `data` 位 | 取数键 | `$scurrentUser` |
| --- | --- | --- | --- | --- | --- | --- |
| `/` | 6543 | 181 | 2.8% | 没有 | 0 次 | 在 |
| `/docs` | 5841 | 453 | 7.8% | 在 | `docs:list` 2 次 | 在 |
| `/me` | 4225 | 488 | 11.6% | 在 | 3 个键 | 在 |

第一行有个反直觉的地方：**整页最大的 `/`，负载最小**。落地页的内容写在模板里，一次数都没取，所以那一页的负载里连 `data` 这个键都不存在。而 `/me` 整页最小（4225 字节），负载占了 11.6%——页面本身轻，发出去的数据反而重。

## 它不是一棵嵌套的 JSON 树

`/docs` 那一段完整读回来长这样（一字未改，只是拆了行）：

```json
[["ShallowReactive",1],
 {"data":2,"state":19,"once":22,"_errors":23,"serverRendered":25,"path":26},
 ["ShallowReactive",3],
 {"docs:list":4},
 [5,12],
 {"slug":6,"title":7,"date":8,"tags":9},
 "pricing-faq","订阅与发票的常见问题","2026-11-24",[10,11],"订阅","发票",
 {"slug":13,"title":14,"date":15,"tags":16},
 "getting-started","第一次登录要准备什么","2026-11-20",[17,18],"上手","登录",
 ["Reactive",20],{"$scurrentUser":21},null,["Set"],
 ["ShallowReactive",24],{"docs:list":-1},true,"\u002Fdocs"]
```

读法：**整个负载是一维数组，除了字符串和数字本身，任何位置写的都是下标**。第二项那个对象里 `"data":2` 的意思是"`data` 的值在数组第 2 位"，第 2 位又是 `["ShallowReactive",3]`，第 3 位是 `{"docs:list":4}`……一路顺着下标跳，最后才落到 `"订阅与发票的常见问题"` 这个真字符串上。官方那一节把这段的形状**完全没有记载**，上面的读法引的是本机 `node_modules` 里两处源码：编码函数在 `@nuxt/nitro-server/dist/runtime/utils/renderer/payload.mjs:5` 导入的 `devalue` 的 `stringify`，而 `{"docs:list":-1}` 那个 `-1` 是 `devalue/src/constants.js:1` 的 `export const UNDEFINED = -1`——**`-1` 不是错误码，是 `undefined` 的占位下标**。

顺带读出三件小事。`["Set"]`、`["Reactive",20]`、`["ShallowReactive",3]` 里第一个元素是标签，浏览器按标签决定还原成什么类型，这套标签是内置的 reducer 注册的（`nuxt/dist/app/plugins/revive-payload.server.js:8-16` 列了 7 个：`NuxtError`、`EmptyShallowRef`、`EmptyRef`、`ShallowRef`、`ShallowReactive`、`Ref`、`Reactive`）。`"\u002Fdocs"` 是 `path` 的值，斜杠被转义了。`/me` 那一段更值得看：

```json
{"me:probe-forward":4,"me:probe-bare":8,"me:probe-picked":9},
{"hasSid":5,"sidPrefix":6,"hasCsrf":5,"csrfLength":7},
false,null,0,
{"hasSid":5,"sidPrefix":6,"hasCsrf":5,"csrfLength":7},
{"hasSid":5},
["Reactive",11],{"$scurrentUser":6,"$sme:probe-leg":12},"服务端"
```

第 4 位和第 8 位是两个字段完全一样的对象，没有合并；但 `hasSid` 与 `hasCsrf` 都指向第 5 位，那个位置只有一个 `false`——**相同的原始值只占一位**。第三行是 `pick` 之后的结果，同一个接口同一个页面，它只剩 `hasSid` 一位。这个键后面几步会一直盯着它。

## 你写下去的名字，读回来多了两个字符

代码里那一行是 `useState<CurrentUser | null>('currentUser', () => null)`。按裸名 `currentUser` 到负载里数，三页都数是 **0 次**；换成 `$scurrentUser`，三页都是 1 次。这不是巧合，`nuxt/dist/app/composables/state.js` 里写着：

```js
const useStateKeyPrefix = "$s";
// ……
const key = useStateKeyPrefix + _key;
const state = toRef(nuxtApp.payload.state, key);
```

`useState('me:probe-leg')` 发出去叫 `$sme:probe-leg`，同理。官方那句 `payload.state.[name-of-your-state]` 讲的是你在代码里怎么称呼它，写进响应体的那一份多挂了两个字符的前缀。这一位是**服务端插件**写的（`app/plugins/current-user.server.ts`），插件在每条路由都跑，所以首页那种没有任何地方读身份的页面也带着它——181 字节里就占着这一位。

## 正文渲过一遍，这段里还有一份

列表页第一篇的标题是「订阅与发票的常见问题」。把整个响应体当字符串数它出现几次，再把负载那一段单独数：

```json
{"样本标题":"订阅与发票的常见问题","正文出现次数":2,"负载出现次数":1,
 "负载里title键次数":2,"负载里slug键次数":2,"负载里date键次数":2,"负载里tags键次数":2}
```

同一句话在这条响应里躺着两份：一份是服务端渲进 HTML、用户看得见的那份；一份是给浏览器水合用的。四个字段名各出现 2 次，因为列表里就两条，每条的字段名都要写一遍。这就是这条线要收敛的对象——**页面用不到的那一份，发出去就是白花花的字节**。

## 让它变一下，确认数字不是读错的

只量一次容易把"读法错了"当成"页面就这样"。所以在落地页的 `<script setup>` 里临时加一行，重新构建，再读：

```ts
useState<string>('demo:payload-813', () => '变异探针')
```

`/` 那页的负载从 **181 字节变成 212 字节**，整页从 6543 变成 6574，那一段里多了这一位：

```json
{"$scurrentUser":3,"$sdemo:payload-813":4},null,"变异探针"
```

一行代码，21 个字节，其中还捎带一个 4 个汉字的字符串值。删掉这一行重新构建，`负载字节` 回到 181、`整页字节` 回到 6543——两个数字都精确复原，说明前面那张表读的是页面本身，不是脚本读错了。

## 把三条判据钉在用例里

手敲命令只能看一次，回归要靠用例。新建 `test/e2e/payload-shape.spec.ts`，三个用例分别钉：三页的字节账与键账、正文与负载的重份、`/console` 未登录被弹回 `/me` 时负载里没有会员数据。核心几条断言：

```ts
expect(首页.有data位, '首页没取过数，负载里不该出现 data 这一位').toBe(false)
expect(门后页.状态键.身份裸名, '负载里并不以裸名出现').toBe(0)
expect(门后页.状态键.身份编码名, '那一位换了个名字进负载').toBeGreaterThan(0)
expect(首页.状态键.身份编码名, '首页没人读身份，那一位照样跟着负载来了').toBeGreaterThan(0)
```

跑法与读回来的行数：

```bash
E2E_PORT=3420 npm run test:e2e -- test/e2e/payload-shape.spec.ts
#   3 passed (20.9s)
```

`E2E_PORT` 是本项目的测试脚本读的变量，默认端口被占住时换一个即可。第三个用例还顺手读到一个容易踩空的地方：`/console` 那趟响应是 302，测试里的 HTTP 客户端会**自动跟跳转**，最终停在 `http://localhost:3420/me`、状态 200。判据如果写成"状态是 302"会一直红，得读最终地址。

## 对不上表

| 看到的现象 | 大概率是 | 怎么确认 |
| --- | --- | --- |
| 源码里搜不到 `__NUXT_DATA__` | 这一页走了纯客户端渲染，或你读的是跳转前的那一趟 | 先 `curl -sI http://localhost:3000/路径` 看状态码 |
| 负载字节读到 0 | 匹配正则把属性顺序写死了（真实标签是 `type` 在前、`id` 在后） | 改成按 `id="__NUXT_DATA__"` 匹配 |
| 按状态名数是 0 | 前缀 `$s` | 换 `$s` 打头的那个名字再数 |
| 首页负载莫名变大 | 落地页新引入了取数或状态位 | 对比 `有data位` 和 `$scurrentUser` 两项 |
| 整页字节每次构建都变 | 预渲染的页面带 `prerenderedAt`，值是构建时间戳 | 只看负载字节与占比，别钉整页字节 |
| 断言"302"一直红 | 客户端自动跟了跳转 | 读最终地址而不是首次状态码 |

这一站的账立在这里：三页各发了多少、那一段是什么形状、状态名出门要加前缀、正文与负载各存一份。有两个官方选项本机这个版本还没有（是 v4.6 才加上的），留到这条线最后一步记账。

下一步 814：给会员区那个取数加 `pick`，同一页前后各读一趟负载字节数，读"少掉的字节"与"页面上少渲了哪几位"。上面 `/me` 里那个只有 `hasSid` 一位的 `me:probe-picked`，已经在提示这条路能省多少。
