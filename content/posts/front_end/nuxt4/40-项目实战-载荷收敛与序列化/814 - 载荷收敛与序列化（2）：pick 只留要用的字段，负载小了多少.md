## 这一页的负载里，多出来的那位有多大

上一站读完三页的账，最扎眼的是 `/docs/getting-started`：整页 7274 字节，负载那一段 1289 字节，占 17.7%——比会员区入口页 `/me`（11.6%）还高。把 `payload.data` 里那一键摊开看，它带着三位：

```text
[pick·接口与负载] {"接口状态":200,"接口键清单":["body","frontmatter","html"],
                  "负载键清单":["body","frontmatter","html"],
                  "负载里字符串位字符数":{"body":85,"html":121},
                  "负载最长串字符数":121,"整页字节":7274,"负载字节":1289,"占比":17.7}
```

再看这一页自己用了什么。模板里读的是 `doc.frontmatter.title`、`doc.frontmatter.date`、`doc.frontmatter.tags`，`useSeoMeta` 读的也是 `frontmatter` 下面那几位；正文那一块是 `<DocBody :slug="slug" />`——796 把它换成了服务端组件，它自己去走一次 `/api/docs/<slug>`，拿到 `page.html` 直接 `v-html` 贴上去。也就是说，页面这一路取回来的 `body` 与 `html` 那两段，**从服务端发出去之后没有任何人读**。它们只是跟着负载又被发了一遍。

## `pick` 筛的是哪一层

官方讲 `useAsyncData` 的那一节，参数表里这一项只有一句：「Only pick specified keys from the result.」——从结果里只挑指定的键。是哪一层，它没写。源码里 `pick` 就三行：

```js
// node_modules/nuxt/dist/app/composables/asyncData.js:281-285
function pick(obj, keys) {
	const newObj = {};
	for (const key of keys) newObj[key] = obj[key];
	return newObj;
}
```

**只按顶层键取**。所以 `pick: ['frontmatter.title']` 得到的不是标题，而是 `{ 'frontmatter.title': undefined }`：那个带点的字符串在顶层找不到，取到 `undefined`。真要往下一层收，得换 `transform`（下一站）。

这一页的写法就加一行：

```ts
const { data: doc, error } = await useAsyncData(`docs:${slug}`, () => $fetch<DocPage>(`/api/docs/${slug}`), {
  immediate: parsed.ok,
  pick: ['frontmatter'],
})
```

## 前后两趟，差值是多少

重新构建，再读同一趟响应：

```text
[pick·接口与负载] {"接口状态":200,"接口键清单":["body","frontmatter","html"],
                  "负载键清单":["frontmatter"],"负载里字符串位字符数":{},
                  "负载最长串字符数":79,"整页字节":6944,"负载字节":959,"占比":13.8}
```

| 读数 | 加 `pick` 之前 | 之后 | 差 |
| --- | --- | --- | --- |
| 整页字节 | 7274 | 6944 | **-330** |
| 负载字节 | 1289 | 959 | **-330** |
| 负载占整页 | 17.7% | 13.8% | -3.9 个点 |
| `payload.data` 那一键的键清单 | `body`／`frontmatter`／`html` | `frontmatter` | 少两位 |
| 负载里最长的串 | 121 字符 | 79 字符 | 那两段都不在了 |

**少掉的 330 字节全部落在负载上**，正文和标签那部分 HTML 一个字没动。

## 页面上少渲了哪几位：一位没少

同一趟里把页面上那四样也读出来：

```text
[pick·页面还在不在] {"标题":"第一次登录要准备什么","第一个标签":"上手",
                    "正文块字符数":121,"正文段数":1}
```

改之前改之后这一行**逐字相同**。最有意思的是那个 `121`：负载里 `html` 那一段是 121 个字符，页面上渲出来的正文块也是 121 个字符——同一段内容，改之前在这条响应里躺两份（一份给用户看、一份给浏览器水合用），改之后只剩看得见的那一份。

这决定了一个判断标准：**能不能削，看的是"负载里那一份有没有人读"，不是"接口回得多不多"**。这一页正文照旧出得来，是因为它压根不从负载里取正文。

## 接口那边一个字没变

`接口键清单` 前后都是 `["body","frontmatter","html"]`。`pick` 生效的位置在源码里只有一处——`asyncData.js:356` 那句 `if (options.pick) result = pick(result, options.pick)`，跑在**取数拿到结果之后**。所以：

- 服务端到接口那一趟该读的正文照样读了；
- 少掉的只是发给浏览器的那一份拷贝。

想少服务端自己的活（比如整篇正文不必备着），手段不在这里，在接口那边少回、或者给这一路加缓存。把 `pick` 当成"减少服务器工作量"来写，是本末倒置。

## 挑错一位会怎样：类型先拦住，运行时才轮到整页

`pick` 的键名拼错、或者留了没人用的一位，第一道闸不是页面而是类型检查。把上面那行换成 `pick: ['body']`（正文那一位，页面没人读），`nuxt typecheck` 立刻报七处：

```text
app/pages/docs/[slug].vue(323,40): error TS2339: Property 'frontmatter' does not exist on type 'Pick<DocPage, "body">'.
```

返回类型跟着 `pick` 收窄成了 `Pick<DocPage, "body">`，模板里每一处 `doc.frontmatter` 都不再成立。**上一站那三页读数里没出现过这件事**，是因为那几位一直是对的。

第二道闸才是运行时。构建这一步不跑类型检查，所以真把带错 `pick` 的代码构建上线，浏览器看到的是：

```text
[pick·页面还在不在] {"标题":"","第一个标签":"","正文块字符数":0,"正文段数":0}
整页字节 3335 ／ 负载字节 475
```

`doc` 本身是有值的（`{ body: "…" }`），`v-if="doc"` 过了，模板里 `doc.frontmatter.title` 在服务端渲染那一站抛错——整条响应换成了错误页。**这一层错误边界接不住**：811 量过，`NuxtErrorBoundary` 里那句 `onErrorCaptured` 的注册被 `if (import.meta.client)` 包着，只管浏览器那一路。所以服务端渲染期写错的字段名，代价是整页，不是局部回退块。

## 会员区那一路：这一项省不出字节

按功能线该先量会员区，量完的结论是**这条路不该用 `pick` 收敛**，三条理由都在代码里：

- 接口 `server/api/console/metrics.get.ts:24-28` 回的就一位：`{ metrics }`；服务层 `server/services/metrics/index.ts:46` 给的是 `{ total, kinds }`，`kinds` 里每项是 `{ kind, count }`。顶层只有 `metrics`，`pick: ['metrics']` 等于没写。
- 页面用到的正是这些位：`app/pages/console/index.vue:48` 读 `metrics.total`，`:50-57` 遍历 `metrics.kinds` 拿 `item.kind` 与 `item.count`；`ConsoleMetricsPanel.vue:19` 读同一个 `total`。**没有哪位是没人读的**，削不动。
- 会员区那一页要真会话才落到两个调用点上，本机没有带库的跑法（连库授权问过六十次没有答复），所以那一页负载里 `console:metrics` 到底占多少字节，**本步读不到**，不拿离线读数凑。

还有一件与这条设计直接相关的：讲 `useAsyncData` 的那一节有一段"同一个键的多次调用必须给一致的选项"，原话是「When multiple `useAsyncData` calls use the same key, they share the same `data`, `error`, `status`, and `pending` refs. Keep the options listed below consistent across these calls」，下面那张清单里明确列着 `pick` 数组与 `transform` 函数。会员区那一路**恰好就是同键两处调用**（783 把键锁在出口 `useConsoleMetrics` 里，页面和面板都走它）——所以真要在这条路上加 `pick`，只能加在出口里，让两处一起生效。源码里那条检查在 `asyncData.js:48-66`，只在开发模式跑，不一致时报 `NUXT_E3004` 并带上 `different \`pick\` option` 这样的字句；本步没能把它读出来（同一个原因：落不到那两个调用点上），记在这里等带库那一趟。

## 判据：把"少掉的字节"钉成能跑的两条

上一站的 `test/e2e/payload-shape.spec.ts` 加了两条，一共 5 条：

```ts
expect(Object.keys(接口回体).sort(), '接口那边照样回三位').toEqual(['body', 'frontmatter', 'html'])
expect(那一位.键清单, '负载里只该留页面真正用的那一位').toEqual(['frontmatter'])
expect(页面.最长串字符数, '负载里最长的串该短下来').toBeLessThan(120)
expect(标题.length, '标题这一行还得渲得出来（它读的是留下来的那一位）').toBeGreaterThan(0)
expect(正文块.length, '正文那一段还得在（它由服务端组件自己取）').toBeGreaterThan(0)
```

```bash
E2E_PORT=3427 npm run test:e2e -- test/e2e/payload-shape.spec.ts
#   5 passed (19.8s)
```

两处写法值得说。其一，负载是一维数组加下标引用（上一站讲的），所以读某一键的形状得先按下标解回去，判据里那个 `摊开()` 干的就是这件事——`["标签", n]` 取 `n`，数字取下标。其二，断言钉的是**关系**（键清单等于什么、最长串短到多少），不是绝对字节数：字节数会随正文内容长度和构建时间戳漂，键清单不会。

## 对不上表

| 看到的现象 | 大概率是 | 怎么确认 |
| --- | --- | --- |
| 加了 `pick`，页面白屏或整页变错误页 | 留的键不是页面读的那一个 | 跑 `npm run typecheck`，模板里每一处读取都会报 TS2339 |
| 负载字节没变 | 那一位本来就不在负载里（例如正文由服务端组件自己取） | 读 `payload.data` 里那一键的键清单，别只看整段字节 |
| `pick: ['a.b']` 取到 `undefined` | 这一项只筛顶层键 | 换 `transform` 往层里去 |
| 接口调用次数变少了 | 不是这一步的效果 | 数服务端那一趟：`pick` 跑在拿到结果之后 |
| 同键两处调用一处带 `pick` 一处不带 | 违反"同键选项要一致" | 开发模式会报 `NUXT_E3004`；生产构建不报，别指望线上有提示 |

这一站把 `pick` 的三件事钉住了：能削多少要前后各读一趟才知道、削的是拷贝不是内容、键名错了类型先拦。下一站 815 换 `transform`——它能往层里去（把 `metrics.kinds` 那种数组拍成页面直接要的形态），代价是它同时改掉客户端手上那份数据，得读水合之后那一趟有没有再发请求。
