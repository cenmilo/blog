## 收口不收结论，收读数

这一站不改任何代码，也不加新判据。它做两件只有收官时才做得成的事：把前面六步各压成一句、并且每句都挂一条本轮重新跑出来的读数；然后把"没配库所以没跑"的那几行列清楚，写明白它们缺的是哪一位。

## 六步各一句

**一、共享的是值，不是对象。** 同一个键位第二次调用不重跑取数函数，第二处读到的是第一处那一份。本轮重打：`[同键] {"取了几次":1,"第一处读到":"3","第二处读到":"3","同一对象":true,"渲染":"3|3|1"}`，反面是 `[各写各的键] {"取了几次":2}`。

**二、键烤进出口，还得锁住。** 只烤进出口不够——出口写成对象那一档，调用方随手补一个 `key` 就能把一趟拆回两趟。本轮静态读数 `[宏的位置与写法] {"出现处":["app/composables/use-console-metrics.ts"],"锁键":true}` 钉的是"宏只出现在导出那一行、且是函数包对象的形状"。

**三、自动生成的键只对调用点唯一。** 不写键时两处调用各发一趟，两串键互不相同；本轮：`[自动键·两个调用点] {"趟数":2,"键":["$fnsmk7hs765az","$f3n6qj8xq8l71l"]}`。同一条判据的另一半是"同一个组件的多个实例共享"，所以两处调用若落在同一行代码上就只剩一趟。

**四、`await` 与否不改服务端那份 HTML。** 带 `await`、去掉 `await`、加 `{ lazy: true }` 三种写法读回来的响应体逐字节相同；改变得了的是"服务端取不取"——`{ server: false }` 那一档 HTML 从 3043 字节掉到 2531、两位标题消失。

**五、界面上要判的是状态那一栏，不是布尔那一位。** 本轮四取值的读数：`[状态·idle] {"立刻":{"status":"idle","pending":"false","data":"(undefined)"},"等了一会儿":"idle"}`。`idle` 时 `pending` 是 `false`（本机没开那个实验开关），所以"还没开始"和"在路上"只能靠 `status` 分。

**六、"不发一趟"有两条路，得找一个只推翻其中一条的动作。** 本轮：`[载荷·第二次挂载] {"第一次":1,"第二次":0,"静态位有那一位":false,"第二次读到":"{\"metrics\":{\"total\":8888,\"kinds\":[{\"kind\":\"login\",\"count\":1}]}}"}`——插槽是空的却仍然不发，所以那不是命中缓存，是同一个键上那份已经跑完的结果被直接复用。区别可验：只有命中插槽那条能被 `getCachedData: () => undefined` 推翻。

另外三条不属任何一步、但每一步都用到了，一并钉在这里：数趟数时要**把每一趟实际用的键一起打出来**；"改了什么都不变"这类否定结论要**配一档一定能红的对照**；借来的那句结论**先量它的前提落不在本层**（`server:false` 那句、`isHydrating` 那一位都是这么翻车的）。

## 没配库跳掉的那三行

这一条线里唯一还没被端到端钉住的东西，就是"用户真进会员区这一页，浏览器发了几趟请求"。三份规格的现跑分档（按用例数报，不按文件数）：

```
Running 6 tests using 3 workers
  ok 1 [site] › test\e2e\payload.spec.ts:16:1 › 三档都得守住的一条：SSR 那份 HTML 里就有列表内容 (235ms)
  ok 4 [site] › test\e2e\payload.spec.ts:41:1 › 首屏那份 HTML：内联载荷与载荷文件按档位不同 (7ms)
  ok 5 [site] › test\e2e\payload.spec.ts:57:1 › 点进 /docs 时走的是哪条路：监听器挂在点击之前 (358ms)
  3 skipped
  3 passed (18.7s)
```

再用 `--list` 复算一遍总盘子：`Total: 6 tests in 3 files`。所以这张表是——`payload.spec.ts` 三条全跑（它不需要库也不需要邮件，读的是公开页 `/docs` 与产物文件）；`async-data-count.spec.ts` 一条、`fetch-parity.spec.ts` 两条，**共三行跳过**。

三行缺的是同一位：两份规格的文件头都写着 `test.skip(DATABASE_URL === '', '需要配了 NUXT_DATABASE_URL 的产物实例（见文件头那行命令）')`。跳过的不是"跑得慢"，是**根本没有可用会话**：进这一页要先有一条真会话，而发那条会话要写库。三行各钉的东西也不同，补的时候才知道该看哪一处：

- `async-data-count.spec.ts:20` 数三种进入方式各发几趟 `/api/console/metrics`（这一条才是"共享有没有真省下一趟"的最终读数）
- `fetch-parity.spec.ts:17` 客户端导航时两种写法各发几趟、页面上两块数字是不是一致
- `fetch-parity.spec.ts:66` 整页加载时浏览器侧发几趟、服务端 HTML 里两块是不是都带着数字

这三行是读者的待跑步骤，命令写在规格文件头：配好 `NUXT_DATABASE_URL` 之后用 `NUXT_E2E_DB=1 npm run test:e2e -- test/e2e/async-data-count.spec.ts test/e2e/fetch-parity.spec.ts` 跑。默认那趟不带这个开关是刻意的——一带上就悄悄把连接串读进来，同一条判据的读数会从"没配库的形状"变成"配了库的形状"，绿灯换了意思比红灯更难查。

所以这一条线**没有写过**这类句子："用户进这一页只发一趟请求"。前面所有趟数都出自运行层那双双会记数的假脚，它们量的是机制，不是浏览器。

## 这一条线立住的规矩

| 规矩 | 为什么 | 哪一站立的 |
| --- | --- | --- |
| 数请求要连"这趟用的键"一起打 | 只数趟数会把缓存串了读成结论 | 第二、三步 |
| 键只留一处，且判据认写法形状 | 位置守卫守不住 `keyy:` 那种错 | 第二、六步 |
| 编译期宏只写在导出那一行 | 写在函数体里运行时就抛错 | 第二步 |
| 否定式结论配一档一定能红的对照 | 三档相同证明不了改动进了产物 | 第五步 |
| 界面判状态那一栏，不判布尔位 | 布尔那位随实验开关变 | 第六步 |
| 同读数两条机制要找区分动作 | 覆盖得掉与覆盖不掉是两条路 | 第七步 |
| 借来的结论先量前提在本层成不成立 | 同一句话在不同层含义不同 | 第三、五、七步 |

## 本线未闭合的账

- 上面那三行端到端（缺真会话与写库）
- `error` 那一位的具体形状（`statusCode`、按 `data.code` 分支）——那是错误边界那条线的题，第六步只交代了"页面显示 `-`"
- 会员区还没用上切片（islands）、异步组件与错误边界，这些属 M4 后续几条线，下一条线尚未登记
- 取数失败时页面除 `-` 之外该说什么（重试入口、话术）
- 一条与本页无关但同族的旧账：地址先归一再比较那条规矩至今没人写；审计写失败的同形也还挂着

## 交付前自查

- 六步各一句、每句后面都跟着本轮工具打印的读数，没有依赖记忆里的数字
- 分档表按用例数报，`--list` 复算过总盘子（6 条 3 份），跳过三行的**缺件与位置**都写清
- 待跑命令与"为什么默认不带开关"一起写，不留"读数是绿的但换了意思"的口子
- 未闭合的账逐行列出，没有把缺端到端的部分写成已验证
- 本线唯一的应用改动仍是第三步那一行锁键，后面四步都是零改动加判据
