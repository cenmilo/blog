## 页面上那一位短横线不是随手写的

`app/pages/console/index.vue` 的数字那一位长这样：

```vue
{{ consoleMetrics ? consoleMetrics.metrics.total : '-' }}
```

前几站把这一份数怎么取、键锁在哪里讲完了，这一站讲**取的时候页面上是什么**：正在路上显示什么，失败了又显示什么。

讲 `useAsyncData` 那一节的返回值表里，`status` 那一行写的是 `Ref<'idle' | 'pending' | 'success' | 'error'>`，同一节还有一小段"Status Values"逐条给定义：`idle` 是函数还没被调用过（例子给的是 `{ immediate: false }`，以及服务端渲的时候 `{ server: false }`）；`pending` 是已经调用而 promise 未落定；`success` 是返回了值；`error` 是抛了错。

同一个表里还有两位容易和它混：`pending`（一个布尔 ref，"请求在途"），以及 `clear()`（把 `data` 退回 `undefined` 或 `default()` 的值、`error` 清空、`status` 设回 `idle`，并取消未完成的调用）。

## 四种取值一个个读出来

上一站那双会记数的脚这里换成**可控**的：能延迟落定，也能直接抛错。六条判据的读数：

```
[状态·pending] {"立刻":{"status":"pending","pending":"true","data":"(undefined)"},"之后":{"status":"success","data":"{\"metrics\":{\"total\":7,\"kinds\":[]}}"}}
[状态·success] {"status":"success","pending":"false","data":"{\"metrics\":{\"total\":7,\"kinds\":[]}}"}
[状态·error] {"立刻":"error","之后":{"status":"error","data":"(undefined)","error":"假脚故意抛的","pending":"false"}}
[状态·idle] {"立刻":{"status":"idle","pending":"false","data":"(undefined)"},"等了一会儿":"idle"}
[状态·clear] {"清之前":"success|{\"metrics\":{\"total\":9,\"kinds\":[]}}","清之后":"idle|(undefined)"}
```

对得上原话的几条：延迟那 40ms 里读到的就是 `pending` 且 `data` 还没有值，落定后同一段探针再读变成 `success`；抛错那一档 `status` 是 `error`、`data` 仍是 `undefined`，而 `error.value.message` 里是那句抛出来的话；`immediate: false` 那一档等了 80ms 还是 `idle`（函数根本没被调用过，等再久也不会自己动起来）；`clear()` 之后从 `success` 回到 `idle`、值退回 `undefined`。

**顺带量到一位开关的现状**：`idle` 那一档 `pending` 那一位读到的是 `false`。表里写着"开了 `experimental.pendingWhenIdle` 之后，`status` 是 `idle` 且没有可用缓存数据时它也是 `true`"——本机没开这个开关，所以 `idle` 时 `pending` 是 `false`。这就是为什么**页面上要区分"还没开始"和"在路上"，只能看 `status`，不能看 `pending`**：默认配置下这两种状态里 `pending` 都是 `false`（`idle`）／`true`（在路上），但 `idle` 那一位的值随实验开关变，`status` 那句定义才是不变的那位。

## 失败的那一档，页面上真的显示什么

前五条都是探针。最后一条不带假脚，挂的是仓库里那个真组件 `app/components/ConsoleMetricsPanel.vue`——这个环境没有可连的站点，那一趟注定失败，正好读"失败了显示成什么"：

```
[状态·真组件失败态] {"状态栏":"error","数字栏":"-"}
```

状态栏是 `error`，数字栏是那一位 `-`。这就是那句兜底的全部作用：**取不到的时候，页面上仍然是一句能读的话，而不是空白，也不是把渲染炸掉。**

把兜底摘掉试一次，`{{ panelMetrics ? panelMetrics.metrics.total : '-' }}` 改成 `{{ panelMetrics.metrics.total }}`，两层各红一次：

```
AssertionError: app/components/ConsoleMetricsPanel.vue 那一行没写兜底：{{ panelMetrics.metrics.total }}: expected false to be true
TypeError: Cannot read properties of undefined (reading 'metrics')
```

静态那条是 `test/unit/console-fetch-surface.test.ts` 新增的判据：扫两个文件模板里所有用到这份数的行，每一位都必须带三元、`??` 或 `v-if`——还原之后它读到的三位是 2 位三元加 1 位 `??`。运行时那条更直接：`data` 的类型本来就是 `Ref<DataT | undefined>`，那一位空着的时候**整个组件渲染不下去**。

## 这四种取值怎么落到界面上

按读到的形状，页面分工是这样：

- `idle`：函数还没跑。这一档只在 `immediate: false`（或者服务端渲时的 `server: false`）出现；页面正常写法下你不太会看见它
- `pending`：在路上。**这是唯一需要"加载态"的一档**——显示"正在取"或者留着那一位 `-`
- `success`：有值了，正常渲染
- `error`：抛错了。**这一档 `data` 也是 `undefined`**，所以兜底那句同时兜住了"还没取到"和"取失败"两种情况；要把两者分开，得读 `error` 那一位

`error` 的具体形状（`statusCode`、`data.code` 那几位怎么分支、失败文案怎么说人话）不属这一站，那是错误边界那条线的题；这一站只管：**每一位用到取数结果的地方都得交代"没有值时显示什么"，并且 `status` 的四种取值里只有 `pending` 需要真正的加载态。**

## 先显示什么，取决于是哪一次进入

把上一站那条线接起来看，"页面上先显示什么"这件事有两种进入路径，两种的路径下第一帧是不一样的：

第一次进这一页（地址栏直接打开、或者从站外点进来），那一趟在服务端就取完了，`status` 落到浏览器时已经是 `success`——所以你**不会看见加载态**，第一帧就是数字。上一站量过的那四位页面写法都是这样：HTML 里那两篇标题一直在那里。

从站内另一页点进来才是第二种：这一段是客户端导航，取数要在浏览器里跑一趟，这时才有 `pending` 那一档可画。上一站那句"不 await 的写法下，客户端导航期间你自己用 `status` 和 `error` 处理加载与错误"讲的就是这一档；`lazy: true` 是把这一档**显式**打开的写法——它的 `status` 起步甚至不是 `pending` 而是 `idle`（上一站那条 `[await·lazy 挡不住]` 读到的正是 `idle`）。

所以页面上的顺序是：**直接进来看不到加载态；站内点进来才看得到**。一位 `<span>{{ status }}</span>` 只在第二种路径里有意义，第一种路径下它永远显示 `success`。这不是浪费——它给了判据一个能读的位置，上面那条真组件读数就是靠它把 `error` 认出来的。

`table` 那一位也一样：模板里写的是 `v-for="item in consoleMetrics?.metrics.kinds ?? []"`，取不到时是一个空列表而不是报错，`<ul>` 里一行都不渲染。这正好是那条静态判据扫到的第三位——它用的是 `??` 而不是三元。

## 撞上了去哪里看

| 撞上的现象 | 大概率是哪一位 | 先看哪里 |
| --- | --- | --- |
| 数字那一位一直是 `-` | 取数失败或还没落定 | 读 `status`：`error` 还是 `pending` |
| 页面白屏、控制台报 `Cannot read properties of undefined` | 模板里某一位没兜底 | 静态那条 `[模板里用到位的清单]` |
| 加了加载态却没出现 | 等的是 `idle` 而不是 `pending` | `[状态·idle]` 那条读数：`immediate:false` 时永远 `idle` |
| `clear()` 之后数据没回来 | 它只清状态不重取 | 想重取用 `refresh()`／`execute()` |

## 交付前自查

- 四种取值各有一条读数，不是照抄文档那四条定义
- `idle` 档顺带量到 `experimental.pendingWhenIdle` 的现状（本机 `false`），并据此说明"为什么界面上判 `status` 而不是判 `pending`"
- 最后一条打的是仓库里的真组件，读的是它自己模板那两位的文本，不是探针的复制品
- 一个坏改动（摘掉兜底）在静态与运行时两层各红一次，第二层是渲染期抛错
- `error` 那一档的具体形状没展开，写清那是错误边界那条线的分工
