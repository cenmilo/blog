## 页面上并排的两块，要的是同一份数

`app/pages/console/index.vue` 是会员区第一页。它自己渲染一块"总共几次"，模板里还有第二块 `<ConsoleMetricsPanel />`，那一块也要这份数。两处都写着一行取数：

```ts
const { data: consoleMetrics, status: metricsStatus } = await useConsoleMetrics('/api/console/metrics')
```

出口只有一处（`app/composables/use-console-metrics.ts`，10 行）：

```ts
export const useConsoleMetrics = createUseFetch({
  key: 'console:metrics',
})
```

这一站开工时先记下两件事。第一，出口与页面那两处的注释都写着"这是量出来的"，还点了两个文章编号，**而那两个编号的文章还没写**——注释提前引用了不存在的证据，这行话本身就不可信。第二，`ConsoleMetricsPanel.vue` 的注释说"这一行用 `useFetch` 且不写键"，代码其实走的就是上面那个出口：注释与代码不一致。两处都按事实改过了，"同一页并排两种写法"那组对照不在这一站做。

## 官方那句说的是什么

讲 `useFetch` 的那一节写得很直白：自动生成的键**只对调用点唯一**，同一个地址在不同组件里各取各的，要共享就得每次给同一个 `key`。同一节还给了做变体的正规姿势——`useFetch` 这个名字是编译器保留的，别自己定义同名函数，要做带默认选项的版本就用 `createUseFetch`。所以上面那 10 行不是风格偏好：把键烤进出口，是让两处调用落到同一个键位的唯一办法。

`useFetch` 内部就是 `useAsyncData` 加一个发请求的函数（`node_modules/nuxt/dist/app/composables/fetch.js:106-115`，键也是在那里生成的：不写就用 `"$f" + 一串哈希`）。这意味着"共键会不会少跑一次"可以在真运行时里量，不需要网络。

## 量出来的三段

新增 `test/nuxt/console-metrics-once.test.ts`（运行时层，happy-dom 里跑真 Nuxt 运行时）：

```
[同键] {"取了几次":1,"第一处读到":"3","第二处读到":"3","同一对象":true,"渲染":"3|3|1"}
[各写各的键] {"取了几次":2}
[出口两处调用] {"data是同一对象":true,"第一处status":"error","第一处data":"\"(空)\"","第一处error":"[GET] \"/api/console/metrics\": 404 Cannot find any path match"}
```

第一段是关键：两处都用同一个键，handler **只跑了一次**——第二处那个会返回 99 的函数根本没被执行，它读到的是第一处的 3。共享的是**值**，不是"再取一遍然后碰巧一样"。第二段是它的反面：两个键位各跑一次，各拿自己那份。

第三段要说清楚它证明了什么、没证明什么。它调的是真出口，两处返回的 `data` 指向同一个对象——但这个环境里没有可连的站点，那一趟请求直接 404、`data` 是空，所以"两个 `undefined` 相等"是平凡真，**不能拿它当共键的证据**（证据是前两段加下面的静态判据）。它真正的用处是把最后一位打出来：`status` 是 `error`、错误是 `[GET] "/api/console/metrics": 404 Cannot find any path match`。**"这一页真发了几趟请求"这一层看不见**，数得清它的是端到端那两份规格（`async-data-count.spec.ts` 一条、`fetch-parity.spec.ts` 两条），而它们在没有数据库的那一档全是跳过的——进这一页要先有一条真会话。

## 键这件事要有静态判据

新增 `test/unit/console-fetch-surface.test.ts`，四条，扫 `app/` 下的 `.ts` 与 `.vue`（连模板注释一起剥）：

```
[键字符串的位置] {"扫到的文件数":15,"出现处":["app/composables/use-console-metrics.ts"]}
[裸取数] {"现场":[]}
[出口调用点] [{"文件":"app/components/ConsoleMetricsPanel.vue","await了吗":true,"实参数":1},{"文件":"app/pages/console/index.vue","await了吗":true,"实参数":1}]
[正控制·useUser 的用处] {"文件数":5,"有":["app/app.vue","app/middleware/console-auth.ts","app/pages/console/index.vue","app/pages/me.vue","app/plugins/current-user.server.ts"]}
```

第四条是正控制：同一个扫描器在同样的目录里读得到另一个组合式函数的用处，所以前三条的空值不是"根本没扫到东西"。

## 撞三次

| 变异 | 结果 | 读数 |
| --- | --- | --- |
| 面板那一处另起一个键：`useConsoleMetrics('/api/console/metrics', { key: 'console:metrics:panel' })` | 1 条红 | `[出口调用点]` 里那一处 `"实参数":2`，失败消息自带文件与原因：`app/components/ConsoleMetricsPanel.vue 那一处多带了选项: expected 2 to be 1` |
| 页面那一处退回裸写法：`await useFetch('/api/console/metrics')` | 2 条红 | `[裸取数] {"现场":["app/pages/console/index.vue"]}` 与调用点清单少一个文件 |
| 出口里把键删掉：`createUseFetch({})` | 静态 1 条红、**运行时层三条全绿** | `[键字符串的位置] {"扫到的文件数":15,"出现处":[]}`；那一层看不到，因为请求本来就 404 |

第三行最该记：把键从出口里摘掉，是最能说明问题的一种坏改动，而它在运行时层什么都不红——**这种"改了没人红"的规矩只能由静态判据守**，判据要写的正好是"字符串只许出现在哪一处"这种可扫的形状。

## 一个符号名让整个文件跑不起来

新判据第一版里写了这么一行：

```ts
const URL = '/api/console/metrics'
```

结果那一份测试**一条都没跑**，输出是 `Test Files 1 failed (1)`／`Tests no tests`，明细只有一行：

```
ReferenceError: Cannot access 'URL' before initialization
```

因为文件顶上还有 `fileURLToPath(new URL(import.meta.url))`——局部常量把全局构造函数遮住了，而它在常量初始化之前就被调用。症状看着像"测试文件没被测到"，其实是收集阶段就炸。改名成 `ENDPOINT` 之后 4 条全绿。**"读不到数"先怀疑读数方法，别急着怀疑被测代码**——这条在上一线的假库形状那处也救过一次。

## 复跑与排错

```
npx vitest run --config test/nuxt/vitest.config.nuxt.ts test/nuxt/console-metrics-once.test.ts
npx vitest run --config vitest.config.ts test/unit/console-fetch-surface.test.ts
```

| 撞上的现象 | 大概率是哪一位 | 先看哪里 |
| --- | --- | --- |
| 同一页两块数字来自不同时刻（一个 3、一个 4） | 两处各写各的键 | `[键字符串的位置]` 与 `[出口调用点]` |
| 面板加了个 `key` 说是要"独立刷新" | 共键被拆 | 静态判据"出口调用不许带第二个实参"会红 |
| 想数清一次进页面发几趟请求 | 这一层数不到（没有可连站点） | 端到端那两份规格，且要有真会话 |
| 测试文件显示"没有测试" | 收集阶段就报错（符号遮蔽、语法） | 看 `ReferenceError`/`SyntaxError` 那一行，别看汇总 |
| 注释里的编号找不到文章 | 编号指针过期或未落地 | 注释只写"由哪份判据钉着"，不写编号 |

## 交付前自查

- 三处改动都改了代码而不是只说：两处注释按事实重写、两份新判据（运行时 3 条＋静态 4 条）
- 共键的效果用"第二个 handler 没跑、值取自第一处"来证，而不是用"两处返回同一个对象"来证（后者在取数为空时是平凡真，正文直接这样写）
- 三个变异各打了什么、什么没打红都记全了：摘掉键在运行时层不红，所以它归静态判据管
- 一个符号名导致的"整份测试没跑"写成了排错条目
- 依旧没有连库：进这一页要真会话，那三条端到端仍跳过，本节不写"真会话下发几趟"的结论
