## 已经给那块包了边界，为什么整页还是没了

前三站读的都是浏览器里那一拍：套上边界之后，抛错只吃掉那块位置，正文、导航、边界外面那块一位没少。带着这个形状往下做，容易得出一个过宽的结论——"这块红过也不会掀整页"。

这一站读两个把它收回原样的形状。第一个：同一次抛错发生在服务端那一次渲染里，探针不再等你点按钮，而是从第一趟响应就在那儿。第二个：官方在讲 `<NuxtErrorBoundary>` 那一节留了一句提示，说换一条路由之后错误会自己清掉——这句里的"错误"有两处状态可选，不分开会读成"框架替你擦了边界的账"。

## 官方给的两句话

讲 `<NuxtErrorBoundary>` 那一节：「handles **client-side** errors happening in its default slot」，再往下是那句提示「If you navigate to another route, the error will be cleared automatically.」讲错误处理那一节的同一段补了范围话：「On client-side, it will prevent the error from bubbling up to the top level, and will render the `#error` slot instead.」——两处都把这一层包装限定在客户端。

## 仓库里加了什么

`app/pages/docs/[slug].vue` 新增一档 `boundary-ssr`：探针不是点出来的，模板里直接挂着，外面是边界。

```vue
<template v-if="实验档 === 'boundary-ssr'">
  <p data-testid="ssr-keep">这块在边界外面 LAB_SSR_KEEP_811</p>
  <NuxtErrorBoundary @error="记边界报错">
    <LabBoomPanel where="render-ssr" />
    <template #error="{ error: 服务端收到的错 }">
      <p data-testid="ssr-slot">边界里的错误槽 LAB_SSR_SLOT_811：{{ … }}</p>
    </template>
  </NuxtErrorBoundary>
</template>
```

`app/components/LabBoomPanel.vue` 多一档 `where="render-ssr"`，抛的是 `LAB_BOOM_811：服务端渲染期抛错（外面套着边界）`——哨兵字样独立一位，才不会和 807 那次的文字混起来。`boundary` 那一档还多了一行读数，读的是**全局**那一位错误：

```ts
const 全局错误 = useError()
const 全局错误文本 = computed(() => (全局错误.value
  ? `${全局错误.value.status ?? ''} ${全局错误.value.message ?? String(全局错误.value)}`.trim()
  : '空'))
```

判据还是 `test/e2e/error-boundary.spec.ts`，这一站加四条（档十三到档十六），整档十六条一起跑 `16 passed`。**服务端那一趟走 HTTP 层读**（看响应码与响应体），因为这一趟浏览器里没有可执行的页面脚本可读。

## 服务端那一路：整条响应被换掉，那层包装一次都没被叫到

```text
[边界·SSR那一路] {"有边界":{"状态":500,"字节":3302,"有边界默认槽":false,"有这一档那块":false,"有正文标记":false,"有错误页状态行":true,"哨兵在响应体里":true},
               "对照组没抛错":{"状态":200,"字节":8588,"有边界默认槽":true,"有这一档那块":false,"有正文标记":true,"有错误页状态行":false,"哨兵在响应体里":false}}
```

抛错那一趟：**状态码 500**、响应体 3,302 字节、正文标记不在、`有这一档那块: false`——连写在边界外面的那块都没了，取而代之的是错误页那一行状态码。对照组是同一份模板不抛错那一档：200、8,588 字节、正文与边界默认槽都在。

这与 807 那次**没有边界**时读到的形状一模一样（那一次是 500、7,184 → 3,305 字节）。所以"有没有这层包装"在服务端这一路读不出差别。原因就在这层包装自己的源码里：`<NuxtErrorBoundary>` 的错误捕获整个被一句客户端判断包着（`node_modules/nuxt/dist/app/components/nuxt-error-boundary.vue:31`，`if (import.meta.client) { … onErrorCaptured(…) }`）——服务端根本没有注册它。**边界的作用范围等于它被注册的那一侧**，这就是官方那句"client-side"的实际分量。

这一趟顺带钉一条安全口径：`哨兵在响应体里: true`。错误页会把那次抛错的 `message` 发到响应里（本站的错误页就是取那一位来说人话的），堆栈没跟来。⇒ **往 `message` 里写什么，等于往响应里写什么**：内部编号、SQL 片段、上游原文都不该进这一位。

判据不是空转的。两处变异：① 把这一档的探针换成不抛错的那一档（`where="value"`），同一趟读回 `{"状态":200,"字节":7589,"有这一档那块":true,"有正文标记":true,"有错误页状态行":false}`，当条红；② 把探针从边界里挪到边界外面（成了兄弟节点），客户端那一趟就等不到回退块，判据超时红。两处改回之后 `16 passed`。

## 同一份模板，只换"发生在哪一拍"：客户端导航过来时边界接住了

上面那一档也能**从站内点过去**（`boundary` 那一档下面有一条 `<NuxtLink>` 指向它）。点过去走的是客户端导航，服务端没有重新渲一遍，这一趟抛错发生在浏览器里。

```text
[边界·同一探针两拍] {"这块还在":1,"边界里的错误槽":1,"错误槽文本":" 边界里的错误槽 LAB_SSR_SLOT_811：LAB_BOOM_811：服务端渲染期抛错（外面套着边界）","探针自己":0,"整页错误页":0,"正文":1,"顺序":" 走到这一档时三条口子的顺序：@error → vue:error → @error → vue:error"}
```

同一位探针、同一个 `where="render-ssr"`，这次读回来的是：边界外面那块还在（`这块还在: 1`）、回退块渲出来了（`边界里的错误槽: 1`，文本里带着那条消息）、整屏错误页没出现（`整页错误页: 0`）。与上一节那趟 500 并排放，**差别只在抛错发生在哪一拍**：服务端那一拍没有捕获可注册，客户端这一拍有。

`顺序` 那一位还顺手回答了另一个常见问题：里面攒着**两截**（`@error → vue:error → @error → vue:error`）——前一截是点`挂上`那一次留的，后截是这一趟探针被挂上留的。 ⇒ **只改查询串的路由变化不会重建页面组件**，页面级那几位状态是攒着的。

## 边界里红过一次之后离开再回来：消失的到底是哪一位

```text
[边界·换路由] {"红过之后":{"错误槽":1,"计数":" 边界里红过：1 次 ","全局位":" 全局那一位错误（useError）：空"},
            "回来之后":{"默认槽":1,"错误槽":0,"计数":" 边界里红过：0 次 ","顺序":" 三条口子被叫到的顺序：还没红过","钩子次数":" vue:error 钩子被叫到：0 次（最近一条：没有） ","全局位":" 全局那一位错误（useError）：空","地址":"http://localhost:3403/docs/getting-started?islandLab=boundary"}}
```

两位同时读，才看得清这句提示在说什么。红过的那一刻，**全局那一位是空的**，回来之后还是空的——边界接住的那次抛错从来没进全局状态，`error.vue` 也从没被叫到。而"回来"读到的形状是整个页面重来一遍：默认槽在场、回退块没了、`红过` 计数从 0 重新开始、三条口子的顺序与钩子次数也归零。这一档页面上那些计数是页面组件自己的状态，客户端换路由把这一页的组件销毁重建，它们自然回到起始值。

⇒ 对边界里那位错误来说，官方那句"自动清掉"读到的机制是**随组件一起没了**，不是"框架把状态擦了"。这条区别有实际后果：**别指望靠跳路由把这次红抹掉**——跳走那一刻它在应用里已经不留痕迹（上一站读到控制台 0 条，这一站读到全局那一位一直是空）。要留下记录，只能在红的那一刻就挂上去。

## 全局那一位确实被换路由清掉——那是整屏错误页在读的一位

官方那句提示真正管的是全局状态。读法：807 那档里点`点一下抛一个致命错`（事件处理器里抛带 `fatal: true` 的 `createError`），整屏错误页出现；然后不走整页刷新，直接拿应用实例上的 router 做一次客户端导航。

```text
[边界·全局那位换路由] {"错误页上":{"状态码":"500","有错误页":1,"地址":"http://localhost:3403/docs/getting-started?islandLab=err"},
                   "换路由之后":{"地址":"http://localhost:3403/","有错误页":0,"有首页正文":1}}
```

换一次路由，整屏错误页就没了（`有错误页: 0`），首页正常渲出来。清它的代码在路由插件收尾那一句里（`node_modules/nuxt/dist/pages/runtime/plugins/router.js:101`）：客户端、且已经过了水合那一拍、且全局那一位有值，就替你调一次 `clearError()`。而"该渲错误页还是渲正常页面"是根组件按全局那一位分的（`nuxt-root.vue:2-7`，两者二选一）。

两位放在一起，这条线的分工就完整了：

| 那一位错误 | 谁写它 | 谁清它 | 服务端渲染时 | 界面上是什么 |
| --- | --- | --- | --- | --- |
| 边界自己的（组件内那一位状态） | 默认槽里的客户端抛错 | 只有那颗按钮，或者那位组件被销毁 | 根本没注册捕获，管不到 | 那一块的 `#error` 回退块 |
| 全局的（`useError()`，在负载里） | `showError`、带 `fatal` 或 `unhandled` 的错 | 自己调 `clearError()`；客户端换路由时框架替你调 | 服务端就把整条响应换成错误页 | 整屏错误页 |

产品上的意思是：**整屏错误页不是边界"升级"出来的**，它由全局那一位决定。边界管的是"这一块红的时候别让整页跟着没"，管不到"这一页的服务端渲染失败"。要让服务端那一路也别掀整页，得在它自己那一层处理——接口回结构化错误、页面按状态渲兜底内容，不是这里再套一层包装能补的。

## 排错表

| 想知道的 | 读哪一位 | 只读一处会错在哪 |
| --- | --- | --- |
| 边界对服务端那一趟有没有用 | 状态码 ＋ 边界外面那块在不在响应里 | 只在浏览器里看会以为"包了就没事" |
| 这次抛错发生在哪一拍 | HTTP 那一趟 ＋ 站内点过去那一趟 | 只读一趟会把"接得住"当成通用结论 |
| 换查询串算不算新页面 | 页面级那一位顺序串攒了几截 | 以为它会归零，就会把攒着的数读成"又红了一次" |
| 换路由清的是哪一位 | 红过那一刻全局那一位空不空 | 只看回退块消失会误以为框架擦了边界的账 |

## 自己动手跑一遍

```bash
npm run build
npx playwright test test/e2e/error-boundary.spec.ts
```

预期 `16 passed`。手点版三段。一：地址栏直接进 `http://localhost:3100/docs/getting-started?islandLab=boundary-ssr`，看到的就是整屏错误页。二：进 `?islandLab=boundary`，点`在边界里挂上那一位会炸的组件`，读那行"全局那一位错误：空"；再点`返回文档列表`、点回那一档，那块位置回到默认槽、`红过` 从 0 重新开始。三：还在 `?islandLab=boundary` 时点`换到服务端那一档`，同一位探针这次被边界接住了，而顺序那一行攒着两截。
