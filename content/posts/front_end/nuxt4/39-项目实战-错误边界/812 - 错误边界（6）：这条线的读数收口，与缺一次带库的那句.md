## 五步走完，桌上剩两件事

前五步读完，应用里其实只有**两处错误状态**：边界自己那一位（组件内部的）和负载里那一位（整屏错误页读的）。前五步读的都是前者——回退块、计数、三条口子、服务端那一拍。这一站做三件事：把后者也读一次，把"会员区到底要不要真加一处边界"按读数裁掉，然后把六步的形状汇成一张能对着改代码的表。

## 六步各留一句

| 第几步 | 读到的形状 |
| --- | --- |
| 807 没有边界时 | 客户端渲染期抛错**不白屏、也没痕迹**（DOM 一位没少、`pageerror` 0 条、新挂那位没渲出来，只有控制台一行）；服务端那一路抛错掀掉整条响应（500、7,184 → 3,305 字节） |
| 808 套上边界 | 那块位置留下看得见的回退（默认槽 1→0、`#error` 槽 0→1），"红过"变成界面上可读的数（计数 0→1）；代价读出来是零。代价的另一面：控制台从此 0 条 |
| 809 槽里那两样 | 交出来的 `error` 是原始错误对象（`可枚举键` 是空数组）；`{{ error }}` 只留 58 个字符是因为 Error 有自己的 `toString`，**抛自拼对象就走 JSON 那一路**（123 字符、字段名全露）。`clearError` 只把边界那位置回空 ⇒ 原因没改掉就再红一次 |
| 810 三条口子 | 一次抛错把 `@error` 与 `vue:error` 按顺序各叫一遍，而且**不在同一拍**（前者读到 null、后者读到值、隔 0.70 毫秒）；`useTemplateRef` 读的是那一个实例自己的状态；边界外那趟只有 `vue:error` 响 ⇒ 全站上报挂它 |
| 811 管不到的两处 | 服务端那一路边界一点作用没有（那层捕获整个写在客户端分支里）；"换路由自动清掉"管的是**负载里那一位**，边界那一位是随组件销毁而消失 |

## 这一站的新读数：直接读负载里那一位

前一站是从"整屏错误页消失没有"倒推那一位被清了没有。这一站直接读它：`$nuxt.payload.error` 就是 `useError()` 背后那一位（包内 `nuxt.js:100` 把 `$nuxt` 挂在 Vue 应用的 `globalProperties` 上），在页面上下文里取它，三个时刻各读一次。

```text
[边界·负载那一位] {"红之前":"undefined",
                 "边界红过":{"负载":"undefined","回退块":1,"整页错误页":0},
                 "致命错之后":{"负载":"对象 status=500 fatal=true unhandled=false message=LAB_BOOM_807：客户端抛的致命错","整页错误页":1},
                 "刚推完":{"负载":"undefined","整页错误页":1,"地址":"http://localhost:3416/"},
                 "界面跟上":{"用时毫秒":47,"负载":"undefined","整页错误页":0,"有首页正文":1}}
```

三件事一次说清：

- **边界里的红从不写进负载**：那一块回退块在场（`回退块: 1`）时，负载那一位还是 `undefined`，整屏错误页也没出现。⇒ "包了边界"与"把错误交给全局"是两条路，别把前者当后者用。
- **带 `fatal: true` 的 `createError` 走的是后者**：负载里躺着一个对象，`status=500`、`fatal=true`、`unhandled=false`，消息就是那句人话。
- **换路由时那一位先被清、界面随后才跟上**：`router.push('/')` 之后立刻读，负载已经是 `undefined`，而那一刻整屏错误页还在（`整页错误页: 1`）；再等 47 毫秒，错误页才换走、首页正文出来。⇒ 清它的代码在路由插件收尾那一句（`pages/runtime/plugins/router.js:101`），而"换没换页面"要等一次渲染。写自动化判据时这一先后可坑人：别用"界面已经变了"去证明"状态已经清了"。

顺手做了一次反向验证：在边界的 `@error` 处理器里补一句 `showError(错误)`——也就是"接住之后又把它交给全局"。结果那一趟**等不到回退块**：应用直接切到整屏错误页，判据当条红（`1 failed`）。⇒ 两条路同时用，"只吃掉这一块"就没了。改回之后 `27 passed`（这条线三个判据文件现跑的总数）。

## 会员区到底要不要真加一处边界

这是这条线留到最后的一个决定。读数给的答案是**不加**，理由有三条，都是量出来的：

1. 会员区那一块的真实失败走的是状态那一路，不是渲染期抛错那一路。接口回 401/500 时，`useAsyncData` 把它收进 `status`，页面渲的是"没取到"的形状——运行时判据现跑读回 `{"状态栏":"error","数字栏":"-"}`（786、787 那两步立的形状，这一站重跑仍绿）。
2. 边界管的是"这一块的代码在渲染期抛了"。会员区现在没有这种代码路径；为了"以后也许有"先包一层，读到的一直是不会出现的那一支，反而把真正该看的形状位挡在包装之后。
3. 上面那句反向验证：**一旦你顺手把边界里的错再交给全局，用户看到的就又是整屏错误页**。在会员区里加一层没人读的包装，等于给这个误操作留了位置。

裁决要能被复核才算数，所以判据里把"那一块确实有失败形状位"钉住了：`app/pages/console/index.vue` 里的 `metrics-status`／`metrics-total`、`app/components/ConsoleMetricsPanel.vue` 里的 `panel-status`／`panel-total` 四位都在，扫描现跑读回

```text
[baseline error boundary] {"vueFiles":22,"boundaryHits":1,"命中边界":["pages/docs/[slug].vue"],"原文命中边界":2,"mainHits":2,"hasErrorPage":true}
```

`boundaryHits: 1` 是这条线自己钉的形状：那一位只在文档详情页的实验位里。哪天会员区真的出现一处渲染期会抛的代码，这条判据就该红一次，改它的时候把理由写清——上一站改判据就是这个流程。

## 六位一起收的账

判据按用例数报（这一站把三个文件一起重跑，不按文件数）：

| 判据文件 | 用例数 | 管什么 |
| --- | --- | --- |
| `test/e2e/error-baseline.spec.ts` | 6 | 没有边界时四种抛错各掀多大一片 |
| `test/e2e/error-boundary.spec.ts` | 17 | 套上边界之后的形状：回退、计数、槽里两位、三条口子、服务端那一拍、负载里那一位 |
| `test/e2e/console-baseline.spec.ts` | 4 | 三条引入前基线 ＋ 边界扫描（含会员区那四位形状位） |
| 合计 | **27** | 一条线跑完的形状 |

被跳过的用例分两类，只有第一类算这条线的欠账：

```text
跳过用例总数（来自日志）：57
  要库: 25
  要内容目录读得到: 14
  要另一趟构建的开关: 10
  要外部服务变量: 8
```

那 25 条要库的用例里，**会员区数字与库里条数对不对得上**这一句还是没读——它要一次带库的跑法（`NUXT_E2E_DB=1` 加上一个能连上的连接串）。这条不是判据写得不好，是环境缺件：这一站把它原样留着，不用离线读数凑数。

## 动手跑一遍

```bash
npm run build
npx playwright test test/e2e/error-baseline.spec.ts test/e2e/error-boundary.spec.ts test/e2e/console-baseline.spec.ts
```

预期 `27 passed`。手点版最能说明这条线的一句：进 `http://localhost:3100/docs/getting-started?islandLab=boundary`，开 Console 面板，点`在边界里挂上那一位会炸的组件`——块里出现回退文本、上面那行计数翻到 1 次、Console 一条错误都没有；再点`清掉它`，计数变 2 次（原因没改掉）。想看见"清干净"那一支，先点`把抛错的原因改掉`再点`清掉它`。

## 收口表与还差的

| 一句 | 现在能不能说 |
| --- | --- |
| 一块数据渲染期抛错不许把整页带走 | 能（808、810、811 三条读数）。注意它管不到服务端那一拍 |
| 红过要留下可读的痕迹 | 能：界面上自己放计数位；上报挂 `@error`（只这一块）或 `vue:error`（全站）——控制台在有边界时是静音的 |
| 会员区的数字与库里数出来的条数一致 | **不能**，缺一次带库的跑法（那 25 条跳过用例里的这一句） |

这条线还留三处没钉到底：`@error` 与 `vue:error` 之间那一拍的成因（读到"只有 1 个注册者"，原来的解释不成立）；`vueApp.config.errorHandler` 那一条口子没开（它会替换默认那一路，前几站读的控制台一行正是默认那一路发的）；把 `createError(...)` 从默认槽里抛出去时槽里读到什么形状还没读（它的 `status`、`fatal` 是可枚举的，插值会走哪条分支未知）。
