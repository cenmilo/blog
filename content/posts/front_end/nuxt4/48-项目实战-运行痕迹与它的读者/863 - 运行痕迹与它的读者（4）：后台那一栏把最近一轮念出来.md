## 数据存着，没人看得见

现在的情况：`/api/admin/task-runs` 能回一页轮次，`task_runs` 那张表一轮写一行，跑成跑砸都会出声。但 `app/pages` 整个目录里找不到 `admin` 这个词——后台不存在。

这一站写四个文件：一个页面、一个路由中间件、一个组件、一个取数出口，连注释一共 120 行。收获在两处：一处是**构建之后那道门消失了**，一处是一栏要念的形状比预想多一倍。

```ts [app/middleware/admin-auth.ts]
export default defineNuxtRouteMiddleware(() => {
  const 眼前的人 = useUser().value
  if (!眼前的人) return navigateTo('/me')
  if (眼前的人.role !== 'admin') return navigateTo('/')
})
```

```vue [app/pages/admin/index.vue]
<script setup lang="ts">
definePageMeta({ middleware: ['admin-auth'] })
if (import.meta.server) {
  useSeoMeta({ robots: 'noindex' })
}
</script>

<template>
  <section>
    <h1>运行痕迹</h1>
    <AdminRunColumn />
  </section>
</template>
```

那一栏自己取数，不接 props：`await useTaskRuns('/api/admin/task-runs')`，而出口把键烤死在里面：

```ts [app/composables/use-task-runs.ts]
export const useTaskRuns = createUseFetch(() => ({
  key: 'admin:task-runs',
}))
```

为什么用函数写法而不是对象写法：对象写法是默认值，调用方给一个同名 `key` 就把它顶掉；函数写法反过来，工厂给的选项压过调用方的。这个区别在运行时量过——同一处调用点带上 `key`，一次访问取两趟；锁住键的写法仍然是 1 趟。这条地址回的是全站的轮次，下一块要显示它的地方出现时，两栏必须念同一个"最近一轮"。

## 具名中间件放进目录不算数

路由中间件分三种：页面里的匿名中间件、`app/middleware/` 里的具名中间件、带 `.global` 后缀的全局中间件。只有第三种每次导航都跑，前两种要在 `definePageMeta` 里点名——官方那句写得很直白，具名中间件是"用在页面上时"才被异步加载。表现是：文件叫 `admin-auth.ts`，放对目录，页面里不写那句声明，`/admin` 谁都能打开。所以有一条判据专门问页面文件里是否出现 `middleware: ['admin-auth']`。

## 第一次端到端：302、落点，以及跟着跳的那次 200

匿名访客直接请求 `/admin`，量到的是这几个数，不是一个 403 页面：

```json
{"裸":302,"落点":"/me","对照console":302,
 "request层":{"status":302,"location":"/me"},
 "跟着跳":200,"浏览器停在":"/me"}
```

服务端那一趟 `navigateTo` 同时把响应状态码定成 302（要 301 得自己写 `redirectCode`）。落点是 `/me`，站内唯一能登录的入口在那一页；已登录但不是管理员的人落点是 `/`——两种人要做的动作不同，折成一个落点的症状是让人反复登录。最后一位是"跟着跳转再问一次"，读到的 200 属于另一页。

这一位最容易看错：拿到 200 就以为门没挡。这一层从来不回 403，被挡住时发的是 302 加一个落点。接口那侧是另一道独立的闸，同一个非管理员会话两边各是这样的读数：

```json
{"页":{"status":302,"落点":"/"},"接口":{"status":403,"code":"FORBIDDEN"}}
```

## 构建之后，门不见了

把构建产物翻出来看，`.output/public/admin/index.html` 躺在那里——89 字节，整份内容是一行 meta 刷新：

```html
<!DOCTYPE html><html><head><meta http-equiv="refresh" content="0; url=/me"></head></html>
```

本站开着 `nitro.prerender.crawlLinks`，构建时预渲染器会顺着链接匿名访问它能发现的每个地址。`/admin` 被首页的链接指着，于是被请求一次；页面门把它弹到 `/me`；预渲染器把**跳转之后**拿到的那份 HTML 存成了那个文件。之后这个地址由静态文件接管：服务端中间件不再跑，管理员打开看到的也是这份壳。

修法是一行路由规则：

```ts [nuxt.config.ts]
routeRules: {
  '/admin/**': { ssr: true, prerender: false },
}
```

这里和官方那段混合渲染的示例有个方向差：那一节把 `'/admin/**'` 写成 `ssr: false`，本站反过来写 `ssr: true`，因为这一栏第一屏就要念出"最近一轮跑过了"，`ssr: false` 的代价是首屏空一帧。共同点是都必须显式登记，而这一格起作用的是 `prerender: false`。

新判据不找 `prerender` 这种关键词，它把两件事分开算：先从页面目录列出所有声明了中间件的文件，再按路由名去问配置里有没有一条规则盖得住它、且那一格里写着 `prerender: false`（glob 键 `'/admin/**'` 要剥掉尾部再比前缀）。抹掉那一行的 `prerender: false`，读数立刻变成：

```json
{"门后页":["/admin","/console","/console/js-lab","/console/nojs-lab"],
 "没盖住":["/admin←app/pages/admin/index.vue"]}
```

它的覆盖面要写明：这一档从"页面里写了声明"出发找门后页，一句声明都没有的新页面它看不见——那一格由前面那条声明判据和端到端那次真请求分工守着。

## 一栏有九种形状，句子只有一份

后端把"没有"分成四种响应，前端折回一种，那一格就又藏回去了。这一栏实际有九种，全在一个纯函数里分支：

```ts [shared/copy/task-run.ts]
export type 轮次栏状态 =
  '正在读' | '没登录' | '不许看' | '读不出来' | '还没跑过'
  | '这一页没有行' | '中途出错' | '没人该降' | '跑过了'
```

离线判据把这九种各问一遍，六种"没有"的句子读出来两两不相等。三处最容易写错：飞行中不许念"读不出来"（那一趟请求没落定时 `data` 也是空的）；`null` 不许念成 0——候选人数是空值就念"最近一轮中途出过错，这些数没读到"，是 `0` 才念"这一期没有人的会员到期"，写反的症状是后台对用户说"没人该降"而真相是那条查询根本没跑成；以及取对那一栏，审计失败读 `auditFailures`，不是审计成功写了几行那一位（`auditRows`）。

时刻按 UTC 出字，不用 `toLocaleString`：

```ts
return `${new Date(毫秒).toISOString().slice(0, 16).replace('T', ' ')}（按 UTC 记）`
```

服务端与浏览器会对同一个毫秒数各算一次，跨时区渲出两个字符串，症状是水合不匹配。离线读数里这一格是直的：进程时区 `Asia/Shanghai`，同一个数念成 `2026-11-09 19:10（按 UTC 记）`，而本地日期是 `10`。

## 判据读屏幕，读的是哪一个位置

端到端那一档第一版这样判断"页面念的是哪一句"：`expect(页面.includes('没人该降')).toBe(true)`。它是绿的，而屏幕上那句话并不在——命中的是页面末尾数据负载里的探针任务名字样。换成读组件里那两个 `data-testid` 之后，读数才是它声称的东西：

```json
{"status":200,"状态位原文":"没人该降",
 "句子位原文":"最近一轮跑过了，这一期没有人的会员到期。",
 "时刻位原文":"2026-10-24 00:53（按 UTC 记）","整页有任务名":true}
```

最后一位仍是 `true`：整页 HTML 里确实找得到任务名，它在负载里，不在人眼看得见的地方。另一档问"两行并存时念哪一行"——先插一个"没人该降"的轮次，再插一个"跑砸了"的轮次：

```json
{"甲":143,"乙":144,"接口第一行":144,"页面状态位":"中途出错",
 "页面句子位":"最近一轮中途出过错，这些数没读到。","最新那轮的空值":null}
```

三条要求同时成立：接口第一行是后插的那轮、页面念新那句、旧那句必须不在屏幕上。最后那位是接口原样交出的空值，没有兜成 `0` 打出去。

## 这一栏什么时候能给人看：一次改角色的读数

`requireAdmin` 的头注释原先写着"角色是登录那一刻从会话表 JOIN 出来的，改角色要等下一次登录才生效"。这句话决定了这一栏能承诺什么，所以现量一次：服务端那个中间件对每个带会话号的请求都重新查库，`role` 是从 `users` 现读的，会话行不存角色，也没有缓存层。于是同一枚会话号，先问拿到 403，把他改成 `admin`、不改会话再问拿到 200：

```json
{"改之前":403,"改之后":200}
```

正确的说法是"下一次请求生效"。但仍然只是"这一次请求读到的角色"：页面渲完之后角色又被改掉，屏幕上这一栏不会自己变。这一格留给下一站。

## 三条老判据随形状红了一次

| 判据 | 之前 | 现在 | 为什么 |
| --- | --- | --- | --- |
| 那两个失败数有没有界面读者 | `[]` | 那个组件文件 | 之前留的报警器，等的就是这一格兑现 |
| 门后页的条数 | 4 | 5 | 后台那一页与会员区同一档，不进索引 |
| 按 `role` 判 admin 的处数 | 1 | 2 | 页面门与接口门是两道，互不引用 |

第三条顺手把纯计数改成逐字名单：只数个数，长出第三个名字时判据只会说"多了 1"，说不出是谁。另有两条硬边界这一站一次没红，是设计上就不该红：应用侧不许直接引服务层（`#server` 只能在 `server/` 内部用），这条地址也只有一处引它——在组件里把地址写两处时它撞红过，读出 `地址出现次数: 2`。

三次变异都撞红了：把词表里一句话写进组件模板 → "句子写在词表之外"红；在调用处补一个 `{ key: ... }` → "调用处自带键"红（键会被顶掉、趟数仍是 1，这条守的是读代码的人以为这一栏另有键）；抹掉配置里那半行 → "有门后页没显式不预渲染"红，真构建一次还能看到那个 89 字节的壳重新长出来。

## 本轮读数与还欠着的格子

单测 448 条／69 个文件，组件档 69 条／17 个文件。端到端全量不带库那趟 260 通过／160 跳过／0 失败（归族：要库 88、要外部变量 43、要内容目录 14、要另一趟构建 11、让路 4）；带库两趟 374／46／0 与 373／47／0。有一趟落地页那档的预取判据闪红一次，单独复跑该文件 7 通过 0 失败——同一趟全量的红绿取决于远端库与并发，不是判据属性。

欠着的四条：真空表那一格带库问不到（共享库里已经有别人的轮次，`total` 不可能是 0）；503 那一格同理；`/api/_health` 不在这一站，看得见痕迹不等于站点健康，收官那一站逐句判时点名；这一栏没有"再取一次"的按钮，服务端渲完就是那一份读数，实时性归下一站。
