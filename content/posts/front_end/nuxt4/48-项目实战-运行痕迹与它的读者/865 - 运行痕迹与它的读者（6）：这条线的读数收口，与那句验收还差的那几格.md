## 那一页念得出两句话，然后呢

后台那一页（`app/pages/admin/index.vue`）现在有两栏。第一栏念最近一轮任务跑出来的那十几个数：候选几个人、真降了几个、几封没发出去、这一轮有没有抛错。第二栏念「有几位停在发送中（几行），最久的那行距上次写入多久」。两栏各挂一个真组件，数据来自两条地址，两条地址开门的那一句都是「必须是管理员」。

看着像「后台」这一格已经填上了。收口要问的是另一件事：这条线一开始承诺过什么，逐句对着今天的站判一遍。这一站一行功能代码都不写，只做这件事，顺带把「什么叫覆盖了」变成能读的数。

## 同一句要求，在五处写着五个范围

搜一个关键词只回一处命中，而那一处往往不是范围最宽的，所以先把句子找齐。这条线相关的写法有五处。

- 成功判据第一条：那句「注册→付费→会员区→后台→定时任务→日志与监控→自托管部署全链」里，「后台」「日志」「监控」各管一段。
- 成功判据第三条：点名响应头里的请求号、一个返回数据库连通情况的健康检查地址、事件重放不产生第二份订阅、到期降级可手工触发并有日志。
- 范围表「管理后台」那一行：用户查询、封禁、订阅手工调整、审计日志、每日到期降级任务、运营指标看板。
- 同表「运维面」那一行：结构化日志、请求号、健康检查、错误上报，外加备份与迁移演练、回滚、部署脚本。
- 运维细节那一节最具体：健康检查就是一个地址，内容三样——数据库连得上、进程起了多久、版本号。

范围不同，判法就必须分开。运维那一行的备份演练与回滚不该由这条线交账；而「管理后台」那一行的「用户查询」「封禁」「订阅手工调整」，六个字句句说的是屏幕上的动作，今天一条都没有。判完要给五份结论。

## 判「做没做」分三层读

判一个动作做没做，代码里有三层可查：那一列在不在、有没有代码写它、有没有代码读它。这一站的读数由 `test/unit/task-run-closure.test.ts` 第 ⑩ 档打印：

```json
{
  "表定义在不在": true,
  "应用侧碰这一列的文件": [],
  "admin 下的端点": 3,
  "审计日志的写者": 1,
  "审计日志的读者": []
}
```

`users.banned_at` 那一列在，而**应用侧碰它的文件是 0 个**。表定义里有它（`db/tables/users.ts:19`），没有任何一行应用代码读它或写它。「封禁」这个动作因此不存在，只剩那个空格子。「有列」比「没做」更容易骗人：只看库结构的人会以为功能已经在那儿了。

`audit_logs` 有一个写者、**零个读者**。降级和踢下线各留了一条，但没有任何接口或页面去查这张表。要求里写的是「审计日志」，它要的是能看见；留了痕而没人看得见，这一格判「没做」。

读者那一层数得出来的只有三条地址——最近轮次、停在发送中的名单、把某个人的会话删掉。列用户没有，改订阅没有。

于是那句要求的判定是：**这条线交付的是「读痕迹」，不是「后台」**。两个词在要求里挨着写，在代码里差着一整段。

## 读文本的那一档，顶不掉跑真东西的那一档

这条线的判据一共八份文件、44 档。第 ⑨ 档把这 44 档按一个机械标准分成两类：

```ts [test/unit/task-run-closure.test.ts]
const 形状式 = /readFileSync\(|去注释\(|列出命中\(|命中文件\(|\.match\(|\.search\(|\.test\(/
```

档体里出现这些调用，说明它读的是源码文本（扫文件、比对字符串位置）；否则它跑的是真东西——调服务函数、挂组件、打活着的服务器、开假库。本轮读回的合计是形状 12／行为 32，而「只有文本档」的文件只有一份：`test/unit/run-surface-baseline.test.ts`，十档全在读文本。

那份文件守的是「代码必须写成什么样」，很有价值；但「读回来的数对不对」这类问题它永远答绿，因为它压根没跑。分类式子本身有盲区，这条也写在判据注释里：`.match(` 算读文本，于是「挂起组件、在渲染出的 HTML 里数 `<button`」那一档被算进形状，而它其实是行为档。另有一条护栏守着分类不出错：两类之和必须等于账本登记的档数。

## 「到点自己跑」这一格，今天谁能证伪

痕迹表里「谁叫起这一轮」有三个值：`schedule`、`manual`、`unknown`。判它的那一个函数只有四行：

```ts [server/services/task-run.ts]
if (!事件?.payload) return 'unknown'
return 'scheduledTime' in 事件.payload ? 'schedule' : 'manual'
```

`schedule` 那一个分支不是没人测：单测里喂一份带 `scheduledTime` 的负载，它回 `schedule`。要区分的是另一件事——带库那一趟真跑出来的痕迹里 `schedule` 一次都没出现：任务层为自己出声的那 9 行日志，`level` 全是 `info`、`trigger` 全是 `unknown`。

原因是这两条路都没经过排期：端到端调的是任务对象的 `run()`，而跑手在测试环境不启动。于是「到点自己跑，库里会多一行 `schedule`」这一句，今天**没有任何一档能证伪**。

同一条纪律这是第十七次撞上：**判据的覆盖范围只能由撞红量出来**。绿灯不答话，所以写进文档的结论只能是一格未覆盖。

## 两格问不到，各自要写出谁来守

后台那条接口有四种「没有」，长成四个不同的样子：没登录 401、角色不对 403、查询串非法 400、没配数据库 503，而「表里真没行」是 200 加一个空数组。带库那一趟问不到其中两格。

- 503 那一格：这一趟的服务是配好库起的，这条地址在这一趟**不该**给 503。那一档钉的是「读到 200」，没配库那一半由不带库那趟的五档守着。
- 空表那一格（`total` 为 0）：共享开发库上这张表总有行，「从来没跑过」在这一趟永远造不出来。它由「没配库时读接口」那一档交账，那一档走的是根本不碰库的那条路。

问不到的格子必须写两句：这一趟为什么问不到，以及它由哪个环境里的哪一档守。只写前一句，后来人会把「这趟没测」读成「这件事没人管」。

## 这一趟的读数只属于这一趟

本轮四组数，端口与环境都点名：

```bash
E2E_PORT=4199 NUXT_E2E_DB=1 npx playwright test --reporter=list
```

- 聚合检查八项全过：单测 457 条／69 文件（比上一站多 2，就是新加的那两档），组件档 71 条／18 文件
- 端到端不带库：260 passed／164 skipped／0 failed
- 端到端带库（端口 4199）：378 passed／46 skipped／0 failed
- 那 46 个 skip 按原因分族：要外部服务变量 17、要内容目录读得到 14、要另一趟构建的开关 11、要库 4
- 本线三份带库文件共 15 档，这一趟 0 skip

分族本身就是判据：46 个 skip 不说明什么，17 个在等一个环境变量说明的才是环境缺件。上一趟带库是 376/48/0，差的 2 档全在「要库」那一族——同一批用例在两趟里被环境放行得不同。所以收口不写「带库已验证」，只写「这一趟、这个端口、这组数」，并允许重跑。

## 三次推倒，各撞红一处

新加的两档也要能被证伪，否则它就是第二份「注释里的承诺」：三个变异各改一处，验完即回。往一个服务端文件里塞一句引用 `banned_at` 的常量，⑩ 红，那一项从空数组变成那个文件名，它认的是「有没有人开始动那一列」；在一份端到端文件的某一档开头加一句 `'sending'.match(/sending/)`，⑨ 红，合计从 12／32 变成 13／31，它认的是分类计数不是一个大概；给第二栏的模板加一个 `<button>`，组件档红，读回「按钮 1」，消息写着「屏幕上出现了一个没有依据的动作」，上一站那条「没有依据就没有回收按钮」由这里守着。

探针删没删干净是靠聚合检查里的 lint 确认的：第二处漏删过一次，检查停在 lint，报出那个变量赋值后从未被使用。**验证「回到原样」要有一条独立的路**，不能靠「记得删了」。

## 交给下一线的几格

- 健康检查：`server/api/` 下没有那个文件，整格没动。
- 封禁、用户查询、订阅手工调整：做出来任何一条都会把 ⑩ 撞红，那正是这一档想要的反应——红了改期望值，别删档。
- `sending` 的回收：三条来源都不给「多久算死」那个数，它欠的是一个能被验收的出处，不是一个实现。
- 命名并轨（任务的注册名与它写进表里的名字是两套）要动文件，等人点头；那两栏的「再取一次」与整页名单，得先谈清给谁看。
