## 表里有行，日志里有声，界面上还是查不到

上一线给每一轮任务留了一行痕迹，上一站又让顺利跑完的那一轮在服务器输出里出了一句。现在你要回答"昨晚那轮跑成什么样"，仍然只有两条路：登进服务器 `grep` 日志，或者手写一条 SQL 问那张表。

这一站加第三条路：一条只读的 HTTP 地址。听起来就是"select 一下再回给前端"，但真写下去要回答的问题一个比一个硬：这条地址该谁问、他翻页翻过头时你回什么、库里一行都没有和数据库没连上是不是同一个样子。

## 第一个问题不是 SQL，是这份数据属于谁

`server/api/` 下的目录名就是路由，这是官方 `directory-structure/server` 那一节定的。本站在这一层已经有两档门：`console/` 走的是"确认你是谁"（登录者本人的订阅、计量），`admin/` 走的是"确认你是不是管理员"。

这张痕迹表记的是什么？"这一轮降了哪些人的级、几封提醒信没发出去"。**这些数据不属于登录者本人。** 把它挂进 `console/` 那一档，等于每个登录用户都能读全站的处理记录——那是一扇谁都能推开的门，而它只需要一个"看起来省事"的目录。

所以新地址落在 `server/api/admin/task-runs.get.ts`，路由就是 `/api/admin/task-runs`。那道闸门用站内已有的 `requireAdmin`，而它把两种拒绝分开发：

```
[痕迹接口·门先于参数] {"裸":{"status":401,"code":"UNAUTHENTICATED"},
"带非法limit":{"status":401,"code":"UNAUTHENTICATED"}}
[痕迹接口·角色不够] {"status":403,"code":"FORBIDDEN"}
```

**401 与 403 混成一个码的写法很常见**，代价落在客户端：它分不清"该去登录"还是"登录了也进不去"，只能把 403 也当未登录处理，跳去登录页再回来一次，回来还是 403。

## 顺序不是排出来的，是有证据的

上面第一行读数里那位 `带非法limit` 才是重点：查询串里写 `?limit=abc`，匿名请求吃的仍然是 **401**，不是 400。因为这道门是整个处理器的第一个动作，参数校验、读库都在它后面。

反过来写会漏什么？校验动作的差别会变成一种可被探测的信息——没登录的人靠 400 与 401 的不同，就能试出"这条地址认哪些参数、每页上限是多少"，一次请求都不需要登录。站内那条删会话的后台地址早就把这条顺序写在了头注释里，同一族。

这一站为此红过一次自己的判据。第一版形状档问的是"门的位置在取数之前吗"，于是把门从函数头挪到参数校验后面再跑，七档全绿——**它只比了门与取数，泄露恰恰发生在门与参数那一段**。补的那一条改成"从函数头往下扫，出现的第一个动作必须是门"，同一个变异立刻报 `读到的第一位是「参数校验」`。这是这条系列第十三次撞上同一条纪律：**判据的覆盖范围只能由撞红量出来**，而且"位置＝顺序"这种静态判断，只在整份文件里那个动作恰好出现一次时才成立，所以先数次数再比位置。

## 四种"没有"要长成四个样子

这是这一条地址最容易做错的地方。把它的响应表摊开：

| 你问的情况 | 响应 | 机器码 |
| --- | --- | --- |
| 没带会话 | 401 | `UNAUTHENTICATED` |
| 带了会话但不是管理员 | 403 | `FORBIDDEN` |
| `limit` 写 0／9999，`offset` 写负数 | 400 | `LIMIT_INVALID`／`OFFSET_INVALID` |
| 这个部署根本没配数据库 | 503 | `TASK_RUNS_UNAVAILABLE` |
| 配了库，表里一行都没有 | 200，`runs: []`、`total: 0` | — |
| 翻页翻过头 | 200，`runs: []`、`total` 大于 0 | — |

倒数第二行与第三行不能合并。**数据库没连上时回 `{runs: [], total: 0}`，界面就会念出"这个站从来没跑过任务"**，而真相是"这一栏现在读不出来"。这两种情况人要采取的动作完全不同，让它们长同一个样子，等于把最贵的那一格又藏回去了——而建那张表的初衷就是把这一格挖出来。

同一层里还有一处更小的同族陷阱：数总轮数的那条聚合语句按 SQL 保证回一行，万一读不到那一行，也不要写成 `?? 0`。读不到就是读不到，交给上面那个 503。

库连不上与没配库在这一格是汇合的（同一个码、同一句话），因为客户端要做的动作一样。那道 catch 只包那一次读：401、403、400 都在它之前抛出，不会被咽掉。

## SQL 为什么不写在接口里

`读最近轮次(限制, 偏移)` 住在 `server/services/task-run-read.ts`，接口只负责门与参数。这条边界不是审美，是判据钉着的：

```
[痕迹面·读写家数] {"写这张表的":["server/services/task-run.ts"],
"读它的":["server/services/task-run-read.ts"],
"递给界面的":["server/api/admin/task-runs.get.ts"],
"界面绕过接口直接读":[]}
```

四家各是一件事。**写者一家、读法一家、递到界面的端点一家、应用侧零家。** 最后那一格是硬边界：页面 import 不到服务层，框架本来就替你挡着——`#server` 这个别名（v4.3 起）只能在 `server/` 内部用，客户端代码里引它会直接报错。想抄近路在页面里读那张表，报的是编译错误而不是运行时提醒。

读口径单独成层的理由与"接口里直接写 SQL"有关：下一个要显示这些轮次的消费者会复制一份 SQL 并自己挑一种排序，于是"页面上第一行那一轮"和"接口回的第一轮"不再是同一件事。顺带说一句，`server/services/` 也不在自动导入范围内（官方那一节只说可以自己往 `server/utils` 里加 helper），跨目录引用一律显式 import。

## 排序要有第二把键，分页要能给出不同答案

那句读法排两把键：`finished_at` 倒序，平手时再按 `id` 倒序。第二把不是装饰——同一秒内跑完两轮是可能的（手工连点两次触发），少它就是把"哪一行排在前面"交给库随手决定，症状是刷新一次顺序变了。

真库上跑出来的读数：

```
[痕迹接口·顺序分页] {"本轮几行":3,"我的顺序":[108,109,110],
"该是顺序":[108,109,110],"limit一给几行":1,"默认那页给几行":3,
"总轮数":3,"翻过头行数":0,"翻过头总数":3,
"三个触发来源":["manual","schedule","unknown"]}
```

`limit=1` 与默认值给出行数不同、翻过头那页是空数组而总数仍然大于 0——这两条是"分页真的进到语句里"的唯一证据。少了 `offset` 会怎样？这条档读到的是"翻过头那页仍有 3 行"。

⚠ 这里的断言只在本轮自己造的那三行之间判顺序，总轮数只判它大于那一组。共享开发库上表里还有别人的行，**判"总轮数等于几"就是表级计数**，同一套用例并行跑时它会随别人写入而变——这一条已经骗过这条系列六次。探针行带本轮独有的前缀，入场先按前缀删干净、退场再删一次。

`total` 的真含义是"表里一共几轮"，不是"这一页之后还剩几页"：排期每天自己跑一轮，两次请求之间这个数会涨。页面要念的正好是前者。

## 空值与 0 在真库上也各归各

这一条地址交出去之前，那张表里两种轮次已经各造了一行：

```
[痕迹接口·空值与0] {"甲的candidates":0,"甲的空格数":0,"乙的candidates":null,
"乙的空格数":15,"甲带句子":"没有","乙带句子":"有"}
```

甲是"跑成了、这一期没人该降"：十五个计数格都有数，`candidates` 是真的 0，没有错误句子。乙是"跑到一半抛错"：十五格全是空值，带一句失败原因。

**把乙读成 0 就是编一个读数**——0 的真含义是"库里一个 member 都没有"，而乙那一轮连候选名单都没读到。同理，`trigger` 那三个值（`schedule`／`manual`／`unknown`）在回体里必须是三个不同的字，`unknown` 不许折成"手工点的"：它的含义是"手上没有证据说这是谁叫起来的"，不是"证据说不是排期"。念成人话是页面那一层的事，而且要带一句兜底给"词表外的值"——那一列是普通文本，不是枚举。

## 你加一条只读地址时的清单

- [ ] 这份数据属于登录者本人吗？不属于就别挂在他那一档的门后面。
- [ ] 那道门是不是处理器的**第一个动作**？只判"在取数之前"不够，参数校验也算泄露。
- [ ] "读不出来"与"结果为空"是两种响应还是同一种？数总数那一句读不到行时，你兜了什么值？
- [ ] 排序有没有第二把键？同一个时刻两行同时出现时谁在前面？
- [ ] 判分页的断言有没有依赖全表行数？共享库上那条断言每次绿的理由可能不一样。

| 撞到的现象 | 为什么 | 怎么办 |
| --- | --- | --- |
| 403 与 401 混成一个码 | 只在接口里写"没权限就 401" | 分工写进一个闸门函数，别在端点里各自发明 |
| 后台念"从来没跑过任务"而其实库没连 | 没配库被兜成空结果 | 503 一种码，聚合读不到行也交空值 |
| 刷新一次，列表顺序变了 | 排序只有时间那一把键 | 补一个单调的第二键，并在断言里判顺序 |
| 判总轮数的用例时不时红 | 断言依赖别人的写入 | 按本轮前缀筛，只判自己那一组与大于关系 |
| 页面想直接读那张表 | 抄近路绕过接口 | 让编译错误替你挡：那道门在接口这一层 |
