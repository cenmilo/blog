前面 275 已经用过 `nuxtApp.hook('page:start', ...)` 这类运行时钩子。但 Nuxt 的钩子名册比那一大截，混在一起看会晕。这一篇先搭一个骨架：**钩子分构建期和运行时两大类，别把它们当同一种东西。**

## 一句底层事实：都是 hookable

官方 hooks 那页开头给了统一底座：

> The hooking system is powered by [unjs/hookable].

后面还会看到事件系统也是 hookable（284 讲过）。也就是说"钩子/事件"这套订阅-触发机制，全 Nuxt 用的是同一个库——区别只在于**在哪个阶段、由谁订阅、订的是哪个名字**。

## 两大类先分开

官方 api/advanced/hooks 那页把钩子名册分成三段：Nuxt Hooks (Build Time)、App Hooks (Runtime)、Server Hooks (Runtime)。先记住最关键的构建期 vs 运行时这条线。

**构建期钩子（Nuxt Hooks / Build Time）**——官方定位：

> These hooks are available for Nuxt modules and build context.

它们在"把项目编译、扫描路由、生成 `.nuxt` 里的模板、装配 Vite/Nitro"这段时间里跑。例子像 `pages:extend`（扫完页面路由后触发）、`build:done`、`nitro:config`（293 里 pages:extend 就是它）。**使用者主要是模块作者**，普通应用代码基本不直接订它们。

**运行时钩子（App Hooks / Runtime）**——官方定位：

> App hooks can be mainly used by Nuxt Plugins to hook into rendering lifecycle but could also be used in Vue composables.

它们在"页面被服务端渲染、水合、客户端导航"这段时间里跑——`app:created`、`vue:error`、`page:start`（275 那张表）。**使用者是插件和组件**，也就是你写应用代码时最常碰的那组。

一条时间线把两者钉住：

```
[构建期]  nuxt build → 扫路由(pages:extend) → 生成模板 → 打包 → 产 .output
   ↓（构建产物部署后）
[运行时]  每次请求/导航：app:created → SSR 渲染 → app:rendered → 水合 → app:mounted → 导航(page:start/finish)
```

构建期钩子只在你 build/开发热重载时跑；运行时钩子在每次真实请求/导航时跑。混用的典型错误是"想用运行时钩子改路由列表"（该用构建期的 `pages:extend`）或"想用构建期钩子响应一次导航"（该用运行时）。

## 第三组：Server Hooks（服务端运行时）

官方还列了运行时的服务端一侧：

> These hooks are available for server plugins to hook into Nitro's runtime behavior.

例子（官方给的）：`defineNitroPlugin` 里 `nitroApp.hooks.hook('render:html', (html, { event }) => {...})`。这组跑在 Nitro 服务端、订的是 Nitro 的渲染生命周期（`render:html`、`render:response`，287 见过），归"服务端插件"用。

三组对齐成一张表：

| 组 | 什么时候跑 | 谁在用 | 在哪个文件里订 |
| --- | --- | --- | --- |
| Nuxt Hooks (Build Time) | 构建/开发时 | 模块作者、构建上下文 | `nuxt.config` 的 `hooks` 节 / 模块 setup 里 `nuxt.hook(...)` |
| App Hooks (Runtime) | 渲染与水合时 | 插件、组件 | `defineNuxtPlugin` 里 `nuxtApp.hook(...)` / 组件 `useRuntimeHook(...)` |
| Server Hooks (Runtime) | 服务端渲染/请求时 | 服务端插件 | `server/plugins` 的 `defineNitroPlugin` 里 `nitroApp.hooks.hook(...)` |

## 别只背名字，先问两件事

拿到一个钩子名，判断它属于哪组、能不能用，官方其实给了两条判据，记这两个问题比背 81 个名字有用：

1. **它跑在哪一侧、哪个阶段？** 构建期（build 时）还是运行时（请求/水合时）？服务端还是客户端？（App Hooks 那张表每条都标了 Environment：Server & Client / Server / Client。）
2. **订它的正确位置在哪？** 应用侧运行时 → 插件或组件；构建期 → `nuxt.config`/模块；服务端运行时 → Nitro 插件。

这两问对了，后面每篇（297 构建期注册、298 App/Server 分工、299 自定义钩子）都只是在这张骨架上填细节。

## 完整清单去哪查

官方对每一组都留了"看源码"的话：App Hooks 那节写 "Check the app source code for all available hooks"，Nuxt Hooks 那节写 "Check the schema source code"。文档表格是节选口径，要穷举就去 `packages/nuxt/src/app/nuxt.ts`（运行时）和 `packages/schema/src/types/hooks.ts`（构建期）。本系列会重点讲最常用的那批。

## 自查

- 先分构建期 vs 运行时：`pages:extend`/`build:done`/`nitro:config` 是构建期，`app:*`/`page:*`/`vue:*` 是运行时，`render:html` 是服务端运行时。
- 订它的位置：构建期在 nuxt.config/模块、应用运行时在插件或组件、服务端运行时在 Nitro 插件。
- 三组底层都是 hookable，机制相同，差在阶段与角色。
- 文档表格是节选，要全量查对应源码文件。
