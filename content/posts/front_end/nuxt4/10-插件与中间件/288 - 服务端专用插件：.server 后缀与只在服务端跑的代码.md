上一篇（287）说插件有"应用侧"和"服务端 Nitro 侧"两套。这一篇聚焦"只在服务端跑的应用侧插件"，讲清三件相关但不同的事：怎么让一个 Nuxt 插件只在服务端加载、怎么让它在渲染岛屿时跳过、以及"服务端专用代码面"（`nuxt/server`）的使用边界。

> 说明：索引给这编号的题面带了个 `#ssr` 条件，但我在 4.x 全量文档里搜 `#ssr` 作为导入名或条件，是零命中——文档没有这个东西。所以这一篇只讲文档确实记载的 `.server` 后缀、`env.islands` 和 `nuxt/server` 边界，不编 `#ssr`。

## 路子一：.server 后缀限定整个插件在哪侧加载

最直接的一条。plugins 那一节的 note：

> You can use `.server` or `.client` suffix in the file name to load a plugin only on the server or client side.

也就是文件名决定加载侧：

- `app/plugins/telemetry.server.ts` → 只在**服务端**加载运行。
- `app/plugins/xxx.client.ts` → 只在客户端（287 的 vue-gtag 就是这么用的）。
- 不加后缀 → 两端都跑。

适合"读请求上下文、初始化服务端资源、只想在 SSR 阶段做一次"的插件。反过来，依赖浏览器 API 的（`window`、DOM、localStorage）就该 `.client`，否则服务端那一趟访问会出问题（这条和水合那一路 278/285 呼应）。

这里要接上 273 讲指令时那句：不加分辨就访问 `ssrContext` 的插件，到客户端会空——要么逻辑里 `import.meta.server` 判侧，要么干脆 `.server.ts` 后缀，让它在客户端根本不被加载。后缀是"整插件级"的限定，`import.meta.server` 是"插件内某段"的限定，粒度不同。

## 路子二：env.islands 让插件在岛屿/服务端组件渲染时跳过

第二条更细。对象写法有个 `env.islands` 键，官方参数表描述：

> Set this value to `false` if you don't want the plugin to run when rendering server-only or island components.

背景补一句：`.server.vue` 组件、`components/islands/` 里的组件（"岛屿"），是被 Nuxt 用一个**隔离的 Vue 应用**单独渲染的，那个隔离应用默认会**把插件再跑一遍**。有些插件在这个"只为渲染一小段静态 HTML"的场景里不该跑（比如它会触发网络请求或全局副作用）——那就 `env.islands: false`：

```ts
export default defineNuxtPlugin({
  name: 'no-island',
  env: {
    islands: false,
  },
  setup (nuxtApp) {
    // 渲染服务端专用组件 / 岛屿时，这个插件不跑
  },
})
```

这条和 `.server`/`.client` 后缀是正交的两回事：后缀管"整个插件在哪一侧加载"；`env.islands` 管"即使在它加载的那一侧，渲染岛屿时跳过不跳过"。

对象写法那些键（含 `env`）和 271 一样，仍要**静态可分析**——别 `env: { islands: import.meta.server ? false : true }` 这种运行时给值。

## 边界：nuxt/server 只能用在服务端构建器打包的代码里

还有一类"服务端专用"是**代码面**层面的，容易被误解，值得单独讲。`nuxt/server` 是服务端代码的导入面（一组和具体运行时无关的服务端工具，v4.6 起）。它有一条硬边界，官方 "Server Code Only" 一节写得很重：

> Importing `nuxt/server` from a Vue component, a plugin or the `shared/` directory fails the build, and the error points you at `#app`, `#imports`, `$fetch` and `useFetch` instead.

后面还给了为什么：

> `nuxt/server` also only works in code that a server builder bundles, because the builder supplies the runtime config, app config, hooks and in-process fetch behind it. Code that runs in the Nuxt process ... has none of these, so don't import `nuxt/server` there: `useRuntimeConfig()` and `useAppConfig()`, for example, return empty objects.

把这段翻译给新手，划清三个层次：

- `nuxt/server` 是给 **`server/` 目录里的服务端代码**用的（handler、服务端工具）。
- 从**组件 / Nuxt 插件 / `shared/`** 里 `import ... from 'nuxt/server'` → **直接构建失败**，报错会把你指回 `#app`/`#imports`/`$fetch`/`useFetch`。它类型在那写能解析（所以 `$fetch` 知道服务端路由返回什么），但代码不许 import。
- 在 **Nuxt 进程本身**跑的代码（`nuxt.config.ts`、模块的 `setup`）里也不该用它——那里没有服务端构建器提供的 runtimeConfig/appConfig/hooks/in-process fetch，`useRuntimeConfig()`/`useAppConfig()` 会返回空对象。

这条 server 那一节也有对应的 important 佐证，讲的是同一层禁令的镜像：

> Do not import Vue app code (components, composables, or other app-only utilities) in your server routes or utilities, and do not import server-only code in your app.

即"app 代码别进 server、server 代码别进 app"，两个方向都禁止跨界 import。

## 三件事别混

| 你想限定的 | 用什么 |
| --- | --- |
| 整个插件只在服务端加载 | 文件名 `.server.ts` 后缀 |
| 插件在渲染岛屿/服务端组件时跳过 | 对象写法 `env.islands: false` |
| 某段逻辑只在服务端执行（同一插件内） | `if (import.meta.server)` |
| 这是给 `server/` 用的服务端工具面 | 从 `nuxt/server` import，且只在被服务端构建器打包的代码里用 |

## 自查

- 只想服务端跑的插件 → `.server.ts`；只浏览器跑的 → `.client.ts`。不写后缀就是两端都跑。
- 插件会在岛屿/服务端组件渲染时白白触发副作用 → `env.islands: false`（对象写法，键要静态可分析）。
- 想在组件/插件/shared 里 `import 'nuxt/server'`？会被构建挡下——那是 `server/` 目录的服务端代码面。app 与 server 代码不得互相 import。
- 别去找文档没有的 `#ssr` 条件；限定跑在哪侧，用的是后缀和 `import.meta.server`/`client`。
