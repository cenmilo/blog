这是一套写给完全没接触过 Nuxt、甚至没写过 Vue 的人的教程。开始之前，先花三分钟把路线看清楚。知道自己在哪、下一站是什么，比埋头往下读有用得多。

官方文档本身是按功能分类的，`getting-started/` 讲怎么用，`directory-structure/` 讲每个目录，`guide/concepts/` 讲原理，`api/` 讲每个函数和组件。这个结构适合查阅，不适合从头学。你会在读自动导入的时候，就需要知道组合式函数的上下文是什么。

所以这套教程换一个顺序，先让你能跑起来，再解释为什么能跑起来。

官方的定位是这套安排的出发点。原话是，Nuxt 使用约定和有主见的目录结构来自动化重复性工作，让开发者专注于推进功能，配置文件仍然可以定制并覆盖它的默认行为。

约定这个词，是全部难点的来源，也是全部便利的来源。教程里每一个知识点，最后都会回答同一个问题，这件事是文件位置决定的，还是配置决定的。

六个阶段，一个一个说。

阶段一，认知奠基。不用 Nuxt 手写一个最小的多页应用，你会被迫亲手做五件事，装依赖、配打包器、配路由表、写一份服务端渲染入口、处理数据。把这份手工账单列清楚，才知道 Nuxt 接走了哪些活。这一阶段结束时的能力是，能用一句话说明 SSR 与纯客户端渲染的差别，并说清 Nuxt 的七个包各自管什么。

阶段二，环境与命令。Node 版本要求、`create nuxt` 建项目、`nuxt dev` 的端口与热更新、`nuxt build` 与 `nuxt generate` 的分别、`nuxt prepare` 和 `nuxt typecheck` 什么时候必须跑。结束时你应该能回答，我敲的这条命令到底产出了什么、落在了哪个目录。

阶段三，目录结构。这一阶段是全套教程的地基，官方把 `app/` 下的目录职责写得很死。`assets/` 是由构建工具处理的网站资源，`components/` 放应用的 Vue 组件，`composables/` 添加你的 Vue 组合式函数，`layouts/` 包裹你的页面并在页面之间避免重新渲染，`middleware/` 在导航到某个特定路由之前运行代码，`pages/` 是基于文件的路由，`plugins/` 在 Nuxt 应用创建时使用 Vue 插件及更多内容，`utils/` 添加可以在组件、组合式函数和页面里使用的函数。

外加三个具体文件，`app.config.ts` 是应用内的响应式配置，`app.vue` 是根组件，`error.vue` 是错误页。以及配置侧的目录，`server/`、`shared/`、`layers/`、`modules/`、`public/`、`test/`。这一阶段结束时你应该能拿到任何一个文件，说出它放在这里会改变什么、放错位置会静默失效还是直接报错。

阶段四，视图与外壳。`app.vue`、`<NuxtPage>`、`<NuxtLayout>` 三层怎么叠，`<ClientOnly>`、`<DevOnly>`、`<NuxtErrorBoundary>` 各解决哪一类崩溃与不匹配。

阶段五，路由与导航。文件名如何变成 URL、动态段与 catch-all 的边界、`definePageMeta` 的每个字段、路由中间件在什么时候跑以及什么时候不跑、`navigateTo` 为什么必须 `await`。这是新手最容易写出看起来能跑但线上不对的一段。

阶段六往后，取数、状态、渲染模式、构建与部署、排错。官方在介绍页里承诺的能力，基于文件的路由、代码分割、开箱即用的 SSR、自动导入、取数工具、零配置 TypeScript、配好的构建工具，会在这一段逐条兑现，因为它们全都落在数据与产物这一层。

怎么读才不白读，三条要求，是我希望你从第一篇就照做的。

第一，每一篇都动手敲。每篇末尾有自查清单，勾不满就说明这篇还没读完。看会不等于写得出来，尤其是自动导入和目录约定这类看不见代码的机制。

第二，遇到报错先定位阶段。装不上或者命令不认，去阶段二。文件放了没生效，去阶段三。页面不出来或者水合报错，去阶段四、五，水合就是浏览器接手服务端送来的那段 HTML、在上面挂回事件的过程。数据不对或者包太大，去阶段六。绝大多数诡异问题的答案，就在它属于哪一层。

第三，别跳着读阶段三。后面的每一阶段都默认你已经知道某个目录会被扫描到哪里、名字怎么生成。跳过它，你会在中间件、布局、模块那几处反复卡住。

前置知识这方面，不要求会 Vue，也不要求懂服务端渲染。需要的是三样东西。会用终端进入目录、执行命令、读报错文本。看得懂 JavaScript 的基础语法，函数、对象、`import` 和 `export`、`async` 和 `await`。知道浏览器会向服务器请求 HTML，以及接口返回 JSON 是什么意思。

官方对 Vue 知识的要求写得很宽松。原话是，虽然使用 Nuxt 并不要求对 Vue 有深入的知识，但我们建议你阅读 vuejs.org 上的文档并过一遍一些示例。

我的建议折中一下，先按这套教程把 Nuxt 跑通一次，再回头补 Vue 的组合式 API。顺序反过来，很容易在一堆新名词里迷失。
