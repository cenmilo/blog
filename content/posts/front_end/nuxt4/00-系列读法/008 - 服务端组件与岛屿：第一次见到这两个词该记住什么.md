这一讲只做一件事，让你第一次遇到这两个词时不慌。服务端组件的细节，渲染流程、缓存、`nuxt-client` 选择性水合，会在组件那一段专门讲，但它的动机值得现在就懂，因为它直接关系到你怎么瘦身首屏 JS。

它要解决的是重复劳动。官方的开场把一个默认行为说得很直白，Nuxt 默认在服务端渲染你的应用，但随后它会把每个组件的 JavaScript 发给浏览器并水合整个页面。对于内容很重、且在客户端从不改变的那些组件，markdown 渲染、语法高亮、CMS 输出，这是白费的工作，用户下载、解析并执行了一段代码，而它唯一的工作只是复现页面上已经存在的 HTML。

这就是问题的全部，HTML 已经在页面上了，浏览器却又跑一遍 JS 把它算出来。

服务端组件，也被称为岛屿组件，反过来做。一个服务端组件在服务端渲染，它的 HTML 被嵌入页面，而它的任何 JavaScript 都不会发给客户端。它的依赖，一个 markdown 解析器、一个高亮库，也留在服务端。

三个名词先钉住。服务端组件等于岛屿组件，官方在同一页里交替使用。省掉的不只是组件本身的 JS，还有它的依赖。

开启方式，默认值让你不用配。组件岛屿由 `experimental.componentIslands` 控制，默认值是 `'auto'`，一旦你的应用包含一个服务端组件或岛屿，它就会自动启用这个特性，所以在多数情况下你不需要任何配置。

这一句很重要，因为它挡住了一种常见误解，很多人以为要用服务端组件必须先开一个实验开关。不用。你需要显式配置的只有两种附加能力。

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  experimental: {
    componentIslands: {
      selectiveClient: true, // 或 'deep'，用于启用 `nuxt-client`
      remoteIsland: false, // 允许渲染来自远程来源的岛屿
    },
  },
})
```

也就是说 `selectiveClient`，岛屿内部再放可交互的客户端组件，和 `remoteIsland`，渲染远程来源的岛屿，这两个才需要你手动打开。

同时要认清风险面，官方在这一节末尾仍写着服务端组件仍然被标记为实验性，并指向 GitHub 上的路线图。能用，但把它的实验性质放进你的升级检查清单里。

用法一，给文件加 `.server` 后缀。给一个组件加上 `.server` 后缀，就把它变成一个独立的服务端组件。

```bash [目录结构]
-| components/
---| HighlightedMarkdown.server.vue
```

像使用其它组件一样使用它。

```vue [app/pages/example.vue]
<template>
  <div>
    <!--
      在服务端渲染；markdown 解析与高亮库不会被包含在你的客户端包里
     -->
    <HighlightedMarkdown markdown="# Headline" />
  </div>
</template>
```

这里有个值得停一下的点，模板里看不出它是服务端组件。标签就是 `<HighlightedMarkdown />`，没有任何 island 前缀。是否只在服务端跑由文件名的后缀决定，这正是 005 讲那条判据里归位置决定的一档。

用法二，放进 `~/components/islands/`。`~/components/islands/` 里的组件同样会被注册为岛屿，可以直接用 `<NuxtIsland>` 渲染，例如对 `~/components/islands/MyIsland.vue` 使用 `<NuxtIsland name="MyIsland" />`。

两种用法的差别不在能力，而在调用形态。`.server.vue` 的写法是 `<HighlightedMarkdown markdown="..." />`，像普通组件一样用。`islands/` 目录的写法是 `<NuxtIsland name="MyIsland" />`，显式通过 `<NuxtIsland>`。

第二种把这是一个岛屿写进了模板里，读代码的人一眼能看到，第一种更简洁，但需要你知道后缀的含义。团队里选一种并写明规范，比混用更容易维护。这是我给的操作建议，官方只是分别给出了两种用法。

配对用法，`.server` 加 `.client`。官方在这里加了一条容易看漏的例外。你也可以把一个 `.server.vue` 组件与一个同名的 `.client.vue` 组件配对，用于服务端与客户端各自实现的进阶场景。在这种情况下这个组件并不是岛屿，客户端那一半会正常水合。

含义是，`.server.vue` 和 `.client.vue` 是一个组件的两半。当它们成对存在时，你得到的是服务端渲染一份、客户端再接管一份的正常同构行为，而不是 JS 完全不发给浏览器那种岛屿效果。所以别指望配对用法能省包体，省 JS 靠的是只有 `.server`、没有 `.client`。

两条硬约束，现在就记住。

第一条，单根元素。服务端组件以及岛屿必须有单个根元素，HTML 注释也被视为元素。

括号里那句尤其容易被忽略，你为了分隔一下留的一条注释，会让它变成两个根节点。这条约束和路由转场那一段讲的单根是同族问题，遇到渲染不出来或多了一段莫名其妙的节点时先想到它。

第二条，它属于实验特性。上一条说了，官方明确仍然被标记为实验性。所以把它用在关键路径上之前，值得在目标 Nuxt 版本上实测一次，而不是只看这篇教程。
