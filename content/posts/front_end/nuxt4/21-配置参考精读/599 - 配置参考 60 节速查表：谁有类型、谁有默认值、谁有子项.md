配置参考那一页很长，但**长得不均匀**：`webpack` 一节下面挂了 42 个子项，而 `future` 一节连一句正文都没有。要知道哪一节能查到东西、哪一节只是把你往外推，就得有一张清点表。

## 先说结论

按页面出现顺序把 **60 个顶层节**逐节数一遍（Type／Default 两列统计的是**该节及其子项范围内的行数**）：

- **没有 `**Type**` 行的节：13 个**。其中 `spaLoadingTemplate` 是唯一"有默认值却没有类型行"的——它的类型说明写在了定性句里（"Boolean or a path to an HTML file…"）。
- **没有 `**Default**` 行的节：20 个。**
- **两行都没有的节：12 个。**
- **整节既无类型行、又无默认值行、也无任何子项的节：11 个**——`compatibilityDate`、`devtools`、`experimental`、`extends`、`features`、`future`、`hooks`、`ignoreOptions`、`pages`、`routeRules`、`telemetry`。这一批是查东西时最该跳过的一档（`hooks` 与 `ignoreOptions` 至少有示例，`features`／`future`／`experimental` 三条干脆只有跳转链接）。
- **子项总数：`###` 101 ＋ `####` 56 ＝ 157。** 分布极度偏：`webpack` 一节 17 ＋ 25，`vite` 一节 15 ＋ 10，`app` 一节 16 ＋ 1；其余大多数节是 0。
- **全页 Type 行合计 161、Default 行合计 138**——也就是说**约每 5 个带类型的条目里就有 1 个不给默认值**。

## 表里几处值得单看

**`typescript` 的 Default 行数比 Type 行数多（6 对 5）。** 原因是 `builder` 这一项**给了默认值却没给类型行**，其余十项各自都有类型行。这一节是全表"类型与默认值不成对"最集中的地方。

**`router` 的 Type 与 Default 都是 2，但 Default 实际出现 4 次。** 因为 `hashMode` 与 `scrollBehaviorType` **各把默认值写了两遍**（正文一行 ＋ 表格式一行），数行数时只计了表格式那两行。同类重复写法在这页不止一处，读到重复不要以为有两个不同的默认值。

**`vite` 与 `webpack` 两节撑起了这份文档的大半。** 两节合计 **`###` 32 ＋ `####` 35 ＝ 67 个子项**，占全页 157 个的 43%；而它们的 Type/Default 都不成对（`vite` 19 对 16、`webpack` 40 对 33）——**子项越多，缺默认值的那些也越多。**

**八节"目录类"配置（`srcDir`、`serverDir`、`buildDir`、`typesDir`、`analyzeDir`、`rootDir`、`workspaceDir`、`modulesDir`）全部类型与默认值齐备**，是全表记载最整齐的一组；它们的默认值都用 `"/<rootDir>"` 这类占位符写法（**`rootDir` 与 `workspaceDir` 的默认值甚至是自我指涉的**）。

**`experimental`、`features`、`future` 三节整节为零（0/0/0/0）**——这三节只有一条 read-more，内容全在讲解页。同一档的还有 `routeRules`、`extends`、`compatibilityDate`、`telemetry`、`devtools`、`pages`、`ignoreOptions`、`hooks` 这些"有正文但没有类型/默认值/子项"的节。

## 怎么把这张表用起来

- **想查取值形状**：优先看 Type 与 Default 都有值的行；Type=0 的那 13 行要点进去读定性句（`spaLoadingTemplate`、`theme`、`css` 等）。
- **想查有没有子项可调**：`###`／`####` 为 0 的节意味着**文档在这一层没有列出任何子键**——例如 `components`（0/0）的 `dirs`、`pathPrefix` 只能去目录那页找。
- **整节全零的 11 行**：不要在配置参考里等答案，直接去讲解页（`guide/going-further/*`、`api/advanced/hooks`、`errors/*`）。
- **两处以上形状相同**（`esbuild`／`vite.esbuild`／`webpack.loaders.esbuild`；顶层 `runtimeConfig`／`nitro.runtimeConfig`；顶层 `routeRules`／`nitro.routeRules`）：文档没写同步规则，改动要实测。

## 自查

- 顶层节 **60**；Type 行合计 **161**、Default 行合计 **138**；子项 `###` **101** ＋ `####` **56** ＝ **157**。
- **13** 节无类型行、**20** 节无默认值行、**12** 节两者都无、**11** 节整节零记载。
- 最整齐的八节：`srcDir`、`serverDir`、`buildDir`、`typesDir`、`analyzeDir`、`rootDir`、`workspaceDir`、`modulesDir`（类型与默认值都在）。
- 最占篇幅的两节：`webpack`（17＋25 子项）、`vite`（15＋10）。
- 三处不成对／重复写法要认得：`typescript.builder` 有默认无类型、`router` 两个子项各写两遍默认值、`spaLoadingTemplate` 有默认无类型。
