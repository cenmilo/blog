`app.vue` 里 import 一个 `.css` 也能生效，但每个页面都要各自 import。

全局样式有个专门的数组，配置项就是 `css`——这一节很短，但里面有两条容易忽略的说明。

## 定义句与两条说明

`## css` 一共两段话：

> You can define the CSS files/modules/libraries you want to set globally (included in every page).
>
> Nuxt will automatically guess the file type by its extension and use the appropriate pre-processor. You will still need to install the required loader if you need to use them.

- **类型**：`array`
- **默认**：**这一节没列。**

拆四条：

| 说法 | 原文 | 含义 |
| --- | --- | --- |
| 三种对象都能放 | CSS files / modules / libraries | 文件、模块、库这三种形态都在支持范围内 |
| 作用面 | set globally（included in every page） | 每一项都进**每个页面**，不是当前页 |
| 靠扩展名判定 | guess the file type by its extension | **后缀决定用哪个预处理器**，不是内容嗅探 |
| loader 自备 | still need to install the required loader | Nuxt 只做类型猜测，**不装依赖** |

第四条是这一节唯一的"坑"位：`.scss` 写得再对，没装 `sass` 也用不了。官方在样式那一页给过对应动作——**用 Tailwind/UnoCSS 之外的预处理器要先装包**，本节的措辞与之吻合。

## 官方示例：三种写法一次给全

```ts
export default defineNuxtConfig({
  css: [
  // Load a Node.js module directly (here it's a Sass file).
    'bulma',
    // CSS file in the project
    '~/assets/css/main.css',
    // SCSS file in the project
    '~/assets/css/main.scss',
  ],
})
```

三行注释与三条值一一对应，值得逐个看：

- **`'bulma'`**：只给包名。注释里那句 "here it's a Sass file" 是官方在说明**从包名解析到的入口是 Sass 源文件**——也就是说第一项属于"库"这一类，而它仍然需要预处理器在场（对应上面第四条）。
- **`'~/assets/css/main.css'`**：项目里的普通 CSS，路径用 `~` 别名。
- **`'~/assets/css/main.scss'`**：项目里的 SCSS，靠 `.scss` 后缀判定预处理方式。

**别名 `~` 在这里能用**，这来自 `alias` 的默认表（`~` 指向 `<rootDir>/app`）与"别名会自动加进生成的 TypeScript 配置"那条规则。

样式表之间谁覆盖谁，这一节没有一句涉及——**数组项之间的层叠先后，官方在配置参考与样式页都没写规则**。要知道实际结果只能看产物：构建后在浏览器 Styles 面板里看同一条规则最终生效的是哪份文件，或直接检查生成的 CSS 里两段的先后。

## 放进这个数组的东西长什么样

`css` 是全局注入的地方，与之相对的是组件里 `<style scoped>` 那种局部写法（那属于 Vue 的能力，Nuxt 不另立规则）。判断标准很直白：**这份样式是每个页面都要的，还是某个组件自己的？**

从文档能给的两个实例看，数组项通常是：

```ts
export default defineNuxtConfig({
  css: ['animate.css'],
})
```

（这一条来自样式那一页给的外部库用法：**把 CSS 框架当包名直接写进数组**。）以及上面示例里的两个项目内路径。

**这里放的是"要注入的样式"，不是"要处理的文件目录"。** `app/assets/` 那节说的是这类资源交给构建器处理、并且**不会自动扫描**——也就是说：把 `.css` 放进 `app/assets/` 不等于它会全局生效，**要全局注入必须显式写进 `css` 数组**。这两件事常被混在一起。

## 与 postcss 的关系

`css` 数组里的文件走的是构建器的样式管道，PostCSS 插件链在这之后作用。配置参考里对应的节是 `postcss`，它只有两个子项（`order` 与 `plugins`），下一篇单独读。

一句要点先放在这里：**`postcss.order` 排的是插件之间的顺序，不是样式表之间的顺序**——这个键名很容易被误当成"控制 `css` 数组谁覆盖谁"的开关。

## 自查

- `css` 是 `array`、本节**没有默认值**，作用面是"included in every page"（每个页面都注入）。
- Nuxt 按**扩展名**猜预处理器，但**required loader 要自己装**——写了 `.scss` 不等于装了 `sass`。
- 官方示例三条对应三种写法：包名（`'bulma'`，注释说明它是 Sass 文件）、项目内 CSS 路径、项目内 SCSS 路径，路径用 `~` 别名。
- 数组项之间的层叠顺序文档没写规则，只能构建后在 Styles 面板或产物 CSS 里核对。
- 放进 `app/assets/` 不等于全局生效；全局注入必须显式写进 `css` 数组，而 `postcss.order` 管的是插件顺序不是样式表顺序。

## 下一篇

下一篇 550 读 `postcss`：这一节比想象的小得多——只有 `order`（一个没有默认值的 `function`）与 `plugins`（下面点名 `autoprefixer` 与 `cssnano` 两项），而默认插件链那份清单写在样式那一页而不是这里。
