从别的项目拷过来的 `vite.config.ts` 一直在，你往里加了插件、改了 `resolve.alias`，构建却毫无反应。

不是配置写错了，是**这个文件根本不会被读**。

## 官方那句定性

配置页的 External Configuration Files 一节第一句：

> Nuxt uses `nuxt.config.ts` file as the single source of truth for configurations and skips reading external configuration files.

**"single source of truth"（唯一来源）＋"skips reading"（跳过读取）**——不是报错、不是警告，是不读。所以文件留着不会失败，只会静默无效，这正好是最难查的一种状态。

## 四份文件，四个键

同节给的表格四行，原文照搬：

| Name | Config File | How To Configure |
| --- | --- | --- |
| Nitro | ~~`nitro.config.ts`~~ | Use `nitro` key in `nuxt.config` |
| PostCSS | ~~`postcss.config.js`~~ | Use `postcss` key in `nuxt.config` |
| Vite | ~~`vite.config.ts`~~ | Use `vite` key in `nuxt.config` |
| webpack | ~~`webpack.config.ts`~~ | Use `webpack` key in `nuxt.config` |

**表格里那四份文件名是带删除线的**——官方用排版直接表达"这个文件不该存在"。四个去处都在 `nuxt.config` 顶层，也就是配置参考里那 60 个顶层节中的四个。

## B5004：撞上了会看到什么

留着这些文件时会碰到兼容性提示 `NUXT_B5004`，标题是 External config file not supported，正文把成因说得很直：

> Nuxt found a standalone `vite.config` or `webpack.config` file next to your `nuxt.config`. Nuxt manages the bundler internally and ignores these files, so they are usually leftovers from a migration or a copied non-Nuxt project.

三件事在这句里：**Nuxt 内部管理打包器**（所以不需要外部文件）、**这些文件被 ignore**、**它们的来历通常是迁移或拷贝非 Nuxt 项目**。注意这一页点名的文件只有 `vite.config` 与 `webpack.config` 两个——`nitro.config` 与 `postcss.config` 出现在下面的映射清单里，不在触发描述中。

Resolution 给的是顺序，不能颠倒：

> Move the configuration into `nuxt.config` under the matching key, then delete the external file:

- `vite.config`：用 `vite` 键
- `webpack.config`：用 `webpack` 键
- `nitro.config`：用 `nitro` 键
- `postcss.config`：用 `postcss` 键

```ts
export default defineNuxtConfig({
  vite: {
    // your Vite config here
  },
})
```

**"先搬、再删"是官方原文的顺序。** 先删文件等于先把配置丢掉，再想搬已经没有原本内容了。

## 另一类：六份各管各的

配置页紧接着给第二类表，标题句是 **"Here is a list of other common config files"**，六行如下：

| Name | Config File | 官方给的去处 |
| --- | --- | --- |
| TypeScript | `tsconfig.json` | 指向 `directory-structure/tsconfig` |
| ESLint | `eslint.config.js` | 指向 ESLint 官方配置文档 |
| Prettier | `prettier.config.js` | 指向 Prettier 官方配置文档 |
| Stylelint | `stylelint.config.js` | 指向 Stylelint 官方配置文档 |
| TailwindCSS | `tailwind.config.js` | 指向 Nuxt Tailwind 模块文档 |
| Vitest | `vitest.config.ts` | 指向 Vitest 官方配置文档 |

两张表的分工因此不同：**第一类是"Nuxt 跳过读取"，要搬进 `nuxt.config`；第二类是"由各自工具读取"，就该改那份文件本身。**

而且**第二类的"去处"一栏只有 TypeScript 那一行指回 Nuxt 文档，其余五条全是外链**。对到实际场景上：给测试改配置就得动 `vitest.config.ts`——测试文档给的那三份示例都写在这个文件里，把它并进 `nuxt.config` 反而是错的。

## 一处容易搞混的地方

第二类里 `tsconfig.json` 与 Nuxt 生成的类型配置是两回事。配置参考的 `alias` 那节说明这些别名会被自动加进生成的 TypeScript 配置（`.nuxt/tsconfig.app.json`、`.nuxt/tsconfig.server.json` 等），要在其上继续扩展就往 `alias` 或 `typescript.tsConfig` 里加。**生成的那些 `tsconfig.*.json` 在 `.nuxt` 目录里，不是你项目根的那份 `tsconfig.json`。**

## 自查

- `nuxt.config.ts` 是唯一配置来源，外部配置文件**被跳过读取**（不报错，静默无效）。
- 四份失效文件与四个键一一对应：`nitro.config.ts`→`nitro`、`postcss.config.js`→`postcss`、`vite.config.ts`→`vite`、`webpack.config.ts`→`webpack`；官方表格里这些文件名带删除线。
- `NUXT_B5004` 的成因是"打包器由 Nuxt 内部管理、这些文件被忽略、通常是迁移或拷贝残留"，其触发描述只点名 vite/webpack 两份；处理顺序是**先搬进对应键、再删文件**。
- 第二类六份配置（`tsconfig.json`、`eslint.config.js`、`prettier.config.js`、`stylelint.config.js`、`tailwind.config.js`、`vitest.config.ts`）由各自工具读取，别并进 `nuxt.config`。
- `alias` 等会被自动写进 `.nuxt` 下生成的 `tsconfig.*.json`，与项目根那份 `tsconfig.json` 不是同一个文件。
