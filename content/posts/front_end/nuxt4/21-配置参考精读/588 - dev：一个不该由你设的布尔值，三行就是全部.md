想"用配置把项目切成开发模式"，就会去搜 `dev` 这一节——它确实存在，也确实是个布尔。但那三行里的第二行是给这个念头的答复。

## 三行记载

`## dev` 的全文：

> Whether Nuxt is running in development mode.
>
> Normally, you should not need to set this.

- **Type**: `boolean`
- **Default:** `false`

第一句的主语是 **Nuxt**（"Nuxt 是否正运行在开发模式下"），这是一个**被判断的事实**，不是一个功能开关。第二句 "Normally, you should not need to set this." 就是从这个读法推出来的：既然是描述当前运行状态，**写它的人本来就不该是你**。

值得记一笔的是，这一节**没有任何一处解释"设了会怎样"**。所以"手动设成 `true` 能不能让生产构建带上 dev 行为"这种问题，**在文档里没有依据**，只能实测；而按第一句的语义，这种做法本身就不是它的用途。

## 它的正确用法是在代码里读

整套 4.x 里没有 `dev: true` 的示例，但把它当条件读的地方有四类，恰好是这个键的真实使用面：

- 模块结构那一页，示例里直接打印它：

```ts
console.log(nuxt.options.dev) // `true` or `false`
```
- 构建器那一页讲 `bundle` 实现：**"Your `bundle` implementation typically branches on `nuxt.options.dev`"** ——开发期与构建期要走不同分支。
- 模块作者迁移指南里，某条变更的例外条件是 "Unless it is for `nuxt dev` purpose only and **guarded with `if (nuxt.options.dev) { }`**" ——用守卫把它圈在 dev 里。
- Kit 的安装依赖那一页里有一个 `options.dev` 字段：**"Whether the command should install the packages as dev dependencies."**

第四条是**同名陷阱**：那个 `options` 是 `installNuxtModule`／安装依赖函数的参数对象，它的 `dev` 意思是"作为 devDependency 安装"，与 `nuxt.options.dev`（当前是不是开发模式）不是一回事。写模块时这两处名字会一起出现，混了就是安装位置或分支条件出错。

## 与相邻几个键的界线

`dev`、`devServer`、`devtools`、`features.devLogs` 都带 "dev" 这个词，管的东西完全不同：

| 键 | 管什么 | 本节给的形状 |
| --- | --- | --- |
| `dev` | 当前是不是开发模式（状态） | `boolean`，默认 `false` |
| `devServer` | 开发服务器的端口、host、HTTPS、CORS 等 | 六个子项（见上一篇，多数缺项） |
| `devtools` | 是否启用 DevTools | **连类型行都没有**（见下一篇） |
| `features.devLogs` | 把服务端日志流到浏览器 | 只在特性页有正文，配置页是空壳 |

另外还有一个易混的 `dev`：CLI 命令 `nuxt dev`。它是**启动开发服务器这件事本身**，不是配置项——而且正是运行这条命令时 `nuxt.options.dev` 才会是真。**"用命令进入 dev" 和 "用配置声明 dev" 不是同一条路**，后者文档没给你用。

## 自查

- `## dev` 三行：状态描述句 ＋ "不该由你设" ＋ `boolean`／`false`。
- **无 Example、无 See、也没有一句说"设了会怎样"**；想靠它切换构建行为，无依据。
- 真实使用面是读：`nuxt.options.dev` 出现在模块结构、构建器 `bundle` 分支、模块作者迁移守卫三处。
- Kit 安装依赖的那个 `options.dev` 是"装成 devDependency"的意思，**同名不同义**。
- 与 `devServer`／`devtools`／`features.devLogs`／`nuxt dev` 命令分清：这四个东西没有一个等价于 `dev` 配置项。

## 下一篇

下一篇 589 看 `## devtools`：两句说明——"Enable Nuxt DevTools for development." 和 **"Breaking changes for devtools might not reflect on the version of Nuxt."**——之后**既没有类型行也没有默认值行**，而开关的另一半在 CLI 那一侧：`nuxt devtools enable` 会把 DevTools 装到全局，并把偏好**存进用户级的 `.nuxtrc`**，两层谁优先没有写。
