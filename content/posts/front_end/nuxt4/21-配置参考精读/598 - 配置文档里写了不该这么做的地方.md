配置写错不一定是报错。更多时候是它照收不误、然后悄悄不生效——比如你把加载屏的时间戳塞进构建期才定的那个路径，或者把目录里已有的插件又抄了一遍。这一篇只做一件事：把文档里所有否定句捞出来。

## 十四处原文

| 位置 | 原文（照抄要点） | 该怎么做 |
| --- | --- | --- |
| `app.buildAssetsDir` | "This is set at build time and **should not be customized at runtime**." | 这个资源目录名在构建期就定了；别在运行时改它 |
| `devServer.url` | "**should not be set directly** as it will always be overridden by the dev server with the full URL (for module and internal use)" | 要改访问地址只设 `host` 与 `port`；这一项是给模块与内部用的 |
| `rootDir` | "It is normally **not needed to configure** this option." | 它由启动路径决定（`nuxt ./my-app/`），一般别写 |
| `workspaceDir` | "It is normally **not needed to configure** this option."（与上句**逐字相同**） | Nuxt 会尝试自动检测，monorepo 之外别动 |
| `dev` | "**Normally, you should not need to set this.**" | 它是"是否正运行在开发模式"的状态位，不是开关 |
| `vue.runtimeCompiler` | "**Never** compile templates built from user-provided or otherwise untrusted input; doing so is **equivalent to `eval`** and can lead to cross-site scripting or remote code execution." | 打开这一项之前确认模板来源可信；这条是安全警告不是风格建议 |
| `webpack.extractCSS` | "However, note that it is **not recommended to extract everything into a single file**." | 全站合成一个 CSS 文件是被官方点名的不推荐做法 |
| `components`（目录页） | "Alternatively, **though not recommended**, you can register all your components globally…" | 全量 `global: true` 会给每个组件生成异步 chunk；改用 `~/components/global` 或 `.global.vue` |
| `plugins` callout | "these plugins **do not need to be listed** in `nuxt.config` **unless you need to customize their order**. All plugins are deduplicated by their src path." | 目录里的插件本来就会自动注册；写进配置只为改顺序，写了也不会重复加载 |
| `router.options` callout | "**Only JSON serializable options should be passed by Nuxt config.**" | 函数型选项（`history`、`scrollBehavior`）走 `router.options.ts` 文件 |
| `app.config`（`::caution`） | "**Do not put any secret values inside `app.config` file.** It is exposed to the user client bundle." | 密钥进 `runtimeConfig` 顶层（非 `public`）；app config 整体进包 |
| `app.config`（workaround） | 在 Nitro 配置里塞 `plugins: [vue()]` 的做法 "this approach is **not recommended**"，`::warning` 补"may lead to unexpected behavior and bugs" | 别用这条绕法；Vue 组件不能直接在 `app.config.ts` 里 import 是已知限制 |
| `nitro`（透传高级选项） | 官方提示这些配置**会影响生产部署**，而 Nitro 配置接口可能随 Nuxt **次版本**变化 | 写进 `nitro` 的东西每次升级都要复查；生效与否要构建验证 |
| `getting-started/configuration` | "it is **strongly recommended to use the `.ts` extension** for the `nuxt.config` file. This way you can benefit from hints in your IDE to avoid typos and mistakes" | 用 `.ts`，理由是可拿到 IDE 提示、少打错键名 |

最后一行之前还有一句更基础的：**"Nuxt uses `nuxt.config.ts` file as the single source of truth for configurations and **skips reading external configuration files**."** —— 外部配置文件（`postcss.config.js`、`vite.config.ts` 这类）不会被读，对应的值必须写进 `nuxt.config` 的对应节。这条也算"不该"：不该再去找那些独立文件。

## 三条不是禁令、但常被当成禁令读

**`hashMode` 的那句不是建议，是后果。** 原文是 "When enabled, the **URL is never sent to the server** and **SSR is not supported**." —— 它没说不许用，而是说开了之后服务端拿不到路径、SSR 不可用。

**`routeRules` 上那个 Experimental 标的是 API 形状。** 配置页写的是 "This is an experimental feature and **API may change in the future**"，而不是"不要在生产用"；同页别处（部署、预渲染、渲染概念）都把它当稳定能力在示例里使用。

**`experimental` 里那些开关的 `::note` 是"可能消失"。** 措辞是 "these features are experimental and **could be removed or modified in the future**"——依赖某个开关的项目要能在它被移除时改回来，这是选型成本，不是功能警告。

## 自查：把这几条当一次 code review

改 `nuxt.config` 之后，按顺序过一遍：

1. 有没有把**状态位当开关写**（`dev`、`test`、`rootDir`、`workspaceDir`）？这四处的说明句都在告诉你"通常不需要设"。
2. 有没有设**会被覆盖的键**（`devServer.url`）？
3. 有没有在运行时改**构建期定下的值**（`app.buildAssetsDir`）？
4. 密钥有没有出现在 `app.config` 或 `runtimeConfig.public`／`runtimeConfig.app` 下面？
5. 有没有为了"全局组件""CSS 合成单文件""在 app.config 里 import 组件"去做**官方点名不推荐**的三件事？
6. 模板编译（`vue.runtimeCompiler`）打开时，输入源是否全部可信？
7. 写进 `nitro` 的高级项，这次升级复查过没有？
8. 还有没有把插件、模块从目录里**重复抄进配置**（`plugins` 会按 src 路径去重；`modules` 那一节**没有**这句去重保证）？
