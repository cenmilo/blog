你在配置里删掉一行，想确认"不写的时候框架用什么值"。翻到那一节，只有 `- **Type**: object` 一行，没有默认值。

这种情况在这一页不是意外，是常态的一部分。

## 先量一下缺多少

这一页里：

| 项目 | 数量 |
| --- | --- |
| 带 `- **Type**` 的条目 | 161 |
| 带 `- **Default**` 的条目 | 138 |

**差出来的约二十三个选项只声明了类型，没给默认值。** 典型例子是 `nitro` 节下的 `routeRules`：整节只有 `- **Type**: object` 一行，没有说明也没有默认。所以按"文档没写默认值就是某个值"去推断，是没有依据的——只能取证。

## 默认值的两种排版

写默认值的地方本身有两种格式，认出来能省不少困惑：

**第一种是字面值，键名后带冒号。** 例如：

```ts
- **Type**: `string`
- **Default:** `"/<rootDir>/.nuxt/analyze"`
```

这是 `analyzeDir` 那节的原文；`appId` 也一样（`- **Default:** \`"nuxt-app"\``），而且它额外在正文里把默认值写进句子（"Defaults to `nuxt-app`."），同一件事给两遍。布尔型的写法是 `boolean` 配 `false`（`test`、`debug` 那几节）。

**第二种是结构，键名后不带冒号，紧跟一段 JSON 代码块。** 例如 `alias`、`app.head`、`runtimeConfig`、`extensions`：

```json
{
  "~": "/<rootDir>/app",
  "@": "/<rootDir>/app",
  "~~": "/<rootDir>",
  "#build": "/<rootDir>/.nuxt"
}
```

（上面只截了 `alias` 默认 JSON 里的四行，整份是十行。）这种格式的含义是**默认值是一个对象骨架**，你要看整块才能知道有哪些键，不能只看一行。

## 两类占位符要分开读

**第一类：`<rootDir>` 这种尖括号。** 它出现在 `alias` 的十行默认值与 `analyzeDir` 的默认路径里，意思是**"这一处取另一节的值"**——`<rootDir>` 就是 `rootDir` 那一节解析出来的项目根。所以看到 `"/<rootDir>/.nuxt/analyze"` 别当字面字符串，它说的是"项目根下的 `.nuxt/analyze`"。同类的还有 `#build` 指向 `/<rootDir>/.nuxt`、`#internal/nuxt/paths` 指向 `/<rootDir>/.nuxt/paths.mjs`——**这些默认值告诉你的是产物里那些文件的位置规则**。

**第二类：看起来像真值其实是样例。** `buildId` 的默认写的是 `"4a2e2d30-418f-41df-8e58-ed5df06de7fd"`，一个 UUID 形状的串。同一串值也出现在 `runtimeConfig` 的默认 JSON 里。**这一节没有说明这串值怎么生成**，只说它"匹配一次构建"、可能含项目状态的哈希——所以它是格式示意，不是"你的构建会拿到这个 ID"。要确认自己项目的实际值，只能在构建产物或运行时配置里读。

## 缺默认值时的取证办法

文档不给的地方，只能自己读框架解析后的结果。有官方依据的落点是：**在 Nuxt 进程里读 `nuxt.options`**——这一点在讲服务端导入那页写得直接：`nuxt.config.ts`、模块的 `setup` 这类跑在 Nuxt 进程里的代码没有服务端运行时那套东西，**"Read `nuxt.options` instead"**。

于是最短的确认方式是往配置的 `hooks` 里加一行打印：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  hooks: {
    'modules:before'() {
      console.log('[probe]', JSON.stringify(this.options.routeRules))
    },
  },
})
```

**这段是本系列给的取证写法，官方在配置参考里没有给这种示例。** 它的用途是把"文档没写默认值"变成"我机器上实际是什么"：能打出 `undefined` 就是没设、没有默认；能打出对象就是框架在某处填了值，接着回去找是谁填的（往往是某个模块或 Nitro）。

另一条更省事的对照法：`nuxt prepare` 会创建 `.nuxt` 并生成类型，生成的类型里带的默认声明可以作旁证——这一页没说它等于运行时值，所以只当线索，别当结论。

## 自查

- 161 条有类型、138 条有默认值，**约二十三个选项只有类型**（`nitro.routeRules` 是代表）；缺默认值不等于有某个默认值。
- 两种排版要认：字面值用 `- **Default:**`，结构用 `- **Default**` 加一段 JSON（`alias`/`app.head`/`runtimeConfig`）。
- 尖括号 `<rootDir>` 是占位符，指向 `rootDir` 解析出的项目根，不是字面路径的一部分。
- UUID 那种默认值（`buildId`）是格式示意，文档没写生成规则，别把它当自己的实际值。
- 确认实际值有官方依据的落点是读 `nuxt.options`（Nuxt 进程内），用 `hooks` 打印是最短路径；`nuxt prepare` 生成的类型只作旁证。
