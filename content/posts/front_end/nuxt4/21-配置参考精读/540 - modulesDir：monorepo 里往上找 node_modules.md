mono-repo 里最常见的一类怪事：包确实装着（`node_modules` 在仓库根），但构建时报找不到，或者 PostCSS 插件加载不上。

有一个键专门管这件事，名字很容易被误读成"模块放哪"。

## 这键管的是解析路径

`## modulesDir` 第一句给出了用途，而且点名了三处具体使用者：

> Used to set the modules directories for path resolving (for example, webpack's `resolveLoading`, `nodeExternals` and `postcss`).

**它是"路径解析用的模块目录"**，不是扫描目录。被点名的三项里，`resolveLoading` 与 `nodeExternals` 是 webpack 侧的行为，`postcss` 是插件解析——这解释了一种典型症状：**同一份依赖，业务代码里 import 得到，但打包器一侧的解析失败**，因为两侧找依赖的规则不一样。

紧接着两句：

> The configuration path is relative to `options.rootDir` (default is current working directory).
> Setting this field may be necessary if your project is organized as a yarn workspace-styled mono-repository.

- **类型**：`array`
- **默认**：`["/<rootDir>/node_modules"]`

三个读数：**值是数组**（可以一次给多个目录）；**相对路径按 `options.rootDir` 算**，而官方在这句里补了"默认是当前工作目录"；**适用条件是一句"可能需要"（may be necessary）**，绑在 yarn workspace 风格 mono-repo 上，不是常规配置项。

官方示例只有一行：

```ts
export default defineNuxtConfig({
  modulesDir: ['../../node_modules'],
})
```

`../../` 是**从应用目录往上两层**——这正是 workspace 布局里"依赖装在仓库根、应用在 `packages/web` 这种位置"的形状。

## 别和 dir.modules 混

这两个名字读起来像同一件事，实际完全不同：

| 键 | 官方定义 | 管什么 |
| --- | --- | --- |
| `modulesDir` | Used to set the modules directories for **path resolving** | 哪些 `node_modules` 参与解析（数组） |
| `dir.modules` | The **modules directory**, each file in which will be auto-registered as a Nuxt module | 本地模块文件放哪、默认 `"modules"` |

`dir.modules` 那一行的措辞与 `dir.plugins`、`dir.middleware` 是同一套（"each file ... auto-registered"），属于"目录里每个文件都被自动注册"那一类；而 `modulesDir` 没有任何自动注册语义。

再补一个容易混进来的：`modules` 顶层节（`## modules`）是**声明要加载哪些模块/图层**的地方，与前两者都不同。**三个名字相近的键各管一层：加载什么（`modules`）、本地模块文件在哪（`dir.modules`）、依赖从哪里解析（`modulesDir`）。**

## 什么时候真的需要动它

能确证的触发条件是那句 yarn workspace。判断顺序应该是：

1. 先看依赖是不是真的在应用目录的某个上溯 `node_modules` 里——不在，就不是这键的问题。
2. 症状是否落在被点名的三项上（webpack 的 `resolveLoading`／`nodeExternals`／`postcss`）。用 Vite 构建时前两项不适用，官方也没说 Vite 侧读不读这个值——**`modulesDir` 对 Vite 构建的影响，文档未说明**。
3. 改的时候按官方示例的相对形状写（相对 `rootDir`），并留意图里那条默认值本身是 `["/<rootDir>/node_modules"]`：**要不要把它也列进去，官方没写**——`['../../node_modules']` 这一行是数组的完整替换还是追加，从这一节读不出来。

第 3 点是这节最容易出事的地方：类型是数组，示例只给一个元素，而默认值里那个"根下 `node_modules`"在示例中消失了。**两种读法都有合理性，文档没有裁决**，只能两种写法各跑一次构建看结果。

## 自查

- `modulesDir` 是 `array`、默认 `["/<rootDir>/node_modules"]`，用途是**路径解析**，官方点名 webpack 的 `resolveLoading`、`nodeExternals` 与 `postcss` 三处。
- 相对路径按 `options.rootDir` 算，官方补了"默认是当前工作目录"；适用条件是 yarn workspace 风格 mono-repo（措辞是 may be necessary）。
- 示例 `modulesDir: ['../../node_modules']` 是从应用目录往上两层找依赖。
- 它不是 `dir.modules`（那个是本地模块文件目录、文件被自动注册为模块），也不是顶层 `modules`（声明加载哪些模块）。
- 数组值是替换还是追加、以及对 Vite 构建是否有影响，文档都没写——两种写法各跑一次构建来定。
