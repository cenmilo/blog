`ssr: false` 是一个键、一个布尔。但关掉它同时改变三件事：生成出来的 HTML、还能不能用接口、以及部署时要带什么。

## 这一节的记载

`## ssr` 一句到底：

> Whether to enable rendering of HTML - either dynamically (in server mode) or at generate time. If set to `false` generated pages will have no content.

- **类型**：`boolean`
- **默认**：`true`

**"either dynamically (in server mode) or at generate time"** 这一句把它的作用面说成两件事：**跑着的服务端**每次请求渲 HTML，以及 **generate 时**把页面渲成静态文件。关掉之后两条一起关——这就是"generated pages will have no content"的由来。

配置参考里没有第三条信息（没有示例，也没有注意事项）。要理解后果得去另外两页。

## 后果一：生成的页面是空壳

部署页那句和上面完全对上：**"Alternatively, you can prerender your site with `ssr: false` (static single-page app). This will produce HTML pages with an empty `<div id="__nuxt"></div>` where your Vue app would normally be rendered."**

紧跟着是官方自己的取舍判断：**"You will lose many SEO benefits of prerendering your site, so it is suggested instead to use `<ClientOnly>` to wrap the portions of your site that cannot be server rendered (if any)."**

也就是说：**官方的建议不是整站关掉，而是把不能服务端渲染的部分圈出来**。渲染概念页给的是同一套 CSR 权衡，只是从两头说：

| 官方列的 CSR 好处 | 官方列的 CSR 坏处 |
| --- | --- |
| 开发速度（不必操心代码的服务端兼容性，例如直接用 `window` 这类浏览器专属 API） | 性能：用户要等 JS 下载、解析、执行才能看到内容 |
| 更便宜：可以放在任意静态服务器，只要 HTML/CSS/JS 文件 | SEO：索引与更新客户端渲染的内容更慢，爬虫首次抓取不会等界面渲完 |
| 离线：代码全在浏览器里跑，断网也能继续工作 | — |

那页还给了适用画像：**重度交互、不需要被索引、用户频繁回访的应用（SaaS、后台系统、网页游戏）**，并说明它能靠浏览器缓存跳过后续访问的下载阶段。

配套的一条 `::note`：如果确实要用 `ssr: false`，**应当在 `~/spa-loading-template.html` 放一份 HTML**，作为水合完成之前的加载屏（并留了指向 `spaLoadingTemplate` 的 read-more）。

## 后果二：接口全没了

`ssr` 关掉本身不移除服务器；**移除服务器的是预渲染那一步**。渲染概念页的 `::warning` 写得很硬：

> If you prerender your app with the `nuxt generate` or `nuxt build --prerender` commands, then you will not be able to use any server endpoints as no server will be included in your output folder. If you need server functionality, use `nuxt build` instead.

这句给了唯一那个判断标准：**输出目录里没有服务器，所以 `server/` 里的东西全不可用；要服务端能力就改回 `nuxt build`。**

顺带一条与运行时配置有关的：环境变量那页写着 **"for a purely static site, it is not possible to set runtime configuration after your project is prerendered"**——纯静态站里 `runtimeConfig` 在构建时就定死了。**这一条对 `ssr: true` 的 SSG 站点同样成立**（预渲染之后没有进程再读环境变量），只是它的措辞挂在"纯客户端"那段下面。

## 后果三：只需要三个文件

那页的 Deploying a Static Client-Rendered App 小节还有一条实用做法：默认 `nuxt generate`/`nuxt build --prerender` **会把每个页面各自渲成一份静态 HTML**，但纯客户端渲染通常只需要 `index.html` ＋ `200.html` ＋ `404.html`，让宿主对所有请求都发这几份。

做法是改路由预渲染集合，官方示例是往 `nuxt.hooks` 里塞一句：

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  hooks: {
    'prerender:routes' ({ routes }) {
      routes.clear() // Do not generate any routes (except the defaults)
    },
  },
})
```

注释那句是官方的：**"Do not generate any routes (except the defaults)"** ——清掉路由、只留默认那几份，结果就是它列的三个文件。

对照上一篇讲过的 `prerender:generate` 钩子（能逐个跳过 `index.html`/`200.html`/`404.html`）：一个管"要渲哪些路由"，一个管"某条已生成的路由要不要留下"，两条都在同一份文档里但分工不同。

## 与路由级开关的关系

`ssr` 不是全局独占。**`routeRules` 的九个属性里就有 `ssr: boolean`**——官方措辞是 "Disables server-side rendering of the HTML for sections of your app and make them render only in the browser with `ssr: false`"，混合渲染那份示例正是 `'/admin/**': { ssr: false }`。

所以两者是包含关系：**顶层 `ssr` 关掉是全站没有服务端渲染；要"后台只跑浏览器、内容页仍然服务端渲"，用路由规则按路径关。** 附带一条：被 `ssr: false` 覆盖的路由，其页面组件会被从服务端 bundle 里排除（那是构建期优化，不改变服务器发出的内容）。

## 自查

- `ssr` 是 `boolean`、默认 `true`，一句说明同时管"服务端动态渲染"与"generate 时渲染"，关掉后**生成的页面没有内容**。
- 官方对整站关掉的判断是"丢掉预渲染的 SEO 好处"，建议改用 `<ClientOnly>` 圈出不能服务端渲染的部分。
- 关掉后配套三件事：准备 `~/spa-loading-template.html` 当加载屏；预渲染的输出不含服务器，`server/` 端点全不可用（要服务端能力就 `nuxt build`）；纯静态通常只需三个文件，可用 `prerender:routes` 里 `routes.clear()`。
- 纯静态站的 `runtimeConfig` 无法在预渲染后再设。
- 需要按路径控制就用 `routeRules` 的 `ssr: false`，它还会把对应页面组件从服务端 bundle 排除。
