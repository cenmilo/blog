同样是往 `pages/` 里加目录，`parent/`、`child@sidebar.vue`、`(marketing)/` 这三种写法会让 URL 变成完全不同的样子。这一篇把三种放在一起对比，看完能直接选对。

## 一、嵌套路由：URL 分层，父页面必须有出口

官方定义："**可以配合 `<NuxtPage>` 显示嵌套路由。**"目录结构：

```bash [Directory Structure]
-| pages/
---| parent/
-----| child.vue
---| parent.vue
```

生成的路由记录（注意 `children`、`name` 与子 `path`）：

```js
[
  {
    path: '/parent',
    component: '~/pages/parent.vue',
    name: 'parent',
    children: [
      {
        path: 'child',
        component: '~/pages/parent/child.vue',
        name: 'parent-child',
      },
    ],
  },
]
```

| 观察 | 结论 |
| --- | --- |
| 子记录 `path: 'child'` | **不带前导斜杠**——它是相对父级的 |
| 子记录 `name: 'parent-child'` | 名字是"父名-子名"（112 讲的推导规则在这里落地） |
| URL 是 `/parent/child` | 由父 `path` 与子 `path` 拼出 |

而显示条件是硬性的一句：**"要显示 `child.vue` 组件，你必须插入 `<NuxtPage>` 组件到 `app/pages/parent.vue` 内部。"**

```vue {}[pages/parent.vue]
<template>
  <div>
    <h1>I am the parent view</h1>
    <NuxtPage :foobar="123" />
  </div>
</template>
```

父页面可以在这个出口上传 prop，官方示例是子页面用 `defineProps` 接住：

```vue {}[pages/parent/child.vue]
<script setup lang="ts">
const props = defineProps({
  foobar: String,
})

console.log(props.foobar)
</script>
```

重建时机用 `Child Route Keys` 那一节：官方说"**如果你想更多地控制 `<NuxtPage>` 组件何时重新渲染（例如为了过渡），你可以通过 `pageKey` prop 传入一个字符串或函数，或者通过 `definePageMeta` 定义一个 `key` 值**"——`<NuxtPage :page-key="route => route.fullPath" />` 或 `definePageMeta({ key: route => route.fullPath })`（092 展开过这两条等价路径）。

## 二、命名视图：URL 不变，一个路由填多个出口（v4.5）

官方定义：**"单个路由可以通过给每个出口一个 `name`、并为每个名提供一个兄弟页面文件，渲染进父组件里的多个 `<NuxtPage>` 出口。"** 文件名约定：**"使用 `name@view.vue` 文件名约定来声明一个与默认路由文件并列的命名视图。"**

```bash [Directory Structure]
-| pages/
---| parent/
-----| child.vue
-----| child@sidebar.vue
---| parent.vue
```

然后从父页面按名字渲染每个出口：

```vue [pages/parent.vue]
<template>
  <div>
    <NuxtPage />
    <aside>
      <NuxtPage name="sidebar" />
    </aside>
  </div>
</template>
```

官方的结果描述整句都要记住：

> 当用户导航到 `/parent/child` 时，`child.vue` 渲染进默认的 `<NuxtPage />`，而 `child@sidebar.vue` 渲染进 `<NuxtPage name="sidebar" />`。**没有匹配到命名视图的出口会留空。**

这里和嵌套路由的关键差别：**URL 只有一个（`/parent/child`），但页面里有两块内容同时被这个路由填。** 嵌套是"一层套一层，子内容在主列"，命名视图是"主列 + 侧栏这种并列槽位"。

还有一条会让人白写代码的限制：**"`definePageMeta` 只从默认路由文件读取。在 `name@view.vue` 兄弟文件里声明的 meta 对路由没有影响。**"——所以侧栏那个文件里写 `definePageMeta`（比如想给它单独的 `middleware` 或 `title`）是无效的，路由级元数据只能写在 `child.vue`。

官方把这一节链接到 vue-router 的 Named Views 文档，机制同源、约定不同。

## 三、路由组：只为组织文件，不进 URL

官方定义与动机写在一句里：**"某些情况下，你可能想把一组路由归在一起、同时又不影响文件式路由。为此你可以把文件放进一个用圆括号包裹的文件夹——`(` 和 `)`。"**

```bash [Directory structure]
-| pages/
---| index.vue
---| (marketing)/
-----| about.vue
-----| contact.vue
```

官方的结果：**"这会为你的应用生成 `/`、`/about` 和 `/contact` 页面。`marketing` 分组在 URL 结构方面会被忽略。"**

也就是说 `about.vue` 的 URL 是 `/about`——**目录名消失了**。这是三种写法里唯一"加目录但不改 URL"的。

### v4.3 起：组名可以读回来

官方加了一节 **Accessing Route Groups**（带 v4.3 徽章）："**路由组会自动出现在路由元数据里，作为 `route.meta.groups`。这让你能在组件里访问分组信息，用于条件逻辑、样式或其他目的。**"

```vue {}[pages/(marketing)/about.vue]
<script setup lang="ts">
const route = useRoute()

console.log(route.meta.groups) // Output: ['marketing']
</script>

<template>
  <div>
    <p v-if="route.meta.groups?.includes('marketing')">
      This is a marketing page
    </p>
  </div>
</template>
```

注意官方示例的判断写法是 `groups?.includes('marketing')`——**`groups` 是数组，用 `.includes()` 判，不是字符串比较**。

`definePageMeta` 那一侧对应的键也说明了两点（类型 `string[]`）："**基于目录结构，页面所属的路由组。对于位于路由组内的页面会自动填充。**"

## 三种写法对照

| 你想做的事 | 该用 | URL 结果 | 代价 |
| --- | --- | --- | --- |
| `/parent/child` 这种层级，父内容常驻 | 嵌套路由 | 多一层路径 | **父页面必须自己插 `<NuxtPage>`**，否则子内容不显示 |
| 主列 + 侧栏这种并列区域，URL 只有一个 | 命名视图（v4.5） | 不变 | `definePageMeta` 只在默认文件生效；不匹配的出口留空 |
| 只是想把文件分类归档（营销页、后台页） | 路由组 `(group)` | 组名被忽略 | 组信息要靠 v4.3 的 `route.meta.groups` 才读得回来 |

再加一条与 114 的分工：**圆括号 `()` 是"分组、不进 URL"，方括号 `[]` 是"参数、进 URL"**。`(id)/x.vue` 里的 `id` 不会成为参数，`[id]/x.vue` 里的才会。
