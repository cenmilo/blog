路由表建起来之后，有两件事一定会碰到：**根路径给谁**，以及"这个 URL 不该有内容"时怎么办。官方对这两件事都只给了很有限的几种手段，其余的写法都是无效的。

## 首页：只有一条映射

官方原话只有一句：**"`app/pages/index.vue` 文件会被映射到你应用的 `/` 路由。"**

放在推演里看更清楚——官方那组目录与生成结果的对照中，`index.vue` 产出的就是这条：

```json
{
  "path": "/",
  "component": "pages/index.vue"
}
```

两个推论：

- **`/` 只有一个来源**：`index.vue` 这个文件名。别的写法（`home.vue` → `/home`）不会占住根路径。
- **`app/pages/` 目录不存在时连 vue-router 都不装**（054、090），自然也就没有 `/`——这时候屏幕上的是 `app.vue` 自己。

## 子首页：靠 `index.vue`，不靠父文件

这是官方那条优先级 note 的直接后果，原文：

> **命名父路由会优先于嵌套的动态路由。对于 `/foo/hello` 路由，`~/pages/foo.vue` 会优先于 `~/pages/foo/[slug].vue`。使用 `~/pages/foo/index.vue` 与 `~/pages/foo/[slug].vue` 来用不同的页面分别匹配 `/foo` 和 `/foo/hello`。**

把三种文件组合摆开看：

| 你有的文件 | 产生的匹配 |
| --- | --- |
| `pages/foo.vue` | `/foo` |
| `pages/foo/[slug].vue` | `/foo/:slug` |
| **两者都有** | `/foo/hello` 被 **`foo.vue`** 抢走（官方明说父路由优先） |
| `pages/foo/index.vue` + `pages/foo/[slug].vue` | `/foo` 与 `/foo/hello` 各自一个页面 ✔ |

**结论：想要"栏目首页 + 栏目详情页"这一对，正确写法是 `foo/index.vue` 与 `foo/[slug].vue`，而不是 `foo.vue` 加 `foo/[slug].vue`。**

## 未匹配路径：官方给的手段是 catch-all

官方说明："如果你需要一个 catch-all 路由，就用一个像 `[...slug].vue` 这样的文件名来创建它。**它将匹配该路径下的\*所有\*路由。**"

```vue [app/pages/[...slug].vue]
<template>
  <p>{{ $route.params.slug }}</p>
</template>
```

参数形状有个必须实测一次才记得住的点。官方接着写：

> 导航到 `/hello/world` 会渲染：
>
> ```html
> <p>["hello", "world"]</p>
> ```

**`params.slug` 是一个数组**，不是一个字符串。这决定了写法：拼回路径要 `slug.join('/')`，取第一段是 `slug[0]`（注意 join 之后**没有前导斜杠**）。

放在 `pages/` 根目录时，`/hello/world` 这种任意深度都会被它接住——这也是为什么很多人用它做站内兜底页。但官方在这一节的定位只是"catch-all 路由"，**没有**把它定义成"404 页的替代方案"：接住之后要不要报 404，是你在那个页面里决定的（下一节）。

## 主动给 404：两条官方通道

### 通道一：`validate` 返回 false

官方在路由章节给的定义：**"该 `validate` 属性接受 `route` 作为参数。你可以返回一个布尔值来决定这是否是一个可以用这个页面渲染的有效路由。如果你返回 `false`，会造成一个 404 错误。你也可以直接返回一个带 `status`/`statusText` 的对象来自定义返回的错误。"**

官方示例（校验 id 必须由数字组成）：

```vue [pages/posts/[id].vue]
<script setup lang="ts">
definePageMeta({
  validate (route) {
    // Check if the id is made up of digits
    return typeof route.params.id === 'string' && /^\d+$/.test(route.params.id)
  },
})
</script>
```

这段顺手回答了一个常见问题：**路由参数是字符串**——官方这里同时判了 `typeof route.params.id === 'string'` 和"由数字组成"。

更复杂的场景官方给的替代是匿名中间件（"If you have a more complex use case, then you can use anonymous route middleware instead."）。

### 通道二：`throw createError(...)`

错误处理页给的例子是"数据取不到就当不存在"：

```vue [pages/movies/[slug].vue]
<script setup lang="ts">
const route = useRoute()
const { data } = await useFetch(`/api/movies/${route.params.slug}`)

if (!data.value) {
  throw createError({
    status: 404,
    statusText: 'Page Not Found',
  })
}
</script>
```

**`createError` 抛出去之后两侧行为不同**，这是最容易踩空的一条：

> 如果你抛出一个用 `createError` 创建的错误：
> - **在服务端**，它会触发一个全屏的错误页，你可以用 `clearError` 清掉它。
> - **在客户端**，它会抛出一个**非致命**错误交由你处理。如果你需要触发全屏错误页，可以通过设置 **`fatal: true`** 来做。

所以同一份代码，在服务端渲染时是整页错误、在客户端导航时只是被记录下来的非致命错误——**要让客户端导航也看到错误页，必须显式 `fatal: true`。**

`statusText` 还有一条格式硬约束（官方 tip）：

> `statusText` 属性是给简短、符合 HTTP 规范的状态文本用的（例如 "Page Not Found"）。它只应包含水平制表符、空格与可见 ASCII 字符（`[\t\u0020-\u007E]`）。对于详细的描述、多行消息或含非 ASCII 字符的内容，你应当始终改用 `message` 属性。

**也就是说中文文案不能放 `statusText`**，要放 `message`。

还有一条与安全相关的：在开发环境中，错误的 `cause` 会被保留并暴露给你的错误页，以便追踪原始错误；**在生产环境中，cause 绝不会出现在错误响应或错误页的 payload 里。**

## 静态托管时的未匹配路径

上面都发生在有服务器的情形。纯静态托管时，"这个路径不存在"是主机的事，官方给的是两个兜底文件：

| 文件 | 官方说明 |
| --- | --- |
| **`200.html`** | 当你希望**客户端路由来接手这个 URL** 时，对未匹配路径提供它 |
| **`404.html`** | 当主机应当**保持 404 状态、同时仍然加载你的应用**时提供它 |

并且三条限制写得很实：`nuxt generate` 与 `nuxt build --prerender` 会把它们写进 `.output/public/`，**没有预渲染的普通 `nuxt build` 不写**；混合路由规则下要靠 route rules 加这几个兜底，或者跑一次预渲染构建；主机侧要指向你的服务商所期望的那个文件。

还有一个默认状态要注意：**"默认情况下 `404.html` 是一个空壳，所以你的 `error.vue`（以及它的布局和数据）只会在客户端应用启动之后才出现。"** 要它在构建时就渲染好，开这一项：

```ts
export default defineNuxtConfig({
  experimental: {
    prerenderErrorPages: true,
  },
})
```

官方的解释是："Nuxt 随后会在构建时用一个**合成的 404 错误**渲染 `error.vue`，并把结果写入 `404.html`，它会在你的主机提供它的那个 URL 上就地水合。可以传入一个 400 到 599 之间的状态码数组（`[404, 500]`）来发出更多页面，如果你的主机能提供它们的话。"

## 一张表：我要 404，该用哪个

| 场景 | 手段 | 备注 |
| --- | --- | --- |
| 参数不合法（`/posts/abc`） | `definePageMeta({ validate })` 返回 `false` | 也可返回 `{ status, statusText }` 自定义 |
| 记录不存在（数据库查不到） | 页面里 `throw createError({ status: 404, statusText: 'Page Not Found' })` | 客户端导航要全屏错误页需 `fatal: true` |
| 中文/多行说明文字 | 放 `message`，不要放 `statusText` | `statusText` 只允许 tab/空格/可见 ASCII |
| 想让任意路径先进自己的页面再判断 | `[...slug].vue` catch-all | `params.slug` 是数组 |
| 纯静态站要"仍然是 404 状态" | 主机提供 `404.html` | 默认是空壳；开 `experimental.prerenderErrorPages` 才真渲染 |
| 纯静态站想让客户端路由接管 | 主机提供 `200.html` | 由 `nuxt generate`/`--prerender` 写出 |
