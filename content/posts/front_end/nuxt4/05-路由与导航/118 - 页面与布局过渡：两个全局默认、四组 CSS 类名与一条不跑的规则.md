配了 `pageTransition` 却发现换页时动也不动，八成是没配 CSS，或者那次导航同时换了布局。这一篇把过渡的三段——配置、CSS、行为差异——一次配齐。

## 两个开关，不是一个

官方在开头就把工具点明了："Nuxt 利用 Vue 的 `<Transition>` 组件来为你的页面和布局应用过渡。"

| 键 | 管什么 |
| --- | --- |
| `app.pageTransition` | 页面之间的过渡 |
| `app.layoutTransition` | 布局之间的过渡 |

官方对这两个键的取值说了同一件事："**`pageTransition` 与 `layoutTransition` 两个键都接受可 JSON 序列化的 `TransitionProps`，你可以传入自定义 CSS 过渡的 `name`、`mode` 和其他有效的 transition 属性。**"

`mode` 官方在示例里两次标注 `// default`，默认值是 **`out-in`**。全局默认值长这样：

```ts
export default defineNuxtConfig({
  app: {
    pageTransition: {
      name: 'fade',
      mode: 'out-in', // default
    },
    layoutTransition: {
      name: 'slide',
      mode: 'out-in', // default
    },
  },
})
```

## 只配第一项不会有任何效果

官方的启用顺序写得很具体："你可以启用页面过渡，为你所有的页面应用一个自动的过渡"：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  app: {
    pageTransition: { name: 'page', mode: 'out-in' },
  },
})
```

紧接着下一句才是让动画真正出现的那半步：**"要开始在你的页面之间添加过渡，请把下面这些 CSS 添加到你的 `app.vue`。"**

```vue [app/app.vue]
<template>
  <NuxtPage />
</template>

<style>
.page-enter-active,
.page-leave-active {
  transition: all 0.4s;
}
.page-enter-from,
.page-leave-to {
  opacity: 0;
  filter: blur(1rem);
}
</style>
```

类名的构成规律是 **`{name}-` 加四个阶段**：

| 类名 | 官方示例里的作用 |
| --- | --- |
| `.page-enter-active` | 进入过程的过渡定义（`transition: all 0.4s`） |
| `.page-leave-active` | 离开过程的过渡定义 |
| `.page-enter-from` | 进入的起始状态（这里是 `opacity: 0; filter: blur(1rem)`） |
| `.page-leave-to` | 离开的结束状态（与 enter-from 同组写在一起） |

**注意这四组类名写在 `app.vue` 里，不是写在页面里**——官方的两处指引（页面过渡、布局过渡）都说"添加到你的 `app.vue`"。

然后是那条会让人白折腾的 warning：

> **如果你改变了 `name` 属性，你也必须相应地重命名 CSS 类。**

`name: 'fade'` 配上 `.page-enter-active` 是不会有动画的——前缀必须一致。

## 布局过渡：为什么"换了布局就没有动画"

官方在页面过渡那一节挂了这条 note，是排查时的第一条判据：

> **如果你在换页面的同时也换布局，那么这里设置的页面过渡将不会运行。你应当改设一个布局过渡。**

布局的开关是 `app.layoutTransition`，官方示例给的是 `layoutTransition: { name: 'layout', mode: 'out-in' }`，CSS 同样是那四组、前缀换成 `layout`：

```css
.layout-enter-active,
.layout-leave-active {
  transition: all 0.4s;
}
.layout-enter-from,
.layout-leave-to {
  opacity: 0;
}
```

官方为这一节准备的例子正好把"换布局"这件事演示出来：`app/pages/about.vue` 里 `definePageMeta({ layout: 'orange' })`，而 CSS 那段示例的 `app.vue` 写的是 `<NuxtLayout><NuxtPage /></NuxtLayout>`。也就是说——**从 default 布局走到 orange 布局的那次导航，动的应该是布局过渡。**

单页也可以指定自己的布局过渡，官方说法与写法："与 `pageTransition` 类似，你可以使用 `definePageMeta` 在页面组件上应用一个自定义的 `layoutTransition`"：

```vue [pages/about.vue]
<script setup lang="ts">
definePageMeta({
  layout: 'orange',
  layoutTransition: {
    name: 'slide-in',
  },
})
</script>
```

## 三层写法：谁覆盖谁

官方对"覆盖"这件事只写了一条明确的规则，就这一条：

> **要覆盖全局过渡属性，请使用 `definePageMeta` 为单个 Nuxt 页面定义页面或布局过渡，并覆盖在 `nuxt.config` 文件里定义的任何页面或布局过渡。**

```vue [pages/some-page.vue]
<script setup lang="ts">
definePageMeta({
  pageTransition: {
    name: 'bounce',
    mode: 'out-in', // default
  },
})
</script>
```

所以这三层的关系是：

```
app.pageTransition / app.layoutTransition   ← 全局默认
        ↑ 被覆盖
definePageMeta({ pageTransition / layoutTransition })   ← 单页（官方明确：覆盖全局）
```

至于 `<NuxtPage>` 上那两个 `transition` / `keepalive` 属性，官方是把它当作"全局启用的另一个入口"介绍的（091 引过那句："你可以在 nuxt.config 文件里启用它们，**或者**通过在 `<NuxtPage>` 上设置 `transition` 和 `keepalive` 属性来启用"）。它与单页 `definePageMeta` 同时出现时的取舍，官方没有写成一条规则，下一篇会把能确认的与需要实测的分清楚。

## 关闭的两级写法

官方给的是同一件事的两个层级：

> `pageTransition` 与 `layoutTransition` 可以为某个具体路由禁用：

```vue [pages/some-page.vue]
<script setup lang="ts">
definePageMeta({
  pageTransition: false,
  layoutTransition: false,
})
</script>
```

> 或者在 `nuxt.config` 里全局关闭：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  app: {
    pageTransition: false,
    layoutTransition: false,
  },
})
```

这一句也解释了 `pageTransition` 的类型为什么是 `boolean | TransitionProps`——`false` 是一个合法取值，不只是"不设"。

## 两类进阶写法

### JavaScript 钩子

官方的适用说明："**对于高级用例，你可以使用 JavaScript 钩子来创建高度动态和自定义的页面过渡。这种方式为 GSAP 这类 JavaScript 动画库提供了完美的用例。**"写法是把钩子放进 `pageTransition` 对象里：

```vue [pages/some-page.vue]
<script setup lang="ts">
definePageMeta({
  pageTransition: {
    name: 'custom-flip',
    mode: 'out-in',
    onBeforeEnter: (el) => {
      console.log('Before enter...')
    },
    onEnter: (el, done) => {},
    onAfterEnter: (el) => {},
  },
})
</script>
```

**`onEnter` 的第二个参数是 `done`**——这是官方签名里带的，用 JS 钩子时必须调用它，否则 Vue 不知道动画何时结束。

### 动态过渡（方向随参数变）

官方说明："**要使用条件逻辑应用动态过渡，你可以借助内联中间件给 `to.meta.pageTransition` 指派一个不同的过渡名。**"官方示例把判断写得很保守：

```vue [pages/[id].vue]
<script setup lang="ts">
definePageMeta({
  pageTransition: {
    name: 'slide-right',
    mode: 'out-in',
  },
  middleware (to, from) {
    if (to.meta.pageTransition && typeof to.meta.pageTransition !== 'boolean') {
      to.meta.pageTransition.name = +to.params.id! > +from.params.id! ? 'slide-left' : 'slide-right'
    }
  },
})
</script>

<template>
  <h1>#{{ $route.params.id }}</h1>
</template>

<style>
.slide-left-enter-active,
.slide-left-leave-active,
...
</style>
```

那段条件里的两重判断不是多余的：**`pageTransition` 的类型是 `boolean | TransitionProps`**，所以必须先确认它是对象（`typeof !== 'boolean'`）才能改 `.name`——这正是 117 里"meta 可以被内联中间件改写"的一个合法用例（中间件跑在导航阶段，早于渲染）。

### 还有一条硬前提

所有过渡都建立在 Vue 的 `<Transition>` 上，官方用 important 块写了那条限制：

> 因为 Nuxt 使用 Vue 的 `<Transition>` 组件，**你想动画化的页面或布局必须有单个根元素**。多个根元素（片段）的页面或布局无法被动画化，所以过渡不会运行、在路由之间导航甚至可能报错。**Nuxt 会在开发模式下就此警告你。**把模板包在一个根元素里（例如一个 `<div>`）。

"过渡不跑"的排查顺序到这里就完整了：**单根 → CSS 前缀对上 `name` → 是不是换布局那类导航。**
