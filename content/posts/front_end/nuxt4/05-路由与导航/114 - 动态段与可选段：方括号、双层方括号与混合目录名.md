`[id]` 大家都认识，但 `[[id]]` 少打一层、或者以为"少一层就是可选"，路由就会表现得很奇怪。这一篇只管方括号这件事。

## 基本规则：放进方括号就是参数

官方原文两条，连着看：

> 如果你把任何东西放进**方括号**里，它就会被转换成一个动态路由参数。**你可以在一个文件名或目录名里混合多个参数，甚至混入非动态文本。**

第二句常被忽略：参数段不必占满整个文件名。`users-[group]` 就是一个"文字 + 参数"的目录名，`[id]` 是它下面的参数文件。

## 混合命名：官方那组示例

```bash [Directory Structure]
-| pages/
---| index.vue
---| users-[group]/
-----| [id].vue
```

官方接着给出取值方式与结果：

```vue [app/pages/users-[group]/[id].vue]
<template>
  <p>{{ $route.params.group }} - {{ $route.params.id }}</p>
</template>
```

> 导航到 `/users-admins/123` 会渲染：
>
> ```html
> <p>admins - 123</p>
> ```

从这一例能抽出三条：

| 结论 | 依据 |
| --- | --- |
| 目录名里的 `[group]` 与文件名里的 `[id]` 都成为参数 | `$route.params.group` 与 `$route.params.id` 都在同一个页面里取得到 |
| 目录里的静态文本 `users-` 原样留在 URL 里 | 命中的路径是 `/users-admins/123` |
| **参数名就是方括号里那个词** | 官方示例里 `[group]` 对应 `params.group`、`[id]` 对应 `params.id` |

## 可选段：必须是双层

官方这句话把写法钉死了：

> 如果你希望一个参数是**可选的**，**你必须**把它包在**双层方括号**里——例如 `~/pages/[[slug]]/index.vue` 或 `~/pages/[[slug]].vue` **会同时匹配 `/` 和 `/test`**。

这一句里有三个必须记住的点：

| 点 | 说明 |
| --- | --- |
| **单层 = 必填** | 官方给可选段单独规定写法，反过来说 `[slug]` 少一段就不匹配 |
| **双层 = 可选** | 只有 `[[slug]]` 才同时匹配"带值"和"不带值"两种路径 |
| **官方给了两种形态** | `[[slug]]/index.vue` 与 `[[slug]].vue`，两者都同时匹配 `/` 与 `/test` |

对照表：

| 文件 | 匹配 |
| --- | --- |
| `pages/[slug].vue` | 只有 `/something`（少一段就不命中） |
| `pages/[[slug]].vue` | `/` **和** `/test`（官方原话） |
| `pages/[[slug]]/index.vue` | `/` **和** `/test`（官方原话） |

**`[[slug]].vue` 这一种最值得记**：它让一个文件同时当首页和带参数页——官方举的就是"同时匹配 `/` 和 `/test`"。这正好是"我想少写一个 `index.vue`"的场景。

而 `[[slug]]/index.vue` 那一种，把可选段放在目录上，页面文件仍是 `index.vue`；两种形态官方都认可，选哪种取决于你要不要在这个目录下再放别的文件。

## 取值：两个口径 + 判空

官方给了两条访问路径。

**模板里直接用 `$route`**：`{{ $route.params.group }} - {{ $route.params.id }}`。

**Composition API**——官方的说明是：

> 如果你想用 Composition API 访问路由，有一个全局的 `useRoute` 函数，它允许你像在 Options API 里用 `this.$route` 那样访问路由。

```vue
<script setup lang="ts">
const route = useRoute()

if (route.params.group === 'admins' && !route.params.id) {
  console.log('Warning! Make sure user is authenticated!')
}
</script>
```

这个官方示例的写法值得学一手：**`!route.params.id`**——官方自己就把 param 当成"可能取不到"的值来判断。可选段场景下这一步是必须的：没带那一段时它就是空值。

至于类型，111 已经取过证据：官方在 `validate` 的示例里同时判了 `typeof route.params.id === 'string'` 和"由数字组成"，说明**参数取到的是字符串**，要数字得自己转。

## 优先级：官方那条 note 必须一起记

可选段解决的是"深度可选"，但**同名冲突**要靠另一条规则处理。官方的 note：

> **命名父路由会优先于嵌套的动态路由。对于 `/foo/hello` 路由，`~/pages/foo.vue` 会优先于 `~/pages/foo/[slug].vue`。使用 `~/pages/foo/index.vue` 与 `~/pages/foo/[slug].vue` 来用不同的页面分别匹配 `/foo` 和 `/foo/hello`。**

| 组合 | `/foo` 归谁 | `/foo/hello` 归谁 |
| --- | --- | --- |
| `foo.vue` + `foo/[slug].vue` | `foo.vue` | **`foo.vue`**（父路由优先，抢走了） |
| `foo/index.vue` + `foo/[slug].vue` | `foo/index.vue` | `foo/[slug].vue` ✔ |

所以两条规则各管一件事：**双层方括号管"这一段可有可无"，`index.vue` 管"这一层的首页归谁"。** 想同时要两者，就写成 `foo/[[slug]].vue` 这一类形态，或者按官方建议把首页做成 `foo/index.vue`。
