Named and anonymous middleware are executed only on the routes specified in the middleware property of the page(route) meta defined in the corresponding page components.**"；`redirect`"**The redirection happens before any navigation guard and triggers a new navigation with the new target location.**"。服务端重定向的后果官方也写了："**Any redirection on the server will result in a `Location:` header being sent to the browser; the browser then makes a fresh request to this new location. All application state will be reset when this happens, unless persisted in a cookie.**"。把钩子表叠在这条线上，才有完整的可诊断版本：`app:created` →（SSR）`app:rendered` → `render:html`；客户端 `app:beforeMount` → `app:mounted`；每次导航 `page:loading:start` → `page:start` → `page:finish` → `page:loading:end` → `page:transition:finish`，外加 `link:prefetch` 在点击之前就发生。

路由这一路走来，知识点是散着的：`redirect`、`validate`、三类中间件、`key`、Suspense、过渡、播报、进度条、预取。**它们真正的差别是发生在哪一步**。这一篇按官方生命周期那一章的顺序把它们串一遍，之后遇到"这段代码为什么没跑"，你可以先定位步骤再定位代码。

## 先分清两条时间线

官方那一章把生命周期切成两半，两半的**触发条件不一样**：

> On the server, the following steps are executed **for every initial request** to your application.

> This part of the lifecycle is **fully executed in the browser**, no matter which Nuxt mode you've chosen.

第一句限定的是"**初始请求**"——服务器只在有人真正请求这个 URL 时走那七步。**点击 `<NuxtLink>` 换页时，服务端那七步不会重跑**。第二句说的是浏览器里那部分跟模式无关。这个区分决定了后面所有排障的方向。

## 服务端：一次初始请求的七步

按官方 `::steps` 的顺序：

| 步 | 官方要点（原话摘录） | 关联钩子 |
| --- | --- | --- |
| ① Server plugins | "When Nitro starts, it initializes and executes the plugins under the `/server/plugins` directory."；能"Capture and handle application-wide errors / Register hooks that execute when Nitro shuts down / Register hooks for request lifecycle events" | — |
| ② Server middleware | "After initializing the Nitro server, middleware under `server/middleware/` is executed **for every request**." | — |
| ③ App plugins | "The Vue and Nuxt instances are created first. Afterward, Nuxt executes its app plugins."（含内置的 Vue Router 与 `unhead`，以及 `app/plugins/` 里无后缀与 `.server` 后缀的） | **`app:created`** |
| ④ Route validation | "**After initializing plugins and before executing middleware**, Nuxt calls the `validate` method if it is defined in the `definePageMeta` function." | — |
| ⑤ App middleware | 三类中间件；服务端重定向的连带后果 | — |
| ⑥ Page and components | "Nuxt renders the page and its components and fetches any required data with `useFetch` and `useAsyncData` during this step." | — |
| ⑦ HTML Output | "Nuxt combines the rendered components with settings from `unhead` to generate a complete HTML document." | **`app:rendered`**，之后 Nitro 侧 **`render:html`** |

第 ② 步那条 `::warning` 值得单独记住，因为它和第 ⑤ 步的返回值规则完全不同：

> Returning a value from middleware will terminate the request and send the returned value as the response. **This behavior should generally be avoided to ensure proper request handling!**

**Nitro 服务端中间件"返回东西 = 把它当响应发出去"**，而 Vue 侧路由中间件的返回值是导航指令（132）。两者同名、规则相反，串到这张时间线上才不会混。

第 ⑥ 步的三条限制同样在这张表里最实用：

> Since there are no dynamic updates and no DOM operations occur on the server, Vue lifecycle hooks such as `onBeforeMount`, `onMounted`, and subsequent hooks are **NOT** executed during SSR.

> By default, Vue pauses dependency tracking during SSR for better performance.

> There is no reactivity on the server side because Vue SSR renders the app top-down as static HTML, making it impossible to go back and modify content that has already been rendered.

以及那条 `::important`：**在 `<script setup>` 顶层写需要清理的副作用（例如 `setInterval`）会留下来**，因为"the unmount hooks will never be called during SSR"——官方给的解法是"move your side-effect code into `onMounted` instead"。

## 客户端首屏：五步

| 步 | 官方要点 | 关联钩子 |
| --- | --- | --- |
| ① App plugins | 与侧服务端"similar"，但自定义插件是"无后缀 + `.client` 后缀"那批 | **`app:created`** |
| ② Route validation | "This step is the same as the server-side execution" | — |
| ③ App middleware | "Nuxt middleware runs on both the server and the client. If you want certain code to run in specific environments, consider splitting it by using `import.meta.client` ... and `import.meta.server`" | — |
| ④ Mount Vue app and hydrate | "Calling `app.mount('#__nuxt')` mounts the Vue application to the DOM. If the application uses SSR or SSG mode, Vue performs a hydration step..." | **`app:beforeMount`** → **`app:mounted`** |
| ⑤ Vue lifecycle | "Unlike on the server, the browser executes the full Vue lifecycle." | — |

第 ④ 步里两个说法直接影响水合对不对：

> During hydration, Vue recreates the application (**excluding Server Components**), matches each component to its corresponding DOM nodes, and attaches DOM event listeners.

> To ensure proper hydration, it's important to maintain consistency between the data on the server and the client. For API requests, it is recommended to use `useAsyncData`, `useFetch`, or other SSR-friendly composables. These methods ensure that the data fetched on the server side is reused during hydration, **avoiding repeated requests**. Any new requests should only be triggered after hydration, **preventing hydration errors**.

**这两句是 145/146 之外的第三条数据侧规则**：SSR 取过的数据靠 `useFetch`/`useAsyncData` 在水合时被复用；水合前不要发新请求。

## 换页时走的那条线：把钩子叠上去

首屏之后，每次点链接的导航顺序是这样（每一步都取自官方原句）：

| 顺序 | 发生什么 | 依据原话 |
| --- | --- | --- |
| 1 | 链接进视口/被 hover 时**已经预取过** | `link:prefetch` — "Called when a `<NuxtLink>` is observed to be prefetched."（Client） |
| 2 | 若该路由直接匹配且带 `redirect` → **在所有导航守卫之前**跳转 | "The redirection happens before any navigation guard and triggers a new navigation with the new target location." |
| 3 | `validate` 跑（若定义了） | lifecycle："before executing middleware"；失败可返回 `false` 或 `{ status, statusText }`（111） |
| 4 | 全局中间件跑；命名/匿名按 `meta.middleware` 指定的路由跑 | "Nuxt executes all global middleware on the initial page load (both on server and client) **and then again before any client-side navigation**." |
| 5 | 中间件返回值成为导航指令（`navigateTo` / `abortNavigation` / false） | 见 124、127、132 |
| 6 | `page:loading:start` 触发 → 进度条起来 | "Called when a route navigation begins (before resolution) **or when the page key changes**." |
| 7 | 目标页 chunk 已在（或此时才取）→ Suspense pending | `page:start` — "Called on Suspense inside of `NuxtPage` pending event." |
| 8 | 页面 `setup()` 与数据解析完 → Suspense resolved | `page:finish`；`app:suspense:resolve` — "On Suspense resolved event." |
| 9 | `page:loading:end` 收尾，进度条淡出 | "Called after `page:finish`"；`finish()` 后 500 ms 重置（146） |
| 10 | 过渡结束 | `page:transition:finish` — "After page transition onAfterLeave event." |
| 11 | 布局是否换、是否重建由 `key`/`pageKey` 决定 | 137；`page:loading:start` 那句"or when the page key changes"就是这条的连带 |
| 12 | 标题变了就播报；标题没变就不播 | `useRouteAnnouncer` 靠 Unhead 的 `dom:rendered` 读标题（144） |
| 13 | 滚不滚回顶部由 `scrollToTop` 与 router 的 `scrollBehavior` 决定 | 138 |

**这张表最值得记住的是第 6 步那句补充**：进度条起来了，**不代表页面组件的 `setup()` 重跑了**——官方原话就是"May fire without the page component's `setup()` re-running if the page is reused (e.g. with a static `key` in `definePageMeta`)"。数据有没有重新取，要看 `useFetch`/`useAsyncData` 有没有被再次调用，不能看进度条。

## 中途可以"下车"的出口

一条导航能在这些地方终止或改道，全部都有官方依据：

| 出口 | 位置 | 后果 |
| --- | --- | --- |
| `routeRules` 的 `redirect` | 服务端最外层（140） | 到不了 Vue 侧 |
| Nitro server middleware 返回值 | 服务端 ② | 直接把返回值当响应发出（官方警告应避免） |
| `definePageMeta({ redirect })` | 守卫之前 | 触发一次新导航 |
| `validate` 返回 `false` | 守卫之前一步 | 匹配不到别的则 404 |
| `validate` 返回 `{ status, statusText }` | 同上 | "respond immediately with an error (other matches will not be checked)" |
| 中间件返回 `navigateTo(...)` | 守卫里 | 见 124；服务端重定向会发 `Location:` |
| 中间件返回 `abortNavigation()` | 守卫里 | 导航取消，停在当前页（127） |
| `createError` | 页面/数据侧 | 进错误页（111、095） |
| 组件抛错 | 渲染侧 | `<NuxtErrorBoundary>` 只在客户端捕获（095） |

服务端那次"改道"的代价官方写得很直白：

> Any redirection on the server will result in a `Location:` header being sent to the browser; the browser then makes a fresh request to this new location. **All application state will be reset when this happens, unless persisted in a cookie.**

**所以服务端 `redirect` 不是"换个页面渲染"，而是"整个请求重来一次"**，状态只靠 cookie 活下来。

## 排障索引：症状 → 先查哪一步

| 症状 | 先怀疑 | 验证方式 |
| --- | --- | --- |
| 点了链接白屏一下才出现 | chunk 没预取：链接不是 `<NuxtLink>`、或 `no-prefetch`、或 `custom` | 看 Network；`link:prefetch` 是否触发（145、147） |
| 中间件里 `await` 的跳转没生效 | `navigateTo` 没 await/return | 124 |
| 同一次导航中间件跑了两遍 | 全局中间件本来就会"首屏 + 每次客户端导航"各跑；错误页还会再跑一轮 | 128、本节表格第 4 步 |
| 页面数据没重新取 | 页面实例被复用（静态 `key`）；进度条闪过不代表重跑 `setup()` | 146 那句原文 |
| 布局在换页时重建（或反过来） | `key`/`pageKey` 与 `<NuxtLayout>` 的 name 变化 | 092、137、139 |
| 过渡没跑 | 布局变了，`pageTransition` 就不会执行 | 118 |
| 屏幕阅读器没声音 | 两个路由 `<title>` 相同 | 144 |
| 顶部进度条一直是红的 | `finish({ error: true })` 设过 `error` 状态，组件只有 `errorColor` 没有 `error` prop | 146 |
| `definePageMeta` 的字段在构建期读不到 | 可提取的只有六个 key，且必须静态可提取；顺序上 `pages:extend` 早于扫描 | 143 |
| 内部路径 404 | `/public` 文件与同域另一个应用需要 `external` | 147 |
