无障碍问题最难的地方是"不知道要查什么"。官方那一节只有五节，能自查的项目是有限的、可穷举的。

这一篇把它们列成一张表。**每条判据都来自官方原文**，出处标在最后一列，不掺任何页外规则。

## 十二条自检

| # | 检查什么 | 判据 | 依据 |
| --- | --- | --- | --- |
| 1 | 装了 `<NuxtRouteAnnouncer>` | 放 `app.vue` 或 `app/layouts/`，作用是加一个隐藏元素把页面标题变化播报出去 | 483（**v3.12+**） |
| 2 | 装了 `<NuxtAnnouncer>` | 表单校验、toast、加载态这类页面内变化归它；**官方明写"必须加这个组件，播报才会渲染到 DOM"** | 485（**v4.4.2+**） |
| 3 | 每条路由的 `<title>` 可区分 | 播报器读的就是 Unhead 渲出的标题；**两条路由共用同一标题时，用户在切换过程中什么都听不到** | 481、484 |
| 4 | 全局标题模板写在对的地方 | 函数形态**不能放 `nuxt.config`**，官方建议在 `app.vue` 设 `titleTemplate` | 481、488 |
| 5 | 站内链接一律 `<NuxtLink>` | 它渲出真 `<a href>`，因此**可聚焦、进 tab 顺序、支持中键与新标签页打开**；这三项在 `<div @click>` 上要自己实现 | 482、456 |
| 6 | `public/` 文件与同域另一应用标了 `external` | 否则走的是 Vue Router 内部导航，会撞到意料之外的 404 | 482、147 |
| 7 | 当前项的 `aria-current` 够用 | 匹配当前路由的链接**已经自带 `aria-current="page"`**；多页表单这类场景官方给的替代是 `aria-current-value="step"` | 482 |
| 8 | skip link 是第一个 tab 停靠点 | 官方原话"A skip link as the first tab stop of your app is the conventional fix, and it helps on the initial page load too" | 482 |
| 9 | `<main>` 带 `tabindex="-1"` | `<main>` 本身不可聚焦；**官方明确反对用正值**（会把元素挪进 tab 顺序） | 482 |
| 10 | 导航后焦点落点验过 | 官方写明"Vue Router 不会移动焦点，Nuxt 也不会"；要在每次导航后交给主区，配方是一个 `.client` 插件里 `afterEach`＋`nextTick` | 482 |
| 11 | 滚动改动尊重 reduced motion | 默认行为是新路由滚到顶、返回恢复位置、命中锚点滚动；改法指向 `scrollBehaviorType` 或 `router.options.ts`，并附一句"平滑滚动应尊重用户的 `prefers-reduced-motion`" | 489 |
| 12 | `<html>` 上有 `lang` | 官方把语言与"站点标题默认值、favicon"并列为放在 `app.head` 的静态项；但它**不能放响应式数据**，语言会切换就得改用 `useHead()` | 486 |

第 12 条之外还有一条附属检查：`viewport` 与 `charset` 是框架默认给的（`width=device-width, initial-scale=1`、`utf-8`），要改有带键的写法——官方**没有对缩放行为给任何建议**（文档未记载）。

## 最后一条不是清单，是动作

官方整页只给了一个验收动作，写在 Focus Management 末尾那条 `::tip`：

> Navigate around your app with the keyboard alone. Tabbing from the skip link into `<main>` after a couple of navigations will surface most focus problems quickly.

**只用键盘在应用里走一圈**，从 skip link tab 进 `<main>`，几次导航之后大部分焦点问题会自己冒出来。上面十二条里第 5、8、9、10 条都能在这一趟里同时验掉。

## 五个反例（都取自官方原话）

| 反例 | 官方怎么说 |
| --- | --- |
| 用带 `@click` 调 `navigateTo` 的 `<div>` 做导航 | 那三项能力（可聚焦、tab 顺序、中键与新标签页）**都得你自己重新实现** |
| 两条路由用同一个 `<title>` | "users hear nothing on the way between them" |
| `<main>` 给正的 `tabindex` | "would move the element in the tab order and surprise everyone else" |
| 需要交互的组件设成 `hydrate-never` | 组件目录那一节的最佳实践第 5 条：需要用户交互的组件不应该设为永不水合 |
| 把整站设成 `noScripts` 求快 | 页面外观一致，但官方写的是"the page simply never hydrates, which means nothing on it is interactive"；`nuxt-client` 与交互岛屿在其中不会激活 |

最后一行是 456 那篇列过的性能↔可访问性冲突里最尖锐的一条，这里作为反例复述。

## 一个工具，三条资源

工具方面官方只点名一个：

> `@nuxt/a11y` surfaces accessibility problems in your components while you develop, alongside the practices below. It is in alpha, so expect its API to change.

作用是**开发期把组件里的可访问性问题暴露出来**；限制也写在同一句里——**处于 alpha，预期 API 会变**。

页末列出的三条资源，是官方对"与 Nuxt 无关那部分"（对比度、表单语义、ARIA、替代文本）给的去处：

- Web Accessibility Initiative (WAI)：`w3.org/WAI/`
- MDN: Accessibility：`developer.mozilla.org/en-US/docs/Web/Accessibility`
- Understanding WCAG 2.1：`w3.org/WAI/WCAG21/Understanding/`

要划清一句：这三条是**指向**，官方在那一节里**没有任何一处声明"按它做就符合某个 WCAG 等级"**（文档未记载）。所以合规结论不能拿这一节当依据，只能拿这三份外部文档与你们自己的评审。

## 自查

- 十二条里最容易被整批漏掉的是第 2、3 条：装了路由播报器不等于页面内变化也会播；标题不可区分则播报器形同虚设。
- 第 1 与第 2 有版本门槛，分别要求 v3.12+ 与 v4.4.2+；老版本升级前先确认这一点。
- 第 8、9、10 三条一次键盘巡检就能覆盖。
- 反例五条都对应官方原话，任何一条被同事质疑时能直接回指出处。
- 官方只给方向（三条资源）不给合规结论，别把这一节当达标证明。

## 下一篇

下一篇 488 专门讲标题那一层的机制：`titleTemplate` 可以是字符串（`%s` 占位）也可以是函数，但**要用函数就不能写在 `nuxt.config` 里**，官方建议放 `app.vue` 好让它作用于全站；还有 `templateParams` 提供额外占位符，以及 `definePageMeta` 里那个 `title` 是**构建期通过宏提取的**，所以不能动态设置。

## 本文依据

- 无障碍页五节的全部可自查句：Route Announcements（隐藏 live region 写入新标题、"reads the title that Unhead rendered"、共用 `<title>` 则什么都听不到、`useRouteAnnouncer` 用于换内容或换紧急度、页面内变化用 `<NuxtAnnouncer>`＋`useAnnouncer`）、Page Titles（每条路由可区分标题是单件最有价值的事、`app.vue` 全局模板与页面各填自己那部分、元数据标题在布局里读）、Links（真 `<a href>` 三项能力与 `<div @click>` 反面、`aria-current="page"`、`aria-current-value="step"`、`external`）、Focus Management（成因句、skip link 为第一个 tab 停靠点、`tabindex="-1"` 与反对正值、`.client` 插件配方、`::tip` 只用键盘走一圈）、Scroll Behavior（默认三种滚动、`scrollBehaviorType`、`router.options.ts`、`prefers-reduced-motion`）、Useful Resources 三条原文与地址、`::tip` 关于 `@nuxt/a11y` 及其 alpha 声明（`guide/best-practices/accessibility`）
- `<NuxtRouteAnnouncer>` 与 `<NuxtAnnouncer>` 两节的版本 `::important`（v3.12+、v4.4.2+）、位置（`app.vue` 或 `app/layouts/`）、"You need to add the `<NuxtAnnouncer>` component to your app for the announcements to be rendered in the DOM."（`api/components/nuxt-route-announcer`、`api/components/nuxt-announcer`）
- SEO 页：`app.head` 示例（`title` 默认兜底、`htmlAttrs.lang`、favicon）与"不会变的东西放这里"句、`::important` 不能放响应式数据、Default Tags 两条默认值与 keyed 改法（`getting-started/seo-meta`）
- `hydrate-never` 不用于需要交互的组件（`directory-structure/app/components`）；`noScripts` 的"nothing on it is interactive"与岛屿例外（`guide/going-further/features`）
