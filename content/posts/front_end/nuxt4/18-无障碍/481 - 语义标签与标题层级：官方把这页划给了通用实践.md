评审时说"页面标题层级要合规"，同事翻了一遍 Nuxt 文档，回来说没找到规则。他没找错地方——**这一页确实没写层级规则**，而且它连语义标签都不打算讲。

这一篇说清这页划走了什么、留下了什么，以及留下的那一条要求为什么比看上去严重。

## 官方划走的那三样

第一句原文：

> Most of what makes an app accessible is not specific to Nuxt: color contrast, form semantics, and ARIA work the same here as in any Vue or plain HTML application, and the resources at the end of this guide cover them well.

**色彩对比度、表单语义、ARIA** 被点名"与 Nuxt 无关"，去处是"本指南末尾的资源"。这三样加起来正是"语义标签该用什么、层级怎么排"的大部分答案——**官方明确把它交给了通用 Web 实践**，所以在这页查不到不是遗漏。

这一页里唯一沾到元素语义的一句，是 Links 那一节对 `<NuxtLink>` 的说法：它渲出真 `<a href>`，所以**可聚焦、进 tab 顺序、支持中键与"在新标签页打开"**，而这三项是你用带 `@click` 调 `navigateTo` 的 `<div>` 得自己重新实现的东西。除此之外，本页没有任何标签选用规则。

## 标题层级：这页没有规则

关于 h1-h6，官方在这页**一个字都没提**（文档未记载）。能查证到的只有示例代码里出现过的标签：

- `error.vue` 那一页的示例用 `<h1>{{ error.status }}</h1>`
- 错误处理那一页的示例用 `<h2>{{ props.error?.status }}</h2>`

**这两处只是示例，官方没有把层级写成要求**——所以不能拿它们当"h1 只能有一个"之类的依据。层级规则要从通用实践那一侧拿。

## 留下来的那条硬要求：文档标题

这页对标题的要求集中在 Page Titles 一节，第一句就是理由：

> Because the route announcer follows the document title, giving every route a distinct title is the single most valuable thing you can do.

**播报器跟着文档标题走**，所以"每条路由一个可区分的标题"被官方称为**单件最有价值的事**。

反面也写了，就在 Route Announcements 那一节：

> The announcer reads the title that Unhead rendered, so it is only as useful as your titles are. If two routes share the same `<title>`, users hear nothing on the way between them.

两句合起来是一条可验证的判断：**播报能力上限等于你的标题质量**；两条路由共用同一个 `<title>`，用户在它们之间切换时**什么也听不到**。

这里说的标题是 `<head>` 里的 `<title>`（由 Unhead 渲染），不是页面上那个可见的大标题。**两者可以不一致，而播报只看前者**。

## 官方给的两种写法

**主路：全局模板 + 各页填自己那部分。** 官方原话是"在 `app.vue` 设一个全局模板，让每个页面填上自己的那部分"：

```vue [app.vue]
<script setup lang="ts">
useHead({
  titleTemplate: title => title ? `${title} - Nuxt` : 'Nuxt',
})
</script>
```

```vue [app/pages/about.vue]
<script setup lang="ts">
useHead({
  title: 'About us',
})
</script>
```

这两段配合的效果是：**页面没写标题时落到模板的假分支（`'Nuxt'`）**，写了就变成"页面标题 - 站点名"。模板函数拿到的入参就是页面给的标题——这解释了那个 `title ? ... : ...` 的三元式为什么必须写。

**另一条：标题来自路由元数据。** 官方给的句子是：

> If your titles come from route metadata rather than from the page itself, you can read `definePageMeta` values from `useRoute` in a layout.

也就是说，标题存在 `definePageMeta` 里时，读它的地方是**布局**，用 `useRoute` 取元数据值。

## 这条要求和别的无障碍工作的关系

480 那篇排的那个顺序（**是我的读法，不是官方次序**）在这里落地：先做标题，再谈播报器。因为 483/484 要讲的 `<NuxtRouteAnnouncer>` 与 `useRouteAnnouncer` 里，前者**默认动作就是写标题**——标题没区分度，那个组件等于装了个哑的。

顺带一条口径：`titleTemplate` 支持函数形态，也支持带 `%s` 占位符的字符串（`useHead` 参数表里那句"Can be a string with `%s` placeholder or a function"）。官方在这页给的是函数形态。

## 自查

- 这页不讲色彩对比度、表单语义、ARIA，也不讲标题层级；前者交给页末资源，后者**文档未记载**。
- 示例里出现过 `<h1>`、`<h2>`，但那是示例，不是层级规则。
- 唯一硬要求：每条路由的 `<title>` 要可区分；共用标题时切换过程中听不到任何播报。
- 写法是 `app.vue` 的 `titleTemplate`（含没标题时的假分支）＋页面各自 `title`；元数据驱动就在布局里用 `useRoute` 读 `definePageMeta`。
- 播报器读的是 Unhead 渲出的文档标题，不是页面上可见的标题。

## 下一篇

下一篇 482 讲焦点：官方把话说得很直——客户端导航后焦点留在原地，通常就是用户刚点的那个链接，**Vue Router 不动它，Nuxt 也不动**。给的第一配方是 skip link 作为应用的第一个 tab 停靠点，`<main>` 本身不可聚焦，要加 `tabindex="-1"`，而且官方特别提醒**不要用正值**，那会把这个元素插进别人的 tab 顺序里。
