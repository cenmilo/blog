读屏软件念中文内容用了英文发音表，第一件要查的事是 `<html>` 上有没有 `lang`。你去官方无障碍那一节找这个属性——那一节没有。它在讲 SEO 元信息的那一节。

这一篇把两件事分开讲：**语言属性有明确写法**，**替代文本没有规则**。

## lang 的官方位置

SEO 那一节讲 `app.head`（写在 `nuxt.config.ts` 里静态定制全站 head）时给的示例，三样东西一起出现：

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  app: {
    head: {
      title: 'Nuxt', // default fallback title
      htmlAttrs: {
        lang: 'en',
      },
      link: [
        { rel: 'icon', type: 'image/x-icon', href: '/favicon.ico' },
      ],
    },
  },
})
```

配的那句是选型依据：

> It's good practice to set tags here that won't change such as your site title default, language and favicon.

**站点标题默认值、语言、favicon** 被并列成"不会变的东西"，所以放这里。注意这段里的注释也是官方写的：`title` 那行标的是 "default fallback title"——**它是兜底标题**，与 488 要讲的 `titleTemplate` 假分支是一对。

## 但它不能放响应式数据

同一节上面一条 `::important`：

> This method does not allow you to provide reactive data. We recommend using `useHead()` in `app.vue`.

这条决定了多语言站点的写法：**语言会在运行时变，所以不能只在 `nuxt.config` 里设**。

`useHead` 那一侧的落点是参数表里这一行：

> `htmlAttrs`: `HtmlAttributes` - Sets attributes of the `<html>` tag. Each object property is mapped to the corresponding attribute.

**对象每个属性映射到一个 HTML 属性**，而 `useHead` 支持响应式入参（那一节 Parameters 段对 `meta` 那句"All properties support reactive values (`ref`, `computed`, `reactive`) or can be a function returning the metadata object"）。

把两句合起来——语言随用户切换而变时，`useHead({ htmlAttrs: { lang: locale.value } })` 是可走的写法。**这个具体组合是我的推法**：官方分别写明了"`app.head` 不能放响应式数据、建议用 `useHead`"与"`htmlAttrs` 每个属性映射到对应属性"，但没有一处把 lang 当响应式的例子讲。

## 顺带：两个默认值也在 head 这一层

同页还有一句容易被跳过的规定：

> Some tags are provided by Nuxt by default to ensure your website works well out of the box.
>
> - `viewport`: `width=device-width, initial-scale=1`
> - `charset`: `utf-8`

**`viewport` 与 `charset` 是框架默认给的**，官方说多数站点不用改，要改就用带键的写法：

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  app: {
    head: {
      // update Nuxt defaults
      charset: 'utf-16',
      viewport: 'width=device-width, initial-scale=1, maximum-scale=1',
    },
  },
})
```

`viewport` 这条和可访问性有实际关系（缩放），但**官方在这一节没写任何关于缩放的建议**（文档未记载），这里只把默认值和改法记下来。

同一段还有个 `::note` 提醒 favicon：设了 `app.cdnURL` 时 `public/` 里的资源从 CDN 提供，但 `app.head` 里写死的 `href: '/favicon.ico'` 这类字面量**不参与 `cdnURL` 解析**，要指向解析后的位置就得在 `app.vue` 里用 `useHead()` 拼 `useRuntimeConfig().app` 的 `cdnURL || baseURL`（422 记过这条）。

## 替代文本：4.x 没有规则句

把整个 4.x 文档搜一遍可以看到：`alt` 只出现在**示例代码**里，没有任何一句把它写成要求。能查到的四处都在资源那一节：

```vue
<img
  src="/img/discover.png"
  alt="Discover Nuxt"
>
```

以及动态拼路径时的那段（`:src` 与 `:alt` 配对出现，值是 `props.name`）：

```vue
<script setup lang="ts">
const props = defineProps<{ name: string }>()
const imageUrl = computed(() => `/img/${props.name}.png`)
</script>

<template>
  <img
    :src="imageUrl"
    :alt="props.name"
  >
</template>
```

这两处的信息量到此为止：**官方演示了 `alt` 可以写、可以是动态绑定**，但**没有一句"每张图片必须有 alt"或"装饰性图片该怎么写"**。无障碍页的第一句正是这个边界的说明——ARIA、表单语义、对比度都归通用 Web 实践，页末资源才是去处：

> Most of what makes an app accessible is not specific to Nuxt: color contrast, form semantics, and ARIA work the same here as in any Vue or plain HTML application, and the resources at the end of this guide cover them well.

所以按 Nuxt 文档写不出"替代文本合规检查"，要查得看 HTML 规范那一侧。这一篇不给任何规则，只说明**它不在这份文档里**。

## 自查

- `lang` 的官方写法是 `app.head.htmlAttrs.lang`，与默认标题、favicon 并列在"不会变的东西"那一句里。
- 但 `app.head` 不能放响应式数据（`::important` 原话），官方建议改用 `app.vue` 里的 `useHead()`；`htmlAttrs` 每个属性映射到对应 HTML 属性。
- `viewport` 与 `charset` 由框架默认提供（`width=device-width, initial-scale=1` 与 `utf-8`），可用带键的写法改。
- favicon 的字面量路径不走 `cdnURL`，要指向解析后的位置得用 `useHead()` 拼运行时配置。
- **`alt` 在 4.x 只有示例、没有规则句**；替代文本要求属于通用 Web 实践，官方在无障碍页第一句就把这一类划走了。
