点了带 `#comments` 的链接，页面一下就跳到底，没有过渡——你想让它平滑滚过去。改的地方有两个：配置项，或者 `router.options.ts`。

这一篇把滚动这一节的原文与它牵出的配置边界一起收掉，顺便把 480-489 的出口列清楚。

## 三种默认行为

官方一句话全给了：

> Nuxt scrolls to the top on a new route, restores the previous position when the user goes back, and scrolls to hash targets.

三种情形分别对应：**新路由**滚到顶部、**用户后退**时恢复先前的位置、**命中 hash 目标**时滚到那个锚点。

这一句同时是 482 那条"焦点不重置"的对照组——滚动位置框架管了，焦点不管。

## 出口一：scrollBehaviorType

官方对这一项的定性只有六个字："Customize the scroll behavior for hash links."，配置位置与形态是 `router.options`，默认值 `auto`。

自定义路由那一节给的场景与示例正好对着"平滑滚动"这件事：

> You can optionally customize the scroll behavior for hash links. When you set the config to be `smooth` and you load a page with a hash link (e.g. `https://example.com/blog/my-article#comments`), you will see that the browser smoothly scrolls to this anchor.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  router: {
    options: {
      scrollBehaviorType: 'smooth',
    },
  },
})
```

注意官方给的触发条件是**加载带 hash 的页面**，示例 URL 就是 `.../my-article#comments`。也就是说这一项管的是锚点滚动的行为，不是"新路由滚不滚到顶"——那三种默认行为里，这一项只碰第三种（文档未写它如何影响前两种）。

无障碍那一节在这之后加了一句限定，是这一篇要留的要求句：**平滑滚动应当尊重用户的 `prefers-reduced-motion` 设置**。

## 出口二：router.options.ts 里自己写

官方给的第二条路是 "or write your own `scrollBehavior` in `router.options.ts`"，并在同一条句子里指向自定义路由那一节。

这条路存在的原因在配置那侧写着：`nuxt.config` 里能设的路由选项**只有 JSON 可序列化的七个**——

- `linkActiveClass`
- `linkExactActiveClass`
- `end`
- `sensitive`
- `strict`
- `hashMode`
- `scrollBehaviorType`

`scrollBehavior` **要传函数**，所以它不在这份名单里，只能去 `app/router.options.ts`。

同页还有两条相邻事实值得一起记：

**`hashMode`** 的定性是"URL 不会发给服务器、且不支持 SSR"，默认 `false`（这一项与 447、466 提过的"`serverPathFallback` 在 hashMode 下无效"、"`early404` 在 hashMode 下自动关闭"连成一条线）。

**`future.compatibilityVersion: 5` 下路由默认大小写敏感**以匹配 Nitro，要退回不敏感就把 `router.options.sensitive` 设 `false`（官方 `::note` 原话）。

同页还给了一个更进阶的口子：自定义 history——**一个接 base URL 并返回 history 模式的函数，返回 `null` 或 `undefined` 时 Nuxt 回退到默认 history**。

## 三条资源与一条边界

无障碍页末尾列的三条，是官方对"页外规则"的唯一指向：

| 资源 | 地址 |
| --- | --- |
| Web Accessibility Initiative (WAI) | `w3.org/WAI/` |
| MDN: Accessibility | `developer.mozilla.org/en-US/docs/Web/Accessibility` |
| Understanding WCAG 2.1 | `w3.org/WAI/WCAG21/Understanding/` |

要划清的边界：这三条是**去处**，不是承诺。那一节里**没有任何一处写着"按它做即符合某级 WCAG"**（文档未记载），所以合规结论只能来自这三份文档本身与你们自己的评审。

## 自查

- 三种默认滚动：新路由到顶、后退恢复位置、hash 目标滚动；这一项配置只针对第三种。
- `scrollBehaviorType` 默认 `auto`，设 `'smooth'` 后加载带 hash 的页面会平滑滚到锚点；改它之前记住要尊重 `prefers-reduced-motion`。
- 想完整接管滚动只能去 `app/router.options.ts` 写 `scrollBehavior`——`nuxt.config` 侧只开放七个 JSON 可序列化选项。
- `hashMode` 为真时 URL 不发服务端且不支持 SSR，它会连带让 `serverPathFallback`、`early404` 失效。
- cv5 下路由默认大小写敏感，退法是 `router.options.sensitive: false`。
- 三条资源是外部去处，不是达标证明。
